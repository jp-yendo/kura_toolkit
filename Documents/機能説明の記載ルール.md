# 機能説明の記載ルール

機能の名前と説明を書く場所ごとに、記載のレベルと書き方をそろえるためのルール。
機能を追加・変更したときは、このルールに沿って次の 3 か所をそろえて更新する。

| 場所 | 内容 | 記載のレベル |
| --- | --- | --- |
| ダッシュボードの説明 (`features.<id>.desc`。全ロケール) | 2 文の要約 | 何をする機能かが一目で分かる程度 |
| `README.md` / `README-ja.md` の「1. 概要」の各機能 | 箇条書き | 利用者ができることをひととおり (形式・条件を含む) |
| `Documents/システム仕様.md` | 仕様 | 実装・判断の理由まで |

## 共通

- 実際にできることだけを書く。書く前に、画面と `Documents/システム仕様.md` で今の機能を確かめる
- 利用者から見た言葉で書く。内部の名前 (ライブラリ名・ファイル名・パラメーター名など) や専門用語 (LUFS など) は使わない。
  ただし、利用者が目にするもの (Thumbs.db・SVG・字幕の形式名など) はそのまま書く
- 画面の項目名と同じ言葉を使う (例: 「音量をそろえる」を「音量の調整」と言い換えない)
- 名詞を並べて「〜などで加工する」のようにまとめない。動作は「〜したり、〜したりします」と動詞で並べる
- 機能名を 3 つ以上並べるときは「、」で区切る (「音声分離・加工、音声変換、読み上げ」。機能名の中の「・」と区別するため)
- 日本語と英語で同じ内容・同じ順に書く

## 機能名

- 実際にできることの主なものが名前から分かるようにする。単独で使える処理が 2 つある機能は「・」でつなぐ
  (例: 分離しなくても加工だけを使えるため「音声分離・加工」)
- 英語は各語の頭を大文字にし、2 つをつなぐときは「&」を使う (例: 「Audio Separation & Processing」)

## ダッシュボードの説明

- 2 文で書く。日本語は 2 文で 50〜80 文字程度を目安にする (カードの高さをそろえるため)
  - 1 文目: 何を、どうするか。「〜します」で終える
  - 2 文目: その機能ならではの特徴、または主な補助の機能。可能の形 (「〜できます」「〜られます」「〜れます」) で終える
- かっこ・形式の一覧・動作の条件は書かない (README に書く)
- 英語は 2 文とも命令形で始める (例: 「Split songs ...」「Compare the results ...」)

## README の機能の箇条書き

- 1 項目に 1 つのできることを書き、1 文で終える。文末に句点 (英語はピリオド) を付けない
- 並べる順: 主な処理 → 細かな指定・オプション → 結果の比較・確認 → 保存・書き出し → モデルなどの管理 → 学習
- 文末:
  - 利用者が行うこと: 日本語は可能の形 (「〜できます」「〜選べます」など)、英語は命令形
  - アプリが自動で行うこと: 日本語は「〜します」「〜変わりません」など、英語は平叙文
- 形式や対応する環境などの条件は、文の後ろのかっこに書く (例: 「(NVIDIA GPU を搭載した Windows・Linux)」)
- 対応する形式は具体的に挙げ、「・」(英語は「,」) で区切る
- 「アプリ設定」は設定できる項目の一覧のため、「次の項目を設定できます。」の後に項目を名詞で並べる
