# Kura Toolkit システム仕様

## 1. 概要

Kura Toolkit は、以下のツールを 1 つにまとめた Electron 製デスクトップアプリケーション。

| カテゴリ | 機能 | 主に使う外部のツール・ライブラリ |
|---|---|---|
| オーディオ | オーディオ正規化 | ffmpeg / ffprobe (7 章) |
| オーディオ | 音声分離 | audio-separator と UVR のモデル (14 章) |
| オーディオ | 音声変換 (声のモデルの学習を含む) | Applio / RVC (15 章) |
| オーディオ | 読み上げ (声のモデルの学習を含む) | Style-Bert-VITS2 の派生版 (16 章) |
| 動画 | チャプターカット | ffmpeg / ffprobe (8 章) |
| 画像 | SVG 変換 | @neplex/vectorizer (VTracer。9 章) |
| ツール | クリーンアップ | なし (10 章) |

音声機能が使う Python・パッケージ一式・モデルの取得と削除 (13.3) は、各音声機能の画面と不足の案内から
呼び出すダイアログで行う (13.14)。

音声分離・音声変換・読み上げの仕様は 13〜16 章に記す (主な設計上の判断とその理由は 13.13)。

## 2. アーキテクチャ

- Electron (main: CommonJS/tsc、renderer: React + MUI + Vite)
- renderer は HashRouter によるページ遷移 (開発時・配布時とも同一)
- main プロセスは `src/main/services/` に機能実装、`src/main/ipc/` に IPC ハンドラを配置
- preload (`src/preload/index.ts`) が `window.kuraToolkit` として型付き API を公開
- 入力・出力ともにアプリ側の制限は設けない (利用者の入力を尊重する)。入力の大きさ・長さ、設定値・制御タグの値の上限、
  エラーの件数や詳細 (外部プロセスの出力など) の切り詰めは行わない。値として意味を持たないもの (0 以下の話速など) だけを
  誤りとする。メモリは節約するように作り、長い音声や大きなファイルも、全体をメモリに置かずに区切って扱う。
  ライブラリの仕様で全体をメモリに読み込むもの (音声分離・音声変換のライブラリなど) はその仕様に従う
- `src/main/` から `src/renderer/` の import は禁止 (i18n は renderer 専用)。main はエラーコード
  (`FFMPEG_NOT_FOUND` など) を返し、renderer 側で翻訳する (`components/common/errorMessage.ts`)。翻訳の無いエラー
  (OS やライブラリのエラーなど) も本文をそのまま出さず、表示言語の「処理に失敗しました。(詳細)」の文に詳細として添える。
  画面に出す文言 (ファイルを選ぶダイアログの種類の名前を含む) はすべてロケールファイルに置く
- 音声機能 (分離・変換・読み上げ) の推論と学習は、利用者の指示でダウンロードした Python の仮想環境上の
  補助プロセスで行う (13 章)。Python 本体・ライブラリ・モデルはアプリに同梱しない
- アプリは 1 つしか起動しない (`app.requestSingleInstanceLock`)。2 つ目を起動すると、起動中のウィンドウを前面に出して
  (最小化していれば元に戻して) 終わる。ライブラリ・モデル・キャッシュ・作業ディレクトリ (3 章「保存場所」) を複数のアプリが
  同時に書き換えないため

## 3. 設定の永続化

- 保存先: `~/.kura_toolkit/settings.json`
- main プロセスの `services/settings.ts` が管理。読み込み時に既定値と deep-merge して欠損キーを補完し、
  書き込みは一時ファイルへ書いてから rename するアトミック方式
- 設定ファイルが無い場合は、初回の起動として既定値で始める。ファイルがあるのに読めない・JSON として解釈できない・
  オブジェクトでない場合は、ファイルを上書きしない (既定の設定で上書きすると、利用者の設定が失われるため)
  - 起動中は既定の設定をメモリ上で使い、設定ファイルへの書き込みは断る (`SETTINGS_FILE_UNREADABLE`)
  - 起動時はほかの画面を出さず、確認 (`components/settings/SettingsLoadErrorDialog.tsx`) だけを出す
    (既定の設定のまま各機能が動き出さないようにするため)。ファイルの場所と読めなかった理由を示し、次のどちらかを選ばせる
    - 既定の設定で続ける: 読めなかったファイルを同じフォルダに `settings.broken-<YYYYMMDD-HHmmss>.json` の名前で残し、
      既定の設定を保存する (`settings:resetBroken`)。残した場所は通知で示す
    - 終了する: ファイルには触れずにアプリを終了する
- スキーマ (バージョン 1):

```jsonc
{
  "version": 1,
  "app": { "theme": "system | light | dark", "language": "ja | en" },
  "ffmpeg": { "ffmpegPath": "", "ffprobePath": "" },       // 空文字 = PATH から自動検出
  "search": { "threads": 4 },  // ファイル探索に使うスレッド数 (初回起動時に決めて保存する)
  "storage": {                   // 保存場所 (下記「保存場所」)。空文字 = 既定の場所
    "libraryDir": "",            // ライブラリディレクトリ
    "modelDir": "",              // モデルディレクトリ
    "workDir": "",               // 作業ディレクトリ (一時ディレクトリ。空 = OS の一時ディレクトリ)
    "cacheDir": "",              // キャッシュディレクトリ
    "cacheRetentionDays": 30     // キャッシュの保持期間 (日。1 以上)
  },
  "audioNormalizer": {
    "outputDir": "", "targetLufs": -13, "sampleRate": 44100,
    "bitrateMode": "cbr | vbr", "bitrate": 160
  },
  "cleanup": {
    "customDirs": [],            // ユーザーが追加した検索対象ディレクトリ
    "selectedTargets": [],       // 前回検索したときのクリーンアップ対象
    "selectedRoots": []          // 前回検索したときの検索対象ディレクトリ
  },
  "voice": {
    "export": {                  // 分離・変換・読み上げの書き出しで共用 (13.8)
      "format": "mp3 | flac", "sampleRate": 44100, "bitrateMode": "cbr | vbr", "bitrate": 160
    },
    "symbolReadings": { "ja": null, "en": null, "zh": null },         // 記号の読み。null = 言語定義の初期値
    "updatePromptVersion": ""    // 更新の確認を出したアプリの版 (同じ版では 1 回だけ確認する)
  }
}
```

- `search.threads` (探索のスレッド数) は常に実数値を保存する
  - 初回起動時 (設定ファイルが無い、または値が未決定) にだけ
    `max(1, min(4, floor(論理コア数 / 2)))` を算出して保存する。既に値があるときは触らない
  - 設定画面での制限は **1 以上**のみ (上限は設けない)。起動時に決める上限 4 は初期値のためのもので、
    実行時には適用しない
  - ディレクトリを走査する処理 (クリーンアップの検索) はこの値を上限とする
- 保存タイミングは項目の性質で分ける
  - アプリ設定 (テーマ・言語・ffmpeg のパス・探索のスレッド数)・クリーンアップのカスタムディレクトリ: UI 変更時に即時保存
  - 各機能の実行パラメータ (オーディオ正規化の出力設定・クリーンアップの検索条件):
    **その機能を実行したときに、保存済みの値と異なる場合だけ**書き込む。
    入力途中の値をファイルへ書かないため、1 文字打つたびの保存が発生しない
  - チャプターカットと画像 SVG 変換のパラメータ: 保存しない (下記 8 章・9 章)。
    値は zustand ストア上のみで保持し、アプリを起動するたびに既定値へ戻る
  - 保存場所: 作業ディレクトリとキャッシュの保持期間は変えた時点で、ライブラリ・モデル・キャッシュディレクトリは
    移動が完了したときに書き込む
  - 音声機能: 書き出しの設定 (形式・サンプリング周波数・ビットレートモード・ビットレート) は変えた時点で保存する。
    記号の読みは編集ダイアログで保存したときに書き込む。分離・変換・読み上げの実行パラメーターは保存せず
    (プリセットは 13.10)、zustand ストア上のみで保持する

### 保存場所 (`services/storage.ts` / `services/work-dir.ts` / `components/settings/StorageSection.tsx`)

アプリ全体で共有する 4 つの場所。それぞれ独立して変更する (1 つを変えても他は動かない)。
設定が空なら既定の場所を使い、既定の場所は設定ファイルに書き込まない。設定画面の「保存場所」で変更する。

| 場所 | 既定 | 中身 | 変えたとき |
|---|---|---|---|
| ライブラリディレクトリ | `~/.kura_toolkit/libraries` | 外部のライブラリ (Python 本体と、ライブラリごとの仮想環境・ソース一式)。ライブラリごとのディレクトリに分け、今後のライブラリもこの下に追加する | 中身を選んだフォルダへ移動し、そのフォルダをライブラリディレクトリにする |
| モデルディレクトリ | `~/.kura_toolkit/models` | ダウンロードしたモデルと、学習・取り込みしたモデル。分類 (`audio` など) の階層を挟み、ほかの種類のモデルもこの下に追加する | 中身を選んだフォルダへ移動し、そのフォルダをモデルディレクトリにする |
| キャッシュディレクトリ | `~/.kura_toolkit/cache` | 消しても作り直せるもの (ライブラリが作るキャッシュ・分離のモデル一覧と取得元)。ライブラリごとのディレクトリに分ける。保持期間を過ぎたものは起動時に消す | 中身を選んだフォルダへ移動し、そのフォルダをキャッシュディレクトリにする |
| 作業ディレクトリ | OS の一時ディレクトリ (Linux は `~/.kura_toolkit/temp`。使うときに無ければ作る) | 一時ディレクトリ。アプリはその中に処理ごとの `kura_toolkit_<ランダムな値>` フォルダを作り、全機能の一時ファイル (その処理の中で作って使い、消すものだけ) をそこに置く | 選んだ一時ディレクトリを以後の作業ディレクトリにする (移動はしない) |

- ライブラリ・モデル・キャッシュディレクトリは、選んだフォルダをそのままその保存場所として使う (中にフォルダを挟まない)
- 移動と既定の場所に戻す操作は、ライブラリ・モデル・キャッシュのそれぞれで行う (13.2)。既定の場所へ戻した場合は設定を空にする。
  既定の場所に戻す操作は、誤って押さないよう各項目のメニューに置く
- Windows では、設定したパスに ASCII 以外の文字が含まれる場合に注意を出す (C で書かれた一部のライブラリが、Windows で
  ASCII 以外のパスを開けないため)。設定画面の各項目と、ダウンロードの画面 (`storageNonAscii`) に出す
- 保存場所の設定 (ライブラリ・モデル・キャッシュ・作業ディレクトリ) は `saveSettings` で書き込む。先にファイルへ書き、書けた場合だけ
  起動中の設定を変える。書けなければ `SETTINGS_SAVE_FAILED` で失敗させ、起動中の設定も元の場所のまま保つ
  (保存できないまま起動中だけ新しい場所を使うと、次の起動で元の場所を使い、起動中に新しい場所へ置いたものを見失うため)
- 保存場所どうしは重ねられない (同じ場所・一方がもう一方の中。`STORAGE_OVERLAP`)
- 設定ファイルと音声機能のパラメーターのプリセットは `~/.kura_toolkit/` に置く。Electron が管理する状態 (キャッシュなど) だけを
  Electron の既定の場所 (userData) に置き、設定・ライブラリ・モデルとは分ける
- 作業ディレクトリ
  - 設定するのは一時ディレクトリそのもの (既定は OS の一時ディレクトリ。Linux の `/tmp` はユーザー間で共有されるため、
    Linux は `~/.kura_toolkit/temp`)。共用の一時ディレクトリでもよく、空である必要は
    ない。アプリはその直下に、一連の処理ごとに `kura_toolkit_<ランダムな値>` のフォルダを作り、要らなくなったら消す (下表)
    (名前の接頭辞でアプリのものと分かるため、ほかのソフトのファイルと混ざらず、片付けでほかのファイルに触れない)
  - ライブラリ・モデル・キャッシュディレクトリ (またはその中) は選べない (`STORAGE_OVERLAP`)
  - 選んだフォルダが無くなっている場合 (ドライブの取り外し・名前の変更など) は、作らずに処理を止める
    (`WORK_DIR_MISSING`。利用者の知らない場所にフォルダを作らないため)。画面はアプリ設定の「保存場所」の確認を案内する。
    作業ディレクトリを変えるときも、選んだフォルダが無ければ `WORK_DIR_MISSING` で断る
  - 変更は、処理中 (実行中のジョブがある間) と、今の作業ディレクトリにアプリの `kura_toolkit_*` フォルダ (下表) が残っている間
    (作業の結果があるときなど) は断る (`WORK_DIR_IN_USE`。前の場所に残ったものを後から消せなくなるため)。
    確かめる前に、待機中の常駐の補助プロセス (作業ディレクトリに一時ファイルの置き場を持ち続ける) を止めて終了を待ち、
    クリーンアップの一覧にあるものを消し終えるのを待つ (消せなかったものが残っていれば断る。OS の再起動などで
    消せるようになれば、次の起動時の片付けで消える)。設定を保存できなければ失敗とし (`SETTINGS_SAVE_FAILED`)、元の場所を使い続ける
- 作業ディレクトリに置くのは、その処理の中で作って使い、消すもの (中間ファイル・外部のプロセスの作業場所など) だけ。
  最終的に別の場所へ置くもの (ダウンロードしたファイル・展開する書庫・pip のキャッシュ) は、置き場所が別のドライブの
  場合にコピーと削除が発生しないよう、置き場所と同じディスクに直接書く (13.3)。作業ディレクトリの直下に、一連の処理ごとに
  `kura_toolkit_<ランダムな値>` のフォルダを作る (アプリ名の接頭辞の後に意味は持たせず、分類の階層も作らない)。
  ロックされて消せなくても他の処理に影響せず、残ったものは次の起動時に消える。フォルダの場所は、その処理を行う側が
  持つ (機能の作業は、renderer が作る作業の識別子 (ランダムな値) をフォルダ名に使う) (`work-dir.ts`)

| 用途 | 内容 | 消すタイミング |
|---|---|---|
| 機能の作業 (分離・変換・読み上げの画面ごとに 1 つ) | 機能の中で使い続けるもの (音声機能の入力を変換した WAV・候補・重ねた音・移調した伴奏・合成結果) | 機能の中で要らなくなったもの (破棄した候補・作り直した合成結果・読み上げの音声など) はその時点でクリーンアップの一覧に積む。作業全体は別の機能へ移ったとき・新しい作業を始めるとき (13.6) |
| 処理 (1 回ごと) | 1 回の処理の一時ファイル (音声機能の中間ファイル・学習の指示ファイルと学習の途中のデータ・pip の要件ファイル・チャプターカットの一時ファイル) | 処理の完了・エラー・キャンセルのいずれでも、その時点でクリーンアップの一覧に積む |
| 外部のプロセス (1 つごと) | 外部のプロセス 1 つ分の一時ファイル (`TEMP` / `TMP` / `TMPDIR` の向け先。Python・ffmpeg・ffprobe・nvidia-smi・PowerShell のプロセスごとに作る) | そのプロセスが終了した時点でクリーンアップの一覧に積む |

- 必要になった時点で作り、要らなくなった時点でクリーンアップの一覧に積む (`discardLater`)。一覧に積んだものは、
  次の処理を始めるとき (`startJob`) と、機能の画面に入ったとき (`storage:cleanupWork`) にまとめて消す (`runCleanup`。
  完了は待たない)。すぐに消さないのは、終了したばかりのプロセスや再生がファイルを掴んでいて消せないこと (Windows) を
  減らすため。消せなかったものはエラーにせず一覧から外し、次の起動時の片付けに任せる
- 同じ名前で作り直したもの・使い回すもの (`produceFile` の結果、同じ組み合わせの重ねた音・移調した伴奏・合成結果) は、
  一覧に積まれていても一覧から外す (`keepWorkFile`。使っているものを次のクリーンアップで消さないため)
- アプリの終了 (ウィンドウを閉じる・アプリを終了する・終了の信号 SIGINT / SIGTERM) は、実行中の処理のキャンセルとして
  扱う (`main/index.ts` の `before-quit`)。すべての処理をキャンセルし、外部プロセスの終了と各処理の後片付け
  (作りかけのものをクリーンアップの一覧に積む・消す) が終わるのを待ってから終える (`waitForJobsToFinish` と
  `stopAllWorkersAndWait`。待つのは 10 秒まで)。更新のインストールでの終了は更新器に任せる。
  シャットダウン時の強制終了や、開発時に `yarn dev` を止めた場合 (Windows では Electron が強制終了される) は
  後片付けできないため、次の起動時の片付けに任せる
- クリーンアップの一覧のもの (作業ディレクトリの中) は、アプリの終了時には消さない (終了を待たせないため)。終了時に残っていたもの
  (作業の結果) と強制終了で残ったものは、次の起動時に消す (`removeLeftoverWorkFiles`)
- 利用者が意識しない場所 (ライブラリ・モデル・キャッシュのディレクトリ) に残った、前回の起動で完了しなかった導入の
  残りは、記録を持たずに名前で見分けて、次の起動時に裏で消す (`removeInstallLeftovers`)。対象は、強制終了で残った
  作りかけ (`python.staging`・`python.tar.gz`・各ライブラリの `source.staging`・`source.tar.gz`・展開する zip の
  `<名前>.staging`・`manifest.json.tmp`・`cache.json.tmp`) と、意図しない失敗の後に残した取得途中のファイル
  (`.part`。Python 本体とソース一式の書庫・各項目のファイル・分離モデルの置き場所の `*.part`) と `pip-cache`。
  作りかけの声のモデル (`.staging-*`) と学習セットの記録の無い音声は、それぞれの片付けで消す
  - アプリは 1 つしか起動しないため (2 章)、起動した時点で作業ディレクトリにある `kura_toolkit_*` フォルダは、
    すべて前回の残り物になる。起動時に一覧にして、起動を待たせずに裏で消す (新しい処理はランダムな名前のフォルダを
    作るため、残り物と取り違えない)
- ffmpeg・ffprobe・nvidia-smi (`runTool`) と PowerShell (クリーンアップのドライブ一覧) は、作業ディレクトリを使えない場合
  (選んだフォルダが無いなど) だけ、OS の一時ディレクトリのまま起動する (`toolTempEnv`。ffmpeg の検出や音声の解析など、
  作業ディレクトリが無くても動く必要がある処理のため)
- キャッシュディレクトリ (`cache-dir.ts`)
  - 置くのは消しても作り直せるものだけ。中はライブラリごとのディレクトリ (`audio-separator`・`applio`・`style-bert-vits2`)
    に分ける。各ライブラリが自分で作るキャッシュ (numba・matplotlib・Hugging Face・torch など。13.4) は、そのライブラリの
    ディレクトリの下に書かせ、中身はライブラリに任せる
  - 古いものは使うたびに消すのではなく、起動時にまとめて消す (`removeExpiredCache`。起動は待たせない)。ファイルごとに、
    アプリが読み書きするもの (分離のモデル一覧と取得元) は利用記録 (`cache.json`) の最終利用日時で、ライブラリが作るもの
    (使ったことをアプリが知れないもの) は最終更新日時 (作った・作り直した日時) で判断し、保持期間
    (`storage.cacheRetentionDays`。既定 30 日) を過ぎたものだけを消す。そのライブラリを使い続けていても、古いファイルは消える
    (次に使うときにライブラリが作り直す)。最終アクセス日時は使わない (OS や設定によって更新されないため)
  - 消せなかったもの (使用中など) はエラーにせず次回に回す。中身が空になったフォルダも消す
  - パッケージ一式を消すと、キャッシュディレクトリのそのライブラリのディレクトリも消す (使うものが無くなるため)

## 5. ジョブ管理 (長時間処理)

- `services/job-manager.ts` が管理。jobId は renderer が `crypto.randomUUID()` で生成し、
  開始 invoke の引数として渡す。invoke の解決 = ジョブ完了
- 進捗・ログ・発見アイテムは `job:event` チャンネルで push する
  (`JobEvent = { jobId, kind: 'progress' | 'log' | 'item' | 'scan' | 'wait', percent?, current?, total?, message?, payload?, scan?, waiting?, phase? }`)
  - `scan` はディレクトリ走査の進捗 (総数が事前に分からないため `percent` を持たず、一定間隔でまとめて送る)
  - `wait` は GPU の順番待ちの開始 (`waiting: true`) と終了 (`waiting: false`) (13.5)
  - `phase` は今の処理の段階 (`id`・段階の中の進み具合 `fraction` (0-1)・回数で数える段階の `current` と `total`)。
    11 章の進捗ダイアログが段階の名前と残り時間を示すのに使う
- `job:cancel` で登録済み子プロセス (ffmpeg 等) を kill し、ループ系はフラグ確認で中断する。
  キャンセルは例外ではなく `{ cancelled: true }` を含む結果として返す
  - `onJobCancel(jobId, handler)` でキャンセル時の処理を登録できる (戻り値で登録を解除する)。
    音声機能は Python の補助プロセスをプロセスツリーごと終了させるのに使う
  - 音声機能の処理 (分離・変換・読み上げ・学習など) は、キャンセルを `KURA_CANCELLED` のエラーとして
    返すものがある。renderer は `components/voice/voiceErrors.ts` の `isCancelledError` で判定し、
    エラーとしては表示しない
- ウィンドウクローズ時は全ジョブを自動キャンセルする

## 6. ffmpeg 実行基盤

- `services/ffmpeg/ffmpeg.ts` / `ffprobe.ts`
- パス解決: 設定値優先。空なら PATH の各ディレクトリを `fs.access` で走査して検出
  (`where`/`which` の出力パースは文字コード依存のため行わない)。ffprobe が未設定で ffmpeg のパスが
  設定済みの場合は、ffmpeg と同じディレクトリを優先して探す
  - macOS / Linux では Finder やランチャーから起動すると PATH が最小限になるため、
    PATH に加えて既定のインストール先も探索する
    (macOS: `/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`、`/sw/bin`、`/usr/bin`、`/bin`。
    Linux: `/usr/local/bin`、`/usr/bin`、`/bin`、`/snap/bin`、`/var/lib/flatpak/exports/bin`)
- 実行は必ず `spawn(cmd, argsArray)` (shell 不使用) で行い、日本語パス・cp932 の引用問題を回避する
- 出力のパースは `-print_format json` と `-progress pipe:1` の機械可読出力のみに依存する
- 進捗は `-progress pipe:1 -nostats` の `out_time_us` を対象長で割って算出する
- 未検出・失敗はエラーコード付きメッセージ (`FFMPEG_NOT_FOUND` / `FFPROBE_NOT_FOUND` /
  `FFMPEG_FAILED: <stderr>` / `FFPROBE_FAILED: <stderr>` / `KURA_CANCELLED`) で表現する

## 7. オーディオ正規化 (`services/audio-normalizer.ts`)

- 一覧に加えたとき (`audio:probe`): 加えたファイルの長さとチャンネル数を `ffprobe -show_streams -show_format` の JSON から
  取得して一覧に示す (調べられないファイルは空欄。解析・正規化のときにエラーとして示す)。LUFS は解析が要るため解析のときに求める
- 解析:
  - チャンネル数: `ffprobe -show_streams` の JSON から取得 (一覧に加えたときに取得したものを、解析の結果で更新する)
  - ラウドネスと True Peak: `ffmpeg -i <file> -af loudnorm=I=-16:LRA=11:TP=-1.5:print_format=json -f null -` の
    stderr 末尾の JSON ブロックから `input_i` (LUFS) と `input_tp` (dBTP) を抽出 (測った値のため、指定した目標の値の
    影響は受けない)。一覧には LUFS を示し、どちらも正規化で使うために一覧に覚える。無音などで測れないものは空欄
- 正規化: 曲全体に一定量の音量をかけるだけにし、曲の中の強弱 (盛り上がりや静けさ) を保つ
  - かける量 = 目標の LUFS - 測った LUFS。ただし、上げた後の True Peak (測った True Peak + かける量) が上限の
    -1.5 dBTP を超える場合は、上限に収まる量までにする (その曲は目標に届かない。結果のダイアログに「目標まで
    上げられなかったファイル」として、仕上がりの LUFS とともに示す)。上限は曲全体で最も大きいピークから決めるため、
    曲のどの部分も上限を超えず、リミッターなどで一部だけ音量を変えることもない。上限に余白があるのは、非可逆圧縮での
    書き出しやサンプリング周波数の変換でピークが少し上がるため
  - 測った値は解析で求めたものを使う (解析した曲は測り直さない)。解析していない曲 (測った値が無い曲) は、正規化の中で先に
    測ってから書き出す (測った値は一覧に反映する)。測れない曲 (無音など) は書き出さず、失敗として示す
    (`LOUDNESS_UNKNOWN`)。元のファイルを上書きした曲は、一覧の測った値を消す (前のファイルの値のため。次の正規化で
    測り直す)
  - loudnorm による正規化 (2 回目) は使わない。loudnorm は、測定値を渡し、指定した LRA が曲の LRA 以上で、上げた後の
    ピークが上限以下の場合だけ一定量の上げ下げ (linear) になり、それ以外は曲の中で音量を細かく調整する方式 (dynamic) に
    切り替わって強弱が変わるため
  - コマンド: `-af volume={かける量}dB -map_metadata 0 -map 0:a:0 {映像の指定} -c:v copy {形式ごとの引数}` (タグを保持)。
    映像は、元の形式のままなら `-map 0:v?` ですべて写す (動画の映像・アルバムアート)。ほかの形式では、アルバムアート
    (`attached_pic`) を入れられる形式 (MP3・FLAC・AAC・ALAC) に限って、それだけを写す (どの形式も動画の映像は入れられない
    ため、動画ファイルは音声だけになる。Ogg Vorbis・Opus・WAV にはアルバムアートを入れない)
  - 仕上がりの LUFS は、非可逆圧縮 (MP3 など) では高い音域が削られるため、目標より少し下がることがある
  - 全体の進み具合の配分では、測る必要がある曲は測る分 (読み込み 1 回分) を足し、ファイルの中の前半を測定、後半を
    書き出しに当てる
- 出力形式 (`outputFormat`): 「元の形式のまま」と、書き出しの形式 (MP3 (既定)・FLAC・Ogg Vorbis・Opus・AAC (M4A)・WAV・
  ALAC (M4A)) から選ぶ。書き出しの形式と形式ごとの設定は、音声機能の書き出し (13.8) と共通 (`shared/audio-format.ts`・
  `components/common/AudioFormatFields.tsx`)。音声の無いファイルは書き出さず、スキップとして示す (`NO_AUDIO_STREAM`)
  - 元の形式のまま: 選択肢は出さず、元のファイルの値を引き継いで同じコーデックで書き出す (mp3→libmp3lame / aac / vorbis→
    libvorbis / opus→libopus / flac / alac / pcm_* はそのまま。ほかのコーデックはスキップして示す (`UNSUPPORTED_CODEC`))。
    サンプリング周波数とチャンネル数は指定しない (音量を変えるだけでは変わらない)。FLAC・ALAC はビット数 (16 / 24bit) を、
    PCM はコーデックでビット数を引き継ぐ。非可逆はビットレートを、音声のストリームの値 (無ければ、映像の無いファイルに
    限ってファイル全体の値) で引き継ぐ。固定ビットレートのものは同じ値になり、可変ビットレートのもの (平均の値しか
    分からない) と Vorbis (ファイルに書かれた目安の値) は、同じくらいのビットレートになる。非可逆は書き直すたびに
    わずかに音質が落ちる
  - 書き出しの形式の指定は 13.8 を参照
- 出力: 出力先ディレクトリ + 入力と同じ名前。書き出しの形式を選んだ場合は、拡張子をその形式のもの (`.mp3`・`.flac`・
  `.ogg`・`.opus`・`.m4a`・`.wav`) にする。出力先が未指定の場合は入力と同じディレクトリになり、出力の名前が入力と同じに
  なる場合 (元の形式のまま、または入力と同じ拡張子の形式) は**元のファイルの上書き**になる。実行前チェックも、この出力の
  名前で判定する
  - 出力は常に出力先の一時ファイル (`{名前}.kura-tmp{拡張子}`) へ書き、成功してから `rename` で正式な名前にする。
    途中で失敗・キャンセルした場合は一時ファイルだけを削除するため、上書きするはずだった既存のファイル
    (元のファイルを含む) はそのまま残る。元のファイルの上書きでは、ffmpeg が読み込み中のファイルへ直接書けないためでもある
  - 実行前チェック (`audio:checkOutputs`): 出力パスの決定規則は main が持ち、renderer は
    正規化ボタンを押した時点で結果を受け取って次のように分岐する
    - `duplicated` (複数の入力が同じ出力パスになる。別ディレクトリの同名ファイルを 1 か所へ
      出す場合) が 1 件でもあれば、**どう実行しても互いを上書きするため実行そのものを止める**
      (確認ではなく警告通知)。`normalizeFiles` 側でも開始前に `DUPLICATE_OUTPUTS` を投げる
    - `existing` (既に存在する出力パス) があれば確認ダイアログで一覧を示し、承認するまで実行しない。
      出力先が空欄のときは入力ファイル自身が必ず対象になる
    - パスの比較は Windows のみ大文字小文字を無視する (`process.platform` で切り替え)
- 入力の追加: ファイルの追加・ディレクトリの追加・ドラッグ&ドロップに対応する。
  ディレクトリはサブディレクトリまで再帰的に走査し (`files:collect`)、対象拡張子の音声ファイルだけを
  名前順に取り込む (加えたファイルの長さとチャンネル数をその場で調べる)。renderer からはファイルとディレクトリを判別できないため、
  ドロップされたパスは絞り込まずに main へ渡し、展開と絞り込みは main が行う
- 出力設定 (出力先・ターゲット LUFS・出力形式と形式ごとの設定) は画面内の状態として編集し、
  解析または正規化を実行したときに保存済みの値と比較して、異なる場合だけ settings へ書き込む
- 画面構成: 上のボタン列 (追加・一覧クリア)、解析/正規化ボタン、出力設定の枠は高さを固定し、
  ファイル一覧が残りの高さを埋める。行があふれた分は一覧の枠内でスクロールする
  (見出し行は `stickyHeader` で残す)。ウィンドウが低くて全体が収まらない場合は
  一覧を最低 180px 確保したうえでページ側がスクロールする
- ファイル一覧は `tableLayout: fixed` で列幅を固定する (ディレクトリ 40% / 長さ 96px / チャンネル 112px /
  LUFS 88px / 残りがファイル名)。長さは「分:秒」(1 時間以上は「時:分:秒」)。**全ての列で折り返しを行わず、行の高さを 1 行に揃える**。
  ファイル名とディレクトリは収まらない分を末尾省略し、全文は `title` 属性 (ホバー) で確認できる
- エンコードと入力の検証の補足:
  - libmp3lame の CBR は `-b:a` の指定だけで行い、`-cbr 1` は付けない (`-cbr` は libopus 用の
    オプションで、libmp3lame では使われず「Codec AVOption cbr has not been used for any stream」の
    警告が出るだけのため)
  - サンプリング周波数の選択肢は 8000 / 11025 / 12000 / 16000 / 22050 / 24000 / 32000 / 44100 / 48000 Hz
  - VBR の品質値は、ビットレートの全選択肢を上記のとおり実効ビットレートに対応付ける
  - チャンネル数とコーデックは ffprobe の JSON 出力から判定する (stderr の文言はロケールや出力書式に
    依存するため)
  - libopus は 8000/12000/16000/24000/48000 Hz しか受け付けず、既定の 44100 Hz では必ず
    エンコードに失敗する。エンコーダが libopus のときは指定値以上で最も近い対応値へ丸めてから
    `-ar` に渡す
  - ターゲット LUFS の入力を loudnorm の有効範囲 (-70〜-5) で検証する

## 8. チャプターカット (`services/chapter/`)

動画のチャプター情報の取得 (probe)、範囲の切り出し (cut)、分割 (split) を行う。
切り出しと分割は、ストリームコピーとフレーム精度の再エンコード (accurate) のどちらでも行える:

- probe: `ffprobe -show_chapters` / `-show_streams -show_format` の JSON からチャプター・ストリーム情報を取得
  - `ChapterProbeResult.streams` に各ストリームの種別・コーデック・解像度・チャンネル数・
    サンプルレート・ビットレート・言語・タイトルを整形して含める。
    renderer は「チャプター一覧」見出しの**ファイル情報ボタン**から、この内容をダイアログで表示する
    (常時表示はせず、読み込んだ時点の解析結果をいつでも確認できるようにする)
- cut: 開始チャプター〜終了チャプター (省略時は最終) の範囲を切り出す
  - ストリームコピー時は開始点を直前の映像キーフレームへ吸着
    (`packet=pts_time,flags` を探索窓 30 秒から 4 倍ずつ拡大しながら走査)
  - accurate 時は元コーデック・ビットレート・pix_fmt を引き継いで再エンコード
    (VIDEO_ENCODERS/AUDIO_ENCODERS マップ、ビットレート不明時は crf 既定値または 64000×ch の概算)
  - 2 パス構成: pass1 で `-ss/-to` 切り出し (`-map 0 -map -0:d`、`-avoid_negative_ts make_zero`)、
    出力実測 (映像 start_time のずれ・巻き戻り) で基準を補正した FFMETADATA を生成し、
    pass2 で `-map_metadata 0 -map_chapters 1 -c copy -copyts` により埋め込み
    - 全体のメタ情報 (タイトル・作者・説明など) は入力から引き継ぎ、チャプターだけ
      FFMETADATA から取り込む。`-map_metadata 1` にすると FFMETADATA の内容で全体が
      置き換わり、元のタグが消える。分割時も各パートが同じ扱いになる
  - **実際の切り出し開始位置の実測**: `-ss` にキーフレームを指定しても、デマルチプレクサが
    さらに手前のキーフレームへ巻き戻ることがある (mkv で頻発。cue の粒度による)。
    ここを取り違えるとチャプター位置と字幕の時刻がまとめてずれるため、
    `出力の長さ` から開始位置を逆算し、内容は必ずキーフレームから始まることを利用して
    近傍のキーフレームへ吸着させる (`findNearestKeyframe`)
    - mkv はストリーム単位の長さ (`stream.duration`) を返さないため、
      コンテナ全体の長さ (`format.duration`) で代用する。この代用が無いと補正が働かない
  - **字幕とカバーアートは pass1 から必ず除外する** (`-map -0:s` と attached_pic の除外)。
    字幕には切り出し開始より前から表示され続けているパケットがあり、これを pass1 に含めると
    `-avoid_negative_ts make_zero` の基準がその古い時刻になり、映像・音声を含む全体の時刻が
    ずれる (出力の先頭が 0 秒にならず、字幕トラックだけが数十秒前方にずれて再生時に表示されない)。
    カバーアートも同じ理由で除外する (mp4 の attached_pic は pts=0 のため基準を 0 に固定してしまう)
  - 字幕は範囲ごとに個別のファイルへ切り出し、pass2 で入力として合流させる
    - テキスト字幕 (srt/ass/ssa/vtt): 単体抽出して TS 側で時刻を再構成する
      (`shiftTextSubtitles`。範囲外のイベントは捨て、開始をまたぐものは 0 に丸める)
    - **VOBSUB (dvd_subtitle) で表示領域の大きさを持たない場合** (mp4 に格納されたものは
      コンテナ側にしか大きさが無い): そのまま取り出すと大きさが失われ、再生時に
      既定の 720x480 として拡大されて**巨大化・色化け**する (VLC) か、**表示されない** (MPC)。
      この場合は映像と同じ大きさを `-canvas_size` に与えて同一コーデックで作り直し、
      字幕自身に大きさを持たせる。再エンコード時は時刻が元のまま残るため
      `-output_ts_offset` で切り出し開始を 0 に揃える
    - それ以外 (PGS・mov_text 等): `-copyts` + 入力側/出力側の `-ss` で範囲を切り出す
      (出力側 `-ss` により切り出し開始前のパケットが落ちる。字幕はフレーム間の依存が無いため
      映像と違って途中から切り出しても問題ない)。pass1 の実測とのずれは pass2 の
      `-itsoffset` で吸収する
    - pass2 では `-map {n}:s` で字幕だけを取り込む (一時ファイルにも mp4 のチャプター用
      トラックが付くため)。言語・タイトルのタグと既定/強制フラグ (`-disposition:s:N`) を
      元ストリームから引き継ぐ。指定しないと ffmpeg が入力ごとに既定フラグを立て、
      既定の字幕が複数ある状態になってプレイヤーの選択が変わってしまう
  - 出力名: `{入力ベース名}-{fromラベル}-{toラベル}{拡張子}` (ラベルはタイトル優先、
    Windows 禁止文字をサニタイズ)。出力先は指定ディレクトリまたは入力と同じ場所
  - **ビットマップ字幕 (VOBSUB / PGS 等) がある場合、mp4 系の指定でも mkv で書き出す**
    (`resolveSubtitleFriendlyOutput`)。理由は次のとおりで、拡張子を変えた場合はログに残す
    - PGS は mp4 に格納できない
    - VOBSUB は mp4 だと表示領域の大きさとパレットを ffmpeg が元の形で書けず、
      VLC で巨大化・緑色化する (MPC は問題なし)。元ファイルは正常に再生できるため、
      ffmpeg が書く mp4 の字幕サンプル記述を VLC が解釈できないことが原因。
      mkv では両プレイヤーとも正常に表示できる
  - 切り出しモードでは出力ファイル**名**を明示指定でき、指定時は自動命名より
    優先される。**出力先は常に出力先ディレクトリで決まり、ファイル名側には出力先を持たせない**
    (出力先の指定が 2 か所に分かれるのを避けるため)
    - renderer: ファイル名の入力欄はテキスト入力のみ (ファイル保存ダイアログは使わない)。
      パスを貼り付けるなどしてディレクトリ部が混ざった場合は、その部分を出力先ディレクトリ欄へ移し、
      ファイル名欄には最後の要素だけを残す
    - main (`naming.ts` の `namedOutputPath`): 受け取った名前も `path.basename` で最後の要素だけを使い、
      禁止文字をサニタイズする。拡張子が無い場合は ffmpeg が出力形式を決められないため、
      入力と同じ拡張子を補う
- split: 指定チャプター群の直前を分割点として複数範囲に分割し、各範囲を cut と同一処理で出力。
  出力名の重複は処理前に検出してエラー (`DUPLICATE_OUTPUTS`)
- 出力先の決定 (範囲の算出と出力名の生成) は `planCut` / `planSplit` に集約し、実行前チェックと
  本処理の両方から同じ関数を使う。規則が 2 か所に分かれて食い違うのを防ぐため
- 実行前チェック (`chapter:checkCut` / `chapter:checkSplit`): 生成される出力パスと、そのうち
  既に存在するものを返す。renderer は実行ボタンを押した時点で呼び出し、既存ファイルがあれば
  一覧付きの確認ダイアログを出して、承認するまで実行しない
- 一時ファイル (pass1 の出力・切り出した字幕・カバーアート・チャプター情報) は作業ディレクトリの
  処理用のフォルダに置き、成否・キャンセルを問わず範囲ごとの処理の終わりに消す (3 章「保存場所」)。
  出力先に書くのは出力のファイルだけ (書き終えるまでは下記の一時的な名前)
- 出力は pass2 で出力先の一時ファイル (`{名前}.kura-tmp{拡張子}`) へ書き、成功してから正式な名前にする
  (`produceFile`)。失敗・キャンセルした場合は一時ファイルだけを消すため、上書きするはずだった既存のファイルはそのまま残る
- renderer からは、チャプターを配列の添字で指定する (利用者はチャプター一覧の UI で選ぶ)
- 画面構成: ファイルを読み込むまではドロップ領域がページ全体の高さを占める。読み込み後は
  上部の細いバー (高さ 72px、読み込み中のファイルパスを表示) に切り替わり、
  チャプター一覧が残りの高さを埋めて、あふれた行は一覧の枠内でスクロールする
  (見出し行は `stickyHeader` で残す)
  - 一覧の枠は `Panel` 自身をスクロール枠にする。`TableContainer` の `component={Panel}` は
    使わない。MUI は `sx` を className に変換して渡すが `Panel` は className を受け取らないため、
    レイアウト指定 (flex・overflow) が全て捨てられてページ全体がスクロールしてしまう
- **設定は一切保存しない**。出力先ディレクトリ・フレーム単位で正確に切り出す・出力ファイル名・
  モード・チャプターの選択はすべて `stores/chapterStore.ts` の状態として保持し、
  アプリを起動するたびに既定値 (出力先は空文字 = 入力と同じディレクトリ、accurate は false) へ戻る。
  出力先と accurate は入力ファイルを変えても引き継ぎ、出力ファイル名は入力ごとに破棄する
- エラーコード: `NO_CHAPTERS` / `INVALID_RANGE` / `NO_SPLIT_POINT` / `DUPLICATE_OUTPUTS` / `OUTPUT_EQUALS_INPUT` /
  `WORK_DIR_MISSING` (選んだ作業ディレクトリが無い。3 章「保存場所」)

## 9. 画像 SVG 変換 (`services/vectorizer.ts`)

- `@neplex/vectorizer` (vtracer の NAPI バインディング、非同期 API) を使用。外部プロセスなし
- パラメータは vtracer と同一 (colorMode / hierarchical / filterSpeckle / colorPrecision /
  layerDifference / mode / cornerThreshold / lengthThreshold / spliceThreshold、maxIterations=10 固定)
- **パラメータは settings.json へ保存しない**。既定値は `stores/vectorizerStore.ts` の
  `DEFAULT_VECTORIZE_PARAMS` に持ち、値は画像・変換結果と同じくストア上のみで保持する。
  そのためアプリを起動するたびに既定値へ戻る (画面を行き来しただけでは戻らない)
- 入力: png / jpg / jpeg / bmp / gif / tiff。元画像のプレビューは main が `kura-media://` の URL を返し、img で表示する
  (画像の中身を renderer へ文字列で渡さないため)。SVG の変換結果は main が作業ディレクトリのファイルに置き
  (最後の 1 つだけ。画像を選び直すか変換し直すと前のものは片付ける)、同じく URL で表示し、保存はそのファイルを写す
- 画面構成: 左が元画像と SVG プレビューの上下 2 分割、右が変換パラメータ (幅 320px 固定)
  - 上下の仕切りは `SplitPane` でドラッグして高さを配分できる (初期は 1:1、上下とも最低 15%)。
    配分は保存せず、画面を開き直すと 1:1 に戻る
  - SVG プレビューは `ZoomableImage` で拡大縮小できる。見出しの右にズーム操作
    (縮小・現在の倍率 = クリックで実寸・拡大・全体表示) を置く。Ctrl + ホイールでも拡大縮小し、
    枠からはみ出しているときはドラッグで表示位置を動かせる
  - 倍率は SVG の実寸 (svg 要素の width/height) に対する比率。全体表示では枠に収まる倍率で表示し、
    実寸より大きくは拡大しない。変換し直すと全体表示に戻る
- ネイティブモジュールのため electron-builder の `asarUnpack` に `**/node_modules/@neplex/**` を指定

## 10. クリーンアップ (`services/cleanup.ts` / `cleanup-targets.ts` / `dir-walker.ts`)

- 対象 11 種。**対象の一覧は OS によらず共通**で、
  プラットフォームごとに項目が増減することはない。OS による差があるのは Zone.Identifier の
  検出方法のみ (下記):
  - `Zone.Identifier` — 現れ方がプラットフォームで異なるため 2 通りの検出を行う (対象自体は全環境で利用可能)
    - Windows: NTFS の代替データストリーム。`path + ':Zone.Identifier'` の有無で検出し (判定方法は下記)、
      削除は `fs.unlink` (ゴミ箱へは移動できないため。本体ファイルは残る)。
      ファイルごとに判定するため、この判定は Windows でのみ実行する
    - Windows 以外: Windows からコピーしたり書庫を解凍すると、ADS を保持できないファイルシステム上では
      `元のファイル名:Zone.Identifier` という通常のファイルとして現れる。ファイル名がこの接尾辞で
      終わるものを検出し、通常のファイルとしてゴミ箱へ移動する。
      Windows のファイル名に `:` は使えないため、この判定は全環境で実行しても誤検出しない
      (`Zone.Identifier` 単体や `x:Zone.Identifier.bak` のような名前は対象外)
  - ファイル名完全一致: `Thumbs.db` / `.DS_Store`
  - 前方一致: `._*`
  - ディレクトリ名完全一致: `.AppleDouble` / `.fseventsd` / `.Spotlight-V100` / `.AppleDB` /
    `.AppleDesktop` / `.TemporaryItems` / `Network Trash Folder`
- 検索対象: ホームディレクトリ + ドライブ/ボリューム列挙 + カスタムディレクトリ (settings に保存)
  - Windows: WMI (`Get-CimInstance Win32_LogicalDisk` を PowerShell 経由で JSON 取得、
    対象フィールドは ASCII のみ) の `DriveType` を使用し、CD/DVD 等の光学ドライブ (DriveType=5) は
    書き込み不可のため列挙から除外する。リムーバブル (2) は「(USB)」、ネットワーク (4) は「(NW)」を
    ラベルに付与。メディアの入っていないリムーバブルスロットはアクセス確認で除外。
    WMI が使えない環境では A:-Z: の存在確認 (`fs.stat`) によるフォールバック列挙 (種別判定なし)
  - macOS: `/Volumes` 配下のマウントポイントを列挙。Linux: `/media`、`/media/<user>`、
    `/run/media/<user>`、`/mnt` を列挙。いずれも `fs.access(W_OK)` で書き込み権限を確認し、
    光学メディアや読み取り専用のディスクイメージを除外する (権限の確認のみで書き込みは行わない)。
    容量は `fs.statfs` で取得
- 除外 (ディレクトリ名で判定、大文字小文字無視。プラットフォームごとに切り替え):
  - Windows: `Program Files` / `Program Files (x86)` / `Windows` / `AppData` / `ProgramData` /
    `Recovery` / `$Recycle.Bin` / `System Volume Information`
  - macOS: `Library` (巨大で走査が長時間化するため) / `Applications` / `System` / `private` /
    `.Trash` / `.DocumentRevisions-V100` / `.MobileBackups` / `.PKInstallSandboxManager*`。
    加えて `.app` で終わるディレクトリ (アプリケーションバンドル) は署名を壊さないため走査しない
  - Linux: `proc` / `sys` / `dev` / `run` / `boot` / `lost+found` / `.Trash` / `.Trash-1000`
- 走査 (`services/dir-walker.ts` + `workers/dir-walker-worker.ts`): 反復 (スタック) 方式、
  シンボリックリンクは辿らない、アクセス不可はスキップ。対象ディレクトリにマッチした場合は配下を走査しない。
  判定そのもの (対象の定義とディレクトリ 1 個ぶんの走査) は `services/cleanup-targets.ts` にある。
  **ワーカーから読み込むモジュールは electron に依存させない** (ワーカーからは electron を使えない)
  - **`worker_threads` で並列化する**。スレッド数は `search.threads`。1 のときはワーカーを起こさず
    同一プロセスで走査し、ワーカーの起動に失敗した場合も同じ経路へ落として必ず動くようにする
    (そのときは黙って遅くならないよう警告をコンソールへ出す)
  - **asar 内のファイルはそのまま Worker のエントリにできる**ため、`asarUnpack` での展開も
    `app.asar.unpacked` へのパス置換も不要 (Electron 43 の配布ビルドで、asar 内のワーカーが
    起動して走査まで完了することを実測で確認済み)。ワーカー内の `require` も asar 内で解決される
  - ワーカー内では**同期 fs (`readdirSync` / `statSync`) を使う**。ワーカーのイベントループは
    塞いでよく、非同期版の libuv ディスパッチ往復を丸ごと省けるため
  - 作業単位は「ディレクトリ 1 個」と「ADS 判定だけを行うファイル群 (512 件単位)」の 2 種類。
    **ADS 判定をディレクトリから切り離せるようにしているのは、ファイルが数万ある単一ディレクトリが
    1 スレッドに固定されて並列化が効かなくなるため**
  - **ワーカーが 1 つでも落ちた場合は、逐次走査でやり直す**。落ちたワーカーに渡してあった分は
    取り戻せず結果が欠けるため、検出漏れを黙って返さないようにする
  - ワーカーは受け取ったディレクトリを起点に自分のローカルキューで再帰し、
    **手が空いたワーカーがいるときだけ**キューを分けて親へ返す (spill)。
    1 ディレクトリごとに親と往復すると、走査そのものよりメッセージの往復が高くつくため。
    手が空いたワーカーの数は `SharedArrayBuffer` 上のカウンタで共有する
  - 走査を始める前に、main 側でルートの浅い階層 (最大 2 階層) だけを展開してから配る。
    序盤に 1 スレッドしか動けない状態を避けるため
  - キャンセルは `SharedArrayBuffer` 上のフラグを `Atomics` で共有し、メッセージの往復を待たずに
    全ワーカーへ伝える
- ADS (Zone.Identifier) の判定は `fs.statSync(path + ':Zone.Identifier', { throwIfNoEntry: false })`
  を使う。存在しないときでも例外も Promise も生成しないため、`fs.open` より速く判定でき、
  走査ファイル数ぶん効く
  - **ディレクトリ一覧から ADS の有無を知る手段は Windows に無い**ため、ファイルごとの判定は避けられない。
    ディレクトリ列挙が返す `FILE_ATTRIBUTE_*` に ADS の有無を示すビットは無く、
    ストリーム列挙 API (`FindFirstStreamW` 等) はファイル単位。MFT の直読みは管理者権限が必要。
    `dir /r` は一覧に ADS を混ぜて出せるが、内部は結局ファイル単位のストリーム列挙で `statSync` より遅い
  - **ボリューム単位で判定を省くこともできない**。`Win32_LogicalDisk.FileSystem` も
    `GetVolumeInformation` の `FILE_NAMED_STREAMS` も `::$DATA` プローブも当てにならず、
    FAT32 かつ名前付きストリーム非対応と申告しながら実際には ADS を保持するクラウドドライブ
    (Google ドライブ) が存在する
- 進捗: 検索済みディレクトリ数・発見件数・スレッドごとの現在位置を、
  **150 ms ごとにまとめて** `job:event (kind='scan')` で push する。
  総ディレクトリ数が事前に分からず完了予測できないため進捗バーは出さない
  (画面側の見せ方は「11. UI 構成」の進捗ダイアログを参照)。
  削除は総数が分かるため、確定バーと `n / m` を出す
- 削除: 通常のファイル/ディレクトリは `shell.trashItem` でゴミ箱へ移動。
  Windows の ADS (`kind: 'ads'`) のみ `fs.unlink` で直接削除する
- 削除後は失敗項目のみ一覧に残し、再検索を選択できる
- 検索対象ディレクトリの並びは、ユーザープロファイル / ボリューム / カスタム の 3 区分にする
  - ボリュームとカスタムは見出し自体がチェックボックスになっており、配下をまとめて切り替えられる。
    一部だけ選択されている場合は中間状態で表示する
  - 実際に検索へ渡すのは配下の項目 (葉) のパスのみで、見出しは操作用の要素として扱う
  - ボリュームは列挙結果が 1 件以上あるときだけ表示する。カスタムは「ディレクトリを追加...」の
    置き場として、項目が無くても常に表示する
  - 見出しのチェックが全選択の役割を果たすため、検索対象側に「全てチェック」ボタンは置かない
    (クリーンアップ対象は区分が無く 11 項目あるため、そちらには置く)
- 画面構成: クリーンアップ対象と検索対象ディレクトリの枠は内容の高さに合わせて広がり内部スクロールを持たない。
  結果一覧が残りの高さを埋め、あふれた分はその枠内でスクロールする。
  全体が画面に収まらない場合はページ側でスクロールする
- 検索して対象が 0 件だった場合は、閉じるまで残るダイアログで通知する
  (一瞬で消える通知では見落とされるため)
- 検索条件 (クリーンアップ対象と検索対象ディレクトリ) の保存と復元:
  - 検索を実行したときに、保存済みの条件と異なる場合だけ settings へ書き込む
    (並び順の違いは同一とみなし、同じ条件での再検索では書き込まない)
  - 起動後の最初の 1 回だけ設定から復元する。画面を行き来しただけでは
    選択が巻き戻らないようにするため、ストア側で復元済みかどうかを持つ
  - 取り外したドライブなど一覧に無くなった検索対象は、一覧の読み込み後に選択から外す
    (画面に出ていない対象が検索に渡らないようにするため)
- macOS の権限 (フルディスクアクセス):
  - アプリはサンドボックス外のため、デスクトップ・書類・ダウンロード・外部/ネットワークボリューム
    へのアクセスは entitlements ではなく TCC に従う。未許可の場合 `readdir` は EPERM となり
    静かにスキップされてしまうため、`cleanup:getCapabilities` で権限を判定して画面上部に案内を表示する
  - 判定は TCC 保護領域 (`~/Library/Application Support/com.apple.TCC`、`~/Library/Safari`) の
    読み取り可否で行う (副作用のない読み取りのみ)。判定できない場合は誤った警告を避けるため許可済み扱い
  - 案内には「システム設定を開く」(`x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`)
    と「再確認」ボタンを置く。許可の反映にはアプリの再起動が必要な旨も文言に含める
  - TCC ダイアログに表示される利用目的は `electron-builder.yml` の `mac.extendInfo`
    (`NSDesktopFolderUsageDescription` など) で定義する。未定義だとダイアログが出ずに拒否される場合がある

- 進捗ダイアログ (`components/common/ProgressDialog.tsx`) は全機能で共用する。
  受け取る項目は、進捗バー (`percent` / `showProgressBar`)、件数 (`current` / `total`)、残り時間 (`remaining`)、
  短い状況一行 (`status`)、現在の処理対象 (`message`)、開閉して見せる詳細行 (`details`)
  - 処理の段階: main は今の段階 (`JobEvent.phase`。id と、段階の中の進み具合 0-1、回数で数える段階は回数と総数) を送る
    (`emitPhase`。音声機能は `voice/job-progress.ts` の `voicePhase` / `ffmpegPhase` / `workerEvents`。Python の補助プロセスは
    `Context.phase`)。`useJobRunner` は段階の文言 (`jobPhases.<id>`、回数がある場合は `jobPhasesCounted.<id>`) を `status` に出し、
    進み具合が分かる段階では残り時間を添える (「残り 約 1 分 20 秒」)。残り時間は段階が始まってからの経過時間と進み具合から
    見積もり、1 秒ごとに更新する。始まって 3 秒未満は示さない。段階 (手順) が変わったとき・同じ段階で進み具合が戻ったとき
    (アンサンブルの次のモデル、特徴の抽出の 2 本目の進捗バーなど) は見積もり直す (回数が変わるだけでは見積もり直さない)。
    段階に入ってから最初に進み具合が届いた時点を見積もりの起点にし、段階の始めのモデルの読み込みなど、進み具合に
    表れない準備の時間は含めない (含めると学習の 1 回目の見積もりが大きく外れる)。表記は長さに応じて丸める (10 秒未満は 1 秒、1 分未満は 5 秒、
    10 分未満は 10 秒、1 時間未満は 1 分、それ以上は 5 分単位。`formatEta`)
  - 音声機能の段階: 準備・音声の読み込み・モデルの読み込み・分離・分離した音声の仕上げ・声の変換・音量の調整・伴奏の移調・
    伴奏との重ね合わせ・合成・音声の作成・話速の調整・音声のつなぎ・書き出し・学習の各段階 (`VoicePhaseId`)。
    ffmpeg の処理は `-progress` の再生位置から、Python の処理は区切り・区間・tqdm の進み具合から、学習は回数から進み具合を求める
  - 手順で進む処理 (学習): 段階に何番目の手順か (`step` / `steps`) を添え、「手順 2 / 5: 特徴を抽出しています」の
    ように示す (`jobPhaseStep`)。手順ごとの重さは学習する音声の量や環境で大きく変わり、全体の割合は決められないため、
    進捗バーは手順ごとに 0〜100% とし、残り時間も今の手順のものを示す。手順の中の進み具合が分からない間は、進捗
    バーを不定にする (`JobEvent.percent` に null を送る)。手順が変わったときは見積もり直す
  - 分離の準備 (末尾に無音を足す処理) は ffmpeg の再生位置から進み具合を求める。モデルの読み込みは進み具合を
    知る手段が無いため、残り時間を示さない
  - ダウンロード (バイト数で進む)・学習用の音声の追加 (件数で進む) は、全体の進み具合から残り時間を見積もる
    (`useRemainingTime`)。声のモデルの取り込み・書き出しは数秒で終わるため示さない
  - 段階を持たず、全体の進み具合 (`percent`) が処理の量に比例する処理は、全体の進み具合から残り時間を見積もって
    `remaining` に渡し、件数 (「1 / 3」) と同じ行に間を空けて並べる (件数が無い処理は単独の行) (`hooks/useRemainingTime.ts`。見積もり方・表記・示し始めるまでの時間は段階の残り時間と同じ)。オーディオ正規化
    (解析・正規化。全体の進み具合は各ファイルの音声の長さの合計を最大とし、ファイルが終わるたびにその長さを足す。解析・
    正規化とも、ファイルの中の進み具合 (ffmpeg の `-progress`) も長さに比例させて足す (ファイルが 1 つでも進み、残り時間を
    見積もれるように)。長さは一覧に加えたときに調べたものを使い、分からないファイルは分かったファイルの
    平均とする)・チャプターカット (分割は切り出す範囲の長さの合計を最大とする。再エンコードは時間がかかるため)・保存場所の
    移動 (別のドライブへのコピーしたバイト数) で使う。すぐ終わる処理 (SVG 変換など) と、全体の量が分からない処理
    (クリーンアップの検索) では出さない
  - **完了予測ができない処理では `showProgressBar={false}` にして進捗バーを出さない**。
    総数が分からないまま不確定バーを出しても何も伝わらないため (クリーンアップの検索)
  - `message` の欄は**常に固定の行数を確保**する。処理対象が変わるたびに高さが動くと
    ちらつくため。必要な行数は用途で違うので `messageLines` で渡す
    (既定 1 行。フルパスのような長文を出す画面だけ 2 を指定する)
  - `details` を渡すと「詳細を表示 / 詳細を隠す」ボタンがキャンセルと同じ行の左端に出る。
    閉じている間は場所を取らない。開いた領域は**行数 (= 並列数) に応じた高さで固定**し、
    折り返さずに枠の中で縦横スクロールさせる (パスを 1 行で通して読めるようにするため)。
    横スクロールバーの高さを見込まないと最終行が隠れるので、その分を加えて高さを決める
  - 余白: アクション行があるときは本文の下余白を詰める (アクション行が持つ余白と合わせる)。
    **ボタンが 1 つも無い画面 (SVG 変換、チャプター解析中) ではアクション行自体が出ない**ため、
    本文の下余白は既定のまま残す

## 12. データベース

データベースは使用しない。設定と音声機能のデータは JSON ファイルで保存する。
各 JSON ファイルの項目・型・関連は `Documents/テーブル定義.md` に 1 ファイル 1 表でまとめる。

- 音声機能のデータファイル (取得の記録・声のモデルの情報・パラメーターのプリセットなど) が読めない・JSON として解釈できない場合は、
  そのファイルを示して失敗させる (`DATA_FILE_CORRUPT: <パス>`。空の内容として扱うと、次に書き込んだときに元の内容が
  失われるため)。無いことがあるファイル (取得の記録・パラメーターのプリセットなど) は、無ければ初期状態として扱う。設定ファイルの扱いは 3 章

## 13. 音声機能の共通基盤 (`services/voice/`)

音声分離 (14 章)・音声変換 (15 章)・読み上げ (16 章) が共用する仕組み。
ダウンロードの画面は `components/voice/VoiceLibraryDialog.tsx` (呼び出し方は 13.14)。

基本方針:

- 利用者の操作を妨げない。判断が必要な場面では、状況とリスクを示したうえで利用者に選ばせ、
  選んだ結果は利用者の責任とする (例: 安全な方式で読み込めないモデルの取り込み、13.9)
- 容量の大きいファイルは、従量課金の可能性を考慮し、利用者の確認なしにダウンロードしない (13.3)
- Python 本体・ライブラリ・モデルはアプリに同梱しない。同梱するのは、軽量でライセンス上同梱できる
  テキストデータ (学習用の読み上げ文) に限る
- 処理速度や待ち時間は制約としない。有料のモデルや API は使わない
- 読み上げの対象の言語は日本語・英語・中国語。ffmpeg / ffprobe のパスと表示言語はアプリ設定のものを使う
- ffmpeg / ffprobe はアプリ設定 (PATH からの検出、またはパスの個別指定) で決まるものを、Python 側の処理にも使わせる (13.4)。
  Windows は winget で導入した Gyan.FFmpeg、macOS は Homebrew の ffmpeg を想定する。伴奏の移調と話速の微調整には
  rubberband フィルタを使う。すべての ffmpeg のビルドに含まれるわけではないため、フィルタの一覧から有無を調べ、
  無い場合はそれを必要とする処理を使おうとした時点で、指定中の ffmpeg では使えないことと見直し方を示す
- 音の位置がずれる ffmpeg のフィルタ (rubberband・ノイズ除去の afftdn) は、ずれを打ち消して使う (`runAlignedFilter`)。
  どちらにも、ずれを補正するオプションは無い。出力は設定とサンプリング周波数ごとに一定量ずれ (出力のタイムスタンプには
  表れない)、出力の長さは入力と同じのため、遅れた分の入力の末尾の音はフィルタの中に残ったまま出力されない。また、
  処理を始めた直後の音を正しく処理しない (afftdn は弱め、rubberband は失う)。そこで、同じ設定・同じサンプリング周波数で
  短いクリック音 (16 個) を処理してずれを測り (中央値。各クリック音を探す範囲は、伸縮後のクリック音の間隔の半分より
  狭くする。話速を大きく上げると間隔が詰まり、隣のクリック音を拾うため。測った値は ffmpeg・設定・周波数ごとに覚える)、
  入力の前後に 1 秒の無音を足して処理し、出力から元の音の範囲をずれの分だけ動かした位置から切り出して、長さを
  「元の長さ ÷ 話速」にそろえる。afftdn は先頭・途中・末尾の音とも位置と大きさが変わらない。rubberband は先頭と末尾の
  音も失わないが、移調・伸縮で音の形が変わるため、個々の音の位置は厳密には定まらない
- 分離・変換では、パラメーターを変えた結果を「候補」として一覧に並べ、聞き比べて選ぶ (読み上げは作成した音声を 1 つだけ持つ。16.1)。
  再生は、候補や再生対象を切り替えても再生位置が変わらない同期再生とする (13.7)

### 13.1 対応環境と処理装置 (`platform.ts`)

- 対応するのは **Windows (x64)**・**macOS (Apple Silicon、macOS 14 以降)**・**Linux (x64)** のみ。
  それ以外 (Intel Mac・Arm 版 Windows・Arm 版 Linux・macOS 13 以前) では、各機能の画面とダウンロード画面に
  理由を表示して機能を使えなくする (`unsupportedReason`: `os` / `arch` / `macosVersion`)
  - Intel Mac と Arm 版の Windows・Linux は、使用する PyTorch などの版が配布されていないため。
    macOS 13 以前を除くのは、使用する PyTorch などが macOS 14 以降を対象としているため
- 処理装置
  - Windows・Linux: `nvidia-smi` を PATH から探して実行し、NVIDIA GPU を検出する (実行できなければ NVIDIA GPU なしとする)。
    ドライバーの版と Compute Capability (CC) から CUDA 版 PyTorch の種類を決める (`selectCudaFlavor`)

    | 条件 | 使う PyTorch |
    |---|---|
    | ドライバー 580 以上かつ CC 7.5 以上 | cu130 |
    | ドライバー 570 以上かつ CC 7.0 以上 | cu128 |
    | CC 10 未満かつドライバー 528 以上 (Linux は 525 以上) | cu126 |
    | 上記以外・NVIDIA GPU なし | CPU 版 (GPU はあるがドライバーが古い場合はドライバーの更新を案内する) |

    CUDA 版は PyTorch の配布元 (`download.pytorch.org/whl/<種類>`) から取る。CPU 版は、Windows は PyPI のもの、
    Linux は配布元の CPU 版 (`whl/cpu`。PyPI の Linux 版は CUDA のライブラリ一式を含むため)。macOS は PyPI のもの

  - macOS: MPS を使う。未対応の演算は `PYTORCH_ENABLE_MPS_FALLBACK=1` で CPU に回して続行する
  - 分離・変換・読み上げで GPU の失敗 (CUDA・MPS のメモリ不足、CUDA・cuDNN・cuBLAS のエラー、MPS のエラー) が起きた場合は、
    補助プロセスが GPU に読み込んだものを手放してから、その要求だけを CPU で 1 回やり直す (`runtime.run_with_cpu_fallback`。
    OS によらない)。次の要求は再び GPU から始める
  - 検出結果は保持し、ダウンロード画面の「再検出」で取り直す (GPU やドライバーの交換に追随するため)。
    CUDA 版の種類が変わると、パッケージ一式は「更新が必要」になる (`componentVariant`)
- Windows では Microsoft Visual C++ 再頒布可能パッケージ (`vcruntime140.dll` / `vcruntime140_1.dll` /
  `msvcp140.dll`) を System32 で確認し、無ければダウンロード画面で配布ページへ案内する
- 読み上げのモデルの学習は **CUDA 版の PyTorch を使える NVIDIA GPU を搭載した Windows と Linux のみ** (`ttsTrainingAvailable`)。
  それ以外では、学習の画面に「そのような環境で作成したモデルを書き出して取り込めば使える」旨を表示する。
  学習専用のダウンロード項目も、それ以外の環境では選べない

### 13.2 保存場所の中の構成 (`paths.ts` / `library.ts`)

保存場所 (ライブラリ・モデル・作業ディレクトリ) はアプリ全体の設定 (3 章「保存場所」)。音声機能はその中に次の構成で置く。

- ライブラリディレクトリ: Python 本体と、ライブラリごとのディレクトリ (`LIBRARY_NAMES`)

```text
<ライブラリディレクトリ>/
├── manifest.json            # Python 本体とパッケージ一式の取得記録 (テーブル定義.md)
├── python/                  # Python 本体 (python-build-standalone)
├── python.tar.gz            # (取得・展開中だけ) Python 本体の書庫
├── pip-cache/               # pip のキャッシュ (意図しない失敗の後は再試行のために残る。全て成功したとき・キャンセルしたとき・次の起動時に消す)
├── audio-separator/         # 音声分離 (audio-separator)
│   └── venv/                # 仮想環境
├── applio/                  # 音声変換 (Applio)
│   ├── venv/
│   ├── source/              # ソース一式 (変換・RVC の学習の処理本体)
│   └── source.tar.gz        # (取得・展開中だけ) ソース一式の書庫
└── style-bert-vits2/        # 読み上げ (Style-Bert-VITS2)
    ├── venv/
    ├── source/              # 学習用のリポジトリ一式 (tts-train)
    └── source.tar.gz        # (取得・展開中だけ) ソース一式の書庫
```

- キャッシュディレクトリ: ライブラリディレクトリと同じ名前のライブラリごとのディレクトリ (3 章「保存場所」)

```text
<キャッシュディレクトリ>/
├── cache.json               # アプリが読み書きするキャッシュの最終利用日時 (テーブル定義.md)
├── audio-separator/
│   ├── huggingface/・torch/・torchinductor/・xdg/・numba/・matplotlib/  # このライブラリが作るキャッシュ
│   ├── model-list.json      # 分離モデルの一覧 (導入したパッケージから得る)
│   └── model-sources.json   # 分離モデルのファイルの取得元と大きさ (配布元に問い合わせた値。13.3)
├── applio/                  # (同上のライブラリが作るキャッシュ)
└── style-bert-vits2/
```

- モデルディレクトリ: 分類 `audio` の下に機能ごと (`MODEL_GROUP_DIRS`)

```text
<モデルディレクトリ>/
├── manifest.json            # ダウンロードしたモデルの取得記録 (テーブル定義.md)
└── audio/
    ├── separation/          # 分離モデル・UVR のモデル設定 (audio-separator が読む場所)
    ├── conversion/
    │   ├── predictors/      # RMVPE・FCPE
    │   ├── embedders/       # ContentVec など
    │   ├── pretraineds/     # RVC の学習用の事前学習モデル
    │   ├── voices/<ID>/     # 学習・取り込みした声のモデル (13.9)
    │   └── training-sets/<ID>/  # 学習セット (set.json と audio/<音声の ID>.wav。13.15)
    └── tts/
        ├── bert/            # BERT (日本語・英語・中国語)
        ├── nltk_data/       # 英語の発音推定のデータ
        ├── ready/<名前>/    # すぐに使えるモデル (JVNV)
        ├── pretrained/・pretrained_jp_extra/・slm/・wespeaker/  # 学習用の事前学習モデル・話者埋め込み
        ├── voices/<ID>/     # 学習・取り込みした声のモデル (13.9)
        └── training-sets/<ID>/  # 学習セット (13.15)
```

- 取得状況の記録は場所ごとに分ける (ライブラリディレクトリの `manifest.json` は Python 本体とパッケージ一式、
  モデルディレクトリの `manifest.json` はモデル)。それぞれの場所を個別に移動しても、記録が中身と一緒に動くようにするため
- ソース一式は自身の中の決まった場所でモデルを探すが、リンク (シンボリックリンク・ジャンクション・ハードリンク) は使わない。
  上流がモデルを読む箇所を Python 側の補正で差し替え、モデルディレクトリのファイルを直接読ませる (13.4)。
  学習の事前学習モデルもコピーせず、モデルディレクトリから直接読ませる
- 常駐の補助プロセスは、そのライブラリのディレクトリで動かす (Applio はソース一式の場所を基準にファイルを探すため、
  変換はソース一式の場所で動かす)
- 保存場所の移動 (`moveStorage` / `storage-merge.ts`。設定画面から、ライブラリ・モデル・キャッシュのそれぞれで行う)
  - 中身を選んだフォルダへ移し、そのフォルダを新しい場所にする。移動先を指定しない場合は既定の場所へ戻し、設定を空にする
  - 今の場所の中・外側 (`STORAGE_MOVE_NESTED`)、ほかの保存場所や作業ディレクトリと重なる場所 (`STORAGE_OVERLAP`) は選べない。
    中身のある移動先は、同じ種類の保存場所 (直下にその保存場所が持つ名前だけがあるもの。モデルは `manifest.json`・`audio`、
    ライブラリは `manifest.json`・`python`・各ライブラリのフォルダなど、キャッシュは `cache.json`・各ライブラリのフォルダ) に限る (`STORAGE_TARGET_NOT_EMPTY`。
    ほかのファイルと混ぜないため)。OS がフォルダやドライブを開いたときに作る情報 (macOS の `.DS_Store`・`._*`、
    macOS のボリュームの `.Spotlight-V100`・`.fseventsd`・`.Trashes`・`.TemporaryItems`、Windows の
    `Thumbs.db`・`desktop.ini`) と、前回の移動が途中で終わって残った一時フォルダ (`.kura-move-*`。移動の始めに消す) は
    ほかのファイルとみなさない。別の端末から写したモデルディレクトリ・ライブラリディレクトリも選べる
  - 中身のある移動先へは、まとまり (単位) ごとにマージする。モデルのファイルの一部などの単位では扱わない
  - キャッシュディレクトリには単位が無い。すべてどの単位にも属さないファイルとして扱い、移動先に無いものだけを移す
    (上書きするかの確認は出さない)。利用記録 (`cache.json`) は両方のものを合わせ、両方にあるものは新しいほうの日時にする。
    移動の後は分離のモデル一覧を読み直させる
    - モデルディレクトリの単位: ダウンロードしたモデル (取得記録の項目ごと。すぐに使えるモデルの名前・言語の変更も
      そのモデルと一緒に扱う)・分離のパッケージ一式に付属するモデル設定・声のモデル (`voices/<ID>/`)・学習セット
      (`training-sets/<ID>/`)
    - ライブラリディレクトリの単位: Python 本体・ライブラリ (仮想環境の単位。`audio-separator/`・`applio/`・
      `style-bert-vits2/`。読み上げと読み上げの学習用は同じライブラリ)
    - 複数のダウンロードしたモデルが共有するファイル (同じ系統の Roformer の分離モデルが共有する設定ファイル `.yaml`。
      配布元の同じファイル) は、どの単位にも入れず、比べる対象にもしない。移動先に無い場合だけ移し、上書きでモデルを
      消すときも消さない (移動先のほかのモデルが使うため)。共有は移動元・移動先の両方の取得記録から求める
    - 取得記録のファイルの一覧は、保存場所の中に収まるパスだけを扱う (絶対パス・空・保存場所の外を指すものは無視する。
      別の端末から来た記録で、保存場所の外のファイルを消したり移したりしないため)。展開して zip を消すもの (NLTK のデータ
      など) は、展開したフォルダ (zip と同じ名前) もその単位に含める
    - 移動元にだけある単位は移す。移動先にだけある単位はそのまま使う。両方にある単位 (同じ項目 ID・同じ声のモデルの ID・
      同じ学習セットの ID。ID は UUID のため、同じ ID は同じものを写したもの。記録が無くても移動先の同じ場所に
      ファイル・フォルダがあるものも含む) は、確認画面で単位ごとに移動元と移動先の
      最終更新日時 (中のファイルで最も新しいもの)・ファイル数・合計サイズを並べ、上書きするかを利用者が選ぶ。
      上書きする場合は移動先の単位を削除してから移し、上書きしない場合は移動先の単位を使う。すべての単位を選ぶまで
      実行できない (選んでいない単位があれば `STORAGE_MOVE_UNDECIDED`)
    - 取得記録 (`manifest.json`) は、移した単位の記録を移動元から写してマージする (ライブラリを置き換えた場合は、
      そのライブラリに属するパッケージ一式の記録をすべて移動元のものにする)。すぐに使えるモデルの名前・言語の変更
      (`ready-model-overrides.json`) は、移したモデルは移動元のもの (無ければ変更なし) にし、上書きしなかったモデルは
      移動先のままにする
    - 記録 (取得記録・すぐに使えるモデルの変更) は、中身を動かす前に両方の場所のものを読み、形を確かめる
      (壊れていれば `DATA_FILE_CORRUPT` で、何も動かさずに止める)。移動先の取得記録が別の種類の保存場所のもの
      なら、その移動先は選べない (`STORAGE_TARGET_NOT_EMPTY`)。声のモデル・学習セットの記録が読めない場合は、
      ID を名前として示す (1 つが壊れていても移動できるようにするため)
    - どの単位にも属さないファイルは、移動先に無いものだけを移す。シンボリックリンクは辿らず、リンクそのものを移す
      (保存場所の外を指すリンクを辿って、外のファイルを移さないため)。作りかけのもの (名前が `.` で始まるフォルダの中) と、
      取得の再試行のためだけに残しているもの (pip のキャッシュ・Python 本体の書庫の取得途中のファイル) と、書きかけで残ったもの
      (`python.tar.gz`・`python.staging`・`*.tmp`) は移さない
    - 移動元は、上書きしなかった単位も含めて、移動が終わった後にすべて削除する
  - 移動の確認画面を出す前に、移動と同じ確認で移動先を確かめ、両方にある単位と移す量を求める (`planStorageMoveTo`。
    選べない場所を確認の後で知らせないため。中身を数えるため、調べている間は進捗の画面を出す)
  - ほかのジョブ (分離・変換・読み上げ・学習・ダウンロードなど) の実行中と、学習セットへの音声の追加中は断る
    (`LIBRARY_BUSY`。13.3)。移動の間は、学習セットの作成・名前の変更・削除・音声の追加と削除・学習の開始も断る
    (`LIBRARY_BUSY`。古い場所に書かれて移動から漏れないため)。移動はダウンロード・削除と同じく 1 つずつ順に実行する
    (`withLibraryLock`)
  - 移動の前に常駐の補助プロセスをすべて止め、終了するまで待つ (`stopAllWorkersAndWait`。Windows では、終了しきって
    いないプロセスが読み込んだ DLL やモデルのファイルを掴んでいて、移動に失敗するため)
  - 中断は、先に始まった処理を待っている間と補助プロセスの終了を待っている間も受け付ける。順番が来た時点と補助プロセスが
    終了した時点で中断を確かめ、中断されていれば何も移さずに終える (同じドライブの移動でも中断できるようにするため)。
    中身を調べている間とコピーの間も受け付け、置き換えを始める前なら何も変えずに終える
  - 同じドライブ (ボリューム) かは、移動元に小さなファイルを作り、移動先へ名前の変更で移せるかを試して判定する
    (ネットワークドライブや仮想ドライブでは、ドライブの識別番号だけでは判定を誤ることがあるため)。同じドライブなら、移す単位を名前の変更だけで移し、コピーしない。ウイルス対策
    ソフトなどが一時的にファイルを開いている場合に備えて少し待ちながら再試行し (`utils/rename-retry.ts`)、それでも
    移せなければ使用中として止める (`STORAGE_IN_USE`)。移動元に試しのファイルを作れない場合 (読み取り専用など) は、
    名前の変更では移せないため、別のドライブと同じくコピーで移す
  - 別のドライブなら、コピーを始める前に移動先の空き容量を確かめ、移すものすべての大きさに足りなければ何もせずに断る
    (`STORAGE_NO_SPACE`。上書きする単位は、コピーし終えてから移動先の単位を削除するため、その分も含めて必要)
  - 別のドライブなら、移す単位をまず移動先の中の一時フォルダ (`.kura-move-<ランダム>`) へコピーする。コピー中は進捗を出し、
    中断・失敗したら一時フォルダを消して元のまま (移動先の単位は削除していない) 元の場所を使い続ける。コピーし終えてから、
    単位ごとに置き換える (ここからは中断しない)。ファイルは少しずつ読み書きし、大きなファイルのコピー中でも中断が
    すぐ効くようにする。コピーしたファイルの更新日時は元のものにする (移動の後も、まとまりの最終更新日時で比べられる
    ようにするため)。macOS・Linux では権限 (実行の権限) も元のものにする (Python 本体などを写した後も実行できるようにするため)。
    単位の中のシンボリックリンクは、単位の中を相対パスで指すものはリンクのまま写し (同じ中身を二重に写さないため)、
    それ以外はリンク先の中身 (ファイルの中身・ディレクトリの中) を写す。指す先の無いリンクは読み飛ばす。自分を含む親の
    ディレクトリを指すリンクがあれば、際限なく辿ることになるため止める (`STORAGE_LINK_LOOP`)
  - 置き換えの途中で失敗した場合は、移し終えたものを元へ戻して元の場所を使い続ける (上書きを選んで削除した移動先の
    単位は戻らない)
  - 移動が終わった後に元の場所を消せなかった場合も、移動は成功として扱う。残った場所は結果 (`remainingPath`) で返し、
    画面で残っていることを知らせる
  - 新しい場所を設定に保存できなかった場合は失敗とする (`SETTINGS_SAVE_FAILED`。移動は終わっているが、
    次の起動で元の場所を使ってしまうため)。このとき起動中の設定も元の場所のまま変えない (3 章「保存場所」)
  - ライブラリディレクトリの移動では、設定を保存する前に、移動先の仮想環境の `pyvenv.cfg` に記録された Python 本体の場所を
    新しい場所に書き換え、移動先の仮想環境で `import torch` を実行して動作を確かめる (設定を保存できなかったときに、
    仮想環境が元の場所を指したまま残らないようにするため)。書き換えは、記録の `home` (Python 本体の実行ファイルのある
    フォルダ) から仮想環境を作ったときのライブラリディレクトリを求めて置き換える (別の場所・別の端末から写した
    ライブラリも、この場所を指すようにするため)。Python が起動して失敗した仮想環境、仮想環境の Python が無いもの、
    記録を書き換えられないもの (`pyvenv.cfg` が無い・`home` がライブラリの Python 本体を指していない) だけを
    「再取得が必要」(broken) にし、利用者がダウンロード画面で取り直す (作り直しはパッケージの再ダウンロードを伴うため、
    自動では行わない)
  - Python を起動できない場合 (Windows で Visual C++ 再頒布可能パッケージが無い `VC_RUNTIME_MISSING` など) は仮想環境の
    問題ではないため broken にしない。中身は移し終えているため設定は保存してから、そのエラーで失敗を知らせる

### 13.3 ダウンロードと削除 (`spec.ts` / `library.ts` / `installer.ts` / `downloader.ts`)

- ダウンロード物の定義は `spec.ts` に固定する (版・取得元 URL・大きさ・SHA-256)。取得元の URL はファイルごとに 1 つで、
  その URL からだけ取得する。Hugging Face と GitHub のファイルはコミットまたはタグを固定した URL で取得する。
  使う版はアプリが決め、利用者による更新はできない
  - 例外: UVR のモデル設定 (TRvlvr/application_data の `main` ブランチ) と NLTK のデータ (nltk_data の `gh-pages`
    ブランチ) は、配布元がブランチでしか公開していないため、ブランチの URL から取得し、大きさと SHA-256 を定義に持たない
    (内容が配布元の更新に従って変わり得る)
  - 小さな設定ファイル (すぐに使えるモデル・WavLM・wespeaker の設定) は大きさと SHA-256 を持たず、ソース一式の書庫
    (Applio・Style-Bert-VITS2) は大きさだけを持つ
- 分離モデルの取得元 (`separator-models.ts`): 一覧 (`model-list.json`) はファイルごとに取得元の候補 (UVR と
  audio-separator の配布場所) を持ち、ファイルは候補のうち 1 か所にだけある
  - 候補を先頭から HEAD で問い合わせ (404 = その場所に無い。それ以外の失敗はエラー)、ファイルがある URL と大きさを
    キャッシュディレクトリの `audio-separator/model-sources.json` に保存する (テーブル定義.md)。取得はその URL からだけ行う
  - 一覧を得たときと、大きさの分からない分離モデルがある状態でダウンロードのダイアログを開いているときに、取得元が
    まだ分からないファイルをまとめて問い合わせる (`probeSeparatorSizes`。同時に 8 件まで。問い合わせに失敗したファイルは
    記録せず、次の機会に問い合わせ直す)
  - 問い合わせの途中で一覧と取得元の記録を読み直させた場合 (`forgetSeparatorModelList`。パッケージ一式の削除・導入、
    ライブラリディレクトリ・キャッシュディレクトリの移動) は、残りの問い合わせをやめ、それまでの結果も記録も保存もしない (世代の番号で判定する。
    消した場所にフォルダを作り直したり、古い場所の結果を書き込んだりしないため)
  - どの候補にも無いファイルを持つモデルは、取得できないものとして理由とともに示す (`separatorModelNotFound`)。
    この結果はアプリの起動中だけ覚え、次に起動したときに調べ直す
  - ダウンロード時に取得元がまだ分からないファイルはその場で調べ、どの候補にも無ければその項目を失敗とする
    (`SEPARATOR_MODEL_NOT_FOUND`)
  - VIP モデルは一覧に出さない (13.13)。一覧が無い場合 (分離のパッケージ一式を削除したときなど) も、取得済みの
    分離モデルはファイル名を名前として示し、削除できるようにする
- 項目は「Python 本体」「パッケージ一式」(separator / converter / tts / tts-train)「モデル」(1 モデル単位) の 3 種類。
  状態は `missing` (未取得) / `installed` / `outdated` (版が定義と違う) / `broken` (ファイルの欠落・動作確認の失敗)
- **すべてのダウンロードは、利用者が対象を選んで実行を指示したときだけ行う**。補助プロセスからの通信も
  環境変数 (13.4) と上流への補正で止め、未取得のモデルを勝手に取得させない
- ダウンロード (`downloadItems`): 選んだ項目に未取得の前提項目を足し、取得する順に並べて 1 つずつ取得する。
  項目ごとと全体の進捗を出し、中断できる。失敗した項目があっても残りを続け、終了後に失敗した項目だけを
  再試行できる (前提項目が失敗した項目は `PREREQUISITE_FAILED`)
  - ファイルは保存先に直接取得する。取得中は保存先のフォルダに `<名前>.part` として書き、SHA-256 を確かめてから
    正式な名前にする。取得途中のファイルの扱いは、中断の理由で分ける (共通の決まり):
    - キャンセル (アプリの終了に伴うキャンセルを含む) は、その処理をやめた (しなかったことにする) ものとして、
      取得途中の `.part` を消す (`fetchAsset`)。同じ取得をもう一度するとは限らず、残すとごみになり続けるため
    - ネットワークの切断などの意図しない失敗では `.part` を残し、アプリを起動したまま取得し直したときに続きから取得する
    - 完了しないままアプリを終了した場合は、次の起動時に消す (`removeInstallLeftovers`)
  - 配信元が圧縮して送る場合 (raw.githubusercontent.com の JSON など、`Content-Encoding` 付き) は、
    `Content-Length` が展開後の大きさと異なるため、大きさの照合と続きからの取得を行わない
  - 応答やデータが 120 秒届かなければ打ち切って失敗とする (再試行すれば続きから取得する)
  - 展開する zip (NLTK のデータ) は、zip と同じ場所の `<名前>.staging/` に展開し、中の `<名前>/` を正式な場所へ移してから
    展開途中のフォルダと zip を消す (失敗・キャンセルでも展開途中のものは消す)。取得済みかどうかは、展開を終えたフォルダが
    あるかで判定する。展開の途中で止まったものを展開済みと取り違えず、次の取得で展開し直すため
  - ダウンロード・削除・保存場所の移動 (ライブラリ・モデル・キャッシュディレクトリ) は、ジョブが別でも 1 つずつ順に実行する
    (`withLibraryLock`)。同じ仮想環境への同時の導入や、導入中の pip のキャッシュの削除を防ぐため
  - ダウンロード・削除・保存場所の移動は、ほかのジョブ (分離・変換・読み上げ・学習など。ダウンロードと移動は自身のジョブを
    除く) の実行中は始めずに断る (`checkLibraryIdle` → `LIBRARY_BUSY`)。それらの処理は仮想環境やモデルのファイルを使っており、
    入れ替え・削除・移動すると処理が失敗したり、使用中のファイルを消せずに中途半端な状態が残ったりするため
  - 表示する容量: 単体ファイルは定義の大きさ (分離モデルは、取得元を調べたときに得た大きさ)。
    パッケージ一式は固定の目安 (CUDA 版 PyTorch の実測値 + その他のパッケージの目安 + ソース一式)
- Python 本体: python-build-standalone の CPython 3.11.17 (install_only_stripped) の書庫を、展開先と同じディスク
  (ライブラリディレクトリの `python.tar.gz`) に取得し、`python.staging/` に展開してから `python/` に置き換える。
  書庫と展開途中のものは、成功・失敗・キャンセルを問わず消す
  - tar.gz の展開 (Python 本体・ソース一式) では、シンボリックリンクとハードリンクの項目を展開しない (保存場所にリンクを
    作らないため)。そのため macOS では、リンクである `bin/python3` ではなく、版番号の付いた実体 (`bin/python3.11`) を
    Python 本体の実行ファイルとして使う (`spec.ts` の `pythonExecutable`)
- パッケージ一式 (`installComponent`)
  - `python -m venv --without-pip --copies <ライブラリ>/venv` で仮想環境を作り、Python 本体の pip を
    `python -m pip --python <仮想環境の python> install --progress-bar raw -r <作業ディレクトリ>/requirements.txt
    -c <名前>.lock.txt` の形で仮想環境に向けて使う。`--progress-bar raw` の機械可読の出力から進捗を読む
  - `requirements.txt` は `<名前>.in` から作る (`resolveRequirements`)。`-r <別の名前>.in` の取り込みを展開し、
    Windows・Linux では `torch`・`torchaudio`・`torchvision` の版を `<版>+<cu126|cu128|cu130>` (Linux の CPU 版は
    `<版>+cpu`) に書き換える (`sys_platform` の条件付きの行は、この OS に当てはまるものだけを書き換える)。pip が OS の既定の文字コードで読むため ASCII だけで書く
  - 既にある仮想環境は、その Python で動作を確かめて使い回す。Python が起動して失敗した (`PYTHON_BROKEN`) 場合だけ
    壊れたものとして作り直し、Python を起動できない場合 (作業ディレクトリが無い・実行環境が足りないなど) は作り直しても
    直らないため、そのエラーで失敗させる
  - `--copies` により、どの OS でも仮想環境に Python 本体へのリンクを作らずファイルを写す (保存場所の移動で、
    ファイルをそのまま写せるようにするため)。macOS・Linux では python-build-standalone の実行ファイルが libpython を
    実行ファイルからの相対位置 (`../lib`) から読むため、作成後に `libpython3*.dylib` / `libpython3*.so*` を仮想環境の
    `lib/` に写す。Linux の venv が作る `lib64` (`lib` へのシンボリックリンク) は使われないため消す (保存場所に
    リンクを残さないため)
  - Windows・Linux の CUDA 版と Linux の CPU 版では、`--extra-index-url` に download.pytorch.org の該当する index
    (cu126 / cu128 / cu130 / cpu) を加える
  - ソース一式 (Applio・Style-Bert-VITS2) は GitHub のタグのアーカイブを、展開先と同じディスク (そのライブラリの
    ディレクトリの `source.tar.gz`) に取得し、`source.staging/` に展開してから `source/` に置き換える。書庫と展開途中の
    ものは、成功・失敗・キャンセルを問わず消す。Applio は `assets/config.json` を雛形から作る
  - pip に渡す要件ファイルは作業ディレクトリの処理用のフォルダに作り、pip の終了後に消す
  - パッケージを入れ替える間は、仮想環境のファイルを使っている常駐の補助プロセスを止め、終了を待つ
  - 導入後に代表的なモジュールの import で動作を確かめ、失敗したら記録しない
  - pip のキャッシュは仮想環境への展開先と同じディスク (ライブラリディレクトリの `pip-cache/`) に置き、ダウンロードの
    ジョブが全て成功したとき・キャンセルしたときに消す。同じ PyTorch を使うパッケージ一式を続けて導入するときと、
    意図しない失敗の後の再試行で取得し直さないため
  - 利用者の pip の設定 (`PIP_` で始まる環境変数と設定ファイル) は持ち込まない (`PIP_CONFIG_FILE` に null デバイスを指定)
  - 入れるパッケージの版は固定版 (`src/python/requirements/*.lock.txt`) で固定する。
    PyTorch (torch・torchaudio、分離では torchvision も) はプラットフォームと CUDA 版で変わるため、`.in` 側で版を固定し
    lock には含めない。分離の torchvision は torch と対になる版を OS ごとに指定する (Windows・Linux 0.26.0 / macOS 0.29.1)。
    分離の diffq は Windows では diffq-fixed 0.2.4、macOS・Linux では diffq 0.2.4 とし、macOS・Linux ではソースから
    ビルドされる (macOS は Xcode Command Line Tools、Linux は C/C++ のコンパイラーが必要。13.13)
- 意図しない失敗のときに残すのは、アプリを起動している間の再試行でそのまま使われるものだけ: 取得途中の `.part`
  (続きから取得する)、pip のキャッシュ (取得済みのパッケージを使う)、作りかけの仮想環境 (動作を確かめて使い回す)。
  キャンセルでは `.part` と pip のキャッシュを消す。`.part` と pip のキャッシュは次の起動時にも消す
- アプリの更新で版が変わった項目 (`outdated` / `broken`) があれば、起動時に一覧と合計容量を示して
  更新するかを確認する (`VoiceUpdatePrompt`)。確認はアプリの版ごとに 1 回だけ出し
  (`settings.voice.updatePromptVersion`)、「後で」を選んでもダウンロード画面から更新できる
- 削除 (`removeItems`): 項目単位で行う。ジョブにはせず、終わるまで待って結果 (項目ごとの成否) を返す
  - 常駐の補助プロセスを止め、終了を待ってから消す (掴まれているファイルは消せないため)
  - 項目のファイルと一緒に、その項目の取得途中で止まった `.part` (書庫のものを含む) も消す (以後は再利用されないため)。
    展開する zip は、展開したフォルダと展開途中のもの (`.staging`) も消す
  - 読み上げのすぐに使えるモデルを消すと、`ready-model-overrides.json` のそのモデルの記録 (名前と言語の変更) も消す
    (`ready-model-overrides.ts` の `clearReadyModelOverride`。声のモデルの画面とダウンロードのダイアログのどちらから消しても同じ。
    取得し直したときは元の名前と言語で使う)
  - Python 本体を消すと、すべての仮想環境も消える (確認画面で明示する)。仮想環境をすべて消す場合は、
    Python 本体も消すかを利用者が選べる
  - 消すと使えなくなる機能を確認画面に示す (消す各項目の `usedBy` (その項目を使う機能) を合わせたもの)
  - パッケージ一式を消すと、そのライブラリのディレクトリ (仮想環境・ソース一式) ごと消し、キャッシュディレクトリの
    そのライブラリのディレクトリ (ライブラリが作ったキャッシュ・分離のモデル一覧と取得元) も消す。
    パッケージ一式と一緒にモデルディレクトリへ取得したファイル (分離のモデル設定・話者埋め込みの wespeaker) も消す。
    ダウンロードしたモデルはモデルディレクトリにあり、別の項目として個別に消す
  - tts を消すと tts-train (学習用のソース一式など) も消える。tts-train だけを消す場合、読み上げの仮想環境に
    追加したパッケージは残す (共有している依存パッケージを壊さないため)
  - 他の取得済みモデルと共有しているファイル (分離モデルの設定ファイルなど) は残す
  - 利用者の声のモデル (学習・取り込み) は、ここでは消さない
- 機能の利用時に必要な項目が欠けていれば、`checkFeature` の結果から不足項目を示してダウンロード画面へ案内する。
  処理の途中で未取得のモデルが必要になった場合も、同じ案内を出す。エラーは分離が `MODEL_NOT_INSTALLED`、変換と学習が
  `MODEL_REQUIRED` で、どちらも `<コード>: <項目 ID>, <項目 ID>` の形で不足項目を持つ。renderer は両方から不足項目を取り出す
  (`voiceErrors.ts` の `missingItemsFromError`)

### 13.4 Python の実行 (`python-env.ts` / `python-worker.ts` / `src/python/kura_voice/`)

- 構成
  - Python は python-build-standalone のビルド済みの単体 Python を、利用者の承認後にダウンロードして使う
    (uv などの外部の環境管理ツールは使わない)。版は 3.11 とする。3.10 は 2026 年 10 月末でサポートが終了し、
    PyTorch も 2.15 から 3.11 以上が必要になる。3.11 はセキュリティ修正が 2027 年 10 月まで提供される
  - Python 本体は 1 つとし、コンポーネント (分離・変換・読み上げ) ごとに標準の venv で仮想環境を作る。
    コンポーネントごとに必要な PyTorch の版が異なるため (audio-separator は Apple Silicon で PyTorch 2.13 以上を要求する)
  - 各コンポーネントの採用元: 分離は audio-separator (PyPI)、変換は Applio (GitHub のソース一式)、
    読み上げは Style-Bert-VITS2 の独立派生版 (sync-dev-org 版。推論は PyPI の style-bert-vits2-mk、学習はリポジトリの処理)
- 環境変数 (`buildPythonEnv`)
  - 利用者の環境の Python 関連の変数を持ち込まない (`PYTHONHOME`・`PYTHONPATH`・`PYTHONSTARTUP`・`PYTHONUSERBASE`・
    `VIRTUAL_ENV`・`CONDA_PREFIX`・`CONDA_DEFAULT_ENV`・`AUDIO_SEPARATOR_MODEL_DIR` と、`PIP_` で始まる変数を除く)
  - 各ライブラリのキャッシュの書き込み先 (`HF_HOME`・`TORCH_HOME`・`XDG_CACHE_HOME`・`NUMBA_CACHE_DIR`・
    `MPLCONFIGDIR` など) をキャッシュディレクトリのそのライブラリのディレクトリに向ける (中身はライブラリに任せ、
    保持期間を過ぎたファイルは起動時に消す。3 章「保存場所」)。`NLTK_DATA` はモデルディレクトリのデータを指す
    (削除後の残留と、確認を経ないダウンロードを防ぐ)。英語の発音推定 (g2p_en) は読み込み時に zip の名前
    (`taggers/averaged_perceptron_tagger.zip` など) でデータを探すため、zip の名前で見つからない場合は展開済みのフォルダを
    探すようにする (`runtime.patch_nltk_zip_lookup`。読み上げと学習の両方。アプリのダウンロードは zip を展開して残すため)
  - モデルの場所: `KURA_APPLIO_MODELS` (モデルディレクトリの `audio/conversion`)・`KURA_SBV2_MODELS` (`audio/tts`)。
    上流への補正 (下記) がこの場所のファイルを読ませる
  - `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE` などで通信を止め、利用状況の送信を止める
  - `TEMP` / `TMP` / `TMPDIR` は、プロセスを起動する側 (`process-runner.ts` / `python-worker.ts`) がプロセスごとに
    作業ディレクトリにそのプロセス用のフォルダを作って渡し、そのプロセスが終了した時点で消す (3 章「保存場所」)
  - `PYTHONDONTWRITEBYTECODE=1`: 同梱スクリプトの隣に `__pycache__` を作らせない (macOS ではアプリ本体の署名が壊れるため)。
    パッケージは導入時に pip がバイトコードを作成済み
  - ffmpeg / ffprobe はアプリ設定で解決したもののフォルダを PATH の先頭に置く (Python 側はこれを PATH から使う)
  - Windows は `USE_LIBUV=0` (PyTorch の分散処理の初期化が学習で失敗するのを避ける)
- 常駐の補助プロセス (`worker.py --component <separator|converter|tts>`、コンポーネントごとに 1 つ)
  - 標準入出力で 1 行 1 件の JSON をやり取りする。要求は `{id, method, params}`、応答は `{id, result}` または
    `{id, error: {code, message, detail}}`、途中経過は `{id, event}`
  - ライブラリが標準出力へ書く文字で通信が壊れないよう、Python 側で標準出力 (fd 1) を標準エラーへ付け替え、
    通信には複製した元の標準出力を使う
  - 読み込んだモデルを保持し、候補を作り直すたびに読み直さない。要求は 1 件ずつ順に処理する
  - 保持するのは、開いている機能で使う処理役だけ (`setVoiceFeature`。renderer が機能 (`featureOf`) を移るたびに
    `voice:setFeature` で知らせる)。音声分離は分離、音声変換は分離と変換、読み上げは読み上げの処理役を、最初に使った
    ときに起動して保持する。機能を離れたら、処理中でなければすぐ、処理中なら終わったときに止める。ほかの機能から
    一時的に使った処理役 (ダウンロード画面での分離モデルの一覧作りなど) は、使い終わったら止める。Python を使う機能が
    増えても、同時に動く処理役はその機能で使うものだけになる
  - ジョブのキャンセル時はプロセスツリーごと終了させ (Windows は `taskkill /T /F`、macOS・Linux はプロセスグループへの
    シグナル (SIGTERM。5 秒で終了しなければ SIGKILL))、次の要求で起動し直す。終了させたプロセスはその時点で切り離し、処理中の要求はキャンセルとして終える。
    古いプロセスの終了を待たずに次の要求で新しいプロセスを起動でき、古いプロセスの終了通知と標準エラーは
    新しいプロセスに影響させない。順番を待つ間にジョブがキャンセルされた要求は、プロセスを起動せずに終える。
    標準エラーは main のコンソールへ流し、処理中の要求の間に出たものをすべて異常終了時の詳細に使う
    (要求ごとに改めるため、常駐プロセスの出力を溜め続けない)
  - 外部プロセスの出力 (`process-runner.ts` / `python-worker.ts`) は行に分け (`output-lines.ts`)、失敗時の詳細には
    すべての行を使う。`\r` で書き換えられる行 (tqdm などの進捗表示) は、端末に最後に残る内容だけを残す
  - ファイルの移動・削除・入れ替え (保存場所の移動・作業ディレクトリの変更・項目の削除・パッケージ一式の導入) の前は、
    止めたうえで終了を待つ (`stopAllWorkersAndWait`)。キャンセルなどで先に終了させ、まだ終了していないプロセスも、
    終了するまで覚えておいて同じく待つ (ファイルを掴んだままの可能性があるため)。15 秒以内に終了しないプロセスがあれば失敗とし
    (`PYTHON_STOP_TIMEOUT`)、画面はアプリを再起動してからやり直すよう求める。アプリの終了時は、処理のキャンセルと
    後片付けを待ってから止めて終了を待つ (3 章。待つのは 10 秒まで。待ちきれなかった場合も `will-quit` で止める)
  - エラーは `<コード>: <詳細>` の形のメッセージで renderer へ返す。詳細が無い (Python 側がコードをそのまま
    メッセージにした) 場合はコードだけにする。renderer (`voiceErrors.ts`。処理は `components/common/errorMessage.ts`) は既知のコードを表示言語の文に置き換え、
    詳細が無い場合は詳細を入れる括弧ごと取り除く
- 学習は常駐プロセスを使わず、駆動スクリプト (`rvc_train.py` / `sbv2_train.py`) をジョブごとに起動する。
  駆動スクリプトは上流の学習スクリプトを `script_runner.py` 経由で順に実行し、出力からエポックを読み取って
  進捗 (段階とエポック、学習以外の段階は上流のスクリプトの tqdm の進捗バー「n/全体」から求めた手順の中の進み具合
  `fraction`。1% 刻みで送り、新しいバーで 0 に戻る) を返す。出力のうち Python の例外の行 (`RuntimeError: ...` など) の最後のものを覚えておき、
  スクリプトが失敗した場合 (`TRAINING_STEP_FAILED`) と、学習が終わってもモデルが作られなかった場合
  (`TRAINING_NO_MODEL`) の詳細として示す。例外の行が無いまま異常終了した場合は終了コードを示し、
  Windows の異常終了のコードは 16 進と意味で示す (例: `0xC0000005 (access violation)`)
  - 駆動スクリプトは、作業ディレクトリに main プロセスが作ったジョブのフォルダをカレント
    ディレクトリにして動く。指示ファイル (`job.json`) と学習の途中のデータはこのフォルダに置き、学習が終わった時点
    (成功・エラー・キャンセル) で main プロセスがフォルダごと消す (15.6・16.8)
  - `script_runner.py --patch <applio|sbv2> --root <上流のソース一式> -- <スクリプト> ...` の形で起動する。`--root` の
    場所を import の検索先に加えるため、ソース一式の外のフォルダをカレントディレクトリにしても上流のスクリプトが動く
  - スクリプトがアプリの定めたエラーを返す場合は、`KURA_ERROR: <コード> <詳細>` の 1 行を出力する。駆動スクリプトは
    この行を見つけると、同じコードと詳細のエラーとして学習を止める
- 上流への補正 (Python 側で読み込み時に当てる)
  - audio-separator: モデルの自動ダウンロードを止める。音声の読み書きに soundfile を使う
  - Applio: 常駐の補助プロセスは、カレントディレクトリをソース一式の場所にして読み込む (学習の各段階のカレント
    ディレクトリは 15.6)。wget によるダウンロードを止める。
    faiss が ASCII 以外のパスを開けない問題を、メモリ経由の読み書きで回避する。
    変換では Applio の `pipeline` を通さない (`pipeline` はインデックスのパスの中の `trained` をすべて `added` に
    書き換えてから使うため、`D:\pretrained\...` のように語を含むパスが壊れる)。インデックスは渡されたパスからそのまま読み
    (`converter_service.py` の `rpc_convert`)、区間ごとに Applio の `voice_conversion` を呼ぶ。インデックスはコピーせず、
    声のモデルのフォルダのものをそのまま読む。
    ピッチ抽出 (RMVPE・FCPE) と埋め込み (ContentVec など) のモデルを、ソース一式の中ではなくモデルディレクトリから読む
    (`runtime.patch_applio_model_paths`。読み込み済みのモジュールが取り込んだ参照も差し替える)。
    学習の特徴量の抽出は、上流が子プロセスに分ける処理を同じプロセスで行う (`rvc_extract.py`。子プロセスには補正が効かないため)。
    事前学習モデルは学習スクリプトへモデルディレクトリのパスを直接渡す
  - Style-Bert-VITS2: BERT と WavLM をモデルディレクトリから読む (`runtime.patch_sbv2_model_paths`・学習の設定)。
    学習の初期値 (G_0 / D_0 / DUR_0 / WD_0) は、学習用のフォルダにコピーせず、モデルディレクトリの事前学習モデルから
    直接読む (`KURA_SBV2_PRETRAINED`)。上流は初期値の読み込みに失敗すると例外を握りつぶして一から学習を続けるが、
    少ない音声では使えないモデルになるため、読み込めなければ `KURA_ERROR` の行で `TRAINING_PRETRAINED_UNREADABLE` を
    知らせてから、上流の `except Exception` で捕まらない例外で学習を止める。
    学習時は話者埋め込みモデル (wespeaker) をモデルディレクトリのファイルから読む。
    学習のテキストの前処理 (`preprocess_text.py`・`bert_gen.py`) では、pyopenjtalk の補助プロセスの待ち受けポートを
    固定の 7861 から OS が空きとして返すポートに置き換え (同じポートで待ち受ける別のプロセスに接続しないため)、
    ユーザー辞書は上流のソース一式の `dict_data/user.dic` ではなくカレントディレクトリ (ジョブのフォルダ) の `user.dic` に
    作って読ませる (上流のソース一式を書き換えないため)。学習スクリプトは GPU が 1 つでもモデルを DDP (DistributedDataParallel) で包むが、
    1 プロセスで学習するときは、中のモデルをそのまま呼ぶ同じ形の包み (`.module` を持ち、`state_dict` の
    `module.` 接頭辞も同じ) に置き換える。Windows では gloo による CUDA の勾配の集約で PyTorch 2.11 が
    アクセス違反で落ちるため (1 プロセスでは集約するものが無く、結果は変わらない。Applio は GPU が複数のときだけ DDP を使う)
  - 学習 (両方): PyTorch の分散処理 (GPU が 1 つでも使われる) の待ち受けポートを、OS が空きとして返すポートに置き換える
    (`MASTER_PORT`。上流は Applio が 20000〜55555 の乱数、Style-Bert-VITS2 が設定の固定値)。
    Windows では Hyper-V などが予約したポートの範囲に当たると待ち受けに失敗し、学習が始まらないため

### 13.5 GPU の排他 (`gpu-lock.ts`)

- GPU を使う処理 (分離・変換・読み上げ・学習) は、アプリ全体で 1 つずつ順に実行する (`withGpu`)。
  順番待ちの間にジョブがキャンセルされたら、待ちから外れる
- 順番待ちに入ったときと抜けたときに `wait` のジョブイベントを送る。画面 (`hooks/useJobRunner.ts`) は待っている間、
  進捗の文言を「他の処理が終わるのを待っています (モデルの学習中は長くかかることがあります)」(`voice.common.waitingGpu`) に
  置き換える (学習中は長く待つことがあり、
  止まって見えないようにするため)。画面はジョブの通知を常に購読し、ジョブの ID を処理の開始前に設定する
  (開始直後に届く順番待ちの通知を取りこぼさないため)
- GPU の順番を得るたびに、他の常駐プロセスへ `unload` を送ってモデルを手放させる
  (`setGpuSwitchHandler` → `unloadOtherWorkers`)

### 13.6 作業ディレクトリの使い方 (`work-dir.ts`)

- 作業ディレクトリの `kura_toolkit_*` フォルダが、アプリ全体の一時ファイルの置き場 (3 章「保存場所」)。音声機能は機能の作業を
  機能 (メニューの機能。分離・変換・読み上げ) ごとのフォルダに、1 回の処理の中間ファイルを処理ごとのフォルダに置く
- 機能の作業は、同じ機能の中 (機能のタブの移動など) では残し、別の機能へ移ったときに破棄する (`stores/featureWork.ts`。
  画面の状態を新しい作業にし、作業のフォルダをクリーンアップの一覧に積む。確認は出さない。ただし読み上げに保存していない
  文章がある場合は、移る前に確認する。16.1)。読み上げは文章と設定を残し、作成した音声だけを破棄する
- renderer から渡されたパス (再生・破棄・分離・変換・合成・書き出しの入力) は、その作業のフォルダの中のものに限る
  (`isInsideWork`。外のパスが含まれていれば `INVALID_PATH` で断り、何もしない)
- 中間ファイルは 32bit 浮動小数の WAV とする (段階を重ねても音割れや精度の低下が起きないようにするため)。
  ライブラリが 16bit で保存する箇所 (Applio の変換結果、audio-separator の VR 方式のモデルとアンサンブル) があるため、
  変換と分離の補助プロセスでは soundfile で書く WAV をすべて 32bit 浮動小数にする (`runtime.write_wav_as_float`)
- 時間の位置と長さは、どの処理でも入力と同じに保つ (伴奏とボーカル、タイミング指定の行などを重ねたときにずれないようにするため)。
  ライブラリの都合で位置がずれたり末尾が欠けたりするものは、アプリ側で補う (分離は 14 章、変換は 15.2、rubberband は 13 章の基本方針の各項)。
  確認方法: 入力と出力の音量の包絡の相互相関 (0.5ms 刻み) と、クリック音のピーク位置で、先頭・中間・末尾のずれと長さを比べる
- チャンネル数の変換では音量を変えない。ステレオ -> モノラルは左右の平均、モノラル -> ステレオは同じ音量のまま左右に置く
  (`channelFilter`。ffmpeg の既定 (`-ac`) は、モノラル -> ステレオで各チャンネルを -3dB、ステレオ -> モノラルで左右の和の -3dB
  (左右が同じ音なら +3dB) にするため、そのままでは使わない。ノイズ除去のモデルの出力を入力のチャンネル数とサンプリング
  周波数に戻すときは、`-ac` に `aresample=rematrix_maxval=1` を合わせて、減らすときに左右の平均にする)
- 中間ファイルのサンプリング周波数は、作ったもの (ライブラリ・モデル) の周波数のまま残し、途中で変えない。
  周波数やチャンネル数の違うものを重ねるときは、重ねる処理の中で合わせる。書き出しの設定 (MP3 の周波数など) への
  変換は書き出しのときに 1 回だけ行う (どの設定で書き出しても、途中で落とした精度や周波数の影響を受けないようにするため)
- 作りかけの結果は残さない。分離・変換・読み上げの実行が失敗・キャンセルした場合は、作りかけの候補をその時点でクリーンアップの一覧に積む。
  読み上げで入力の誤りのため作成した音声を返さない場合も同じ。入力の変換 (`prepareInput`) も、失敗したら書きかけを消す
- 同じ組み合わせなら作り直さない結果 (重ねた音・移調した伴奏・合成結果) は、別の名前に書いてから正式な名前にする
  (`produceFile`)。途中で止まった書きかけを、完成したものと取り違えて使い回さないため。書きかけは、作業ディレクトリの中なら
  クリーンアップの一覧に積み、外 (書き出し先・モデルディレクトリなど) ならその場で消す (起動時の片付けの対象外のため)。
  同じものを同時に頼まれた場合は、先に始めた方の完成を待って使う (`produceShared`)
- 候補の破棄では、その候補のファイル (変換は変換後のボーカルと、伴奏と重ねたものの両方) を消す。
  合成結果を作り直したときは前のものを消す。重ねた音 (再生用・分離の入力・ボーカルの組み合わせ) と移調した伴奏は、
  同じ組み合わせで使い回すため、機能の作業を破棄するまで残す
- 機能は単独で完結し、機能の間で結果を受け渡さない (別の機能で使う場合は、書き出したファイルを読み込む)

### 13.7 プレビュー再生 (`services/media-protocol.ts` / `components/voice/SyncPlayer.tsx`)

- 独自スキーム `kura-media://media/<推測できない識別子>/<ファイル名>` で、main が登録したファイルだけを
  renderer の audio 要素 (と SVG 変換の img 要素) へ公開する (renderer は開発時 http、配布時 file から読み込まれ、file:// を直接参照できないため)。
  Range 要求に部分応答で応える (シークのため)。renderer から再生用 URL を求められるのは作業ディレクトリ内のファイルだけ
  - ファイルは要求された範囲だけを少しずつ読んで返し (`createReadStream`)、全体をメモリに置かない。再生側 (audio 要素) も
    再生位置の先を少しだけ読む。長い音声のプレビューでも、メモリの使用量は音声の長さに比例しない
  - audio 要素は先読みの途中で読むのを止めることがあり、その間はファイルが開いたままになる。Windows では開いている
    ファイルへの上書き (名前の変更) が `EPERM` で失敗するため、公開しているファイルを置き換える前 (学習用の音のフィルターの
    確定) は `releaseMedia` で公開をやめ (新しい読み込みを受け付けない)、開いている読み込みを閉じ終えてから置き換える。
    読み込みを止められた audio 要素は、置き換えた後の新しい URL で読み直す
- 画面の中で同時に鳴るのは 1 つのプレーヤーだけ。再生を始めたプレーヤーが知らせ、ほかのプレーヤーは止まる
  (プレーヤーを並べる画面で、音が重ならないように)
- 同期再生: 1 つのプレーヤーで再生対象を切り替えても再生位置を保つ。分離・変換・合成の画面では、聞く音ごとに名前と
  プレーヤーを 1 行ずつ上下に並べる (切り替えのボタンは使わない)。
  複数の出力を重ねて聞く場合は、main で重ねた WAV を作って再生する (`voice:media:mix`、同じ組み合わせは作り直さない)
- 作り直した音声を差し替える場合 (読み上げ) は再生位置を引き継がず、新しい音声を先頭から、止めた状態で示す
  (`keepPosition={false}`。前の音声の再生位置から新しい音声が始まらないようにするため)
- 再生と停止のボタンは同じ大きさにそろえ、ボタンの内側の余白は負のマージンで打ち消す。左右の端と各要素
  (ボタン・再生位置・時間・書き出し) の間の見た目の間隔は 1 種類 (16px) にそろえる
- 再生は読み込みを終えてから行う (全体を読み込むまで再生のボタンを押せない。再生を始めてから読み込みを待って止まるのを避けるため)。
  読み込みを待つ途中で読み込みの処理を止めた場合 (再生対象の切り替えや、開発時の StrictMode が効果を 2 回実行する場合) は、
  同じ対象でも次に読み込み直す (読み込み済みとして扱うと、読み込み終わりの通知を受けられず再生のボタンが押せないままになるため)。
  再生中かどうかの表示は、押した時点ではなく、音声が実際に鳴り始めた・止まった通知 (playing / pause) で切り替える。
  再生位置は描画のたびに音声の再生位置 (`currentTime`) から取り、そのまま描く (アニメーションで追わせると
  実際の再生位置より遅れ、緩急の付いた不自然な動きになるため)
- プレビューの行は、再生・停止のボタン、波形、時間、行の右端の操作 (書き出しなど) を上下中央にそろえて並べる。
  再生している対象の名前や案内の文字の行は置かない
- 再生位置は、プログレスバーの代わりに波形 (`WaveformView.tsx`) の上の線で示す。表示領域の高さは 72px で固定し、
  ステレオは上下に 2 本、モノラルは 1 本で使う (3ch 以上はステレオにまとめる)。波形は再生済みかどうかに関わらず 1 色で描く。
  クリック・ドラッグでその位置へ移動し (ドラッグ中は位置の表示だけを動かし、
  離したときに移動する)、キーボードでは左右・上下の矢印で 5 秒ずつ、Home / End で先頭・末尾へ移動する
  - 時間の区切り: 大きい区切り (時間を「分:秒」で添える) と小さい区切りを縦線で示す。間隔は、大きい区切りが 8 本以下で、
    その間隔が 64px 以上になる最小のものを、1 / 2 / 5 / 10 / 15 / 30 秒・1 / 2 / 5 / 10 / 15 / 30 / 60 分
    (小さい区切りはそれぞれ 0.5 / 1 / 1 / 5 / 5 / 10 秒・30 秒 / 1 分 / 1 分 / 5 分 / 5 分 / 10 分 / 30 分) から選ぶ
    (例: 5 分の音声は 1 分ごとと 30 秒ごと)。時間の文字は波形に隠れないよう、波形の上に背景色で縁取って描く
  - 波形のデータは main が作る (`waveform.ts`)。ffmpeg で 32bit 浮動小数に展開しながら少しずつ読み、チャンネルごとに
    4096 区間の最小値・最大値にまとめる (音声全体をメモリに置かない)。ファイル (パス・更新時刻・大きさ) ごとに 32 個まで覚える。
    再生対象を切り替えたときは、新しい波形ができるまで前の波形を示す。作れなかった場合は波形なしで再生を続ける
- 再生位置と長さは、音声編集ソフトの一般的な表記に合わせてミリ秒まで示す (「分:秒.ミリ秒」、1 時間以上は
  「時:分:秒.ミリ秒」。数秒の音声でも、進み方と長さが正しく分かるようにするため)

### 13.8 書き出し (`exporter.ts` / `components/voice/ExportDialog.tsx`)

- 書き出しの画面を開くボタンは、どの画面でも「書き出し...」とする (設定の画面を開くことを「...」で示し、保存を表す
  アイコンは付けない。押しただけでは書き出さないため)。音声変換の行ごとの保存 (15.2) は、1 つの音だけを書き出す
  アイコンのボタンで、同じ書き出しの画面を開く
- 形式と形式ごとの設定 (オーディオ正規化の書き出しの形式と共通。`shared/audio-format.ts` の `audioEncodeArgs`、画面は
  `components/common/AudioFormatFields.tsx`)。設定はどれもドロップダウンで選ぶ。「(既定)」は FLAC の圧縮レベルの初期値
  (5) にだけ添える。選んだ形式で使わない設定は画面に出さない。使っている ffmpeg に要るエンコーダーが無い形式は選択肢に出さない
  (`audio:formats`。ffmpeg の `-encoders` の一覧で調べ、ffmpeg のパスごとに覚える)。選んでいない形式の設定も覚えておく
  - MP3 (libmp3lame): サンプリング周波数 (8000 / 11025 / 12000 / 16000 / 22050 / 24000 / 32000 / 44100 / 48000 Hz、
    既定 44100)・ビットレートモード (CBR / VBR、既定 CBR)・ビットレート (320〜8 kbps の 18 段階、既定 160)。CBR は
    `-b:a {n}k`。VBR はビットレートの目安を LAME の品質値 (`-q:a`) へ変換する: 245以上=V0 / 225以上=V1 / 190以上=V2 /
    175以上=V3 / 165以上=V4 / 130以上=V5 / 115以上=V6 / 100以上=V7 / 85以上=V8 / それ未満=V9 (LAME の各 V 設定の
    実効ビットレートに基づく)
  - FLAC: サンプリング周波数・ビット数 (16 / 24bit、既定 24)・圧縮レベル (0〜10、既定 5)。どの圧縮レベルでも音は変わらず
    (ロスレス)、上げるほどファイルが小さく、書き出しに時間がかかる。ffmpeg は 11・12 も受け付けるが、予測の次数が最大 32
    になり、FLAC の subset (どの再生機器でも再生できる範囲。48kHz 以下では次数 12 まで) を超えるため選ばせない
  - Ogg Vorbis (libvorbis。`.ogg`): サンプリング周波数・品質 (0〜10、既定 5。`-q:a`)
  - Opus (libopus。`.opus`): ビットレート (6〜510 kbps の 19 段階、既定 160。可変ビットレートの目安)。Opus は 48000 Hz で
    符号化するため、サンプリング周波数の欄は出さず 48000 Hz で書く
  - AAC (ffmpeg の aac。`.m4a`): サンプリング周波数・ビットレート (320〜32 kbps の 12 段階、既定 160)
  - WAV: サンプリング周波数・ビット数 (16bit・24bit・32bit 浮動小数、既定 24bit)
  - ALAC (`.m4a`。Apple のロスレス): サンプリング周波数・ビット数 (16 / 24bit、既定 24)
  - 初期値: 非可逆の形式 (MP3・Ogg Vorbis・Opus・AAC) は、品質とファイルの大きさのつり合いで決めた MP3 の 160 kbps に
    そろえる (Vorbis の品質 5 は 44.1kHz ステレオで 160 kbps 相当)。ロスレスの形式 (FLAC・ALAC・WAV) は 24bit
  - ロスレスの 24bit は、32bit の入れ物に 24bit の値として書く (`-sample_fmt s32` (ALAC は `s32p`) と
    `-bits_per_raw_sample 24`)
- 書き出しの設定は音声機能の設定 (`settings.voice.export`) として変えた時点で保存し、3 機能で共用する
  (どの画面の書き出しから変えても反映される)。オーディオ正規化の出力設定とは別に持つ
- 書き出す対象が 1 つだけの場合 (読み上げ・音声変換の行ごとの保存) は、形式の設定だけを示し、「書き出す」で開くファイルの保存ダイアログで
  場所と名前を選ぶ (上書きの確認も保存ダイアログで行う)。既定の名前は元のファイル名 (読み上げは
  「モデル名_スタイル_作成日時」。スタイルを持たないモデルは「モデル名_作成日時」。モデル名は一覧と同じ表示名
  (`shared/voice/voice-name.ts` の `voiceDisplayName`。モデルを削除した後は、作成したときの表示名)) に形式の拡張子を付けたもの。以下の書き出し先ディレクトリと対象の選択は、対象が複数ある場合のもの
- 書き出す対象をチェックで選ぶ。ファイル名は「元のファイル名 + 接尾辞 (`_vocals` など)」で自動決定し、
  名前の個別入力と、保存ダイアログによる場所と名前の個別指定もできる。個別に指定した場所は、隣のボタンで取り消せる
- 出力先 (書き出し先ディレクトリ) の既定は元のファイルと同じ場所で、ダイアログを開くたびに既定に戻す。
  実行ボタンが出力先の入力を必要とするのは、選んだ対象に場所を個別に指定していないものがあるときだけ
- 書き出し先のフォルダは作らない (無ければ `EXPORT_FOLDER_MISSING`)。同じ書き出し先が複数ある場合は、
  後のもので上書きされるため止める (大文字小文字は区別しない)
- 上書きになるファイルがあれば一覧を示して確認する。書き出しは別の名前 (`<書き出し先の拡張子を除いた名前>.kura-tmp<拡張子>`) に書いてから
  名前の変更で置き換えるため、失敗しても既存のファイルは残る

### 13.9 声のモデルの管理 (`voice-models.ts` / `pages/voice/VoiceModelsPage.tsx`)

- 音声変換と読み上げのそれぞれに管理画面を置く。モデルはモデルディレクトリの `audio/<conversion|tts>/voices/<ID>/` に保存し、
  情報は同じ場所の `meta.json` に持つ (テーブル定義.md)。`meta.json` が読めないモデルがあると、一覧の取得は
  そのファイルを示して失敗する (`DATA_FILE_CORRUPT`)。一覧を使う画面 (声のモデルの管理・変換・読み上げ) は、
  読めなかった理由を通知で示す
- 作成中のモデル (取り込みの確定・学習) は同じ場所の `.staging-<ID>/` に作り、`meta.json` を書いてから `<ID>/` に
  名前を変える (作りかけのものを声のモデルとして扱わないため)。起動時に、前回の起動で残った `.staging-*` と
  取り込みの展開先 (`.import-*`) を裏で消す (`removeVoiceStagingLeftovers`)

| 機能 | 構成ファイル |
|---|---|
| 音声変換 | `model.safetensors` (重み)・`model.json` (設定値)・`model.index` (検索用インデックス、任意) |
| 読み上げ | `config.json`・`model.safetensors`・`style_vectors.npy` |

- 区分は、ユーザーモデル (`user`: このアプリで学習して作ったモデル) と既存モデル (`existing`: それ以外。ダウンロード・
  取り込みしたもの) の 2 つだけ (`origin`)。画面では区分の名前を出さず、ユーザーモデルにだけアイコンを付ける (「モデルの学習」タブと同じ角帽のアイコン。
  学習で作ったものと分かるように)
  (声のモデルの一覧は行の先頭の列、変換・読み上げの声の選択は名前の右)。それ以外 (ダウンロードしたものか、
  取り込んだものか) は利用者に見せる区別にしない。一覧は区分で分けず、学習・取り込みしたモデルを新しい順に並べ、
  その後にダウンロードしたモデル (読み上げのすぐに使えるモデル) をダウンロードの画面と同じ順に並べる (ダウンロードした
  日は並び順に使わない。配布されたモデルにとって意味のない順のため)
- 表示名は名前だけ (名前を付けていないダウンロードしたモデルは配布時の名前から末尾の `-jp` を除いたもの。モデルの種類などを
  添えない。`shared/voice/voice-name.ts` の `voiceDisplayName`)

- 音声変換のモデルは、変換のときに `model.safetensors` と `model.json` から、Applio が使う形 (.pth を読み込んだものと
  同じ内容) をメモリ上に組み立てる (Applio の `VoiceConverter.load_model` を差し替える)。同じ重みを .pth として
  二重に持たないため

- すぐに使えるモデル (JVNV) はダウンロードした `audio/tts/ready/<名前>/` をそのまま使う。名前と言語の変更は
  `audio/tts/voices/ready-model-overrides.json` に記録する (`ready-model-overrides.ts`)。区分は既存モデル。
  削除はダウンロードした項目の削除として行い、記録も消す (13.3)。ダウンロードしたモデルかどうかは区分ではなく
  `readyItemId` (元になったダウンロード項目) の有無で判断する
- 書き出し: zip (拡張子 `.zip`)。中身は各ツールの標準のファイルで、他のツールでもそのまま使える
  - 読み上げ: Style-Bert-VITS2 のモデルのファイル一式 (`config.json`・`model.safetensors`・`style_vectors.npy`)
  - 音声変換: RVC のモデル (`.pth`) とインデックス (`.index`。ある場合)。名前は書き出し先として選んだファイルの名前。
    `.pth` は、保存している重み (safetensors) と設定 (`model.json`) から、Applio が学習したモデルを書き出すのと同じ形
    (`weight`・`config`・`sr` (「40k」など)・`f0`・`version`・`vocoder`・`embedder_model`・`model_name`) に組み立てる
    (`converter_service.rpc_export_model`)。重みと設定だけなので、制限付きの読み込みでも読める。Applio で読み込んで変換できることを確認済み
  - どちらも `kura-voice.json` (形式・機能・名前・区分と、読み上げのモデルの対応言語) を入れる。本アプリに取り込み直したときに
    名前と区分を戻すためのもので、他のツールは使わない。モデルの情報 (RVC の設定値・読み上げのモデルの種類やスタイル) は
    `kura-voice.json` に持たせず、取り込むときにモデルのファイルから読み直す
- 取り込み: 毎回注意文を表示し、同意した場合だけファイルの選択に進む。検査 (`inspectImport`) で内容を確かめ、
  確定 (`commitImport`) で保存する
  - 注意文の内容: 配布元の利用規約やライセンスに従って利用すること、声の持ち主やキャラクターの権利者の許諾なく
    作られたモデルを使わないこと、なりすましやディープフェイクの作成などに使わないこと、利用の責任は利用者に
    あること。音声変換では、公式に配布されているモデルがある一方で無断で作られたモデルも公開されていること・
    配布条件 (クレジット表示・商用利用・二次配布など) がモデルごとに異なることを、読み上げでは Style-Bert-VITS2 の
    開発陣もなりすまし・ディープフェイク作成目的などでの利用をしないよう求めていることを添える
  - 本アプリで書き出したファイルは同梱の情報から元の区分 (ユーザーモデルか) を復元し、外部で入手したモデルは既存モデルとする。
    取り込むファイルの JSON (`kura-voice.json`・`config.json`) が解析できない、またはオブジェクトでない場合は、
    そのファイル名を示して中止する (`IMPORT_INVALID_FILE`)
  - 取り込むものは、ファイル (複数可)・フォルダ (直下のファイルが対象)・zip (中のファイルが対象) で選ぶ。
    zip を 1 つだけ選び、その中に `kura-voice.json` がある場合は、本アプリの書き出しファイルとして扱う。
    音声変換のモデルは外部の `.pth` と同じ検査と変換 (重みと設定だけを取り出して保存) を通し、名前と区分だけを `kura-voice.json` から戻す
  - zip の中身と書き出しファイルは、声のモデルの置き場と同じディスク (`voices/.import-<ID>/`) に展開し、確定時は
    名前の変更で移す (ドライブをまたぐコピーをしないため)。利用者が選んだ元のファイルは移動も削除もしない
  - 音声変換の候補: `.pth` (学習途中のチェックポイント `G_<数字>.pth` / `D_<数字>.pth` を除き、大きいものから並べる) と
    `.index` (任意。RVC・Applio が推論用に作る `added_` で始まる名前のものを先に並べる)。`.pth` が無ければ中止する
    (`IMPORT_PTH_NOT_FOUND`)
  - 読み上げの候補: `.safetensors` (新しいものから並べる)。`config.json` と `style_vectors.npy` は、選んだ `.safetensors` と
    同じフォルダのものを使う (この形式ではファイル名が決まっているため)。足りなければ中止する (`IMPORT_FILES_MISSING`)
  - 候補が複数ある場合は、先頭に並べたものを選んだ状態で確認画面に選択欄を出し、選び直すとそのファイルで検査し直す
    (`chooseImportFiles`)。どのファイルを取り込むかを黙って決めず、利用者が確かめられるようにするため
  - **安全な読み込み**: pth は読み込み時にファイル内のプログラムが実行され得る形式で、実際に悪意あるモデルが
    公開された例もあるため、`torch.load(weights_only=True)` (テンソルと基本的な型だけを復元し、モジュールの取り込みを
    許さない。重みの数値は通常の読み込みと同じで品質に影響しない) で読む。`style_vectors.npy` は
    `np.load(allow_pickle=False)` (数値の配列としてのみ読む) で読む。safetensors はプログラムを含められない形式。
    読めない場合は取り込みを拒否せず、リスクを示して利用者に許可を求め、許可されたときだけ制限なしで読む。
    理由として、ファイルが読み込もうとしたオブジェクトの名前 (`Unsupported global: ...`) を示す
    (PyTorch の元のメッセージは開発者向けの長い説明と端末の色指定を含むため)。
    制限なしで読み込んだ補助プロセスは読み込み後に終了させる。取り込んだモデルは重みと設定値だけを取り出して
    安全な形式 (safetensors・JSON・数値だけの npy) で保存し直し、以降は危険を伴う読み込みを起こさない
  - 音声変換: RVC のバージョン・サンプルレート・ボコーダー・埋め込み方式を読み取り、扱えない形式は理由を示して中止する
    (`RVC_VERSION_UNSUPPORTED`・`RVC_VOCODER_UNSUPPORTED`・`EMBEDDER_UNSUPPORTED`。版は v1 / v2、ボコーダーは
    HiFi-GAN / MRF HiFi-GAN / RefineGAN、埋め込みは変換に使えるもの)。本アプリの書き出しファイルも中身は `.pth` のため、
    同じ検査を通る。確認画面には埋め込み方式を示す。contentvec 以外の埋め込みで作られたモデルは、変換の実行時に
    対応する埋め込みモデルが無ければ、その項目を選んでダウンロードのダイアログを開く (13.14)
  - 読み上げ: 3 ファイルがそろっているか、`config.json` から JP-Extra 版か多言語版か・対応言語を判定する。
    言語モデルの有無は取り込みでは確かめず、読み上げの時に読み上げる言語の言語モデルを確かめる (16.1)
- Hugging Face の検索: 外部ブラウザでモデル検索ページを開く (`HUB_SEARCH`)。音声変換は検索語 `RVC` とタグ `rvc`、
  読み上げは検索語 `Style-Bert-VITS2` とタグ `style-bert-vits2` で絞り込む
- 削除: 利用者のデータ (学習・取り込み) は再取得できない旨を明示して確認し、OS のゴミ箱へ移す (戻せるようにするため。
  ゴミ箱へ移せない場合だけ完全に削除する)。すぐに使えるモデルはダウンロードの項目として削除し、ダウンロード画面から取り直せる
- 読み上げの多言語版のモデルは、使う言語を利用者が設定できる (JP-Extra 版は日本語に固定)
- 名前: 取り込みと名前の変更で、同じ機能に同じ表示名 (大文字小文字と前後の空白は区別しない) のモデルがあれば
  注意を出す (選択欄で区別できなくなるため)。登録自体は妨げない

### 13.10 プリセット (`presets.ts` / `components/voice/PresetBar.tsx`)

- 分離の条件 (方式の選び方・結果の決め方・全アーキテクチャのパラメーター。14 章) と合成のパラメーターを、種類ごとに
  `~/.kura_toolkit/voice-presets/<separation|mix>.json` に保存する。保存 (上書き・新規)・呼び出し・名前変更・削除ができる。
  方式の選び方 (`method`) と詳細な設定 (`params`) を持たない分離のプリセットは一覧に示さない
- 呼び出しは一覧の項目を押したときに行う (選択中のプリセットを選び直しても呼び出せるように。条件を変えた後に、保存した
  条件へ戻すため)
- 種類は renderer から渡されファイル名に使うため、`separation` と `mix` 以外は断る (`INVALID_PRESET_KIND`)。
  一覧を読めない場合 (`DATA_FILE_CORRUPT`) は、画面がその理由を通知で示す
- 合成には初期のプリセット (軽いリバーブ・リバーブなし・ホール・ボーカルを前に) を用意する。名前は設定の中身を表すものに
  する (配布元などの公式の根拠が無いため、「標準」のような位置づけの名前は付けない)。名前は翻訳キー (`nameKey`) で持ち、
  表示言語に従う。初期のプリセットは上書き・名前変更・削除できない (`PRESET_BUILTIN`)。変えた値は新しいプリセット
  として保存できる。画面では初期のプリセットを選んでいる間、上書き・名前変更・削除の操作を無効にし、変更できない旨を添える

### 13.11 言語定義 (`shared/voice/languages.ts`)

- 言語ごとに、読み上げに使えるモデルの種類 (`TtsModelType`。合成用・学習用)・学習用の文章のファイル・学習に必要な文の数・
  記号の読みの初期値をまとめて持つ。言語を追加するときはここに定義を足すと各画面に反映される

| 言語 | 合成のモデルの種類 | 学習のモデルの種類 | 学習用の文章 |

### 13.13 設計上の判断

| 項目 | 本アプリでの扱い | 理由 |
|---|---|---|
| 対応環境 | Windows (x64)・Apple Silicon の macOS 14 以降・Linux (x64) に限る。それ以外では使えない理由を表示する | Intel Mac・Arm 版の Windows・Arm 版の Linux 向けの PyTorch (必要な版) が配布されていないため |
| 仮想環境への pip の導入 | `--without-pip` で作り、Python 本体に同梱の pip を `--python` で仮想環境に向けて使う | venv が ensurepip で入れる pip 24.0 は進捗の機械可読の出力 (`--progress-bar raw`) に対応せず、進捗を表示できないため |
| Applio の版と導入するパッケージ | 3.6.5 に固定し、変換と学習に必要なパッケージだけを導入する | 版はアプリが決めるため。Applio の requirements は画面 (Gradio) などを含み大きいため |
| 読み上げの言語 | 日本語・英語・中国語 (Style-Bert-VITS2 が扱える言語のすべて)。言語ごとの BERT は読み上げる言語の分だけ取得する | 読み上げにも学習にも、読む言語の BERT だけを使うため |
| 分離モデルの一覧 | audio-separator の一覧のうち VIP モデルは表示しない | VIP は UVR の有償支援者向けで、有料のモデルを使わない方針のため |
| 中国語の発音指定 (phoneme) | ピンインと声調の数字で文字ごとに指定する (`x-pinyin`)。囲めるのはエンジンが読む漢字だけ | 1 文字が 1 音節 (2 音素) に対応し、指定しても音素の数が変わらないため、エンジンの「音素と声調を与えて読ませる」経路をそのまま使えるため |
| 英語の発音指定 (phoneme) | IPA で指定する。ライブラリの語の区切りで複数に分かれる語には使えない (読み替えタグを案内する) | 指定した発音を語単位でしか渡せないため |
| 保存場所の既定 | ライブラリ・モデルは `~/.kura_toolkit` の下、作業ディレクトリは OS の一時ディレクトリ (Linux は `~/.kura_toolkit/temp`) | アプリのデータはホームディレクトリのアプリ用のフォルダに、一時ファイルは OS の一時ディレクトリに置く一般的な配置に合わせるため。Linux の OS の一時ディレクトリ (`/tmp`) はユーザー間で共有されるため、ユーザーごとの場所にする |
| 保存場所の指定 | ライブラリ・モデルディレクトリは、選んだフォルダをそのまま保存場所にする (中にフォルダを挟まない)。選べるのは空のフォルダか、同じ種類の保存場所のフォルダ (中身をまとまりごとにマージする。13.2)。作業ディレクトリは一時ディレクトリそのものを選び (空でなくてよい)、アプリはその中の `kura_toolkit_*` フォルダだけを作り、消す | 利用者が選んだ場所と実際の保存場所を一致させるため。ほかのファイルが入ったフォルダを選べないようにするのは、アプリのファイルと他のファイルを混ぜず、片付けで他のファイルを消さないため。一時ディレクトリは OS や共用のものを選べる必要があり、アプリ名の接頭辞で分けることで同じことを満たすため |
| 保存場所の構成 | ライブラリはライブラリごと、モデルは分類 (`audio` など) と機能ごとのディレクトリに分ける。保存場所はアプリ全体で共有する | 今後ライブラリやモデルの種類が増えても、同じ場所の下に追加できるようにするため |
| 作業ディレクトリ | アプリは 1 つしか起動しない。作業ディレクトリの直下に一連の処理ごとの `kura_toolkit_<ランダムな値>` フォルダだけを (分類の階層を挟まずに) 作り、それだけを消す | 複数のアプリが同じ保存場所を同時に書き換えないため。起動時に `kura_toolkit_*` を前回の残り物と判断でき、他のファイルに触れずに片付けられるため。階層を挟まないのは、一時ディレクトリの中に意味のない階層を重ねないため |
| 一時ファイルの置き場 | 作業ディレクトリには、その処理の中で作って使い、消すものだけを置く。ダウンロード・書庫・pip のキャッシュは置き場所と同じディスクに置く | 置き場所が別のドライブの場合に、コピーと削除が発生して時間がかかり、SSD を消耗させるため |
| 一時ファイルを消す時機 | 不要になった時点で消す (成功・エラー・キャンセルを問わない)。クリーンアップの一覧のもの (作業ディレクトリの中) はアプリの終了時には消さず、終了時に残っていたものは次の起動時に裏で消す | 不要なファイルを残さず、アプリの終了を待たせないため |
| 学習の途中のデータ | 作業ディレクトリのジョブのフォルダに置き、学習が終わったら消す。完成したモデルは、モデルディレクトリの作成中の声のモデルのフォルダに直接書かせる | 上流のソース一式 (ライブラリディレクトリ) を書き換えず、完成したモデルをドライブをまたいでコピーしないため |
| 取り込みのファイルの候補 | 候補が複数ある場合は、先頭に並べたものを選んだ状態で確認画面に示し、選び直せるようにする | 配布物には学習途中のチェックポイントや複数のインデックスが入っていることがあり、どれを取り込むかを利用者が確かめられるようにするため |
| リンク | シンボリックリンク・ジャンクション・ハードリンクを作らない。仮想環境も `--copies` で作る。上流がモデルを読む箇所を補正して、モデルディレクトリのファイルを直接読ませる | OS やファイルシステムの機能に依存する仕組みを持ち込まないため |
| 学習用の音声 | 録音も指定したファイルも、学習セットの中に同じ形式 (16bit・モノラルの WAV) で保存し、学習が終わっても残す。学習セットはモデルディレクトリに置く | 録音と取り込みの途中経過を、アプリを起動し直しても続けられるようにし、別の設定で学習し直せるようにするため。元のファイルを移動・削除しても学習に影響しないため。ライブラリディレクトリはアプリが導入するものの置き場で、利用者のデータはモデルディレクトリ側に置くため |
| 分離の ONNX モデル (MDX-Net) の実行 | onnxruntime は GPU 版 (onnxruntime-gpu) を使わず、ONNX のモデルは CPU で実行する (PyTorch のモデルは GPU を使う) | CUDA / cuDNN の版の組み合わせに依存する GPU 版を避けるため |
| macOS・Linux の分離 | パッケージの一部 (diffq) がソースからのビルドになるため、macOS は Xcode Command Line Tools、Linux は C/C++ のコンパイラーを必要とする (無ければ案内する) | 配布物に使う Python の版向けのビルド済みのものが無いため |
| ダウンロード画面の位置づけ | 必要な箇所から呼び出すダイアログにする | 音声機能を使う途中で必要になるもので、単独で使う機能ではないため |
| 声のモデルの管理と学習 | 音声変換・読み上げの画面上端の切り替えから、入力が無くてもいつでも開ける | 変換や読み上げの作業とは独立して行うため |

### 13.14 画面の構成と呼び出し (`components/voice/VoiceFeatureHeader.tsx` / `stores/voiceLibraryStore.ts`)

- 各音声機能の画面の上端に `VoiceFeatureHeader` を置く
  - 音声変換と読み上げは「変換 (読み上げ)」「声のモデル」「モデルの学習」を切り替えるタブを持つ
    (`/audio/conversion` ⇔ `/audio/conversion/models` ⇔ `/audio/conversion/training`、読み上げも同様)。
    変換する音声や読み上げる文章が無くても、声のモデルの管理と学習はいつでも開ける。
    作業中の内容は zustand ストアに残るため、切り替えても失われない
  - 右端の「ダウンロード管理」でダウンロードのダイアログを開く。開いたときは、その画面の機能のタブを表示する
    (学習の画面では学習の機能のタブ)
  - 音声分離の画面はタブを持たないため、この行は音源を選ぶまでだけ置く。音源を選んだ後は「ダウンロード管理」を
    元の音源の行 (「新しい作業」「書き出し...」の行) に置き、行 1 つ分の表示領域を使わない
- ダウンロードのダイアログ (`VoiceLibraryDialog`) は App に 1 つだけ置き、`openVoiceLibrary({ select, focus })` で開く。
  `select` の項目を選んだ状態で開き、`focus` の機能のタブを表示する (`focus` が無ければ、`select` の項目を最も多く含む
  機能のタブ。`libraryItems.ts` の `featureForItems`)。呼び出す箇所は次のとおり
  - 機能に必要なものが足りないときの案内 (`ReadinessAlert`): 足りない項目を選び、その機能のタブで開く
  - 変換・分離の実行時に必要なモデルが無い場合 (変換は `MODEL_REQUIRED`、分離は `MODEL_NOT_INSTALLED`):
    その項目を選んで開く (学習では、足りない項目を案内に示して開始のボタンを押せなくする)
  - 読み上げ: 読み上げる言語の言語モデルが無いときの案内 (案内のボタンで開く)
  - 声のモデルの「取り込み」: Python 本体とパッケージ一式が無ければ、それを選んで開く
  - 読み上げの声のモデルの「すぐに使えるモデルを取得」: 未取得のすぐに使えるモデルをすべて選び、読み上げのタブで開く
  - ライブラリディレクトリの移動後に、使えなくなったパッケージ一式がある場合 (アプリ設定の保存場所から): それを選んで開く
- ダイアログの上端 (タイトルの下) に実行環境を小さい文字の 1 行で示し (処理に使う装置・ライブラリとモデルの場所・
  設定への移動・再検出。幅が足りなければ折り返す)、その下に機能ごとのタブ (「音声分離」「音声変換」
  「音声変換のモデルの学習」「読み上げ」「読み上げのモデルの学習」) を置く。どちらも本体の外に置き、一覧をスクロールしても動かない。本体には、
  選んだタブの機能に必要な項目を、まとまりごとの表に分けて示す。構成は `shared/voice/requirements.ts` の
  `FEATURE_REQUIREMENTS` に定義し、main の `checkFeature` もこの定義の必須のまとまりの項目で機能を使えるかを判定する
  (定義を 1 か所に保つため)
  - 本体のスクロール枠はタブごとに持つ (全タブを同じ場所に重ねて描き、表示中でないタブは見えなくして操作させない
    (`inert`)。`display: none` にするとスクロール位置が失われるため使わない)。タブを切り替えても、それぞれのタブの
    スクロール位置を保ち、初めて表示するタブは先頭から表示する。ダイアログを開き直したときは、すべてのタブを先頭に戻す
  - まとまりは名前と種別を持ち、見出しは「名前 (種別)」とする (例: 「分離の実行環境 (必須)」「取り込んだ声のモデル用
    (オプション)」)。種別は「必須」(`all`)・「いずれか 1 つ以上」(`anyOf`)・「オプション」(`optional`)。
    まとまりは説明を持て、項目ごとに必要になる条件 (`conditionKey`) を持てる。分離モデルは、
    数が変わるため項目 ID の先頭 (`itemPrefix`) で指定する
  - 読み上げの言語モデルは、読み上げる言語ごとに必要なもの (日本語・英語・中国語の文章は、それぞれの言語の言語モデル)
    のため、「いずれか 1 つ以上」のまとまりに置く。読み上げの必須は Python 本体と読み上げのパッケージ一式だけで、言語ごとの
    言語モデルは読み上げの実行時と読み上げの画面で確かめる (16 章)
  - すぐに使えるモデルは、読める言語の言語モデルの行の下に「すぐに使えるモデル (オプション)」として並べる
    (`RequirementNode.readyModelsFor`。読める言語はダウンロード項目の `readsLanguages`。JP-Extra 版は日本語、多言語版は
    日本語・英語・中国語)。複数の言語を読めるモデルは各言語の下に出し、選択の状態は 1 つ
  - 読み上げの学習の必須は Python 本体と読み上げ・学習のパッケージ一式で、学習する形式の事前学習モデルと、学習する言語の
    言語モデルをそれぞれ「いずれか 1 つ以上」のまとまりに置く (学習ではその言語の言語モデルだけを使う)
  - 項目は前提の関係を階層で示す (Python 本体の下にパッケージ一式など)。階層の上位に無い前提項目 (すぐに使えるモデルに対する
    言語モデルなど) は、行に「前提」として示す。前提項目は選んだ項目と一緒にダウンロードする (13.3)
  - 各行には、項目が何か (概要) と、その機能での役割を示す
  - タブの見出しには、必須の項目が揃った機能に印を付ける。必須の項目に不足がある場合だけ、タブの上端に不足の数と、
    不足している項目をまとめて選ぶ操作を置く (揃っている場合は何も出さない)
  - 同じ項目が複数のタブに出る場合も、選択の状態は 1 つ (どのタブで選んでも同じ)。行は選択が変わったものだけを
    描き直す (`React.memo`。分離モデルは 150 以上並ぶため)
  - 表の中にスクロール領域を作らない (ダイアログの本体だけをスクロールする)
  - 変換の補助モデルのうち SPIN・SPIN v2・日本語 / 中国語 / 韓国語 HuBERT は、取り込んだ声のモデルがその方式で
    作られている場合にだけ必要なため、「取り込んだ声のモデル用」のまとまりに分ける
- 項目の概要の決まり (ダウンロードの画面と分離の画面): 名前や、ほかの欄・行 (配布元・方式・出力・大きさ・ライセンス) に
  出ていること (作者名・方式など) は書かない。配布元の説明や、おすすめの元にしたガイドにある内容だけを書き、根拠の
  無い評価は書かない。種類ごとに同じ形の 1〜2 文にし、使える条件 (OS・GPU など) があれば最後に「〜でのみ使えます」と書く
  - パッケージ類 (Python 本体・パッケージ一式): 何が入っているか + どの機能で使うか + 動作の条件
  - 補助のモデル (ピッチ抽出・特徴抽出・事前学習・言語モデル): 何をするモデルか + どの機能のどこで使うか + 同じ役割の
    ほかのモデルとの違い
  - すぐに使える声: 声の性別とモデルの種類 + 元にした音声 + 読める言語と注意
  - 分離モデル: 何をするモデルか + ほかのモデルと見分けるための特徴 (ボーカルの混ざりにくさ・音の厚み・ノイズ・
    取り除く強さ・速さ・苦手なもの・使う順番など) と使い方。版の違いは、そのモデル自身の概要に書く (「V2 は V1 の
    改良版」を V1 に出さない)。兄弟のモデルとの違いを書くため、概要はモデルごとに持つ。出典は、各作者の Hugging Face の
    モデルカード、UVR・Demucs・KUIELab の GitHub、audio-separator の資料、deton24 のガイド (Instrumental, vocal & other
    stems separation & mastering guide)。出典で確かめられない特徴は書かず、説明が見つからないモデルはその旨を書く。
    利用者の報告に基づく傾向は「〜という報告があります」のように書く
  - 分離の組み合わせ (おすすめ): 何を狙った組み合わせか (audio-separator の `ensemble_presets.json` の description に
    基づく。説明に無い代償などは書かない)
- 分離モデル (`components/voice/SeparatorModelSection.tsx`)。まとまりの見出しの下を、「目的別のおすすめ」と
  「個別のモデル」の 2 つに分け、それぞれ見出しだけを持つ (説明の文は置かない。モデルごとの概要で足りるため)
  - おすすめは目的ごとのタブで切り替える (`separatorPurposes.ts` の `SEPARATOR_PURPOSES`。分離の画面の方式の「おすすめ」と共有する): ボーカル取り出し・伴奏取り出し・
    ボーカルと伴奏の両方・メイン・コーラス・伴奏の分割 (2 段階)・ノイズ除去・残響・エコーの除去。タブの名前と、
    個別のモデルの種類の名前は、同じ目的のものは同じにする。各目的に、
    audio-separator の一覧が持つ検証済みのアンサンブル (`LibraryStatus.separatorEnsembles`。出典は deton24 のコミュニティの
    ガイド) を、何を優先し何を犠牲にするかの説明を添えて示す (配布元は組み合わせの間に順位や「標準」を決めていないため、
    順位の印は付けない)。タブの下の補足と、行に添える回の印 (「1 回目: …」「2 回目: …」) は、2 回に分けて分離する
    「メイン・コーラス・伴奏の分割」だけが持つ (手順の説明が要るため。ほかのタブは補足を出さない)。同梱の組み合わせが無い
    目的 (両方をバランスよく・ノイズ除去・残響・エコーの除去) は単体のモデルを示す。ノイズ除去と残響・エコーの除去の
    モデルは、分離の利用者コミュニティのガイドで声に向くとされているものを選ぶ (ノイズ除去: Mel-Roformer Denoise・
    同 Aggr・UVR-DeNoise-Lite。残響・エコーの除去: Sucial の Fused・anvuew の Less Aggressive・MDX23C De-Reverb・
    UVR-De-Echo-Normal)。ノイズ除去のおすすめのモデル (`NOISE_REMOVAL_MODELS`) は、ノイズ除去の「モデルで除去する」で
    選べるモデルでもある。一覧に無い組み合わせ・モデルは示さない。組み合わせは、
    組み合わせるモデルを組み合わせの行の下に 1 段下げた行として並べる (状態・大きさの確認と
    個別の選択・削除がその場でできる)。組み合わせの行を選ぶと、組み合わせるモデルをすべて選ぶ。用途の説明は ID ごとの
    訳で示す (分離の画面で組み合わせを選んだときも同じ説明を示す)。絞り込みの対象にせず、常にすべて示す
  - 個別のモデルは、上から共通の絞り込み・分離の種類の切り替えボタン・枠の順に置く
    - 共通の絞り込みは、すべての種類のモデルに効く。キーワード (空白 (全角を含む) で区切った語がすべて、行に見えている文字の
      うちほかの絞り込みに無いもの (名前・概要・ライセンス・クレジット) のどれかに含まれるもの。語ごとに別の項目で
      見つかってよい)・方式 (選択肢はいずれかの種類のモデルにあるもの)・おすすめ
      (すべて・おすすめのみ・おすすめ以外。おすすめは目的別のおすすめに載っているモデルで、組み合わせのモデルを含む)・
      取得済みのみ
    - 種類の切り替えボタンは幅が足りなければ折り返し、共通の絞り込みを通ったモデルの数を添える。モデルのある種類は、
      0 件になってもボタンを残す
    - 枠の中には、出力のチップと表を置く。チップは、選んでいる種類の共通の絞り込みを通ったモデルにある出力だけを並べ、
      押すと選び (塗りつぶし)、もう一度押すと外す。選んだ出力をすべて持つモデルだけを示す。種類を切り替えると選んだ
      チップを外す
    - 呼び出し元が 1 種類の分離モデルだけを選んで開いた場合は、その種類を選んだ状態で開く。条件に合うモデルが無ければ
      その旨を示す
  - 各モデルの行には、何をするモデルかの概要・方式・出力・分離の品質 (SDR。分かるもののみ) を示す。概要はモデルの
    ファイル名から翻訳キーを引く (`separatorModelNotes.ts` の `SEPARATOR_MODEL_NOTES`。キーはファイル名から作り
    (`m_` + 英数字以外を `_` にしたもの)、モデルごとに 1 つ持つ)。一覧に出力の名前が無いモデル (Roformer の多く) は、配布元の各モデルの設定ファイルにある出力の名前を
    `SEPARATOR_MODEL_OUTPUTS` に持って示す。audio-separator の版を上げたら、一覧に増えたモデルの概要と出力を足す
  - 種類ごとの表は、名前の順に並べる (`compareSeparatorModels`)
- ダイアログの下端は、左端に「選択した項目を削除」(押すと確認を出す) を置き、ダウンロードの操作 (選んだ項目の数と
  合計の大きさ・「選択した項目をダウンロード」) から離す (誤って押さないため)
- 見出しは、グループの見出しを 16px の太字 (`subtitle1`)、グループの中の小見出し (目的別のおすすめ・個別のモデル) を
  14px の太字 (`subtitle2`) にし、どちらも本文と同じ色にする (上の階層ほど大きくする)
- 余白 (単位は MUI の spacing。1 = 8px) は次の決まりでそろえる。上の階層ほど広く空け、見出しは内容に近づける
  - 機能のタブの中の大きなまとまり (警告・各グループ) 同士: 3
  - グループの中の小見出しのまとまり (目的別のおすすめ・個別のモデル) 同士: 2
  - 見出し・補足文からその内容まで: 1
  - 同じまとまりの中で縦に並ぶ部品 (タブ・絞り込み・種類の切り替え・枠・表) 同士: 1.5 (`Panel` の内側の余白と同じ)
  - 横に並ぶ部品 (入力欄・選択欄・ボタン・チップ) 同士、警告同士、確認のダイアログの段落・箇条書き・警告の間: 1
- ダウンロード・削除・ライブラリの移動などで取得状況が変わったら `notifyVoiceLibraryChanged()` で `version` を増やす。
  取得状況を表示している画面 (`useFeatureReadiness`、分離の方式の一覧、声のモデルの一覧) は、この値の変化で読み直す。
  そのためダイアログで取得した後、呼び出し元の画面をそのまま続けられる

### 13.15 学習セット (`training-sets.ts` / `components/voice/TrainingSetBar.tsx`)

- 学習用の音声に名前を付けて残したもの。音声変換と読み上げのそれぞれで持ち、選択・作成・名前の変更・削除ができる。
  読み上げの学習セットは作成時に言語を 1 つ選び、後から変えない (文の音声はその言語の学習用の文章に対応するため)
- 場所はモデルディレクトリの `audio/<conversion|tts>/training-sets/<ID>/`。名前・言語・音声の一覧を `set.json`
  (テーブル定義.md) に、音声を `audio/<音声の ID>.wav` に置く。利用者が録音・用意した作り直せないデータで、
  ライブラリディレクトリ (アプリが導入するものの置き場) ではなくモデルディレクトリ側に置き、声のモデルとは別の場所にする。
  保存場所の移動ではモデルディレクトリと一緒に移る
- 録音は画面から 1 秒分ずつ 16bit・モノラルの PCM を main へ送り、main が作業ディレクトリの WAV へ追記する
  (`recording.ts`。録音全体を画面のメモリに持たず、長さに上限を設けない)。形式は常に RF64 (64bit の長さを持つ WAV) とし、
  長さ (ds64 の欄) は録音を止めたときに書く。録音のファイルを読むのはアプリの再生 (Chromium) と学習のライブラリ (soundfile) と
  ffprobe だけで、いずれも RF64 を読める (実測で確認)。書き込みに失敗した場合はその時点で録音をやめて理由を示す。
  録音を止めると書き込みを終え、学習セットへ移す (移せなかった場合も作業ディレクトリに残さない)
- 録音はそのまま (16bit・モノラルの WAV)、ファイルは ffmpeg で同じ形式 (サンプリング周波数は元のまま) にして
  学習セットの中に保存する (`encodeTrainingWav`)。録音とファイルの指定で、その後の扱いを同じにするため。
  元のファイルは追加した後に移動・削除してよい。変換は保存先に直接書く (書きかけは別の名前にし、完成してから名前を変える)
- 読み上げの学習セットでは、文ごとに音声を 1 つ持つ。同じ文に録り直した・指定し直したときは前の音声を消す
- ファイルの音声の名前は元のファイル名。学習セットにすでに同じ名前 (大文字・小文字は区別しない) の音声があるファイルは、
  誤った操作とみなして加えず、加えなかったファイルの名前を示す (ほかのファイルは加える。一度に指定した中で重なる場合は
  2 つ目以降を加えない)。読み上げの学習セットで指定し直す場合は、置き換える、その文の今の音声とは比べない。
  録音の名前は録音した日時のため比べない
- ファイルは、ファイルを選ぶボタンのほか、ドラッグ&ドロップでも指定できる (`components/common/FileDropTarget.tsx`。
  ドラッグ中は枠を強調し、対象外の形式だけをドロップした場合はその旨を示す。処理中・録音中は受け付けない)。
  音声変換の学習では音声の一覧の枠に複数をまとめて、読み上げの学習では右の文の枠に 1 つだけ (複数をドロップした場合は
  先頭の 1 つ) をドロップする
- 学習が終わっても (成功・エラー・キャンセル) 学習セットは変えない。学習中・削除中はその学習セットへの音声の追加・
  削除を断り、音声の追加中 (録音の保存・ファイルの変換) は学習と学習セットの削除を始めさせない (`TRAINING_SET_IN_USE`。
  追加の途中で学習を始めると、録り直しで消える前の音声を学習が読むことになるため)。名前の変更は学習中もできる (削除中は断る)。
  学習セットの処理中は、保存場所の移動も断り、移動中は学習セットの操作を断る (`LIBRARY_BUSY`。録音の保存はジョブでは
  ないため、別に確かめる)
- 記録 (`set.json`) が読めない学習セットは一覧から除き、ログに残す (1 つが壊れていても、ほかを使えるようにするため)
- 学習セットの削除はごみ箱に移す (ごみ箱に移せない場合は完全に削除する。声のモデルの削除と同じ `moveToTrash`)。
  音声の削除は完全に削除し、元に戻せないことを示して確認する
- 起動時に、記録 (`set.json`) に無い音声のファイル (追加の途中でアプリが終了して残ったもの) を裏で消す
  (`removeTrainingSetLeftovers`)
- 一覧は更新の新しい順。画面は、機能ごとに最後に選んだ学習セットを起動中だけ覚え、無ければ更新の新しいものを選ぶ
- 学習用の音のフィルター (`TrainingFilterDialog`。13.16): 残響・エコーを除去する・ノイズを除去する・無音部分を除去する・
  音量をそろえるを同時に指定し、この順に加工して、学習用の音声と同じ形式 (16bit・モノラル) にする (聞いた音と置き換える音を
  同じにするため)。設定欄も処理の順に並べる。残響の尾や雑音を除いてから無音を判断すると、無音として除ける部分が増えるため、
  無音部分の除去は残響・ノイズの除去の後に行う
  - 個々の音: 音の行のフィルターのボタン (削除のボタンの左) から開く。初期値は、残響・エコーの除去はチェックなし
    (時間がかかるため)、ほかの 3 つはチェックあり。「加工」を押すたびに、
    元の音から作った結果を下に足す (加工した結果をさらに加工することはしない)。元の音と結果は、カードのクリック
    (再生を含む) で選ぶ。確定で、選んだ結果を学習セットの音のファイルの場所へ移し (同じドライブなら名前の変更。
    元の音のファイルは置き換わって消える)、記録の長さなどを直す。作った結果は作業 (ダイアログを開くたびの作業の
    識別子) の中に置き、確定でもキャンセルでも、閉じる前に作業ごと消す
  - 学習セットのすべての音 (「すべての音にフィルターを適用」): 初期値は無音部分の除去だけチェックあり。すべての音を
    加工してから、まとめて置き換える (キャンセルしたら何も置き換えない。しなかったことにするため)。結果は聞き比べない

### 13.16 声の音の加工 (`audio-filters.ts` / `shared/voice/audio-filters.ts` / `components/voice/AudioFilterFields.tsx`)

- 残響・エコーの除去・無音の扱い・ノイズ除去・音量をそろえるの 4 つ。変換のオプション (15.2)・分岐の「その他」(14 章)・
  学習用の音のフィルター (13.15) で、同じ設定欄・同じ値の初期値・同じ処理を使う (チェックの初期値と処理の順は使う場所ごとに
  決める。音量をそろえるの目標の初期値だけは、分岐の「その他」ではオーディオ正規化の初期値にする)。どれも「チェックすると、その下にスライダーなどを出す」形で、値はチェックを外しても覚えておく
- 使うモデルの欄 (残響・エコーの除去と、ノイズ除去の「モデルで除去する」) は、1 つだけ選ぶ欄 (Autocomplete) にする。
  分離のモデルのタブと同じく、名前・ファイル名・概要・出力で絞り込め (`filterSeparatorModels`)、一覧の各項目に名前
  (前置きを除いたもの) と概要 (`SeparatorModelSummary`) を示し、選んでいる項目は右端のチェックの印で示す。選んだものは
  チップではなく、欄の中に名前を折り返して示し、欄の下に選んだモデルの概要を示す。消す操作をしても選んだものは残し、
  絞り込みの案内の文字は出さない (使うモデルは必ず 1 つ選んでいるため)
- 処理の順は、ノイズが最も残らない順にする。残響・エコーの除去 → ノイズ除去の順は、逆の順より雑音成分がわずかに少ない。
  無音の扱いは、残響の尾や雑音を除いた後で判断する (無音と判断できる部分が増えるため)。変換では、残響・エコーの除去を
  変換前のボーカルにかける (変換後の声には残響がほぼ残らず、変換の後にかけてもほとんど変わらないため)
- 残響・エコーの除去 (`removeReverb`)。方式はモデルだけ (ffmpeg には残響を除くフィルターが無く、音の大きさで下げる
  ゲートでは声と重なった残響を除けないため)。残響・エコーの除去のおすすめのモデル (`DEREVERB_MODELS`。目的別のおすすめの
  「残響・エコーの除去」と同じもの) のうち、取得済みのものから選ぶ (初期値はおすすめの順で先頭の Mel-Roformer Fused)。
  そのモデルで分離し、残響を除いた方の出力 (Fused・MDX23C De-Reverb は `dry`、Less Aggressive は `noreverb`、
  UVR-De-Echo-Normal は `no echo`) を使う。出力は入力のサンプリング周波数とチャンネル数に戻す (ノイズ除去のモデルと同じ)。
  おすすめのモデルを 1 つも取得していなければチェックできない状態にし、ツールチップでダウンロードすると使えることだけを
  示す (リンクは置かない)
- 無音の判断 (`kura_voice/silence.py`): 音のピークから「無音とみなす大きさ」(初期値 -60 dB) より小さい状態が
  「これより長い無音を対象にする」(初期値 0.4 秒) 以上続く部分を無音とする。大きさは 20 ms の RMS を 10 ms ごとに測る。
  ピークからの大きさで判断するため、録音の大きさや音量をそろえる処理の前後で、無音と判断される部分は変わらない。
  無音部分の端では、無音部分の内側で 10 ms かけて音量を変え、無音部分の外側の音は変えない (プツッという音を出さないため)。
  ファイルは区切って 2 回読み (無音を探す・書く)、全体をメモリに置かない
  - 無音部分の雑音を消す (変換・分岐): 無音部分の音量を 0 にする。時間の位置と長さは変わらない
  - 無音部分を除去する (学習用の音のフィルター): 無音部分を取り除いて詰める
  - 初期値の根拠: 大きさは、なるべく消さない側の値。長さは、Applio が学習の前に無音を切る長さ (0.4 秒)
- ノイズ除去 (`removeNoise`)。方式を選ぶ
  - 簡易的に除去する (FFT・速い。初期値の方式): ffmpeg の afftdn。周波数ごとに「雑音とみなす大きさ」(noise_floor) 以下の
    成分を、「雑音を下げる量」(noise_reduction) だけ下げる。初期値は ffmpeg の初期値 (-50 dB・12 dB)。afftdn には、
    続いた長さで雑音を判断するパラメーターは無い。afftdn は音の位置がずれるため、ずれを打ち消して使う (13 章の基本方針)
  - 簡易的に除去する (ウェーブレット・速い): ffmpeg の afwtdn。「雑音の大きさ」(sigma。画面では dB で示し、振幅に直して渡す)
    以下の成分を、「除去の強さ」(percent) の割合だけ除く。初期値は、除去の強さは ffmpeg の初期値 (85%)、雑音の大きさは
    afftdn の雑音とみなす大きさと同じ -50 dB (ffmpeg の初期値 0 は何も除かないため)。ほかのパラメーターは ffmpeg の初期値の
    まま。afwtdn は音の位置がずれない。雑音の大きさを実際の雑音より大きくすると、声も削る
  - モデルで除去する (遅い): ノイズ除去のおすすめのモデル (`NOISE_REMOVAL_MODELS`。目的別のおすすめの「ノイズ除去」と
    同じもの) のうち、取得済みのものから選ぶ (初期値はおすすめの順で先頭)。そのモデルで分離し、ノイズを除いた方の出力
    (Mel-Roformer Denoise は `dry`、UVR-DeNoise-Lite は `no noise`) を使う。強さは持たない。おすすめのモデルを
    1 つも取得していなければ選べない状態にし、ツールチップでダウンロードすると使えることだけを示す (リンクは置かない)。
    おすすめに無いノイズ除去のモデルは選べない
- 音量をそろえる (`normalizeLoudness`): オーディオ正規化と同じく、ファイル全体を一律に上げ下げし、上げた後の True Peak が
  上限 (-1.5 dBTP) を超える場合は上限までにとどめる (強弱は変わらない)。目標の初期値は -16 LUFS
  (話し声の配信でよく使われる値)。分岐の「その他」では、オーディオ正規化の初期値 (-13 LUFS。
  `AUDIO_NORMALIZER_DEFAULT_LUFS`) にする。目標のスライダーの下に LUFS の値の目安を添える。無音などで測れない場合は
  そのまま写す
- 無音の処理は、その機能で使っている Python の処理役で行う (`edit_silence` / `detect_silence`。どの処理役にもある)

## 14. 音声分離 (`separation.ts` / `components/voice/SeparationWorkbench.tsx`)

楽曲などの音声を、ボーカル・伴奏・楽器別のパートなどに分離する単独の機能。分離には audio-separator を使う
(UVR で使われている MDX-Net・VR Arch・Demucs・MDXC の各モデルを扱えるパッケージ)。
同じ分離の操作部 (方式の選択・パラメーター・結果の木と聞き比べ) を、音声変換の画面にも組み込む (15.1)。

- 入力: 音声・動画ファイル (ffmpeg で読めるもの) を内部処理用の WAV にする (`prepareInput`)。
  チャンネル構成は元の音源のまま (3 チャンネル以上はステレオにまとめる)。長さ・チャンネル数・サンプリング周波数の
  いずれかを読み取れない音声は扱わない (`AUDIO_INFO_UNKNOWN`。音声変換の入力と学習用の音声の追加でも同じ)
- 分離の入力は末尾に 1 秒の無音を足したものにし、結果は元の長さ (結果のサンプリング周波数でのサンプル数) に切りそろえる
  (`padEnd` / `convertChannels`)。VR 方式のモデルは末尾の数ミリ秒を処理せずに短く返すため。
  結果の音量は調整しない (audio-separator の `normalization_threshold` は 1 以下しか指定できないため、作成後に無限大へ
  書き換える)。最大値が 1 を超えた結果を下げると、元の音源や他の結果との音量の関係が変わるため。結果は 32bit 浮動小数で、
  1 を超えても割れない
- 方式の一覧 (`listSeparationModels`)
  - audio-separator の `list_models` 相当の一覧 (アーキテクチャ・出力の種類・SDR・表示名) を取得し、
    キャッシュディレクトリの `audio-separator/model-list.json` にキャッシュする (パッケージ一式の版が変わったら取り直す)
  - SDR は配布元 (audio-separator の `models-scores.json`) にある値を、丸めずにそのまま示す (`SeparatorModelSummary`)
  - 一覧はパッケージ一式の導入時に作る。一覧が無い場合 (導入時に作れなかった・アプリの更新で一覧の版が変わった) は、
    分離の画面で方式の一覧を読むときと、ダウンロードのダイアログで音声分離のタブを表示したときに裏で作る
    (`ensureSeparatorModelList`。同時に呼ばれても Python への問い合わせは 1 回)。ダイアログは作成中であることを示し、
    操作は妨げない。作れなかった場合はエラーと再試行を示す (自動では繰り返さない)。利用者が一覧を取得・更新する操作は無い
    (一覧は導入したパッケージ一式から得るもので、パッケージ一式を入れ替えない限り変わらないため)
  - 各モデルに分離の種類 (`vocals` ボーカルと伴奏 / `multi` 楽器ごと / `karaoke` メインとコーラス / `denoise` ノイズ除去
    (歓声の除去を含む) / `dereverb` 残響・エコーの除去 / `other` どれにも当たらないもの (息の分離・男女の声の分割など))
    を持たせる。種類は、モデル名と出力の名前に決まった語が含まれるかで
    分ける (`separator_service.py` の `_categorize`。配布元の分類ではないため、モデルを探すときの一覧のまとまりにだけ使い、
    分離の結果の扱いには使わない。BS-Roformer-SW は 6 分割のため楽器別とする)。
    一覧の作り方を変えたら、保存した一覧の版 (`separator-models.ts` の `LIST_FORMAT`) を上げて作り直させる。
    楽器別では、Demucs 系の 4 分割のモデルはボーカル・ドラム・ベース・その他に、6 分割のモデルはさらにギターとピアノにも分ける
  - アンサンブル: audio-separator 同梱の検証済みの組み合わせと、任意のモデルの組み合わせ
    (結果の決め方を選ぶ) を選べる。一覧に無いモデルを使う組み合わせは示さない。一覧に無い組み合わせを指定された
    場合は止める (`ENSEMBLE_NOT_FOUND`)
- 画面の構成: 元の音源を根にした結果の木を全幅に置き、画面の一番下に書き出し (後述)。方式の選択・プリセット・
  詳細な設定は、分離のダイアログ (`SeparationDialog`) にまとめる (結果を広く並べられるように)
- プリセット (13.10): 方式のタブの上に置き (どのタブでも同じ)、方式の選び方 (おすすめで選んだもの、モデルと結果の
  決め方、または「その他」の加工)・詳細な設定 (全アーキテクチャのパラメーター) を、1 つの条件としてまとめて保存・
  呼び出しする (`SeparationPresetParams`。おすすめにも詳細な設定があるため)。呼び出すと、タブの状態 (保存したときのタブ) から、選んだもの・結果の決め方・詳細な設定まですべて戻す。
  呼び出したプリセットに取得していないものが含まれる場合は、その分は選ばずに知らせる
- 分離のダイアログ: 音の「分岐」と、結果の「パラメーターを変えて作成」から開く。高さは中身によらず一定にし
  (タブや選んだものでダイアログの大きさが変わらないように)、中身が長いときはダイアログの中をスクロールする。見出しは「分離: (分離する音の
  名前)」。左に方式の選び方・詳細な設定、右に「選んだ内容」(`SelectedMethodPanel`) を置き、下端に「分離を実行」を置く。
  2 列のときは列ごとにスクロールし (列はスクロールバーの幅を常に空け、右に余白を取る。スクロールバーと欄の右端が接して操作
  しにくくならないように)、幅が足りないときは選んだ内容を下に置いて全体をスクロールする。選んだ内容は、おすすめでは
  選んだものの名前と特徴、モデルでは選んだモデルをまとまりの順 (まとまりの中は名前の順) に積み重ねて (まとまりの名前・
  名前・概要)、その他ではチェックした加工を処理の順に示す。何も選んでいなければその旨を示す。実行中は進捗を示し、成功したら閉じて結果を木に加える
  (失敗・中止のときは開いたままにし、条件を変えてやり直せる)。新しく分離するときは、前回新しく分離したときの方式と
  詳細な設定を初期値にする
- 方式の選び方 (`SeparationMethodPicker`): 「おすすめ」「モデル」「その他」の 3 つのタブ (おすすめは取得済みのものが
  無ければ出さない)。「その他」は分離をせず、「残響・エコーを除去する」「ノイズを除去する」「無音部分の雑音を消す」
  「音量をそろえる」(初期値はどれもチェックなし) で音を加工した 1 つの出力を作る (13.16。この順に行い、設定欄もこの順に並べる。長さと
  チャンネル数は変わらない)。結果の名前は「その他」、説明はチェックした加工、出力の名前は `Filtered` (フィルターをかけた音。モデルの出力名と同じく、画面の言語によらない英語の固定名)。どれもチェックして
  いなければ実行できない。
  長さを変える加工 (無音部分の除去) は、同じ木のほかの音と時間の関係が変わるため置かない。音量をそろえるは、同じ木の
  ほかの音との音量の関係 (重ねたときの釣り合い) が変わるため、使う人が選んだときだけ行う。
  おすすめとモデルは取得済みのものだけを示し、未取得のものは画面上部の「ダウンロード管理」から取得する
  - おすすめ: ダウンロード画面の目的別のおすすめ (`separatorPurposes.ts`。配布元が検証した組み合わせと、目的に合う
    モデル) を、目的の見出しの下に並べて 1 つを選ぶ。ダウンロード画面と同じく、複数の目的に載るものはそれぞれの目的に並べ
    (目的ごとの関係が分かるように)、2 回に分けて分離する目的の項目にはダウンロード画面と同じ回の印 (「1 回目: …」) を
    添える。どの目的の下のものを選んだかも覚える (`<目的>|<方式>`。目的を含まない値は最初に並ぶものに当てる)。各項目の下と
    選んだ内容には、特徴 (配布元の説明) だけを添える
  - モデル: まとまり (分離の種類) ごとの欄 (Autocomplete) から、取得済みのモデルを選ぶ (欄ごとに複数選べる。名前・
    ファイル名・概要・出力に、空白で区切った語がすべて含まれるものに絞り込める)。まとまりの名前・順はダウンロード画面の
    「個別のモデル」と同じにする (`separatorCategories.ts` の `SEPARATION_CATEGORIES` を共有する)。欄はまとまりごとに
    取得済みのモデルが無くてもすべて示し、欄の名前はまとまりの名前だけにする (無いまとまりの欄は選べない状態にし、欄の下に
    「ダウンロード管理」から取得できることを示す)。欄の中の並びもダウンロード画面と同じ (名前の順。`compareSeparatorModels`)。
    まとまりをまたいでも選べる (何を組み合わせるかは利用者に任せる)。選んでいる項目は右端のチェックの印で示し、選んだものは
    欄の中に名前を切らずに折り返して示す。一覧は欄より広く開く (名前と概要が長いため)。一覧を開くときにその欄の上下の
    画面の空きを測り、広い側へ、その空きに収まる高さで開く (ダイアログの中で開くため、決まった高さでは画面からはみ出して
    選べなくなる)
  - 一覧の各項目と選んだ内容には、ダウンロード画面の行と同じ概要 (何をするモデルか・方式・出力・分離の品質) を示す
    (`SeparatorModelSummary`。ダウンロード画面と共用)。おすすめの組み合わせは配布元の特徴を示す
  - モデルは複数選べる。2 つ以上選ぶと「結果の決め方」の欄を出す (任意の組み合わせ)。各モデルで分離し、各モデルの結果から
    1 つの結果を決める (audio-separator の ensemble algorithm。音を重ねて足す合成ではない)。選択肢ごとに計算のしかたと
    傾向を一行で添える: 平均 (どれかにしか無い音は薄まる。配布元の既定)・中央値 (外れた結果に引っ張られにくい)・
    最小 (大きさが最も小さい値。混ざりは減るが欠けやすい)・最大 (大きさが最も大きい値。欠けにくいが混ざりやすい) を、
    波形のまま行うものと周波数ごとに行うもの (スペクトル) があり、UVR の方法の最大・最小もある (`ensembler.py` の実装に
    基づく。最小・最大は値の絶対値で比べる)
    まとまりは名前と出力の文字の照合で、すべてのモデルに正しく当たるとは限らないため、まとまりをまたいで組み合わせられる。
    ドロップダウンの下には、複数選ぶと各モデルの結果から 1 つの結果を決めることだけを短く補足する (1 つ選ぶ場合や、
    選んだものの外し方などの基本の操作は書かない。「結果の決め方」の欄の下には説明を重ねて出さない)
  - この画面のモデル名は、audio-separator の名前の先頭の方式の前置き (「Roformer Model: 」「VR Arch Single Model v5: 」
    「Demucs v4: 」など) を除いて示す (`separatorDisplayName`。方式は説明の行に別に示すため。一覧・選んだもの・結果で同じ)
- 詳細な設定: 選んだモデルのアーキテクチャの分だけ、閉じた「詳細な設定」の中に示す。
  スイッチは説明が折り返さないよう 1 行を使い、ほかの欄を有効にするスイッチはその欄の直前に置く
  - MDX: セグメントサイズ・オーバーラップ・バッチサイズ・ホップ長・デノイズ
  - VR: ウィンドウサイズ・抽出の強さ・バッチサイズ・TTA・高域処理・後処理とそのしきい値
  - Demucs: セグメントサイズ (既定はモデルの値)・シフト数・オーバーラップ・セグメント処理
  - MDXC: 「セグメントサイズを指定する」とセグメントサイズ (指定しなければモデルの値)・オーバーラップ数・バッチサイズ・
    ピッチシフト
- 実行: 結果を、分離した音の下に加える。各出力は元の音源のチャンネル構成に戻す
  - 進捗は audio-separator が出す進捗バー (tqdm) から読む。バーが変わるたびに 0 から数え直す (`runtime.TqdmBridge`。
    1% 刻みの報告を前のバーの最後の値と比べると、次のモデルの進捗が報告されないため)。アンサンブルなどで複数のモデルを
    順に実行する場合、モデルごとの処理の重さは前もって分からないため、全体の割合は作らない。進捗 (ゲージ) はモデルごとに
    最初から最後まで進め、段階に「音声を分離しています (1 / 3)」のように何番目のモデルかを添えて、ゲージと残り時間が
    実行中のモデルのものであることを示す。残り時間はモデルが替わるたびに見積もり直す。何番目かは、モデルごとに 1 回
    呼ばれる `_separate_file` を数えて知る
- 結果の木 (`separationTree.ts` / `SeparationWorkbench`): 一番上に元の音源の行 (名前・プレーヤー・「分岐」) を
  置き、分離した結果をその音の下に、1 段ずつ右へ字下げして並べる。どの音 (元の音源・出力) からも「分岐」で
  何度でも分離でき、同じ音から分離した結果どうしが兄弟として並ぶ (聞き比べられる)。回数や深さに上限は無い。
  画面の中で同時に鳴るのは 1 つだけ (13.7)
  - 結果の見出しの行: 方式の名前 (一覧と同じ表示名。組み合わせは「モデル名 + モデル名 (結果の決め方)」)・既定から変えた
    パラメーター (無ければ「既定の設定」)・「パラメーターを変えて作成」・削除のボタン
  - 出力の行: 名前・名前の変更・その出力のプレーヤー・「分岐」。出力は、モデル (audio-separator) が返した順と
    名前 (出力のファイル名に付く名前) のまま示す。アプリは名前から意味を判断せず、名前の付け替え・訳・並べ替え・
    役割の割り当てはしない。出力から分離した結果は、その出力の行の下に置く
  - 番号と名前: 同じ音から分離した順に、結果へ番号 (1 から) を付け、出力の名前は「番号-名前」で示す (例: 1-Vocals から
    1 つ目の分離で「1-Vocals」「1-Instrumental」、2 つ目の分離で「2-Vocals」…)。番号は削除しても振り直さず (次の番号は
    それまでの最大の次)、作り直しても変わらない。名前は出力ごとに変えられ (`SepNode.labels`。変えるのは番号の後ろの
    部分で、空にするとモデルが返した名前に戻す)、書き出しのファイル名と音声変換の一覧にもその時点の名前を使う
  - 作り直し: 「パラメーターを変えて作成」で、前回の条件 (方式の選び方と詳細な設定) を入れたダイアログを開く。その結果の
    下に結果があるときは、先に消える音の一覧 (書き出しのファイル名と同じ名前) を示し、了承したらダイアログを開く。
    下の結果は、作り直しを実行した時点で消す (ダイアログを閉じたときは何も消さない)。実行が成功したら結果を上書きし、
    失敗・中止のときは、その結果自体は前のまま残る。出力の名前は、同じ名前の出力が残る分だけ引き継ぐ
  - 削除: 結果と、その下にある結果を消す。下に結果があるときは、消える音の一覧を示して確認する
  - 保存対象 (音声分離の画面だけ): 元の音源以外の出力の行の右端に、チェックとその下の「対象」の 2 行で、書き出す音を
    選ぶチェックを置く (どの行も同じ位置に並べ、列として見せる)。最初はどれも選ばない。結果を消すと、その出力は
    保存対象から外れる
- 各出力は、プレビューでも書き出しでも元の音源のチャンネル構成 (ステレオならステレオ) を保つ
- 書き出し (13.8): 作業の最後に行うものなので、画面の一番下の行に、書き出す音 (保存対象) の数と「書き出し...」を置く
  (音声変換の画面の「次へ」と同じ位置)。「書き出し...」は押せない状態にせず、保存対象が無いときは押したときに
  チェックするよう知らせる。書き出しのダイアログでは形式・その設定・保存先のディレクトリを選び、保存対象をすべて
  書き出す (項目ごとのチェックは出さない)。ファイル名は、元のファイル名 (拡張子なし) と、上の階層からの名前 (書き出す時点の
  名前) を「_」でつないだもの (例: 元の名前が「曲.mp3」で 1-Vocals の下の 2-ボーカル → 「曲_1-Vocals_2-ボーカル.mp3」)

## 15. 音声変換 (`conversion.ts` / `pages/voice/ConversionPage.tsx`)

入力した音声の声質を、選んだ声のモデルの声質に変換する機能。変換方式は RVC とし、変換と学習には Applio を使う。
扱う入力は、楽曲のボーカルの置き換え (分離・変換・伴奏との再合成) と、朗読などの音声の置き換えの 2 つ。

### 15.1 画面の流れ

- 1 つの画面で「入力と分離 → 声質変換 → 合成」の 3 段階 (ステップ) を順に進め、書き出しは合成の段階から行う。
  前の段階に戻って入力 (ボーカル・伴奏) が変わると、以降の結果を破棄することを確認する。
  合成の段階は、選んだ候補が今の入力から作ったものである場合だけ開ける (入力が変わった場合は変換の段階で確認する)。
  合成結果は入力 (伴奏) も含めた組み合わせで作り直しを判定する
- 変換と合成の段階は、左にパラメーターと実行のボタン (「変換を実行」「合成を作成」) を、右に聞く音を 1 行ずつ上下に
  並べる。上に元の音源 (と変換前のボーカル) を置き、その下に結果を置く
- 入力: 楽曲 (分離の操作部 (結果の木。保存対象の列は出さない) を画面内に組み込む)・伴奏のない音声 (分離を省略)
- 楽曲では、分離した音から「変換する音」を 1 つと、「伴奏として重ねる音」を利用者が選ぶ (`conversionStore` の
  `vocalsTrack` / `accompanimentTracks`)。どちらも分離の木と同じ順と字下げで並べ、選んだ変換する音は上の階層からの
  名前で示す。初期値は、変換する音が最後に作った結果のうちモデルが Vocals と名付けた出力、伴奏がその下に結果の無い
  出力 (木の末端) のうち変換する音以外のすべて (同じ音を別の方式で分離して比べた結果があると重なるため、そのときは
  選び直す)。伴奏が複数の音から成る場合は、1 つに重ねたものを合成・再生に使う

### 15.2 変換

- 声のモデル・キーの変更量 (-24〜+24 半音)・ピッチ抽出 (「RMVPE (推奨)」「FCPE」「CREPE」「CREPE (軽量)」。必要なモデルを取得済みのものだけを示す)・インデックスの効き具合・
  音量エンベロープの混合率・子音の保護を指定する。既定はキー 0・RMVPE・0.75・1・0.5。結果は候補として並べる
- 変換のオプション (13.16): 「残響・エコーを除去する」(初期値はチェックなし)・「無音部分の雑音を消す」(初期値はチェック
  あり)・「ノイズを除去する」(初期値はチェックなし)。処理の順に並べる。残響・エコーの除去は変換前のボーカル (モノラルに
  した入力) にかけ、その結果を変換の入力と無音部分の判断に使う。変換後の声の大きさは、除去する前のボーカルにそろえる。
  無音部分の雑音を消すは、変換前のボーカル (モノラルにした入力) の無音部分で、変換後の音量を 0 にする
  (`rpc_convert` の中で、入力全体で無音部分を求めてから、区切りごとの結果にかける)。変換モデルは、入力が無音の部分でも
  雑音を作ることがあるため。ノイズ除去は変換後の声にかけてから、変換前のボーカルと同じ大きさにそろえる。
  チェックしたものを候補のパラメーターの表示に足す
- 変換はアプリが区切って行う (`rpc_convert`)。約 20 秒ごとに、その前後 2 秒の中で最も静かな位置 (10ms 単位) で区切り、
  各区切りの前後に 1 秒ずつ実際の音 (入力の末尾より後は無音) を付けて変換し、付けた分をサンプル単位の位置で切り落として
  順にファイルへ書く。区切りの位置では、前の区切りの結果 (付けた分の中にある) から次の区切りの結果へ 20ms かけて
  受け渡す (クロスフェード)。同じ部分を別々に変換した 2 つの結果を突き合わせると波形に段差 (ぷつっという音) が残るため。Applio 自身の区切り (約 41 秒を超える入力) は使わない。区切りごとに特徴量のフレームが 1 つ (10ms) 足りなく
  なることがあり、その区切りの末尾が消えて以降が 10ms ずつ早まる
  ため。結果全体の最大値が 0.99 を超えると全体を下げる Applio の処理は行わない (変換後に、変換前のボーカルと同じ
  大きさにそろえるため)。入力全体の最大値を 0.95 以下にする Applio の処理は、入力全体に 1 回だけ行う。変換結果の長さは入力と同じ
  (入力は 16kHz で読み込むため長さが 16kHz の 1 サンプル単位に切り上がり、結果が入力の終わりより後ろまで続くことがある。
  その部分は書かない)
- ボーカルは左右を平均したモノラルで変換し、伴奏と合わせるときは左右に同じ音を置いた中央定位のステレオにする
  (元の音源がモノラルならモノラルのまま)。変換結果 (候補) はモデルのサンプリング周波数のモノラルのまま持ち、
  伴奏の周波数・チャンネル数には重ねる処理 (伴奏と重ねた試聴用の音・合成) の中で合わせる (候補の `channels`)。RVC の変換は入力をモノラルとして扱い、Applio も入力を 16kHz の
  モノラルにして読み込むため。左右を別々に変換する方式は、左右の推定のずれで音が揺れやすいため採らない
- 変換後の声は、統合ラウドネス (ffmpeg の `ebur128`。無音の部分を除いて測る) が変換前のボーカル (モノラルにしたもの) と
  同じになるよう、音量をそろえる (`measureLoudness`)。どちらかが無音 (-70 LUFS 以下) で測れない場合はそろえない。
  合成のボーカルの音量 0 dB が、変換前のボーカルと同じ大きさになるようにするため
- キーの変更量がオクターブ単位 (±12 の倍数) 以外なら、伴奏を ffmpeg の rubberband で同じ量だけ移調する
  (位置のずれは打ち消す。13 章の基本方針の rubberband の項)。
  指定中の ffmpeg に rubberband が無い場合は、その時点で理由と ffmpeg の見直し方を示して止める (`RUBBERBAND_UNAVAILABLE`)
  - 移調した伴奏は、作業の中に元の伴奏とキーの変更量ごとに置く (作業のフォルダの `accompaniment/`)。
    同じ伴奏を別のキーで移調したときは、それまでのキーのものを消す (伴奏と重ねた試聴用の音や合成結果は別のファイル)。
    移調は、伴奏と重ねた試聴用の音か合成結果を作るときにだけ行う
- 保存: 変換前のボーカルは、その行の名前の右端に、変換後のボーカルは、候補の見出しの削除のボタンの左に、その音だけを
  書き出すボタン (`SaveAltIcon`) を置く (書き出しのダイアログを 1 項目で開く。ファイル名は元の名前 + 行の名前、
  変換後のボーカルは声のモデル名も付ける)。元の音源には置かない。合成結果は「書き出し」から書き出す。
  プレーヤーの中には操作を置かず、どの行もプレーヤーの幅をそろえて、波形の位置をそろえる
- 再生: 元の音源・変換前のボーカルを上に、候補を作った順に下へ並べる。候補ごとに、声のモデル名とパラメーター・削除の
  行の下に「変換後のボーカル」と「伴奏と重ねた音」の行を置く。候補のカードをクリックする (再生を含む) と選んだ状態に
  なり (枠を強調色にする)、合成ではその候補を使う
- 伴奏と重ねた音: 変換を実行したときには作らない。作る前はプレーヤーを出さず、「伴奏と重ねて聞く」のボタンだけを置き、
  押したときに変換後のボーカルと伴奏を音量を変えずにリバーブなしでそのまま重ねて作る (`renderMix` の `params: null`。
  合成と同じ `rpc_mix` を使い、置き場所は作業の `previews/`)。作った後はボタンの代わりにプレーヤーを示す。伴奏を変えると
  候補ごと破棄する (15.1) ため、作り直しの操作は持たない

### 15.3 合成

- pedalboard で、ボーカル・伴奏・全体の音量と、ボーカルへのリバーブ (部屋の大きさ・高域の減衰・残響音の量・原音の量・
  ステレオの広がり。なしも可) を適用する。パラメーターはプリセットで保存できる
- リバーブの残響音の量・原音の量は、実際の音量の倍率 (原音の量 1 で元の大きさのまま)。pedalboard の Reverb (JUCE) は
  内部で原音の量を 2 倍、残響音の量を 3 倍するため、その分を割って渡す (割らないと、原音の量 0.9 でボーカルが
  約 +5 dB 大きくなる)。初期のプリセットは原音の量を 1 にし、残響音の量で響きの強さを分ける
  (軽いリバーブ 0.2・ホール 0.53・ボーカルを前に 0.13)
- 音割れを防ぐため、重ねた結果のサンプルのピークが -1 dBFS を超える場合は、書き出した結果を全体で一律に下げる
  (2 回目の読み書き)。曲の強弱を変えないため、一部だけ音量を変える処理は行わない
- 合成 (`converter_service.rpc_mix`) は 10 秒ずつの区間ごとに読み込み・処理・書き出しを行い、全体をメモリに置かない。
  効果 (リバーブ) は区間の間で状態を引き継ぐ (`reset=False`) ため、全体を一度に処理した場合と結果は同じ。
  ボーカルと伴奏の長さが違う場合は、短い方が終わった後を無音として扱う
- 画面: 左のパラメーターの下に「合成を作成」を置く。右には元の音源と合成結果を 1 行ずつ上下に並べる
  (合成結果の行は、合成結果を作ってから示す)
- 合成結果は書き出しと同じ処理でレンダリングした結果を再生する。設定や選んだ候補を変えた後に書き出す場合は作り直す
- 合成結果は組み合わせ (変換後のボーカル・伴奏・パラメーター) ごとに作り、同じ組み合わせの結果があれば、移調も合成も
  せずにそれを使う。移調した伴奏が無ければ、合成結果を作るときにだけ作る。新しい合成結果を作ると、前の合成結果は消す
- ボーカルの音量の欄には、0 dB で変換前のボーカルと同じ大きさになることを示す (15.2)

### 15.4 声のモデル

- 区分はユーザーモデルと既存モデル (13.9)。変換のたびに使うモデルを選ぶ

### 15.5 書き出し

- 合成結果と変換後のボーカルを書き出せる (13.8)。書き出しは合成の段階から開き、合成結果が今の設定と合わない場合は、
  書き出しの前に作り直す

### 15.6 学習 (`training.ts` / `pages/voice/RvcTrainingPage.tsx`)

- Windows・macOS・Linux のいずれでも行える (13.1 の処理装置を使う。読み上げの学習と違い NVIDIA GPU は必須ではない)。学習回数 (エポック数) 以外のパラメーターはアプリが決め、利用者は学習回数と名前を指定する
- 学習用の音声は学習セット (13.15) に持つ。画面の上で学習セットを選び (作成・名前の変更・削除もここで行う)、
  アプリ内での録音 (エコーキャンセル・ノイズ抑制・自動ゲイン調整は無効。AudioWorklet で受けて 16bit PCM の WAV にする)、
  または音声ファイル (動画の音声も含む。ffmpeg で読めるもの) の追加で音声を加える。内容と量に制限は設けず、
  変換したい音声に近い環境で録音するとよい旨だけを案内する
  - 画面の並び: 録音・「音声ファイルを追加」と同じ行の右端に「すべての音にフィルターを適用」を置く。その下に音声を
    分離の結果と同じく縦に並べ、各行に名前・長さ・フィルターと削除のボタン、その下に波形のプレーヤーを置く (再生は同時に
    1 つだけ)。一覧の枠は高さを区切らず、画面ごとスクロールする。波形は行が画面に見えてきてから読み込む (`useInView`。
    音声が多い学習セットで、すべての波形を一度に作らないため)。下の行は、件数と合計の長さ、3 文字分ほど空けて学習回数の欄、
    残りの幅いっぱいのモデルの名前の欄、「学習を開始」の順に並べる
  - 音声を学習セットから削除するときは、元に戻せないことを示して確認する
  - 学習が終わっても (成功・エラー・キャンセル) 学習セットは変えない
- 合計 10 秒未満では開始しない (`TRAINING_DATA_TOO_SHORT`)。10 分未満なら注意を出す
- 開始時に学習セットの音声のファイルが無くなっていれば、その音声の名前を示して止める (`TRAINING_FILE_MISSING`)
- 学習回数 (エポック数) は画面で指定する (`RVC_TRAINING_EPOCHS`)。初期値は 200 (Applio の初期値)、範囲は 100〜1000 の整数。範囲外や整数でない値のときは欄を誤りの表示にし、学習を始めさせない (main でも確かめ、
  `INVALID_EPOCHS` で断る)。備考や目安の値は示さない
- そのほかのパラメーターはアプリが決める: サンプルレート 40kHz・RMVPE・contentvec、バッチサイズは CUDA で
  VRAM 8000MB 以上なら 8 それ以外は 4、10 エポックごとに保存
- 流れ: 前処理 → 特徴量の抽出 → 学習 → インデックスの作成 → 完成したモデルを安全な形式で声のモデルとして登録
  (ユーザーモデル)。進捗は手順 (前処理・特徴量の抽出・学習・インデックスの作成・仕上げの 5 つ) ごとに示し、学習は
  エポック、前処理と特徴量の抽出は上流の進捗バーから手順の中の進み具合と残り時間を求める
  - 学習の途中のデータ (前処理した音声・特徴量・チェックポイント) は、作業ディレクトリのジョブのフォルダ
    の実験フォルダ (`logs/<名前>/`) に置き、学習が終わった時点 (成功・エラー・キャンセル) で
    main プロセスがジョブのフォルダごと消す。上流のソース一式の中には書かない
  - 前処理・特徴量の抽出・インデックスの作成は Applio のフォルダをカレントディレクトリにして動かし (Applio の設定と
    無音のサンプルを相対パスで読むため)、実験フォルダを明示して渡す。Applio の学習スクリプトは、ジョブのフォルダを
    カレントディレクトリにして動かす (`<カレントディレクトリ>/logs/<名前>/` にファイルを置くため)。精度の設定は、
    Applio の `assets/config.json` の `precision` をジョブのフォルダの `assets/config.json` に書いて渡す
  - 前処理は、学習セットの音声の一覧を Applio の 1 ファイル分の処理で行う (`rvc_preprocess.py`。
    上流の前処理は 1 つのフォルダの中を処理するため)。音声を得られなかったファイルがあれば、そのファイル名を示して止める
    (`TRAINING_FILE_UNREADABLE`)。前処理で切り出した音声が 1 つも無い (無音や短すぎる音声だけ) 場合も止める
    (`TRAINING_NO_AUDIO`)
  - 特徴量の抽出の後、切り出した音声ごとにピッチ (`f0`・`f0_voiced`) と埋め込み (`extracted`) のファイルがそろっているかを
    確かめ、欠けたものがあれば元のファイル名 (5 件まで、残りは件数) を示して止める (`TRAINING_EXTRACT_FAILED`)。
    Applio は抽出に失敗した音声をエラーの表示だけで飛ばし、そろった音声だけで学習を続けるため
  - インデックスは `rvc_index.py` (Applio の `extract_index.py` を、`faiss.write_index` の書き先を差し替えて動かす) で、
    作成中の声のモデルのフォルダに直接書く (作業ディレクトリが別のドライブでもコピーしないため)。
    作られなかった場合は止める (`TRAINING_NO_INDEX`)
  - 学習が終わっても完成した重みが作られなかった場合は止める (`TRAINING_NO_MODEL`。13.4)
  - 完成した重みは、安全な形式 (`model.safetensors`・`model.json`) にして作成中の声のモデルのフォルダに直接書き、
    声のモデルとして登録する (13.9)

## 16. 読み上げ (`tts.ts` / `pages/voice/TtsPage.tsx` / `shared/voice/`)

入力した文章を音声として読み上げる機能。音声合成のエンジンは Style-Bert-VITS2 の派生版 (13.4) に固定する。

### 16.1 入力と設定

- 声のモデルの種類は JP-Extra 版と多言語版の 2 種類で、どちらの種類も読み上げのパッケージ一式で動く。読み上げには、
  読み上げる言語の BERT だけを使う (`TTS_LANGUAGE_MODEL_ITEMS`)。ダウンロード項目の「日本語の言語モデル」は日本語の
  BERT、「英語の言語モデル」は英語の BERT と英語の発音推定に使う NLTK のデータ (発音辞書を含む)で、互いを前提としない。
  日本語は JP-Extra 版・多言語版のどちらの声でも日本語の BERT で読み、英語と中国語は多言語版の声だけが読める
  (「中国語の言語モデル」は中国語の BERT。中国語の発音推定の辞書 (pypinyin・jieba) は読み上げのパッケージ一式に入っている)。
  日本語だけを読む場合は JP-Extra 版の声が推奨されている

- 入力方法は「通常」(制御タグを含む文章) と「タイミング指定」(行ごとの開始時間・終了時間・テキストの表。16.7) の 2 つ。
  入力方法ごとに内容とファイルを別々に持ち、切り替えても変換しない (どちらの内容も失わない)
- ファイルは入力方法ごとに扱う。通常はテキスト (`.txt`) を開き・保存する。タイミング指定は字幕ファイル (SRT・WebVTT・
  ASS・SSA・SBV) を開き、読み込んだ時点で表に展開して元の形式は覚えない (以後は画面の表を正として扱う)。保存
  (名前を付けて保存を含む) は SRT だけ。SRT を開いた場合は (読み飛ばしたブロックが無ければ) そのファイルを保存先とし、
  それ以外の形式を開いた場合は保存先を持たない (保存時に SRT のファイル名を選ぶ。元のファイルを別の形式で上書きしないため)。この場合も画面には
  開いたファイルを示し (`TimedDocument.sourcePath`)、保存するときの名前の候補は開いたファイルの名前の拡張子を `.srt` に
  変えたものにする。ただし候補が開いたファイルそのものになる場合 (読み飛ばしたブロックがある SRT) は、そのフォルダだけを示す
  (上書きで読み飛ばした区間を消さないため)。作成した音声の書き出しの既定の場所は、その音声を作成したときに開いていたファイルの場所
  (`resultSourcePath`。作成の後に別のファイルを開いても変わらない)
- ファイルの読み込み時に文字コードを判定する (BOM 付き UTF-8・UTF-16、BOM の無い UTF-16 (先頭 4KB の 0 のバイトの偏りで
  判定)、UTF-8、Shift_JIS・GBK)。UTF-8 で読めない場合は、Shift_JIS と GBK の片方でしか読めなければそれを使い、両方で
  読める場合は読み上げの言語で選ぶ (中国語なら GBK、それ以外は Shift_JIS。`loadText` に言語を渡す)。
  読み込んだ改行は LF にそろえる。
  編集は画面上だけで行い、ファイルへの反映は保存操作のときだけ (BOM なしの UTF-8 で、改行は OS の標準 (Windows は CRLF、
  macOS・Linux は LF) にして書く。一時ファイルへ書いてから置き換える)。保存していない変更があれば、新しい文章を始める前と
  ファイルを開く前 (ファイルの選択の前) と、別の機能へ移る前と、アプリを閉じる前に、破棄してよいかを確認する
  (画面には未保存の印を出さない)。アプリを閉じる前の確認は、main がウィンドウを閉じる前に画面へ問い合わせ
  (`window:closeRequested`)、画面が閉じてよいと返したら (`window:confirmClose`) 閉じる。更新のインストールで閉じる場合と、
  画面が落ちた場合は問い合わせない。
  別の機能へ移る前の確認は、タイトルバー・ダッシュボード・ダウンロードの画面からの移動で行う
  (`stores/navigationGuard.ts`。保存していない入力の有無と破棄の仕方は `stores/featureWork.ts` に機能ごとに置く)。
  機能の中のタブの切り替えでは入力が残るため確認しない。別の機能へ移るときに破棄するのは、保存していない方の
  入力方法の変更だけ (最後に読み込んだ・保存した内容に戻す。読み込みも保存もしていない場合は空にする。保存済みの方はそのまま残す)
- 入力中のチェックは打つたびに行うと重いため、入力が 250ms 止まってから行う。入力方法と言語を切り替えたときは待たずに
  すぐ行う (前の内容の誤りが残って見えないようにするため)
- main でも設定値を画面の入力欄と同じ範囲で確かめ、範囲外なら作成を始めない (`TTS_PARAMS_INVALID`)
- 言語 (初期値はアプリの表示言語)・モデルの種類 (`modelType`。JP-Extra 版か多言語版。その言語を読める種類)・
  声のモデル (モデルの種類と言語が合うものだけ)・
  スタイルと強さ・話速・音の高さ・抑揚・テンポのばらつき (`sdpRatio`)・感情表現のばらつき (`noise`)・音の長さのばらつき (`noiseW`)・
  行と行の間の無音 (通常の入力のみ)・記号の読み上げ・時間内に収まらない場合 (タイミング指定のみ。16.7) を指定する。
  テンポのばらつき・感情表現のばらつき・音の長さのばらつき・行と行の間の無音は、閉じた「詳細な設定」の中に置く。
  スタイルは声のモデルが持つもの (`config.json` の `data.style2id` の名前。各スタイルのデータは `style_vectors.npy`) だけを
  示し、アプリでは補わない。スタイルを持たないモデルでは、スタイルとその強さを選べない (合成にスタイルを渡さない)
- 通常の入力は改行で段落に分けて合成し、音のある段落の間にだけ「行と行の間の無音」を入れる。空行・先頭や末尾の改行・
  読み上げる文字の無い段落は無音を足さない (ファイルの末尾の改行などで、意図しない無音が付かないようにするため)。
  段落は文章の改行 (改行の置き換え表記 `&#10;` を含む) で分け、制御タグの中の改行では分けない。長すぎる段落を示すときは、
  元の文章での段落の範囲を示す (タグの中の改行で文章の複数の行にまたがることがあるため)
- 読み上げる言語の言語モデルが未取得なら、ダウンロード画面への案内を出す。読み上げの実行時にも main で確かめ、
  未取得なら `MODEL_REQUIRED: <項目 ID>` を返す
- 作成した音声は 1 つだけ持ち、作成し直すと置き換える (前の音声のファイルはクリーンアップの一覧に積む)。
  読み上げは時間がかからず、同じ入力と設定から簡単に作り直せるため、候補として並べて聞き比べる形にはしない
- 話者を複数持つモデルでは話者を選べる。選んでいるモデルに無い話者の番号 (別のモデルで選んだもの) は、最初の話者として扱う。
  一覧は `config.json` の `data.spk2id` の番号の小さい順で、画面は一覧の何番目かを持ち、main が合成のときに
  モデルの話者の番号 (`spk2id` の値) に直して渡す (番号は連続していないことがあるため)
- 画面の構成: 再生の行は画面の下に置いたままにし、その上の入力と設定の部分の高さを残りに合わせて、
  ページ全体がウィンドウに収まるようにする (ウィンドウが極端に低い場合だけページ全体をスクロールする)。
  設定の部分は長いため、その中だけをスクロールし、「音声を作成」のボタンはスクロールの外 (設定の部分の下) に置く
  (再生のボタンと取り違えないよう、アイコンは付けない)。
  書き出しは作成した音声に対するものなので、再生の行の右端に「書き出し...」のボタンを置き、書き出しの画面 (13.8) を開く

### 16.2 制御タグ (`shared/voice/control-tags.ts`)

- W3C SSML 1.1 のサブセット: `break` (time / strength)、`prosody` (rate / pitch / volume)、`sub` (alias)、
  `phoneme` (ph / alphabet)。`phoneme` の表記のうち SSML の標準は `ipa` (英語) だけで、`x-kana` (日本語のアクセント記法) と
  `x-pinyin` (中国語のピンイン) は、SSML が独自の表記に空けている「x-」で始まる名前を使った、このアプリ独自の表記
- このアプリ独自のタグ: `fit` (mode)。タイミング指定の行で、行の時間内に収まらない場合の扱いを、その行だけ全体の設定から
  変える (`<fit mode="shift"/>`。mode は speedup / overlap / shift / warn)。単独で完結し、行のどこに書いてもよい。
  タイミング指定の行以外で使った場合 (`fitNotTimed`) と、1 つの行に複数書いた場合 (`duplicateFit`) は誤り
  - 入れ子の prosody は話速を掛け合わせ、音の高さと音量は足し合わせる。値の大きさに上限は設けない (話速は 0 より大きい値、
    「-10%」などの割合で表す音の高さは周波数が 0 より大きくなる値だけを受け付ける)
  - 合成は区間ごとに、部分 (読み上げる文・間) を作るたびにファイルへ書き、区間の部分をまとめてメモリに置かない。
    間の無音は 10 秒ずつ書く (長い間でもメモリの使用量は長さに比例しない)
- 制御タグとして扱うのは半角の「<」「>」で書かれ、「<」(閉じタグは「</」) の直後が既知のタグ名で、その後に空白・「/」・「>」の
  いずれかが続くものだけ。それ以外の「<～>」は本文として扱い (括弧内の文字は読み上げ、「<」「>」自体は記号の読み上げの設定に従う)、
  全角の「＜」「＞」は常に本文として扱う。本文に既知のタグと同じ文字列を書くときは `&lt;` などの置き換え表記を使う
  (名前の参照 `&lt;`・`&gt;`・`&amp;`・`&quot;`・`&apos;` と、数値の参照 `&#60;`・`&#x3C;`)
- 属性の値は半角の引用符で囲む。半角の引用符で始めた値は同じ引用符でだけ閉じ、値の中の向き付きの引用符
  (`alias="rock’n’roll"` など) は値の文字として扱う。向き付きの引用符 (「“”」「‘’」) で始めた値は、同じ種類 (二重か一重か) の
  引用符のどれでも閉じられ、一括修正の対象として受け付ける
- 置き換え表記のうち、文字に戻せない数値 (範囲外・サロゲート・タブと改行以外の制御文字。`&#0;` など) は文字に戻さず、
  そのまま本文として扱う
- `phoneme` の `alphabet` の値は、ほかの値と同じく大文字小文字と前後の空白を問わない (`IPA` も `ipa` として扱う)
- 時間と割合の数値は「.5s」のように整数部を省いたものも受け付ける。単独で完結するタグ (`break`・`fit`) は、
  「/」を付けずに開いた直後に空白だけを挟んで閉じタグ (`</break>`) を書いたものも 1 つのタグとして受け付ける
- タイミング指定の行では、SRT の書式タグ (`<b>`・`<i>`・`<u>`・`<s>`・`<font ...>` とその閉じタグ) を読み上げない
  (字幕の本文をそのまま持つため。16.7)
- 構文チェックは入力中にも行い、誤りは行・文字位置・内容を示して編集画面の該当箇所を強調表示する。合成の開始時に誤りがあれば止める
  - 止める誤り: 属性の誤り (属性名の誤り・値の書式不正や値として意味を持たない値・必須の属性の欠落) と、構文の誤り (引用符の閉じ忘れ・
    閉じタグの欠落・対応しない閉じタグ・入れ子の不整合)
  - 単独で完結するタグ (break・fit) の終端の「/」の省略は補って受け入れる。閉じタグが必要なタグに閉じタグが無い場合は止める
  - タグ名・属性名の大文字小文字の違いと、タグ内の向き付き引用符は、一覧を示して一括修正の可否を 1 回だけ確認する。
    承諾されれば編集画面の原文を書き換えて合成を続け、拒否されれば止める
- タグの一覧ダイアログ (`TagListDialog.tsx`) で、説明・属性と値の書式・記述例を示し、カーソル位置への挿入と選択範囲の囲みができる
  (タイミング指定では、最後に操作した行のテキストに入れる)。一覧は「SSML」と「独自形式」のタブに分ける
  (SSML の要素でも独自の表記を使う `phoneme` (日本語・中国語) と、`fit` は独自形式。タブごとにスクロール位置を保ち、
  開くたびに SSML から表示する)。一覧と同じ内容 (選んでいる言語のもの) を、同じ分け方の見出しで Markdown の
  ファイルに保存できる (「ファイルに保存」)。
  挿入と囲みは入力欄への編集として行うため、Ctrl+Z (元に戻す) で取り消せる

### 16.3 日本語アクセント記法 (`shared/voice/accent.ts`)

- `phoneme` の `ph` にカタカナの読みを書き、アクセント核 (音が下がる直前の拍) の直後に「'」、アクセント句の区切りに「/」を置く
  (「'」が無ければ平板型)。本文側には元の表記 (漢字など) を書き、読みとアクセントは属性側に持たせるため、記号が本文に混ざらない
- 東京式アクセントの規則で各拍の高低を求める: アクセント核が 1 拍目なら 1 拍目が高く以降が低い。核がそれ以外の位置なら
  1 拍目が低く、2 拍目から核まで高く、その後が低い。平板型は 1 拍目が低く 2 拍目以降が高い (トーンは 0 が低、1 が高)
- 求めた高低を、読みを表す音素列とトーン列としてエンジンに渡す。エンジンは改行ごとの分割生成を有効にすると
  これらを無視するため、合成は常に改行ごとの分割生成を使わない (改行は main が段落・行に分けて扱う)
- 本文の表記と指定した読みをエンジンが対応付けられない場合 (`InvalidPhoneError`) に限り、読み (カタカナ) を本文として
  合成し直す。それ以外のエラーはそのまま失敗とする (別の原因の失敗を読みの問題として隠さないため)
- 日本語以外の文章中で使われた場合は構文の誤りとして止める

### 16.4 英語の発音指定 (`shared/voice/ipa.ts`)

- 英語の `phoneme` は IPA で指定する。ARPAbet に変換し、指定した位置の語の発音だけを差し替えて合成する
  (同じつづりのほかの語は辞書どおりに読む)。ライブラリの英語の発音推定と同じ処理を、指定した位置の語だけ差し替えて行い
  (`tts_service.py` の `_english_g2p_with`)、合成の間だけライブラリの発音推定と置き換える。位置は、指定の前までの文章と指定した語を
  ライブラリと同じ整えと語の区切りにかけて数える (`_english_overrides`。続けて書いた空白が空の語として数えられるのも
  ライブラリと同じにするため)
- ライブラリは指定した語の直後に続く「-」「'」とその後ろ (「GAN-based」の「-based」、「Kura's」の「's」) を同じ語にまとめる。
  まとめられた後ろの部分は辞書どおりに読み、指定した発音は指定した語の部分だけに使う。短縮形 (`'s`・`'ll`・`'re`・`'ve`・`'d`・
  `'m`) は語尾の音として読み、`'s` は指定した発音の最後の音に合わせる (歯擦音の後は「IH Z」、無声音の後は「S」、それ以外は「Z」)
- 破擦音は連結記号の有無を問わず読む (`tʃ`・`t͡ʃ`・`t͜ʃ` は CH、`dʒ`・`d͡ʒ`・`d͜ʒ` は JH)
- 包んだ語の数と発音の語の数が一致しない場合と、ライブラリの語の区切りで複数に分かれる語は、誤りとして止める
  (`IPA_WORD_SPLIT`。読み替えタグを案内する)

### 16.5 中国語の発音指定 (`shared/voice/pinyin.ts`)

- 中国語の `phoneme` はピンインで指定する (`alphabet="x-pinyin"`。中国語の文章では省略できる)。文字ごとに音節と声調の
  数字 (1〜4、軽声は 5) を続けて書き、空白で区切る (例: `yin2 hang2`)。ü は v と書く (ü・u: も受け付ける)
- 受け付ける音節は、エンジンが扱える音節 (429 種類) に限る (`pinyinSyllable`)。囲む文字はエンジンが読む漢字
  (U+4E00〜U+9FA5) だけとし (`pinyinSurface`)、音節の数を文字数とそろえる (`pinyinCount`)。中国語以外の文章では使えない
  (`pinyinNotChinese`)
- 合成では、文章全体をエンジンの通常の変換で音素と声調にしたうえで、指定した文字の位置の音素と声調だけを指定の
  音節のものに差し替え、「音素と声調を与えて読ませる」経路で合成する (`tts_service.py` の `_chinese_given`)。
  声調は指定どおりで、自動の声調変化 (変調) はしない。位置を合わせられない場合は止める (`PINYIN_ALIGN_FAILED`)

### 16.6 記号の読み上げ

- 実行時に読み上げるかを選べる (既定は読み上げない)。記号と読みは言語ごとに初期値を持ち (例: 「<」は日本語なら
  「しょうなり」、英語なら「less than」、中国語なら「小于」)、利用者が追加・変更できる (`settings.voice.symbolReadings`、言語ごと)
- 文脈によって読みが変わる記号 (「-」「~」「/」など) は、定義では代表的な読みを 1 つ持ち、個別の箇所は読み替えタグ (`sub`) で指定する
- 全角と半角は別の記号として扱い、アプリ全体で全角・半角の変換は行わない。句読点は常に読みの区切りとして扱い、設定の対象外

### 16.7 タイミング指定 (`shared/voice/timed-text.ts` / `components/voice/TimedLinesEditor.tsx`)

- 左に開始時間・終了時間、右にテキストの表で入力する。テキストは複数行にでき、各行で制御タグを使える
  (誤りの確認と一括の修正は行ごとに行い、「N 行目」で示す)。行の追加・下への挿入・削除ができる。
  新しい行は前の行の終了時間から 3 秒の長さで作る
- 時間は「時:分:秒.ミリ秒」で入力する。「分:秒」「秒」の省略形と、小数点の「,」も受け付け、確定時に
  「HH:MM:SS.mmm」に整える (`parseTimeInput` / `formatTimestamp`)
- 次の欄を赤く示し、理由を示す。誤りがある間は読み上げを始めない (`validateTimedLines`)
  - 時間として読めない開始時間・終了時間 (`startFormat` / `endFormat`)
  - 終了時間が開始時間と同じか前 (`endBeforeStart`)
  - 開始時間が、後ろの行の開始時間より後 (行の並びと時間の前後が逆転している。`startAfterLater`)
  - テキストが空 (`emptyText`)
- 行ごとに合成し、開始時間に配置して 1 本の音声にまとめる。行の時間 (開始から終了まで) より短ければ無音で埋める
- 作成時、合成を始める前 (読み上げモデルの読み込みの前) に、合成の単位 (段落や行の中の、間・話速などの変化で区切った文章) が
  言語モデルで扱える長さかを確かめる (`_check_bert_length`)。位置を絶対値で持つ言語モデル (中国語の chinese-roberta-wwm-ext-large)
  は一度に 512 トークン (先頭と末尾の特別なトークンを含む) までしか受け取れず、ライブラリは合成の単位を切らずに渡すため、
  超えると必ず失敗する (実測: 漢字だけで 510 字まで通り、511 字で失敗)。トークンの数は、ライブラリが言語モデルに渡すのと同じ
  文章 (ライブラリの整え。中国語は数字を漢数字に直す) を、その言語モデルの区切り方で数える。超える場合はその段落 (通常の入力。
  `paragraphTooLong`。改行で分けてもらう) や行 (タイミング指定。`rowTooLong`。行を分けてもらう) を示して作成しない
  (アプリでは分けない)。日本語・英語の言語モデル (DeBERTa) は相対位置で上限が無く、長い段落はメモリと時間を使うだけのため
  確かめない (GPU のメモリが足りなければ CPU で作成する)
- 読み上げる文字 (文字か数字) が無い行 (記号だけなど。記号の読み上げの設定を反映した後で判定する) は、
  その行の誤り (`nothingToRead`) として示し、作成しない。通常の入力で、文章全体に読み上げる文字も間も無い場合も同じ
- 1 本にまとめる処理 (`tts_service.rpc_assemble`。通常の入力の段落をつなぐときも同じ) は、10 秒ずつの区間ごとに、その区間に
  重なる部分だけを各音声から読んで足し、ファイルへ順に書く。音割れを防ぐ音量の調整 (全体の最大値が 1 を超える場合に
  全体を下げる) のため、先に同じ方法で最大値だけを求める (2 回読む)。メモリに置くのは区間 1 つ分 (約 2MB) とそれに重なる
  部分だけで、文章の長さに比例しない
- 字幕ファイルの読み込み (`parseSubtitleFile`): SRT・WebVTT・SBV は空行で区切ったブロックごとに時刻の行と本文を、
  ASS・SSA は `[Events]` の `Format` の並びに従って `Dialogue` の行を読む。字幕の装飾は形式ごとに除き、読み上げの
  制御タグは残す。WebVTT は書式タグ (ふりがな `rt` は中身ごと除き、本文だけを読む) とカラオケの時刻を除く。
  SRT・SBV は本文をそのまま持つ (アプリが保存した SRT を開き直しても内容が変わらないようにするため)。SRT の書式タグは
  読み上げのときに読み飛ばす (16.2)。
  文字の参照 (`&lt;`・`&gt;`・`&amp;`) は、どの形式でも元の文字に戻さずそのまま表に入れる (表のテキストでも同じ意味の
  置き換え表記で、戻すと字幕に文字として書かれたタグが本物の制御タグになるため)。WebVTT の `&nbsp;` は空白にし、
  文字の向きの印 (`&lrm;`・`&rlm;`) は除く。ASS は `{}` の中の指定と注釈、図形の命令
  (`{\p1}` から `{\p0}` まで) を除き、行を開始時間の順に並べる (Dialogue は時間の順とは限らないため)。
  除いた後に本文が残らない行 (図形だけ・装飾の指定だけの行) は、読み上げる文字が無いため表に入れない。
  時刻の行が無いブロックが区間の直後にある場合は、本文の途中の空行で分かれたその区間の本文の続きとして読む。
  ただし番号の行 (SRT) や時刻らしい行 (`-->` を含む行など) があるブロックは、時刻の書き方が崩れた区間として続きにしない。
  WebVTT の先頭の `WEBVTT` の行の直後に空行を挟まずに区間が続く場合 (規格外) は、時刻の行から後を区間として読む。
  それ以外の時刻を読めないブロックは読み飛ばし、その数を知らせる
  - 読み込んだ SRT は、読み飛ばしたブロックが無い場合だけ保存先として持つ (保存済みとして扱う)。読み飛ばしがある場合と
    SRT 以外の形式は保存先として持たず、保存するときに保存先を選ばせる (上書きで読み飛ばした区間を消さないため)
- SRT への保存 (`formatSrt`): 時間を読めない行があれば、その行を示して保存しない。本文の空の行は区間の区切りと
  解釈されるため除く
- 行の時間内に収まらない場合の扱いは、画面で全体の設定として「話速を上げて収める (既定)」「次の行と重ねる」
  「後続の行を後ろにずらす」「警告のみ」から選ぶ。行ごとに変える場合は、その行に `fit` タグを書く (16.2)
- 話速を上げる場合は、エンジンの話速を上げて合成し直し、残ったわずかな差を rubberband の時間伸縮で詰める
  (制御タグで話速を指定している行は、その指定に倍率を掛ける)。倍率は、行の中の間 (`break`) の無音を除いた声の部分で求め
  (「(合成した長さ − 間) ÷ (行の時間 − 間)」)、間の長さは保つ。間だけで行の時間を超える場合は、行全体を縮める倍率にする。
  間を含む行は、話速を上げて合成し直しても声の部分がまだ 1% を超えて長い場合 (エンジンの話速が倍率どおりに速くならない)、
  足りない分だけ倍率を上げてもう 1 回合成し直す。残りを時間伸縮で詰めるときは、合成した音声の声の部分だけを切り出して
  同じ倍率で縮め、間の無音は長さを変えずにつなぎ直す (`fitIntoSlot`。合成の結果は声と間の位置 (`parts`) を返す)。
  間の無い行は全体を縮める。rubberband の倍率の上限 (100 倍) を超える場合は、上限以下の倍率に分けて重ねて縮める。
  話速を上げて収める行 (全体の設定、または行の `fit` タグ) がある場合は、合成を始める前に rubberband の有無を確かめる
  (合成や確認の後で失敗しないため)。上限は設けず、1.3 倍を超える行があれば
  行の番号・時間・テキスト・必要な倍率の一覧を示して 1 回だけ確認する。1 回目の合成結果は確認後の続きに使う。
  確認に対応する結果が無い場合と、確認を求めた後に依頼の内容 (文章・設定) が変わった場合は続きから処理せず、
  もう一度実行するよう求める (`TTS_CONFIRMATION_EXPIRED`)
- 実行後に、話速を調整した行とその倍率と、「警告のみ」の行で収まらなかった行とはみ出した秒数を示す
- main でも時間とテキストを確かめ、誤りがあれば始めない (`TTS_TIMING_INVALID`。誤りのある行の番号を示す。
  行が無ければ `TTS_TIMING_EMPTY`)
- 進み具合: 話速を上げて収める行がありうる場合は、1 回目の合成を 60%、話速を上げた合成を 85%、合成し直しを 90%、
  時間伸縮を 95% までとし、残りを 1 本にまとめる処理に当てる。ありえない場合は 1 回目の合成を 95% までとする。
  確認の後の続きでは、1 回目の合成の分を済んだものとして始める。通常の入力は、合成を 90% まで、残りを段落をつなぐ処理に当てる

### 16.8 学習 (`training.ts` / `pages/voice/TtsTrainingPage.tsx`)

- NVIDIA GPU を使える Windows と Linux でのみ行える (上流の Style-Bert-VITS2 が NVIDIA GPU を前提としているため、13.1)
- 学習セット (言語を 1 つ持つ。13.15) を選び、左の文の一覧から文を選んで、右でその文を録音するか、その文に対応する
  音声ファイルを指定する。どの文から録ってもよく、読みたくない文は飛ばしてよい (学習に数えるのは音声のある文だけ)。
  文の一覧はその言語の学習用の文章のすべて。複数の文を続けて録ったファイルの分割は利用者が行い、アプリは自動分割や
  自動書き起こしを行わない。
  提示した文章をそのまま書き起こしとして使う。音声の長さは確かめない (利用者の判断に任せる)。
  録音ではエコーキャンセル・ノイズ抑制・自動ゲイン調整を無効にする
- 学習前の確かめ: 学習を始める前に、長い無音を含む音 (判断はフィルターの「無音部分を除去する」の初期値と同じ。13.16)
  があれば、名前と無音の長さの一覧を示し、「了解して続行」か「キャンセル」を選んでもらう。読み上げの学習では、
  文章と対応しない無音も読み上げの間として覚えられ、ライブラリも前後の無音を切らないため。無音は学習用の音の
  フィルターで取り除ける (13.15)。音声変換の学習では確かめない (Applio が学習の前に無音を切るため)
- 録音中 (録音の開始操作からマイクの許可の確認を含めて止めるまで) は、文の移動と学習セットの切り替えを無効にし、
  録音は録音を始めた時点の学習セット・文に保存する (別の文の録音として保存しないため)
- 録音の画面を離れた後にマイクの許可の確認などの待ちが終わった場合は、開いたマイクと音声処理をその場で閉じる
  (音声機能の録音すべてで同じ。`useRecorder`)
- 学習用の音声の扱いは 15.6 と同じ。文の音声を録り直した・指定し直したときは、前の音声を学習セットから消す。
  文の音声を削除するときは、元に戻せないことを示して確認する
- 学習用の文章 (13.11): 日本語は ITA コーパス (Emotion 100 文と Recitation 324 文。どちらのサブセットも日本語の音の
  組み合わせを豊富に含むよう設計されている) の 424 文。英語は CMU ARCTIC の読み上げ文 (Project Gutenberg の
  著作権切れのテキストから選ばれた 1,132 文)。中国語は Common Voice の文から選んだ 400 文 (13.11)
- 音声のある文が言語ごとの最低の文数以上で学習できる (`TRAINING_DATA_TOO_FEW`)。最低と推奨の文数は言語定義
  (`trainingSentences`) に固定で持ち、画面に示す。最低は録音の合計が約 5 分、推奨は約 15 分になる文数で、読み上げエンジンの
  FAQ (「数分程度でも学習できる」「多くても 45 分程度で十分」) を元にした目安。1 文の長さは読み上げ文の平均から概算する
  (日本語はモーラ数 ÷ 毎秒 7.5、英語は単語数 ÷ 毎秒 2.7、中国語は漢字数 ÷ 毎秒 4.5)。日本語は約 3.2 秒で最低 100 文・
  推奨 290 文、英語は約 3.3 秒で 100 文・280 文、中国語は約 5.4 秒で 60 文・170 文 (10 文単位で切り上げ)。
  日本語は JP-Extra 版と多言語版、英語と中国語は多言語版で学習する。
  必要なのは、学習する形式の事前学習モデルと、学習する言語の言語モデル (特徴量の抽出ではその言語の BERT だけを使う)。
  異なる種類 (JP-Extra 版・多言語版) のモデル同士に互換性は無い
- パラメーターはアプリが決める: バッチサイズは VRAM 12GB 以上で 4 / 10GB 以上で 3 / 8GB 以上で 2 / それ未満で 1、
  エポック数は総ステップ数がおよそ 8000 になるよう 20〜200 の範囲で決める
- 流れ: データの準備 → 前処理 (リサンプリング・テキストの前処理) → 特徴量の抽出 (BERT・スタイル) → 学習 →
  完成したモデル (`model.safetensors`・`config.json`・`style_vectors.npy`) を声のモデルとして登録 (ユーザーモデル)。
  作成したモデルには利用者が名前を付ける。進捗は手順 (データの準備・前処理・特徴量の抽出・学習・仕上げの 5 つ) ごとに
  示し、学習はエポック、前処理と特徴量の抽出は上流の進捗バーから手順の中の進み具合と残り時間を求める
  - リポジトリの学習スクリプトは、作業ディレクトリのジョブのフォルダをカレントディレクトリに
    して動かし、スクリプトが読む `config.yml` と `configs/paths.yml` をそのフォルダに書く。`dataset_root` はジョブの
    フォルダの `Data/`、`assets_root` はモデルディレクトリの作成中の声のモデルのフォルダとし、完成したモデル
    (重み・`config.json`・`style_vectors.npy`) をモデルディレクトリに直接書かせる。スクリプトが作る `<名前>/` の
    フォルダから 3 ファイルを名前の変更で 1 つ上へ移し (重みは `model.safetensors` にする)、そのフォルダを消す
  - 学習の途中のデータ (リサンプリングした音声・特徴量・チェックポイント) はジョブのフォルダの `Data/<名前>/` に置き、
    学習が終わった時点 (成功・エラー・キャンセル) で main プロセスがジョブのフォルダごと消す。上流のソース一式の中には書かない
  - リサンプリングは、学習セットの音声を 1 つずつ読み、`Data/<名前>/wavs/` に 44.1kHz の WAV として書く
    (上流の `resample.py` は 1 つのフォルダの中を処理するため、同じ処理をファイルごとに行う)
  - 学習の初期値はモデルディレクトリの事前学習モデルから直接読み、読めなければ止める
    (`TRAINING_PRETRAINED_UNREADABLE`。13.4)。学習の設定を作る時点で事前学習モデル (`G_0.safetensors`) が無ければ、
    学習を始めずに止める (`TRAINING_PRETRAINED_MISSING`)
  - テキストの前処理で読みを得られない文があれば、その文を除かずに前処理を失敗として止める (上流の `--yomi_error raise`。
    `TRAINING_STEP_FAILED`)。提示した文と録音の対応を黙って減らさないため

### 16.9 声のモデルとすぐに使えるモデル

- 区分はユーザーモデルと既存モデル (13.9)。各モデルにはモデルの種類 (`modelType`) と対応言語を記録し、対応する言語の文章にだけ使う
- すぐに使えるモデル: Style-Bert-VITS2 の作者が公開している JVNV コーパスのモデル (女性 2 種・男性 2 種) を、
  ダウンロードのダイアログから取得する。声のモデルの画面の「すぐに使えるモデルを取得」は、未取得のすぐに使えるモデルを選んだ状態で
  ダイアログを開く (13.14)。JP-Extra 版 (jvnv-F1-jp / F2-jp / M1-jp / M2-jp、本体は約 251MB) と
  多言語版 (jvnv-F1 / F2 / M1 / M2、約 199MB。2.0 より前の形式だが、そのまま使える) がある。
  ライセンスは CC BY-SA 4.0 (学習元の JVNV コーパスから引き継がれている) で、ライセンスと配布元を表示する。
  区分は既存モデル。名前はアプリが自動で付け、利用者が変更できる。JP-Extra 版のモデルは日本語の言語モデルを前提とし、
  一緒に取得してその大きさも合計に含めて示す (多言語版のモデルは読み上げる言語の言語モデルがあれば使えるため、
  前提を持たない)
- 取り込むモデルは設定ファイル (`config.json`)・モデル本体 (safetensors)・スタイル情報 (`style_vectors.npy`) の 3 ファイルで構成される
  (Style-Bert-VITS2 も推論にこの 3 つを必要とし、モデルを共有する場合はこの 3 つを共有するよう説明している)
