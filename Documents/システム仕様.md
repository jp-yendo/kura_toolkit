# Kura Toolkit システム仕様

## 1. 概要

Kura Toolkit は、以下の 4 つのツールを 1 つにまとめた Electron 製デスクトップアプリケーション。

| カテゴリ | 機能 | 移植元 |
|---|---|---|
| オーディオ | オーディオ正規化 | AudioNormalizer (PyQt5) |
| 動画 | チャプターカット | ffmpeg_toolbox/cut-chapter.py (CLI) |
| 画像 | SVG 変換 | vtracer-gui (PyQt5) |
| ツール | クリーンアップ | CleanSweep (PyQt5) |

## 2. アーキテクチャ

- Electron (main: CommonJS/tsc、renderer: React + MUI + Vite)
- renderer は HashRouter によるページ遷移 (開発時・配布時とも同一)
- main プロセスは `src/main/services/` に機能実装、`src/main/ipc/` に IPC ハンドラを配置
- preload (`src/preload/index.ts`) が `window.kuraToolkit` として型付き API を公開
- `src/main/` から `src/renderer/` の import は禁止 (i18n は renderer 専用)。main はエラーコード
  (`FFMPEG_NOT_FOUND` など) を返し、renderer 側で翻訳する

### ディレクトリ構成 (抜粋)

```text
src/
├── main/
│   ├── index.ts                 # 起動・ウィンドウ生成・アプリ情報 IPC

│   │   ├── audio-normalizer.ts  # オーディオ正規化
│   │   ├── chapter/             # チャプターカット (probe/keyframe/encoders/metadata/subtitles/naming/cut/split)
│   │   ├── vectorizer.ts        # 画像 SVG 変換 (@neplex/vectorizer)
│   │   ├── dir-walker.ts        # ディレクトリ走査の並列実行 (ワーカープールの管理)

```

## 3. 設定の永続化

- 保存先: `~/.kura_toolkit/settings.json`
- main プロセスの `services/settings.ts` が管理。読み込み時に既定値と deep-merge して欠損キーを補完し、
  書き込みは一時ファイルへ書いてから rename するアトミック方式
- スキーマ (バージョン 1):

```jsonc
{
  "version": 1,
  "app": { "theme": "system | light | dark", "language": "ja | en" },
  "ffmpeg": { "ffmpegPath": "", "ffprobePath": "" },       // 空文字 = PATH から自動検出
  "search": { "threads": 4 },  // ファイル探索に使うスレッド数 (初回起動時に決めて保存する)
  "audioNormalizer": {
    "outputDir": "", "targetLufs": -13, "sampleRate": 44100,
    "bitrateMode": "cbr | vbr", "bitrate": 160
  },
  "cleanup": {
    "customDirs": [],            // ユーザーが追加した検索対象ディレクトリ
    "selectedTargets": [],       // 前回検索したときのクリーンアップ対象
    "selectedRoots": []          // 前回検索したときの検索対象ディレクトリ
  }
}
```

- `search.threads` (探索のスレッド数) は「自動」という状態を持たず、常に実数値を保存する
  - 初回起動時 (設定ファイルが無い、または値が未決定) にだけ
    `max(1, min(4, floor(論理コア数 / 2)))` を算出して保存する。既に値があるときは触らない
  - 設定画面での制限は **1 以上 100 以下**のみ。起動時に決める上限 4 は初期値のためのもので、
    実行時には適用しない
  - ディレクトリを走査する処理はこの値を上限とする (現状はクリーンアップの検索)
- 保存タイミングは項目の性質で分ける
  - アプリ設定 (テーマ・言語・ffmpeg のパス・探索のスレッド数)・クリーンアップのカスタムディレクトリ: UI 変更時に即時保存
  - 各機能の実行パラメータ (オーディオ正規化の出力設定・クリーンアップの検索条件):
    **その機能を実行したときに、保存済みの値と異なる場合だけ**書き込む。
    入力途中の値をファイルへ書かないため、1 文字打つたびの保存が発生しない
  - チャプターカットと画像 SVG 変換のパラメータ: 保存しない (下記 8 章・9 章)。
    値は zustand ストア上のみで保持し、アプリを起動するたびに既定値へ戻る

## 4. IPC チャンネル一覧

チャンネル定数は `src/shared/constants.ts` の `IPC_CHANNELS` に定義
(preload にはランタイム import 回避のためローカルコピーあり。追加時は両方を更新すること)。

| チャンネル | 方向 | 内容 |
|---|---|---|

| `window:minimize` / `window:maximizeOrRestore` / `window:isMaximized` / `window:close` | invoke | ウィンドウ制御 |
| `settings:get` / `settings:update` | invoke | 設定の取得・部分更新 |
| `ffmpeg:detect` | invoke | ffmpeg/ffprobe の解決結果 (設定値優先、空なら PATH 走査) |
| `dialog:openFiles` / `dialog:openDirectory` / `dialog:saveFile` | invoke | ネイティブダイアログ |
| `files:collect` | invoke | パス群の展開 (ディレクトリを再帰走査し拡張子で絞り込む) |
| `job:cancel` | invoke | ジョブのキャンセル |
| `job:event` | main→renderer | ジョブイベント push (progress / log / item / scan) |
| `audio:analyze` / `audio:normalize` | invoke | オーディオ解析・正規化 |
| `audio:checkOutputs` | invoke | 正規化前の出力先チェック (上書きになるファイル・出力パスの重複) |
| `chapter:probe` / `chapter:cut` / `chapter:split` | invoke | チャプター取得・切り出し・分割 |
| `chapter:checkCut` / `chapter:checkSplit` | invoke | 実行前の出力先チェック (上書きになるファイル) |
| `vectorizer:loadImage` / `vectorizer:convert` / `vectorizer:saveSvg` | invoke | 画像読込・SVG 変換・保存 |
| `cleanup:getCapabilities` / `cleanup:openPermissionSettings` | invoke | 利用可能な対象と権限状態の取得・macOS の権限設定を開く |
| `cleanup:getRoots` / `cleanup:scan` / `cleanup:remove` | invoke | 検索対象列挙・検索・削除 |
| `updater:*` | invoke / push | 自動アップデート (electron-updater) |
| `main:console` | main→renderer | main のログを DevTools へ転送 |

## 5. ジョブ管理 (長時間処理)

- `services/job-manager.ts` が管理。jobId は renderer が `crypto.randomUUID()` で生成し、
  開始 invoke の引数として渡す。invoke の解決 = ジョブ完了
- 進捗・ログ・発見アイテムは `job:event` チャンネルで push する
  (`JobEvent = { jobId, kind: 'progress' | 'log' | 'item', percent?, current?, total?, message?, payload? }`)
- `job:cancel` で登録済み子プロセス (ffmpeg 等) を kill し、ループ系はフラグ確認で中断する。
  キャンセルは例外ではなく `{ cancelled: true }` を含む結果として返す
- ウィンドウクローズ時は全ジョブを自動キャンセルする

## 6. ffmpeg 実行基盤

- `services/ffmpeg/ffmpeg.ts` / `ffprobe.ts`
- パス解決: 設定値優先。空なら PATH の各ディレクトリを `fs.access` で走査して検出
  (`where`/`which` の出力パースは文字コード依存のため行わない)。ffprobe 未設定時は
  ffmpeg と同じディレクトリを優先して探す
  - macOS / Linux では Finder やランチャーから起動すると PATH が最小限になるため、
    PATH に加えて既定のインストール先も探索する
    (macOS: `/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`、`/sw/bin`、`/usr/bin`、`/bin`。
    Linux: `/usr/local/bin`、`/usr/bin`、`/bin`、`/snap/bin`、`/var/lib/flatpak/exports/bin`)
- 実行は必ず `spawn(cmd, argsArray)` (shell 不使用) で行い、日本語パス・cp932 の引用問題を回避する
- 出力のパースは `-print_format json` と `-progress pipe:1` の機械可読出力のみに依存する
- 進捗は `-progress pipe:1 -nostats` の `out_time_us` を対象長で割って算出する
- 未検出・失敗はエラーコード付きメッセージ (`FFMPEG_NOT_FOUND` / `FFPROBE_NOT_FOUND` /
  `FFMPEG_FAILED: <stderr>` / `KURA_CANCELLED`) で表現する

## 7. オーディオ正規化 (`services/audio-normalizer.ts`)

- 解析:
  - チャンネル数: `ffprobe -show_streams` の JSON から取得
  - LUFS: `ffmpeg -i <file> -af loudnorm=I=-16:LRA=11:TP=-1.5:print_format=json -f null -` の
    stderr 末尾の JSON ブロックから `input_i` を抽出 (実測値のためターゲット値の影響は受けない)
- 正規化コマンド:
  `-af loudnorm=I={target}:LRA=11:TP=-1.5:linear=true -ar {rate} -map_metadata 0 -map 0:a:0 -map 0:v? -c:v copy -c:a {encoder} {ビットレート引数}`
  (タグとアルバムアートを保持)
- エンコーダ判定: 入力コーデック維持 (mp3→libmp3lame / aac / vorbis→libvorbis / opus→libopus /
  flac / pcm_* はそのまま)。フィルタ適用には再エンコードが必須のため、未対応コーデックはスキップして警告
- ビットレート: CBR は `-b:a {n}k`。VBR は mp3/vorbis のみ `-q:a` の品質値へ変換する
  (opus は CBR 時のみ `-vbr off`)。flac/pcm はビットレート指定なし
  - mp3 (libmp3lame): 245以上=V0 / 225以上=V1 / 190以上=V2 / 175以上=V3 / 165以上=V4 /
    130以上=V5 / 115以上=V6 / 100以上=V7 / 85以上=V8 / それ未満=V9 (LAME の各 V 設定の
    実効ビットレートに基づく)
  - vorbis (libvorbis): 320以上=q9 / 256以上=q8 / 224以上=q7 / 192以上=q6 / 160以上=q5 /
    128以上=q4 / 112以上=q3 / 96以上=q2 / 80以上=q1 / それ未満=q0
- 出力: 出力先ディレクトリ + 入力と同名。出力先が未指定の場合は入力と同じディレクトリ、
  つまり**元のファイルの上書き**になる
  - ffmpeg は読み込み中のファイルへ直接書けないため、上書きになる場合は同じディレクトリの
    一時ファイル (`{名前}.kura-tmp{拡張子}`) へ出力し、成功してから `rename` で置き換える。
    途中で失敗・キャンセルした場合は一時ファイルだけを削除するため、元のファイルは必ず残る
  - 実行前チェック (`audio:checkOutputs`): 出力パスの決定規則は main が持ち、renderer は
    正規化ボタンを押した時点で結果を受け取って次のように分岐する
    - `duplicated` (複数の入力が同じ出力パスになる。別ディレクトリの同名ファイルを 1 か所へ
      出す場合) が 1 件でもあれば、**どう実行しても互いを上書きするため実行そのものを止める**
      (確認ではなく警告通知)。`normalizeFiles` 側でも開始前に `DUPLICATE_OUTPUTS` を投げる
    - `existing` (既に存在する出力パス) があれば確認ダイアログで一覧を示し、承認するまで実行しない。
      出力先が空欄のときは入力ファイル自身が必ず対象になる
    - パスの比較は Windows のみ大文字小文字を無視する (`process.platform` で切り替え)
  - キャンセル・失敗時は書きかけの出力を削除
- 入力の追加: ファイルの追加・ディレクトリの追加・ドラッグ&ドロップに対応する。
  ディレクトリはサブディレクトリまで再帰的に走査し (`files:collect`)、対象拡張子の音声ファイルだけを
  名前順に取り込む。renderer からはファイルとディレクトリを判別できないため、
  ドロップされたパスは絞り込まずに main へ渡し、展開と絞り込みは main が行う
- 出力設定 (出力先・ターゲット LUFS・サンプルレート・ビットレート) は画面内の状態として編集し、
  解析または正規化を実行したときに保存済みの値と比較して、異なる場合だけ settings へ書き込む
- 画面構成: 上のボタン列 (追加・一覧クリア)、解析/正規化ボタン、出力設定の枠は高さを固定し、
  ファイル一覧が残りの高さを埋める。行があふれた分は一覧の枠内でスクロールする
  (見出し行は `stickyHeader` で残す)。ウィンドウが低くて全体が収まらない場合は
  一覧を最低 180px 確保したうえでページ側がスクロールする
- ファイル一覧は `tableLayout: fixed` で列幅を固定する (ディレクトリ 40% / チャンネル 112px /
  LUFS 88px / 残りがファイル名)。**全ての列で折り返しを行わず、行の高さを 1 行に揃える**。
  ファイル名とディレクトリは収まらない分を末尾省略し、全文は `title` 属性 (ホバー) で確認できる
- 元実装 (AudioNormalizer) からの意図的な変更点:
  - libmp3lame への無効なオプション `-cbr 1` を廃止 (libopus 用のオプションで libmp3lame では
    使われず、「Codec AVOption cbr has not been used for any stream」の警告が出るだけだった。
    libmp3lame は `-b:a` の指定のみで CBR になるため、削除しても出力は変わらない)
  - `-c:a copy` とフィルタ適用の矛盾を解消。フィルタ適用にはデコードが必須のため、
    エンコーダを決定できないコーデックは正規化不能としてスキップし警告する
  - サンプルレート選択肢の誤記 20050 を 22050 に修正
  - VBR の品質マップを全ビットレートに対応させた。元実装は 320k/256k/192k/128k の 4 つだけを
    定義し、残り 14 種は既定値 (mp3=V2, vorbis=q6) に落ちていたため、例えば 8kbps を選んでも
    V2 相当 (約190kbps) で出力されていた。移植版は上表のとおり全選択肢を実効ビットレートに
    対応付ける。このため元実装と値が変わるのは次の 4 点:
    mp3 256k (V1→V0) / mp3 128k (V4→V6) / vorbis 320k (q8→q9) / vorbis 256k (q7→q8)
  - チャンネル数とコーデックの判定を stderr の正規表現から ffprobe の JSON 出力に変更
    (ロケールや出力書式に依存しないため)
  - libopus は 8000/12000/16000/24000/48000 Hz しか受け付けず、既定の 44100 Hz では必ず
    エンコードに失敗する (元実装も同じ問題を持っていた)。エンコーダが libopus のときは
    指定値以上で最も近い対応値へ丸めてから `-ar` に渡す
  - ターゲット LUFS の入力を loudnorm の有効範囲 (-70〜-5) で検証する。元実装は空文字のみを
    弾いており範囲チェックが無かった

## 8. チャプターカット (`services/chapter/`)

cut-chapter.py の全機能 (info / cut / split、--accurate 含む) を TypeScript へ移植したもの。
処理内容は元実装と同一:

- probe: `ffprobe -show_chapters` / `-show_streams -show_format` の JSON からチャプター・ストリーム情報を取得
  - `ChapterProbeResult.streams` に各ストリームの種別・コーデック・解像度・チャンネル数・
    サンプルレート・ビットレート・言語・タイトルを整形して含める。
    renderer は「チャプター一覧」見出しの**ファイル情報ボタン**から、この内容をダイアログで表示する
    (常時表示はせず、読み込んだ時点の解析結果をいつでも確認できるようにする)
- cut: 開始チャプター〜終了チャプター (省略時は最終) の範囲を切り出す
  - ストリームコピー時は開始点を直前の映像キーフレームへ吸着
    (`packet=pts_time,flags` を探索窓 30 秒から 4 倍ずつ拡大しながら走査)
  - accurate 時は元コーデック・ビットレート・pix_fmt を引き継いで再エンコード
    (VIDEO_ENCODERS/AUDIO_ENCODERS マップ、ビットレート不明時は crf 既定値または 64000×ch の概算)
  - 2 パス構成: pass1 で `-ss/-to` 切り出し (`-map 0 -map -0:d`、`-avoid_negative_ts make_zero`)、
    出力実測 (映像 start_time のずれ・巻き戻り) で基準を補正した FFMETADATA を生成し、
    pass2 で `-map_metadata 0 -map_chapters 1 -c copy -copyts` により埋め込み
    - 全体のメタ情報 (タイトル・作者・説明など) は入力から引き継ぎ、チャプターだけ
      FFMETADATA から取り込む。`-map_metadata 1` にすると FFMETADATA の内容で全体が
      置き換わり、元のタグが消える。分割時も各パートが同じ扱いになる
  - **実際の切り出し開始位置の実測**: `-ss` にキーフレームを指定しても、デマルチプレクサが
    さらに手前のキーフレームへ巻き戻ることがある (mkv で頻発。cue の粒度による)。
    ここを取り違えるとチャプター位置と字幕の時刻がまとめてずれるため、
    `出力の長さ` から開始位置を逆算し、内容は必ずキーフレームから始まることを利用して
    近傍のキーフレームへ吸着させる (`findNearestKeyframe`)
    - mkv はストリーム単位の長さ (`stream.duration`) を返さないため、
      コンテナ全体の長さ (`format.duration`) で代用する。この代用が無いと補正が働かない
  - **字幕とカバーアートは pass1 から必ず除外する** (`-map -0:s` と attached_pic の除外)。
    字幕には切り出し開始より前から表示され続けているパケットがあり、これを pass1 に含めると
    `-avoid_negative_ts make_zero` の基準がその古い時刻になり、映像・音声を含む全体の時刻が
    ずれる (出力の先頭が 0 秒にならず、字幕トラックだけが数十秒前方にずれて再生時に表示されない)。
    カバーアートも同じ理由で除外する (mp4 の attached_pic は pts=0 のため基準を 0 に固定してしまう)
  - 字幕は範囲ごとに個別のファイルへ切り出し、pass2 で入力として合流させる
    - テキスト字幕 (srt/ass/ssa/vtt): 単体抽出して TS 側で時刻を再構成する
      (`shiftTextSubtitles`。範囲外のイベントは捨て、開始をまたぐものは 0 に丸める)
    - **VOBSUB (dvd_subtitle) で表示領域の大きさを持たない場合** (mp4 に格納されたものは
      コンテナ側にしか大きさが無い): そのまま取り出すと大きさが失われ、再生時に
      既定の 720x480 として拡大されて**巨大化・色化け**する (VLC) か、**表示されない** (MPC)。
      この場合は映像と同じ大きさを `-canvas_size` に与えて同一コーデックで作り直し、
      字幕自身に大きさを持たせる。再エンコード時は時刻が元のまま残るため
      `-output_ts_offset` で切り出し開始を 0 に揃える
    - それ以外 (PGS・mov_text 等): `-copyts` + 入力側/出力側の `-ss` で範囲を切り出す
      (出力側 `-ss` により切り出し開始前のパケットが落ちる。字幕はフレーム間の依存が無いため
      映像と違って途中から切り出しても問題ない)。pass1 の実測とのずれは pass2 の
      `-itsoffset` で吸収する
    - pass2 では `-map {n}:s` で字幕だけを取り込む (一時ファイルにも mp4 のチャプター用
      トラックが付くため)。言語・タイトルのタグと既定/強制フラグ (`-disposition:s:N`) を
      元ストリームから引き継ぐ。指定しないと ffmpeg が入力ごとに既定フラグを立て、
      既定の字幕が複数ある状態になってプレイヤーの選択が変わってしまう
  - 出力名: `{入力ベース名}-{fromラベル}-{toラベル}{拡張子}` (ラベルはタイトル優先、
    Windows 禁止文字をサニタイズ)。出力先は指定ディレクトリまたは入力と同じ場所
  - **ビットマップ字幕 (VOBSUB / PGS 等) がある場合、mp4 系の指定でも mkv で書き出す**
    (`resolveSubtitleFriendlyOutput`)。理由は次のとおりで、拡張子を変えた場合はログに残す
    - PGS は mp4 に格納できない
    - VOBSUB は mp4 だと表示領域の大きさとパレットを ffmpeg が元の形で書けず、
      VLC で巨大化・緑色化する (MPC は問題なし)。元ファイルは正常に再生できるため、
      ffmpeg が書く mp4 の字幕サンプル記述を VLC が解釈できないことが原因。
      mkv では両プレイヤーとも正常に表示できる
  - 切り出しモードでは出力ファイル**名**を明示指定でき (CLI の `--output` 相当)、指定時は自動命名より
    優先される。**出力先は常に出力先ディレクトリで決まり、ファイル名側には出力先を持たせない**
    (出力先の指定が 2 か所に分かれるのを避けるため)
    - renderer: ファイル名の入力欄はテキスト入力のみ (ファイル保存ダイアログは使わない)。
      パスを貼り付けるなどしてディレクトリ部が混ざった場合は、その部分を出力先ディレクトリ欄へ移し、
      ファイル名欄には最後の要素だけを残す
    - main (`naming.ts` の `namedOutputPath`): 受け取った名前も `path.basename` で最後の要素だけを使い、
      禁止文字をサニタイズする。拡張子が無い場合は ffmpeg が出力形式を決められないため、
      入力と同じ拡張子を補う
- split: 指定チャプター群の直前を分割点として複数範囲に分割し、各範囲を cut と同一処理で出力。
  出力名の重複は処理前に検出してエラー (`DUPLICATE_OUTPUTS`)
- 出力先の決定 (範囲の算出と出力名の生成) は `planCut` / `planSplit` に集約し、実行前チェックと
  本処理の両方から同じ関数を使う。規則が 2 か所に分かれて食い違うのを防ぐため
- 実行前チェック (`chapter:checkCut` / `chapter:checkSplit`): 生成される出力パスと、そのうち
  既に存在するものを返す。renderer は実行ボタンを押した時点で呼び出し、既存ファイルがあれば
  一覧付きの確認ダイアログを出して、承認するまで実行しない
- GUI とのやり取りはチャプター配列の添字で行う (CLI の id/title 指定はチャプター一覧 UI で代替)
- 画面構成: ファイルを読み込むまではドロップ領域がページ全体の高さを占める。読み込み後は
  上部の細いバー (高さ 72px、読み込み中のファイルパスを表示) に切り替わり、
  チャプター一覧が残りの高さを埋めて、あふれた行は一覧の枠内でスクロールする
  (見出し行は `stickyHeader` で残す)
  - 一覧の枠は `Panel` 自身をスクロール枠にする。`TableContainer` の `component={Panel}` は
    使わない。MUI は `sx` を className に変換して渡すが `Panel` は className を受け取らないため、
    レイアウト指定 (flex・overflow) が全て捨てられてページ全体がスクロールしてしまう
- **設定は一切保存しない**。出力先ディレクトリ・フレーム単位で正確に切り出す・出力ファイル名・
  モード・チャプターの選択はすべて `stores/chapterStore.ts` の状態として保持し、
  アプリを起動するたびに既定値 (出力先は空文字 = 入力と同じディレクトリ、accurate は false) へ戻る。
  出力先と accurate は入力ファイルを変えても引き継ぎ、出力ファイル名は入力ごとに破棄する
- エラーコード: `NO_CHAPTERS` / `INVALID_RANGE` / `NO_SPLIT_POINT` / `DUPLICATE_OUTPUTS` / `OUTPUT_EQUALS_INPUT`

## 9. 画像 SVG 変換 (`services/vectorizer.ts`)

- `@neplex/vectorizer` (vtracer の NAPI バインディング、非同期 API) を使用。外部プロセスなし
- パラメータは vtracer と同一 (colorMode / hierarchical / filterSpeckle / colorPrecision /
  layerDifference / mode / cornerThreshold / lengthThreshold / spliceThreshold、maxIterations=10 固定)
- **パラメータは settings.json へ保存しない**。既定値は `stores/vectorizerStore.ts` の
  `DEFAULT_VECTORIZE_PARAMS` に持ち、値は画像・変換結果と同じくストア上のみで保持する。
  そのためアプリを起動するたびに既定値へ戻る (画面を行き来しただけでは戻らない)
- 入力: png / jpg / jpeg / bmp / gif / tiff。プレビューは main が dataURL を返し、
  SVG プレビューは renderer 側で Blob URL の img として表示
- 画面構成: 左が元画像と SVG プレビューの上下 2 分割、右が変換パラメータ (幅 320px 固定)
  - 上下の仕切りは `SplitPane` でドラッグして高さを配分できる (初期は 1:1、上下とも最低 15%)。
    配分は保存せず、画面を開き直すと 1:1 に戻る
  - SVG プレビューは `ZoomableImage` で拡大縮小できる。見出しの右にズーム操作
    (縮小・現在の倍率 = クリックで実寸・拡大・全体表示) を置く。Ctrl + ホイールでも拡大縮小し、
    枠からはみ出しているときはドラッグで表示位置を動かせる
  - 倍率は SVG の実寸 (svg 要素の width/height) に対する比率。全体表示では枠に収まる倍率で表示し、
    実寸より大きくは拡大しない。変換し直すと全体表示に戻る
- ネイティブモジュールのため electron-builder の `asarUnpack` に `**/node_modules/@neplex/**` を指定

## 10. クリーンアップ (`services/cleanup.ts` / `cleanup-targets.ts` / `dir-walker.ts`)

- 対象 11 種 (検出パターンは元実装と同一)。**対象の一覧は OS によらず共通**で、
  プラットフォームごとに項目が増減することはない。OS による差があるのは Zone.Identifier の
  検出方法のみ (下記):
  - `Zone.Identifier` — 現れ方がプラットフォームで異なるため 2 通りの検出を行う (対象自体は全環境で利用可能)
    - Windows: NTFS の代替データストリーム。`fs.open(path + ':Zone.Identifier', 'r')` の成否で検出し、
      削除は `fs.unlink` (ゴミ箱へは移動できないため。本体ファイルは残る)。
      ファイルごとに open を試すため、この判定は Windows でのみ実行する
    - Windows 以外: Windows からコピーしたり書庫を解凍すると、ADS を保持できないファイルシステム上では
      `元のファイル名:Zone.Identifier` という通常のファイルとして現れる。ファイル名がこの接尾辞で
      終わるものを検出し、通常のファイルとしてゴミ箱へ移動する。
      Windows のファイル名に `:` は使えないため、この判定は全環境で実行しても誤検出しない
      (`Zone.Identifier` 単体や `x:Zone.Identifier.bak` のような名前は対象外)
  - ファイル名完全一致: `Thumbs.db` / `.DS_Store`
  - 前方一致: `._*`
  - ディレクトリ名完全一致: `.AppleDouble` / `.fseventsd` / `.Spotlight-V100` / `.AppleDB` /
    `.AppleDesktop` / `.TemporaryItems` / `Network Trash Folder`
- 検索対象: ホームディレクトリ + ドライブ/ボリューム列挙 + カスタムディレクトリ (settings に保存)
  - Windows: WMI (`Get-CimInstance Win32_LogicalDisk` を PowerShell 経由で JSON 取得、
    対象フィールドは ASCII のみ) の `DriveType` を使用し、CD/DVD 等の光学ドライブ (DriveType=5) は
    書き込み不可のため列挙から除外する。リムーバブル (2) は「(USB)」、ネットワーク (4) は「(NW)」を
    ラベルに付与。メディアの入っていないリムーバブルスロットはアクセス確認で除外。
    WMI が使えない環境では A:-Z: の存在確認 (`fs.stat`) によるフォールバック列挙 (種別判定なし)
  - macOS: `/Volumes` 配下のマウントポイントを列挙。Linux: `/media`、`/media/<user>`、
    `/run/media/<user>`、`/mnt` を列挙。いずれも `fs.access(W_OK)` で書き込み権限を確認し、
    光学メディアや読み取り専用のディスクイメージを除外する (権限の確認のみで書き込みは行わない)。
    容量は `fs.statfs` で取得
- 除外 (ディレクトリ名で判定、大文字小文字無視。プラットフォームごとに切り替え):
  - Windows: `Program Files` / `Program Files (x86)` / `Windows` / `AppData` / `ProgramData` /
    `Recovery` / `$Recycle.Bin` / `System Volume Information`
  - macOS: `Library` (巨大で走査が長時間化するため) / `Applications` / `System` / `private` /
    `.Trash` / `.DocumentRevisions-V100` / `.MobileBackups` / `.PKInstallSandboxManager*`。
    加えて `.app` で終わるディレクトリ (アプリケーションバンドル) は署名を壊さないため走査しない
  - Linux: `proc` / `sys` / `dev` / `run` / `boot` / `lost+found` / `.Trash` / `.Trash-1000`
- 走査 (`services/dir-walker.ts` + `workers/dir-walker-worker.ts`): 反復 (スタック) 方式、
  シンボリックリンクは辿らない、アクセス不可はスキップ。対象ディレクトリにマッチした場合は配下を走査しない。
  判定そのもの (対象の定義とディレクトリ 1 個ぶんの走査) は `services/cleanup-targets.ts` にある。
  **ワーカーから読み込むモジュールは electron に依存させない** (ワーカーからは electron を使えない)
  - **`worker_threads` で並列化する**。スレッド数は `search.threads`。1 のときはワーカーを起こさず
    同一プロセスで走査し、ワーカーの起動に失敗した場合も同じ経路へ落として必ず動くようにする
    (そのときは黙って遅くならないよう警告をコンソールへ出す)
  - **asar 内のファイルはそのまま Worker のエントリにできる**ため、`asarUnpack` での展開も
    `app.asar.unpacked` へのパス置換も不要 (Electron 43 の配布ビルドで、asar 内のワーカーが
    起動して走査まで完了することを実測で確認済み)。ワーカー内の `require` も asar 内で解決される
  - ワーカー内では**同期 fs (`readdirSync` / `statSync`) を使う**。ワーカーのイベントループは
    塞いでよく、非同期版の libuv ディスパッチ往復を丸ごと省けるため
  - 作業単位は「ディレクトリ 1 個」と「ADS 判定だけを行うファイル群 (512 件単位)」の 2 種類。
    **ADS 判定をディレクトリから切り離せるようにしているのは、ファイルが数万ある単一ディレクトリが
    1 スレッドに固定されて並列化が効かなくなるため** (実測: 全体の 6 割のファイルが 1 ディレクトリに
    集中したツリーで、切り離す前は 8 スレッドでも 1.3 倍にしかならなかった)
  - **ワーカーが 1 つでも落ちた場合は、逐次走査でやり直す**。落ちたワーカーに渡してあった分は
    取り戻せず結果が欠けるため、検出漏れを黙って返さないようにする
  - ワーカーは受け取ったディレクトリを起点に自分のローカルキューで再帰し、
    **手が空いたワーカーがいるときだけ**キューを分けて親へ返す (spill)。
    1 ディレクトリごとに親と往復すると、走査そのものよりメッセージの往復が高くつくため。
    手が空いたワーカーの数は `SharedArrayBuffer` 上のカウンタで共有する
  - 走査を始める前に、main 側でルートの浅い階層 (最大 2 階層) だけを展開してから配る。
    序盤に 1 スレッドしか動けない状態を避けるため
  - キャンセルは `SharedArrayBuffer` 上のフラグを `Atomics` で共有し、メッセージの往復を待たずに
    全ワーカーへ伝える (実測で要求から復帰まで 15 ms 以内)
- ADS (Zone.Identifier) の判定は `fs.statSync(path + ':Zone.Identifier', { throwIfNoEntry: false })`
  を使う。`fs.open` と違い、存在しないときでも例外も Promise も生成しないため
  **1 件あたり 43us -> 15us** になり、走査ファイル数ぶん効く
  - **ディレクトリ一覧から ADS の有無を知る手段は Windows に無い**ため、ファイルごとの判定は避けられない。
    ディレクトリ列挙が返す `FILE_ATTRIBUTE_*` に ADS の有無を示すビットは無く、
    ストリーム列挙 API (`FindFirstStreamW` 等) はファイル単位。MFT の直読みは管理者権限が必要。
    `dir /r` は一覧に ADS を混ぜて出せるが、内部は結局ファイル単位のストリーム列挙で `statSync` より遅い
  - **ボリューム単位で判定を省くこともできない**。`Win32_LogicalDisk.FileSystem` も
    `GetVolumeInformation` の `FILE_NAMED_STREAMS` も `::$DATA` プローブも当てにならず、
    FAT32 かつ名前付きストリーム非対応と申告しながら実際には ADS を保持するクラウドドライブ
    (Google ドライブ) が存在する
- 進捗: 検索済みディレクトリ数・発見件数・スレッドごとの現在位置を、1 件ごとではなく
  **150 ms ごとにまとめて** `job:event (kind='scan')` で push する。
  総ディレクトリ数が事前に分からず完了予測できないため進捗バーは出さない
  (画面側の見せ方は「11. UI 構成」の進捗ダイアログを参照)。
  削除は総数が分かるので従来どおり確定バーと `n / m` を出す
- 削除: 通常のファイル/ディレクトリは `shell.trashItem` でゴミ箱へ移動。
  Windows の ADS (`kind: 'ads'`) のみ `fs.unlink` で直接削除する
- 削除後は失敗項目のみ一覧に残し、再検索を選択できる
- 検索対象ディレクトリの並びは、ユーザープロファイル / ボリューム / カスタム の 3 区分にする
  - ボリュームとカスタムは見出し自体がチェックボックスになっており、配下をまとめて切り替えられる。
    一部だけ選択されている場合は中間状態で表示する
  - 実際に検索へ渡すのは配下の項目 (葉) のパスのみで、見出しは操作用の要素として扱う
  - ボリュームは列挙結果が 1 件以上あるときだけ表示する。カスタムは「ディレクトリを追加...」の
    置き場として、項目が無くても常に表示する
  - 見出しのチェックが全選択の役割を果たすため、検索対象側に「全てチェック」ボタンは置かない
    (クリーンアップ対象は区分が無く 11 項目あるため、そちらには残す)
- 画面構成: クリーンアップ対象と検索対象ディレクトリの枠は内容の高さに合わせて広がり内部スクロールを持たない。
  結果一覧が残りの高さを埋め、あふれた分はその枠内でスクロールする。
  全体が画面に収まらない場合はページ側でスクロールする
- 検索して対象が 0 件だった場合は、閉じるまで残るダイアログで通知する
  (一瞬で消える通知では見落とされるため)
- 検索条件 (クリーンアップ対象と検索対象ディレクトリ) の保存と復元:
  - 検索を実行したときに、保存済みの条件と異なる場合だけ settings へ書き込む
    (並び順の違いは同一とみなし、同じ条件での再検索では書き込まない)
  - 起動後の最初の 1 回だけ設定から復元する。画面を行き来しただけでは
    選択が巻き戻らないようにするため、ストア側で復元済みかどうかを持つ
  - 取り外したドライブなど一覧に無くなった検索対象は、一覧の読み込み後に選択から外す
    (画面に出ていない対象が検索に渡らないようにするため)
- macOS の権限 (フルディスクアクセス):
  - アプリはサンドボックス外のため、デスクトップ・書類・ダウンロード・外部/ネットワークボリューム
    へのアクセスは entitlements ではなく TCC に従う。未許可の場合 `readdir` は EPERM となり
    静かにスキップされてしまうため、`cleanup:getCapabilities` で権限を判定して画面上部に案内を表示する
  - 判定は TCC 保護領域 (`~/Library/Application Support/com.apple.TCC`、`~/Library/Safari`) の
    読み取り可否で行う (副作用のない読み取りのみ)。判定できない場合は誤った警告を避けるため許可済み扱い
  - 案内には「システム設定を開く」(`x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`)
    と「再確認」ボタンを置く。許可の反映にはアプリの再起動が必要な旨も文言に含める
  - TCC ダイアログに表示される利用目的は `electron-builder.yml` の `mac.extendInfo`
    (`NSDesktopFolderUsageDescription` など) で定義する。未定義だとダイアログが出ずに拒否される場合がある

## 11. UI 構成

- カスタムタイトルバー (`components/TitleBar.tsx`): アプリ名+バージョン+**現在の画面名** /
  ダッシュボードアイコン / カテゴリドロップダウン (オーディオ・動画・画像・ツール) / 設定ギア /
  ハンバーガーメニュー (全ページ + アプリ設定 + 終了) / ウィンドウ制御ボタン
  - 画面名は `navigation/features.ts` の `titleKeyForRoute()` で現在のルートから解決する。
    **各ページ側には画面タイトルの見出しを置かない** (タイトルバーに集約する)。
    画面名は現在地を示す主要な情報のため、二次色ではなく通常の文字色で表示する
- ルート: `/` (ダッシュボード)、`/audio/normalizer`、`/video/chapter-cut`、`/image/svg-converter`、
  `/tools/cleanup`、`/settings`
- 機能一覧は `renderer/navigation/features.ts` のレジストリで一元管理し、
  タイトルバーのメニューとダッシュボードのカードが共用する
- ダッシュボードはカテゴリごとのセクションを `repeat(auto-fit, minmax(250px, 1fr))` のグリッドで
  横並びに配置し、幅が足りなければ折り返す。折りたたみ (Accordion) は持たない
- 全画面で余白・字送りを揃えるため、以下の共通部品を使う (`components/common/`)
  - `PageContainer`: ページ枠。余白 `p: 3`、要素間 `gap: 2`、`minHeight: 100%`
  - `SectionLabel`: セクション見出し。`overline` 体裁 (太字・字間広め・二次色)。右端に操作ボタンを置ける
  - `Panel`: 枠線付き領域。`borderRadius: 2`、内側余白 `p: 1.5`、背景 `background.paper`
  - `AppDialog`: 画面内のダイアログは全てこれを使う。**ダイアログ外のクリックでは閉じない**
    (結果や確認を読まずに閉じてしまうのを防ぐため)。閉じる操作は Esc キーと明示的なボタンのみ
  - `SplitPane`: 上下 2 分割の領域。間の仕切りをドラッグして高さの配分を変えられる
  - `ZoomableImage`: 画像の拡大縮小表示。倍率は親が持ち (`null` = 全体表示)、
    実際に表示している倍率を親へ返す。Ctrl + ホイールで拡大縮小、はみ出し時はドラッグで移動。
    ホイールは React の `onWheel` が passive で `preventDefault` できないため直接登録している
  - `NotificationArea` (App が 1 つだけ描画): アップデート通知と画面内の一時通知を右下にまとめ、
    同時に出るときは縦に積み重ねる。一時通知は `stores/noticeStore.ts` の `showNotice()` で
    どの画面からでも出せる (各ページが個別に通知を描画すると位置が重なるため一元化している)
  - 本文・補足は `body2` を基本とし、`lineHeight` は 1.6 前後に揃える
- テーマ: ライト / ダーク / システム (MUI ThemeProvider)。言語: 日本語 / 英語 (i18next、
  `renderer/i18n/locales/ja.ts` と `en.ts`)
- 配色は `renderer/theme/index.ts` に集約する (画面側に色を直書きしない)
  - 背景: ライトは下地 `#f4f5f7` / 面 `#ffffff`、ダークは下地 `#0a0a0a` / 面 `#161616`。
    ライトで下地をわずかに灰色にしているのは、白い面 (Panel) が沈まないようにするため
  - 通知 (Alert) は `standard` を既定にする。`filled` はダークで背景色に `.dark`、
    文字色を `.main` から算出する MUI の実装のため、緑地に黒文字のような読みにくい
    組み合わせになる。`standard` は両モード向けに設計されており、実測でも
    ライト 9.8:1 / ダーク 14.35:1 のコントラストが得られる
  - 機能カードのアイコン背景は `FEATURE_COLORS` に定義し、白いアイコンとの対比が
    3:1 以上になる濃さにする。Avatar の既定文字色は背景色に追随して暗くなるため、
    アイコン色は白を明示する
  - 文字と背景のコントラストは通常の文字で 4.5:1 以上、大きい文字とアイコンで 3:1 以上を満たすこと
- D&D は Electron の `webUtils.getPathForFile` を preload 経由で使用してファイルパスを取得する
  (`File.path` は使用不可)
- 進捗ダイアログ (`components/common/ProgressDialog.tsx`) は全機能で共用する。
  受け取る項目は、進捗バー (`percent` / `showProgressBar`)、件数 (`current` / `total`)、
  短い状況一行 (`status`)、現在の処理対象 (`message`)、開閉して見せる詳細行 (`details`)
  - **完了予測ができない処理では `showProgressBar={false}` にして進捗バーを出さない**。
    総数が分からないまま不確定バーを出しても何も伝わらないため (クリーンアップの検索)
  - `message` の欄は**常に固定の行数を確保**する。処理対象が変わるたびに高さが動くと
    ちらつくため。必要な行数は用途で違うので `messageLines` で渡す
    (既定 1 行。フルパスのような長文を出す画面だけ 2 を指定する)
  - `details` を渡すと「詳細を表示 / 詳細を隠す」ボタンがキャンセルと同じ行の左端に出る。
    閉じている間は場所を取らない。開いた領域は**行数 (= 並列数) に応じた高さで固定**し、
    折り返さずに枠の中で縦横スクロールさせる (パスを 1 行で通して読めるようにするため)。
    横スクロールバーの高さを見込まないと最終行が隠れるので、その分を加えて高さを決める
  - 余白: アクション行があるときは本文の下余白を詰める (アクション行が持つ余白と合わせる)。
    **ボタンが 1 つも無い画面 (SVG 変換、チャプター解析中) ではアクション行自体が出ない**ため、
    本文の下余白は既定のまま残す
