# Kura Toolkit システム仕様

## 1. 概要

Kura Toolkit は、以下のツールを 1 つにまとめた Electron 製デスクトップアプリケーション。

| カテゴリ | 機能 | 主に使う外部のツール・ライブラリ |
|---|---|---|
| オーディオ | オーディオ正規化 | ffmpeg / ffprobe (7 章) |
| オーディオ | 音声分離 | audio-separator と UVR のモデル (14 章) |
| オーディオ | 音声変換 (声のモデルの学習を含む) | Applio / RVC (15 章) |
| オーディオ | 読み上げ (声のモデルの学習を含む) | Style-Bert-VITS2 の派生版 (16 章) |
| 動画 | チャプターカット | ffmpeg / ffprobe (8 章) |
| 画像 | SVG 変換 | @neplex/vectorizer (VTracer。9 章) |
| ツール | クリーンアップ | なし (10 章) |

音声機能が使う Python・パッケージ一式・モデルの取得と削除 (13.3) は、各音声機能の画面と不足の案内から
呼び出すダイアログで行う (13.14)。

音声分離・音声変換・読み上げの仕様は 13〜16 章に記す (主な設計上の判断とその理由は 13.13)。

## 2. アーキテクチャ

- Electron (main: CommonJS/tsc、renderer: React + MUI + Vite)
- renderer は HashRouter によるページ遷移 (開発時・配布時とも同一)
- main プロセスは `src/main/services/` に機能実装、`src/main/ipc/` に IPC ハンドラを配置
- preload (`src/preload/index.ts`) が `window.kuraToolkit` として型付き API を公開
- `src/main/` から `src/renderer/` の import は禁止 (i18n は renderer 専用)。main はエラーコード
  (`FFMPEG_NOT_FOUND` など) を返し、renderer 側で翻訳する
- 音声機能 (分離・変換・読み上げ) の推論と学習は、利用者の指示でダウンロードした Python の仮想環境上の
  補助プロセスで行う (13 章)。Python 本体・ライブラリ・モデルはアプリに同梱しない
- アプリは 1 つしか起動しない (`app.requestSingleInstanceLock`)。2 つ目を起動すると、起動中のウィンドウを前面に出して
  (最小化していれば元に戻して) 終わる。ライブラリ・モデル・作業ディレクトリ (3 章「保存場所」) を複数のアプリが
  同時に書き換えないため

## 3. 設定の永続化

- 保存先: `~/.kura_toolkit/settings.json`
- main プロセスの `services/settings.ts` が管理。読み込み時に既定値と deep-merge して欠損キーを補完し、
  書き込みは一時ファイルへ書いてから rename するアトミック方式
- 設定ファイルが無い場合は、初回の起動として既定値で始める。ファイルがあるのに読めない・JSON として解釈できない・
  オブジェクトでない場合は、ファイルを上書きしない (既定の設定で上書きすると、利用者の設定が失われるため)
  - 起動中は既定の設定をメモリ上で使い、設定ファイルへの書き込みは断る (`SETTINGS_FILE_UNREADABLE`)
  - 起動時はほかの画面を出さず、確認 (`components/settings/SettingsLoadErrorDialog.tsx`) だけを出す
    (既定の設定のまま各機能が動き出さないようにするため)。ファイルの場所と読めなかった理由を示し、次のどちらかを選ばせる
    - 既定の設定で続ける: 読めなかったファイルを同じフォルダに `settings.broken-<YYYYMMDD-HHmmss>.json` の名前で残し、
      既定の設定を保存する (`settings:resetBroken`)。残した場所は通知で示す
    - 終了する: ファイルには触れずにアプリを終了する
- スキーマ (バージョン 1):

```jsonc
{
  "version": 1,
  "app": { "theme": "system | light | dark", "language": "ja | en" },
  "ffmpeg": { "ffmpegPath": "", "ffprobePath": "" },       // 空文字 = PATH から自動検出
  "search": { "threads": 4 },  // ファイル探索に使うスレッド数 (初回起動時に決めて保存する)
  "storage": {                   // 保存場所 (下記「保存場所」)。空文字 = 既定の場所
    "libraryDir": "",            // ライブラリディレクトリ
    "modelDir": "",              // モデルディレクトリ
    "workDir": ""                // 作業ディレクトリ (選んだフォルダをそのまま使う)
  },
  "audioNormalizer": {
    "outputDir": "", "targetLufs": -13, "sampleRate": 44100,
    "bitrateMode": "cbr | vbr", "bitrate": 160
  },
  "cleanup": {
    "customDirs": [],            // ユーザーが追加した検索対象ディレクトリ
    "selectedTargets": [],       // 前回検索したときのクリーンアップ対象
    "selectedRoots": []          // 前回検索したときの検索対象ディレクトリ
  },
  "voice": {
    "export": {                  // 分離・変換・読み上げの書き出しで共用 (13.8)
      "format": "mp3 | flac", "sampleRate": 44100, "bitrateMode": "cbr | vbr", "bitrate": 160
    },
    "symbolReadings": { "ja": null, "en": null },         // 記号の読み。null = 言語定義の初期値
    "updatePromptVersion": ""    // 更新の確認を出したアプリの版 (同じ版では 1 回だけ確認する)
  }
}
```

- `search.threads` (探索のスレッド数) は常に実数値を保存する
  - 初回起動時 (設定ファイルが無い、または値が未決定) にだけ
    `max(1, min(4, floor(論理コア数 / 2)))` を算出して保存する。既に値があるときは触らない
  - 設定画面での制限は **1 以上 100 以下**のみ。起動時に決める上限 4 は初期値のためのもので、
    実行時には適用しない
  - ディレクトリを走査する処理 (クリーンアップの検索) はこの値を上限とする
- 保存タイミングは項目の性質で分ける
  - アプリ設定 (テーマ・言語・ffmpeg のパス・探索のスレッド数)・クリーンアップのカスタムディレクトリ: UI 変更時に即時保存
  - 各機能の実行パラメータ (オーディオ正規化の出力設定・クリーンアップの検索条件):
    **その機能を実行したときに、保存済みの値と異なる場合だけ**書き込む。
    入力途中の値をファイルへ書かないため、1 文字打つたびの保存が発生しない
  - チャプターカットと画像 SVG 変換のパラメータ: 保存しない (下記 8 章・9 章)。
    値は zustand ストア上のみで保持し、アプリを起動するたびに既定値へ戻る
  - 保存場所: 作業ディレクトリは変えた時点で、ライブラリ・モデルディレクトリは移動が完了したときに書き込む
  - 音声機能: 書き出しの設定 (形式・サンプリング周波数・ビットレートモード・ビットレート) は変えた時点で保存する。
    記号の読みは編集ダイアログで保存したときに書き込む。分離・変換・読み上げの実行パラメーターは保存せず
    (プリセットは 13.10)、zustand ストア上のみで保持する

### 保存場所 (`services/storage.ts` / `services/work-dir.ts` / `components/settings/StorageSection.tsx`)

アプリ全体で共有する 3 つの場所。それぞれ独立して変更する (1 つを変えても他は動かない)。
設定が空なら既定の場所を使い、既定の場所は設定ファイルに書き込まない。設定画面の「保存場所」で変更する。

| 場所 | 既定 | 中身 | 変えたとき |
|---|---|---|---|
| ライブラリディレクトリ | `~/.kura_toolkit/libraries` | 外部のライブラリ (Python 本体と、ライブラリごとの仮想環境・ソース一式・キャッシュ)。ライブラリごとのディレクトリに分け、今後のライブラリもこの下に追加する | 中身を選んだフォルダへ移動し、そのフォルダをライブラリディレクトリにする |
| モデルディレクトリ | `~/.kura_toolkit/models` | ダウンロードしたモデルと、学習・取り込みしたモデル。分類 (`audio` など) の階層を挟み、ほかの種類のモデルもこの下に追加する | 中身を選んだフォルダへ移動し、そのフォルダをモデルディレクトリにする |
| 作業ディレクトリ | `<OS の一時ディレクトリ>/kura_toolkit` | 全機能の一時ファイル (その処理の中で作って使い、消すものだけ) | 選んだフォルダを以後の作業ディレクトリにする (移動はしない) |

- 選んだフォルダを、そのままその保存場所として使う (中にフォルダを挟まない)
- 移動と既定の場所に戻す操作は、ライブラリとモデルのそれぞれで行う (13.2)。既定の場所へ戻した場合は設定を空にする。
  既定の場所に戻す操作は、誤って押さないよう各項目のメニューに置く
- Windows では、設定したパスに ASCII 以外の文字が含まれる場合に注意を出す (C で書かれた一部のライブラリが、Windows で
  ASCII 以外のパスを開けないため)。設定画面の各項目と、ダウンロードの画面 (`storageNonAscii`) に出す
- 保存場所の設定 (ライブラリ・モデル・作業ディレクトリ) は `saveSettings` で書き込む。先にファイルへ書き、書けた場合だけ
  起動中の設定を変える。書けなければ `SETTINGS_SAVE_FAILED` で失敗させ、起動中の設定も元の場所のまま保つ
  (保存できないまま起動中だけ新しい場所を使うと、次の起動で元の場所を使い、起動中に新しい場所へ置いたものを見失うため)
- 保存場所どうしは重ねられない (同じ場所・一方がもう一方の中。`STORAGE_OVERLAP`)
- 設定ファイルと音声機能のプリセットは `~/.kura_toolkit/` に置く。Electron が管理する状態 (キャッシュなど) だけを
  Electron の既定の場所 (userData) に置き、設定・ライブラリ・モデルとは分ける
- 作業ディレクトリ
  - 既定の場所 (`<OS の一時ディレクトリ>/kura_toolkit`) は、必要になった時点でアプリが作り、空になったら消す
  - 選べるのは空のフォルダだけ (既定の場所に戻す場合を除く。`STORAGE_TARGET_NOT_EMPTY`。アプリのファイルと
    他のファイルを混ぜないため)。ライブラリ・モデルディレクトリと重なる場所は選べない (`STORAGE_OVERLAP`)
  - 選んだフォルダが無くなっている場合 (ドライブの取り外し・名前の変更など) は、作らずに処理を止める
    (`WORK_DIR_MISSING`。利用者の知らない場所にフォルダを作らないため)。画面はアプリ設定の「保存場所」の確認を案内する。
    作業ディレクトリを変えるときも、選んだフォルダが無ければ `WORK_DIR_MISSING` で断り、読めない (権限が無いなど)
    場合はその理由のエラーで断る (空かどうかを確かめられないため)
  - 変更は、処理中 (実行中のジョブがある間) と、今の作業ディレクトリにアプリのフォルダ (下表) が残っている間
    (作業の結果があるときなど) は断る (`WORK_DIR_IN_USE`。前の場所に残ったものを後から消せなくなるため)。
    変更の前に、待機中の常駐の補助プロセス (作業ディレクトリに一時ファイルの置き場を持ち続ける) を止めて終了を待ち、
    削除中の一時ファイルが消えるのを待つ。設定を保存できなければ失敗とし (`SETTINGS_SAVE_FAILED`)、元の場所を使い続ける
- 作業ディレクトリに置くのは、その処理の中で作って使い、消すもの (中間ファイル・外部のプロセスの作業場所など) だけ。
  最終的に別の場所へ置くもの (ダウンロードしたファイル・展開する書庫・pip のキャッシュ) は、置き場所が別のドライブの
  場合にコピーと削除が発生しないよう、置き場所と同じディスクに直接書く (13.3)。アプリが作業ディレクトリの中に作るのは、
  次の 4 つのフォルダだけ

| 場所 | 内容 | 消すタイミング |
|---|---|---|
| `session/<作業キー>/` | 作業の結果 (音声機能の入力を変換した WAV・候補・重ねた音・合成結果) | 候補・作業を破棄した時点。作りかけの候補は失敗・キャンセルした時点 (13.6) |
| `jobs/<ID>/`・`jobs/<名前>-<ID>/` | 1 回の処理の一時ファイル (音声機能の中間ファイル・学習の指示ファイルと学習の途中のデータ・pip の要件ファイル・チャプターカットの一時ファイル) | 処理の完了・エラー・キャンセルのいずれでも、その時点 |
| `tmp/<ID>/` | 外部のプロセス 1 つ分の一時ファイル (`TEMP` / `TMP` / `TMPDIR` の向け先。プロセスごとに作る) | そのプロセスが終了した時点 |
| `recordings/<種類>/` | 学習用の録音 (15.6・16.7) | 学習が終わった時点 (成功・エラー・キャンセル) と、録音を一覧から外した・差し替えた時点 |

- すべて必要になった時点で作り、不要になった時点で消す (`removeTemp`)。消した結果空になったフォルダも、
  作業ディレクトリの手前までその場で消す (作業ディレクトリ自体は、既定の場所の場合だけ空になったら消す)。
  終了したばかりのプロセスがファイルを掴んでいる場合 (Windows) に備えて、少し待ちながら再試行する
- アプリの終了時には消さない (終了を待たせないため)。終了時に残っていたもの (作業の結果・録音) と強制終了で
  残ったものは、次の起動時に消す (`removeLeftoverWorkFiles`)
  - アプリは 1 つしか起動しないため (2 章)、起動時に作業ディレクトリにある上表の 4 つのフォルダは、
    すべて前回の残り物になる
  - 4 つのフォルダは、新しい処理が同じ名前で使い始める前に、その場で `.leftover-<ID>` へ名前を変えて分ける。
    削除は起動を待たせずに裏で行う。片付けの途中でアプリが終了して残った `.leftover-*` も、同じく裏で消す

## 4. IPC チャンネル一覧

チャンネル定数は `src/shared/constants.ts` の `IPC_CHANNELS` に定義
(preload にはランタイム import 回避のためローカルコピーあり。追加時は両方を更新すること)。

| チャンネル | 方向 | 内容 |
|---|---|---|
| `app:getInfo` / `app:setTheme` / `app:setLanguage` / `app:quit` | invoke | アプリ情報・テーマ・言語・終了 |
| `window:minimize` / `window:maximizeOrRestore` / `window:isMaximized` / `window:close` | invoke | ウィンドウ制御 |
| `settings:get` / `settings:update` | invoke | 設定の取得・部分更新 |
| `settings:getLoadError` / `settings:resetBroken` | invoke | 設定ファイルを読み込めなかった場合の内容 (場所と理由) の取得・読み込めなかったファイルを別の名前で残して既定の設定を保存する (残した場所を返す) |
| `storage:getInfo` | invoke | 保存場所 (ライブラリ・モデル・作業ディレクトリ) の実際の場所・既定の場所・ASCII 以外を含むか (Windows のみ判定する) |
| `storage:checkMove` | invoke | 移動の確認画面を出す前に、移動先を選べるかを確かめる (移動と同じ確認。13.2) |
| `storage:move` | invoke | ライブラリ・モデルディレクトリの中身を選んだフォルダへ移動し、そのフォルダを新しい場所にする (ジョブ)。移動先なしで既定の場所へ戻す |
| `storage:setWorkDir` | invoke | 作業ディレクトリの場所の変更 (空文字で既定に戻す)。処理中と、今の作業ディレクトリに作業の結果などが残っている間は断る (`WORK_DIR_IN_USE`) |
| `ffmpeg:detect` | invoke | ffmpeg/ffprobe の解決結果 (設定値優先、空なら PATH 走査) |
| `dialog:openFiles` / `dialog:openDirectory` / `dialog:saveFile` | invoke | ネイティブダイアログ |
| `files:collect` | invoke | パス群の展開 (ディレクトリを再帰走査し拡張子で絞り込む) |
| `job:cancel` | invoke | ジョブのキャンセル |
| `job:event` | main→renderer | ジョブイベント push (progress / log / item / scan / wait) |
| `audio:analyze` / `audio:normalize` | invoke | オーディオ解析・正規化 |
| `audio:checkOutputs` | invoke | 正規化前の出力先チェック (上書きになるファイル・出力パスの重複) |

## 5. ジョブ管理 (長時間処理)

- `services/job-manager.ts` が管理。jobId は renderer が `crypto.randomUUID()` で生成し、
  開始 invoke の引数として渡す。invoke の解決 = ジョブ完了
- 進捗・ログ・発見アイテムは `job:event` チャンネルで push する
  (`JobEvent = { jobId, kind: 'progress' | 'log' | 'item' | 'scan' | 'wait', percent?, current?, total?, message?, payload?, scan?, waiting? }`)
  - `scan` はディレクトリ走査の進捗 (総数が事前に分からないため `percent` を持たず、一定間隔でまとめて送る)
  - `wait` は GPU の順番待ちの開始 (`waiting: true`) と終了 (`waiting: false`) (13.5)
- `job:cancel` で登録済み子プロセス (ffmpeg 等) を kill し、ループ系はフラグ確認で中断する。
  キャンセルは例外ではなく `{ cancelled: true }` を含む結果として返す
  - `onJobCancel(jobId, handler)` でキャンセル時の処理を登録できる (戻り値で登録を解除する)。
    音声機能は Python の補助プロセスをプロセスツリーごと終了させるのに使う
  - 音声機能の処理 (分離・変換・読み上げ・学習など) は、キャンセルを `KURA_CANCELLED` のエラーとして
    返すものがある。renderer は `components/voice/voiceErrors.ts` の `isCancelledError` で判定し、
    エラーとしては表示しない
- ウィンドウクローズ時は全ジョブを自動キャンセルする

## 6. ffmpeg 実行基盤

- `services/ffmpeg/ffmpeg.ts` / `ffprobe.ts`
- パス解決: 設定値優先。空なら PATH の各ディレクトリを `fs.access` で走査して検出
  (`where`/`which` の出力パースは文字コード依存のため行わない)。ffprobe 未設定時は
  ffmpeg と同じディレクトリを優先して探す
  - macOS / Linux では Finder やランチャーから起動すると PATH が最小限になるため、
    PATH に加えて既定のインストール先も探索する
    (macOS: `/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`、`/sw/bin`、`/usr/bin`、`/bin`。
    Linux: `/usr/local/bin`、`/usr/bin`、`/bin`、`/snap/bin`、`/var/lib/flatpak/exports/bin`)
- 実行は必ず `spawn(cmd, argsArray)` (shell 不使用) で行い、日本語パス・cp932 の引用問題を回避する
- 出力のパースは `-print_format json` と `-progress pipe:1` の機械可読出力のみに依存する
- 進捗は `-progress pipe:1 -nostats` の `out_time_us` を対象長で割って算出する
- 未検出・失敗はエラーコード付きメッセージ (`FFMPEG_NOT_FOUND` / `FFPROBE_NOT_FOUND` /
  `FFMPEG_FAILED: <stderr>` / `KURA_CANCELLED`) で表現する

## 7. オーディオ正規化 (`services/audio-normalizer.ts`)

- 解析:
  - チャンネル数: `ffprobe -show_streams` の JSON から取得
  - LUFS: `ffmpeg -i <file> -af loudnorm=I=-16:LRA=11:TP=-1.5:print_format=json -f null -` の
    stderr 末尾の JSON ブロックから `input_i` を抽出 (実測値のためターゲット値の影響は受けない)
- 正規化コマンド:
  `-af loudnorm=I={target}:LRA=11:TP=-1.5:linear=true -ar {rate} -map_metadata 0 -map 0:a:0 -map 0:v? -c:v copy -c:a {encoder} {ビットレート引数}`
  (タグとアルバムアートを保持)
- エンコーダ判定: 入力コーデック維持 (mp3→libmp3lame / aac / vorbis→libvorbis / opus→libopus /
  flac / pcm_* はそのまま)。フィルタ適用には再エンコードが必須のため、未対応コーデックはスキップして警告
- ビットレート: CBR は `-b:a {n}k`。VBR は mp3/vorbis のみ `-q:a` の品質値へ変換する
  (opus は CBR 時のみ `-vbr off`)。flac/pcm はビットレート指定なし
  - mp3 (libmp3lame): 245以上=V0 / 225以上=V1 / 190以上=V2 / 175以上=V3 / 165以上=V4 /
    130以上=V5 / 115以上=V6 / 100以上=V7 / 85以上=V8 / それ未満=V9 (LAME の各 V 設定の
    実効ビットレートに基づく)
  - vorbis (libvorbis): 320以上=q9 / 256以上=q8 / 224以上=q7 / 192以上=q6 / 160以上=q5 /
    128以上=q4 / 112以上=q3 / 96以上=q2 / 80以上=q1 / それ未満=q0
- 出力: 出力先ディレクトリ + 入力と同名。出力先が未指定の場合は入力と同じディレクトリ、
  つまり**元のファイルの上書き**になる
  - 出力は常に出力先の一時ファイル (`{名前}.kura-tmp{拡張子}`) へ書き、成功してから `rename` で正式な名前にする。
    途中で失敗・キャンセルした場合は一時ファイルだけを削除するため、上書きするはずだった既存のファイル
    (元のファイルを含む) はそのまま残る。元のファイルの上書きでは、ffmpeg が読み込み中のファイルへ直接書けないためでもある
  - 実行前チェック (`audio:checkOutputs`): 出力パスの決定規則は main が持ち、renderer は
    正規化ボタンを押した時点で結果を受け取って次のように分岐する
    - `duplicated` (複数の入力が同じ出力パスになる。別ディレクトリの同名ファイルを 1 か所へ
      出す場合) が 1 件でもあれば、**どう実行しても互いを上書きするため実行そのものを止める**
      (確認ではなく警告通知)。`normalizeFiles` 側でも開始前に `DUPLICATE_OUTPUTS` を投げる
    - `existing` (既に存在する出力パス) があれば確認ダイアログで一覧を示し、承認するまで実行しない。
      出力先が空欄のときは入力ファイル自身が必ず対象になる
    - パスの比較は Windows のみ大文字小文字を無視する (`process.platform` で切り替え)
- 入力の追加: ファイルの追加・ディレクトリの追加・ドラッグ&ドロップに対応する。
  ディレクトリはサブディレクトリまで再帰的に走査し (`files:collect`)、対象拡張子の音声ファイルだけを
  名前順に取り込む。renderer からはファイルとディレクトリを判別できないため、
  ドロップされたパスは絞り込まずに main へ渡し、展開と絞り込みは main が行う
- 出力設定 (出力先・ターゲット LUFS・サンプルレート・ビットレート) は画面内の状態として編集し、
  解析または正規化を実行したときに保存済みの値と比較して、異なる場合だけ settings へ書き込む
- 画面構成: 上のボタン列 (追加・一覧クリア)、解析/正規化ボタン、出力設定の枠は高さを固定し、
  ファイル一覧が残りの高さを埋める。行があふれた分は一覧の枠内でスクロールする
  (見出し行は `stickyHeader` で残す)。ウィンドウが低くて全体が収まらない場合は
  一覧を最低 180px 確保したうえでページ側がスクロールする
- ファイル一覧は `tableLayout: fixed` で列幅を固定する (ディレクトリ 40% / チャンネル 112px /
  LUFS 88px / 残りがファイル名)。**全ての列で折り返しを行わず、行の高さを 1 行に揃える**。
  ファイル名とディレクトリは収まらない分を末尾省略し、全文は `title` 属性 (ホバー) で確認できる
- エンコードと入力の検証の補足:
  - libmp3lame の CBR は `-b:a` の指定だけで行い、`-cbr 1` は付けない (`-cbr` は libopus 用の
    オプションで、libmp3lame では使われず「Codec AVOption cbr has not been used for any stream」の
    警告が出るだけのため)
  - サンプリング周波数の選択肢は 8000 / 11025 / 12000 / 16000 / 22050 / 24000 / 32000 / 44100 / 48000 Hz
  - VBR の品質値は、ビットレートの全選択肢を上記のとおり実効ビットレートに対応付ける
  - チャンネル数とコーデックは ffprobe の JSON 出力から判定する (stderr の文言はロケールや出力書式に
    依存するため)
  - libopus は 8000/12000/16000/24000/48000 Hz しか受け付けず、既定の 44100 Hz では必ず
    エンコードに失敗する。エンコーダが libopus のときは指定値以上で最も近い対応値へ丸めてから
    `-ar` に渡す
  - ターゲット LUFS の入力を loudnorm の有効範囲 (-70〜-5) で検証する

## 8. チャプターカット (`services/chapter/`)

動画のチャプター情報の取得 (probe)、範囲の切り出し (cut)、分割 (split) を行う。
切り出しと分割は、ストリームコピーとフレーム精度の再エンコード (accurate) のどちらでも行える:

- probe: `ffprobe -show_chapters` / `-show_streams -show_format` の JSON からチャプター・ストリーム情報を取得
  - `ChapterProbeResult.streams` に各ストリームの種別・コーデック・解像度・チャンネル数・
    サンプルレート・ビットレート・言語・タイトルを整形して含める。
    renderer は「チャプター一覧」見出しの**ファイル情報ボタン**から、この内容をダイアログで表示する
    (常時表示はせず、読み込んだ時点の解析結果をいつでも確認できるようにする)
- cut: 開始チャプター〜終了チャプター (省略時は最終) の範囲を切り出す
  - ストリームコピー時は開始点を直前の映像キーフレームへ吸着
    (`packet=pts_time,flags` を探索窓 30 秒から 4 倍ずつ拡大しながら走査)
  - accurate 時は元コーデック・ビットレート・pix_fmt を引き継いで再エンコード
    (VIDEO_ENCODERS/AUDIO_ENCODERS マップ、ビットレート不明時は crf 既定値または 64000×ch の概算)
  - 2 パス構成: pass1 で `-ss/-to` 切り出し (`-map 0 -map -0:d`、`-avoid_negative_ts make_zero`)、
    出力実測 (映像 start_time のずれ・巻き戻り) で基準を補正した FFMETADATA を生成し、
    pass2 で `-map_metadata 0 -map_chapters 1 -c copy -copyts` により埋め込み
    - 全体のメタ情報 (タイトル・作者・説明など) は入力から引き継ぎ、チャプターだけ
      FFMETADATA から取り込む。`-map_metadata 1` にすると FFMETADATA の内容で全体が
      置き換わり、元のタグが消える。分割時も各パートが同じ扱いになる
  - **実際の切り出し開始位置の実測**: `-ss` にキーフレームを指定しても、デマルチプレクサが
    さらに手前のキーフレームへ巻き戻ることがある (mkv で頻発。cue の粒度による)。
    ここを取り違えるとチャプター位置と字幕の時刻がまとめてずれるため、
    `出力の長さ` から開始位置を逆算し、内容は必ずキーフレームから始まることを利用して
    近傍のキーフレームへ吸着させる (`findNearestKeyframe`)
    - mkv はストリーム単位の長さ (`stream.duration`) を返さないため、
      コンテナ全体の長さ (`format.duration`) で代用する。この代用が無いと補正が働かない
  - **字幕とカバーアートは pass1 から必ず除外する** (`-map -0:s` と attached_pic の除外)。
    字幕には切り出し開始より前から表示され続けているパケットがあり、これを pass1 に含めると
    `-avoid_negative_ts make_zero` の基準がその古い時刻になり、映像・音声を含む全体の時刻が
    ずれる (出力の先頭が 0 秒にならず、字幕トラックだけが数十秒前方にずれて再生時に表示されない)。
    カバーアートも同じ理由で除外する (mp4 の attached_pic は pts=0 のため基準を 0 に固定してしまう)
  - 字幕は範囲ごとに個別のファイルへ切り出し、pass2 で入力として合流させる
    - テキスト字幕 (srt/ass/ssa/vtt): 単体抽出して TS 側で時刻を再構成する
      (`shiftTextSubtitles`。範囲外のイベントは捨て、開始をまたぐものは 0 に丸める)
    - **VOBSUB (dvd_subtitle) で表示領域の大きさを持たない場合** (mp4 に格納されたものは
      コンテナ側にしか大きさが無い): そのまま取り出すと大きさが失われ、再生時に
      既定の 720x480 として拡大されて**巨大化・色化け**する (VLC) か、**表示されない** (MPC)。
      この場合は映像と同じ大きさを `-canvas_size` に与えて同一コーデックで作り直し、
      字幕自身に大きさを持たせる。再エンコード時は時刻が元のまま残るため
      `-output_ts_offset` で切り出し開始を 0 に揃える
    - それ以外 (PGS・mov_text 等): `-copyts` + 入力側/出力側の `-ss` で範囲を切り出す
      (出力側 `-ss` により切り出し開始前のパケットが落ちる。字幕はフレーム間の依存が無いため
      映像と違って途中から切り出しても問題ない)。pass1 の実測とのずれは pass2 の
      `-itsoffset` で吸収する
    - pass2 では `-map {n}:s` で字幕だけを取り込む (一時ファイルにも mp4 のチャプター用
      トラックが付くため)。言語・タイトルのタグと既定/強制フラグ (`-disposition:s:N`) を
      元ストリームから引き継ぐ。指定しないと ffmpeg が入力ごとに既定フラグを立て、
      既定の字幕が複数ある状態になってプレイヤーの選択が変わってしまう
  - 出力名: `{入力ベース名}-{fromラベル}-{toラベル}{拡張子}` (ラベルはタイトル優先、
    Windows 禁止文字をサニタイズ)。出力先は指定ディレクトリまたは入力と同じ場所
  - **ビットマップ字幕 (VOBSUB / PGS 等) がある場合、mp4 系の指定でも mkv で書き出す**
    (`resolveSubtitleFriendlyOutput`)。理由は次のとおりで、拡張子を変えた場合はログに残す
    - PGS は mp4 に格納できない
    - VOBSUB は mp4 だと表示領域の大きさとパレットを ffmpeg が元の形で書けず、
      VLC で巨大化・緑色化する (MPC は問題なし)。元ファイルは正常に再生できるため、
      ffmpeg が書く mp4 の字幕サンプル記述を VLC が解釈できないことが原因。
      mkv では両プレイヤーとも正常に表示できる
  - 切り出しモードでは出力ファイル**名**を明示指定でき、指定時は自動命名より
    優先される。**出力先は常に出力先ディレクトリで決まり、ファイル名側には出力先を持たせない**
    (出力先の指定が 2 か所に分かれるのを避けるため)
    - renderer: ファイル名の入力欄はテキスト入力のみ (ファイル保存ダイアログは使わない)。
      パスを貼り付けるなどしてディレクトリ部が混ざった場合は、その部分を出力先ディレクトリ欄へ移し、
      ファイル名欄には最後の要素だけを残す
    - main (`naming.ts` の `namedOutputPath`): 受け取った名前も `path.basename` で最後の要素だけを使い、
      禁止文字をサニタイズする。拡張子が無い場合は ffmpeg が出力形式を決められないため、
      入力と同じ拡張子を補う
- split: 指定チャプター群の直前を分割点として複数範囲に分割し、各範囲を cut と同一処理で出力。
  出力名の重複は処理前に検出してエラー (`DUPLICATE_OUTPUTS`)
- 出力先の決定 (範囲の算出と出力名の生成) は `planCut` / `planSplit` に集約し、実行前チェックと
  本処理の両方から同じ関数を使う。規則が 2 か所に分かれて食い違うのを防ぐため
- 実行前チェック (`chapter:checkCut` / `chapter:checkSplit`): 生成される出力パスと、そのうち
  既に存在するものを返す。renderer は実行ボタンを押した時点で呼び出し、既存ファイルがあれば
  一覧付きの確認ダイアログを出して、承認するまで実行しない
- 一時ファイル (pass1 の出力・切り出した字幕・カバーアート・チャプター情報) は作業ディレクトリの
  `jobs/chapter-<ID>/` に置き、成否・キャンセルを問わず範囲ごとの処理の終わりに消す (3 章「保存場所」)。
  出力先に書くのは出力のファイルだけ (書き終えるまでは下記の一時的な名前)
- 出力は pass2 で出力先の一時ファイル (`{名前}.kura-tmp{拡張子}`) へ書き、成功してから正式な名前にする
  (`produceFile`)。失敗・キャンセルした場合は一時ファイルだけを消すため、上書きするはずだった既存のファイルはそのまま残る
- renderer からは、チャプターを配列の添字で指定する (利用者はチャプター一覧の UI で選ぶ)
- 画面構成: ファイルを読み込むまではドロップ領域がページ全体の高さを占める。読み込み後は
  上部の細いバー (高さ 72px、読み込み中のファイルパスを表示) に切り替わり、
  チャプター一覧が残りの高さを埋めて、あふれた行は一覧の枠内でスクロールする
  (見出し行は `stickyHeader` で残す)
  - 一覧の枠は `Panel` 自身をスクロール枠にする。`TableContainer` の `component={Panel}` は
    使わない。MUI は `sx` を className に変換して渡すが `Panel` は className を受け取らないため、
    レイアウト指定 (flex・overflow) が全て捨てられてページ全体がスクロールしてしまう
- **設定は一切保存しない**。出力先ディレクトリ・フレーム単位で正確に切り出す・出力ファイル名・
  モード・チャプターの選択はすべて `stores/chapterStore.ts` の状態として保持し、
  アプリを起動するたびに既定値 (出力先は空文字 = 入力と同じディレクトリ、accurate は false) へ戻る。
  出力先と accurate は入力ファイルを変えても引き継ぎ、出力ファイル名は入力ごとに破棄する
- エラーコード: `NO_CHAPTERS` / `INVALID_RANGE` / `NO_SPLIT_POINT` / `DUPLICATE_OUTPUTS` / `OUTPUT_EQUALS_INPUT` /
  `WORK_DIR_MISSING` (選んだ作業ディレクトリが無い。3 章「保存場所」)

## 9. 画像 SVG 変換 (`services/vectorizer.ts`)

- `@neplex/vectorizer` (vtracer の NAPI バインディング、非同期 API) を使用。外部プロセスなし
- パラメータは vtracer と同一 (colorMode / hierarchical / filterSpeckle / colorPrecision /
  layerDifference / mode / cornerThreshold / lengthThreshold / spliceThreshold、maxIterations=10 固定)
- **パラメータは settings.json へ保存しない**。既定値は `stores/vectorizerStore.ts` の
  `DEFAULT_VECTORIZE_PARAMS` に持ち、値は画像・変換結果と同じくストア上のみで保持する。
  そのためアプリを起動するたびに既定値へ戻る (画面を行き来しただけでは戻らない)
- 入力: png / jpg / jpeg / bmp / gif / tiff。プレビューは main が dataURL を返し、
  SVG プレビューは renderer 側で Blob URL の img として表示
- 画面構成: 左が元画像と SVG プレビューの上下 2 分割、右が変換パラメータ (幅 320px 固定)
  - 上下の仕切りは `SplitPane` でドラッグして高さを配分できる (初期は 1:1、上下とも最低 15%)。
    配分は保存せず、画面を開き直すと 1:1 に戻る
  - SVG プレビューは `ZoomableImage` で拡大縮小できる。見出しの右にズーム操作
    (縮小・現在の倍率 = クリックで実寸・拡大・全体表示) を置く。Ctrl + ホイールでも拡大縮小し、
    枠からはみ出しているときはドラッグで表示位置を動かせる
  - 倍率は SVG の実寸 (svg 要素の width/height) に対する比率。全体表示では枠に収まる倍率で表示し、
    実寸より大きくは拡大しない。変換し直すと全体表示に戻る
- ネイティブモジュールのため electron-builder の `asarUnpack` に `**/node_modules/@neplex/**` を指定

## 10. クリーンアップ (`services/cleanup.ts` / `cleanup-targets.ts` / `dir-walker.ts`)

- 対象 11 種。**対象の一覧は OS によらず共通**で、
  プラットフォームごとに項目が増減することはない。OS による差があるのは Zone.Identifier の
  検出方法のみ (下記):
  - `Zone.Identifier` — 現れ方がプラットフォームで異なるため 2 通りの検出を行う (対象自体は全環境で利用可能)
    - Windows: NTFS の代替データストリーム。`path + ':Zone.Identifier'` の有無で検出し (判定方法は下記)、
      削除は `fs.unlink` (ゴミ箱へは移動できないため。本体ファイルは残る)。
      ファイルごとに判定するため、この判定は Windows でのみ実行する
    - Windows 以外: Windows からコピーしたり書庫を解凍すると、ADS を保持できないファイルシステム上では
      `元のファイル名:Zone.Identifier` という通常のファイルとして現れる。ファイル名がこの接尾辞で
      終わるものを検出し、通常のファイルとしてゴミ箱へ移動する。
      Windows のファイル名に `:` は使えないため、この判定は全環境で実行しても誤検出しない
      (`Zone.Identifier` 単体や `x:Zone.Identifier.bak` のような名前は対象外)
  - ファイル名完全一致: `Thumbs.db` / `.DS_Store`
  - 前方一致: `._*`
  - ディレクトリ名完全一致: `.AppleDouble` / `.fseventsd` / `.Spotlight-V100` / `.AppleDB` /
    `.AppleDesktop` / `.TemporaryItems` / `Network Trash Folder`
- 検索対象: ホームディレクトリ + ドライブ/ボリューム列挙 + カスタムディレクトリ (settings に保存)
  - Windows: WMI (`Get-CimInstance Win32_LogicalDisk` を PowerShell 経由で JSON 取得、
    対象フィールドは ASCII のみ) の `DriveType` を使用し、CD/DVD 等の光学ドライブ (DriveType=5) は
    書き込み不可のため列挙から除外する。リムーバブル (2) は「(USB)」、ネットワーク (4) は「(NW)」を
    ラベルに付与。メディアの入っていないリムーバブルスロットはアクセス確認で除外。
    WMI が使えない環境では A:-Z: の存在確認 (`fs.stat`) によるフォールバック列挙 (種別判定なし)
  - macOS: `/Volumes` 配下のマウントポイントを列挙。Linux: `/media`、`/media/<user>`、
    `/run/media/<user>`、`/mnt` を列挙。いずれも `fs.access(W_OK)` で書き込み権限を確認し、
    光学メディアや読み取り専用のディスクイメージを除外する (権限の確認のみで書き込みは行わない)。
    容量は `fs.statfs` で取得
- 除外 (ディレクトリ名で判定、大文字小文字無視。プラットフォームごとに切り替え):
  - Windows: `Program Files` / `Program Files (x86)` / `Windows` / `AppData` / `ProgramData` /
    `Recovery` / `$Recycle.Bin` / `System Volume Information`
  - macOS: `Library` (巨大で走査が長時間化するため) / `Applications` / `System` / `private` /
    `.Trash` / `.DocumentRevisions-V100` / `.MobileBackups` / `.PKInstallSandboxManager*`。
    加えて `.app` で終わるディレクトリ (アプリケーションバンドル) は署名を壊さないため走査しない
  - Linux: `proc` / `sys` / `dev` / `run` / `boot` / `lost+found` / `.Trash` / `.Trash-1000`
- 走査 (`services/dir-walker.ts` + `workers/dir-walker-worker.ts`): 反復 (スタック) 方式、
  シンボリックリンクは辿らない、アクセス不可はスキップ。対象ディレクトリにマッチした場合は配下を走査しない。
  判定そのもの (対象の定義とディレクトリ 1 個ぶんの走査) は `services/cleanup-targets.ts` にある。
  **ワーカーから読み込むモジュールは electron に依存させない** (ワーカーからは electron を使えない)
  - **`worker_threads` で並列化する**。スレッド数は `search.threads`。1 のときはワーカーを起こさず
    同一プロセスで走査し、ワーカーの起動に失敗した場合も同じ経路へ落として必ず動くようにする
    (そのときは黙って遅くならないよう警告をコンソールへ出す)
  - **asar 内のファイルはそのまま Worker のエントリにできる**ため、`asarUnpack` での展開も
    `app.asar.unpacked` へのパス置換も不要 (Electron 43 の配布ビルドで、asar 内のワーカーが
    起動して走査まで完了することを実測で確認済み)。ワーカー内の `require` も asar 内で解決される
  - ワーカー内では**同期 fs (`readdirSync` / `statSync`) を使う**。ワーカーのイベントループは
    塞いでよく、非同期版の libuv ディスパッチ往復を丸ごと省けるため
  - 作業単位は「ディレクトリ 1 個」と「ADS 判定だけを行うファイル群 (512 件単位)」の 2 種類。
    **ADS 判定をディレクトリから切り離せるようにしているのは、ファイルが数万ある単一ディレクトリが
    1 スレッドに固定されて並列化が効かなくなるため** (実測: 全体の 6 割のファイルが 1 ディレクトリに
    集中したツリーでは、切り離さないと 8 スレッドでも 1.3 倍にしかならない)
  - **ワーカーが 1 つでも落ちた場合は、逐次走査でやり直す**。落ちたワーカーに渡してあった分は
    取り戻せず結果が欠けるため、検出漏れを黙って返さないようにする
  - ワーカーは受け取ったディレクトリを起点に自分のローカルキューで再帰し、
    **手が空いたワーカーがいるときだけ**キューを分けて親へ返す (spill)。
    1 ディレクトリごとに親と往復すると、走査そのものよりメッセージの往復が高くつくため。
    手が空いたワーカーの数は `SharedArrayBuffer` 上のカウンタで共有する
  - 走査を始める前に、main 側でルートの浅い階層 (最大 2 階層) だけを展開してから配る。
    序盤に 1 スレッドしか動けない状態を避けるため
  - キャンセルは `SharedArrayBuffer` 上のフラグを `Atomics` で共有し、メッセージの往復を待たずに
    全ワーカーへ伝える (実測で要求から復帰まで 15 ms 以内)
- ADS (Zone.Identifier) の判定は `fs.statSync(path + ':Zone.Identifier', { throwIfNoEntry: false })`
  を使う。存在しないときでも例外も Promise も生成しないため、**1 件あたり 15us** で判定でき
  (`fs.open` では 43us)、走査ファイル数ぶん効く
  - **ディレクトリ一覧から ADS の有無を知る手段は Windows に無い**ため、ファイルごとの判定は避けられない。
    ディレクトリ列挙が返す `FILE_ATTRIBUTE_*` に ADS の有無を示すビットは無く、
    ストリーム列挙 API (`FindFirstStreamW` 等) はファイル単位。MFT の直読みは管理者権限が必要。
    `dir /r` は一覧に ADS を混ぜて出せるが、内部は結局ファイル単位のストリーム列挙で `statSync` より遅い
  - **ボリューム単位で判定を省くこともできない**。`Win32_LogicalDisk.FileSystem` も
    `GetVolumeInformation` の `FILE_NAMED_STREAMS` も `::$DATA` プローブも当てにならず、
    FAT32 かつ名前付きストリーム非対応と申告しながら実際には ADS を保持するクラウドドライブ
    (Google ドライブ) が存在する
- 進捗: 検索済みディレクトリ数・発見件数・スレッドごとの現在位置を、
  **150 ms ごとにまとめて** `job:event (kind='scan')` で push する。
  総ディレクトリ数が事前に分からず完了予測できないため進捗バーは出さない
  (画面側の見せ方は「11. UI 構成」の進捗ダイアログを参照)。
  削除は総数が分かるため、確定バーと `n / m` を出す
- 削除: 通常のファイル/ディレクトリは `shell.trashItem` でゴミ箱へ移動。
  Windows の ADS (`kind: 'ads'`) のみ `fs.unlink` で直接削除する
- 削除後は失敗項目のみ一覧に残し、再検索を選択できる
- 検索対象ディレクトリの並びは、ユーザープロファイル / ボリューム / カスタム の 3 区分にする
  - ボリュームとカスタムは見出し自体がチェックボックスになっており、配下をまとめて切り替えられる。
    一部だけ選択されている場合は中間状態で表示する
  - 実際に検索へ渡すのは配下の項目 (葉) のパスのみで、見出しは操作用の要素として扱う
  - ボリュームは列挙結果が 1 件以上あるときだけ表示する。カスタムは「ディレクトリを追加...」の
    置き場として、項目が無くても常に表示する
  - 見出しのチェックが全選択の役割を果たすため、検索対象側に「全てチェック」ボタンは置かない
    (クリーンアップ対象は区分が無く 11 項目あるため、そちらには置く)
- 画面構成: クリーンアップ対象と検索対象ディレクトリの枠は内容の高さに合わせて広がり内部スクロールを持たない。
  結果一覧が残りの高さを埋め、あふれた分はその枠内でスクロールする。
  全体が画面に収まらない場合はページ側でスクロールする
- 検索して対象が 0 件だった場合は、閉じるまで残るダイアログで通知する
  (一瞬で消える通知では見落とされるため)
- 検索条件 (クリーンアップ対象と検索対象ディレクトリ) の保存と復元:
  - 検索を実行したときに、保存済みの条件と異なる場合だけ settings へ書き込む
    (並び順の違いは同一とみなし、同じ条件での再検索では書き込まない)
  - 起動後の最初の 1 回だけ設定から復元する。画面を行き来しただけでは
    選択が巻き戻らないようにするため、ストア側で復元済みかどうかを持つ
  - 取り外したドライブなど一覧に無くなった検索対象は、一覧の読み込み後に選択から外す
    (画面に出ていない対象が検索に渡らないようにするため)
- macOS の権限 (フルディスクアクセス):
  - アプリはサンドボックス外のため、デスクトップ・書類・ダウンロード・外部/ネットワークボリューム
    へのアクセスは entitlements ではなく TCC に従う。未許可の場合 `readdir` は EPERM となり
    静かにスキップされてしまうため、`cleanup:getCapabilities` で権限を判定して画面上部に案内を表示する
  - 判定は TCC 保護領域 (`~/Library/Application Support/com.apple.TCC`、`~/Library/Safari`) の
    読み取り可否で行う (副作用のない読み取りのみ)。判定できない場合は誤った警告を避けるため許可済み扱い
  - 案内には「システム設定を開く」(`x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`)
    と「再確認」ボタンを置く。許可の反映にはアプリの再起動が必要な旨も文言に含める
  - TCC ダイアログに表示される利用目的は `electron-builder.yml` の `mac.extendInfo`
    (`NSDesktopFolderUsageDescription` など) で定義する。未定義だとダイアログが出ずに拒否される場合がある

## 11. UI 構成

- カスタムタイトルバー (`components/TitleBar.tsx`): アプリ名+バージョン+**現在の画面名** /
  ダッシュボードアイコン / カテゴリドロップダウン (オーディオ・動画・画像・ツール) / 設定ギア /
  ハンバーガーメニュー (全ページ + アプリ設定 + 終了) / ウィンドウ制御ボタン
  - 画面名は `navigation/features.ts` の `titleKeyForRoute()` で現在のルートから解決する。
    **各ページ側には画面タイトルの見出しを置かない** (タイトルバーに集約する)。
    画面名は現在地を示す主要な情報のため、通常の文字色で表示する
- ルート: `/` (ダッシュボード)、`/audio/normalizer`、`/audio/separation`、`/audio/conversion`、
  `/audio/tts`、`/video/chapter-cut`、`/image/svg-converter`、`/tools/cleanup`、`/settings`
  - 音声変換・読み上げの中で切り替える画面 (メニューには出さず、機能の画面上端の切り替えから開く):
    `/audio/conversion/models`、`/audio/conversion/training`、`/audio/tts/models`、`/audio/tts/training`。
    画面名は機能の名前とし (`navigation/features.ts` の `SUB_ROUTE_TITLES`)、どの画面かは切り替えの表示で示す (13.14)
- 機能一覧は `renderer/navigation/features.ts` のレジストリで一元管理し、
  タイトルバーのメニューとダッシュボードのカードが共用する
- ダッシュボードはカテゴリごとのセクションを `repeat(auto-fit, minmax(250px, 1fr))` のグリッドで
  横並びに配置し、幅が足りなければ折り返す
- 全画面で余白・字送りを揃えるため、以下の共通部品を使う (`components/common/`)
  - `PageContainer`: ページ枠。余白 `p: 3`、要素間 `gap: 2`、`minHeight: 100%`
  - `SectionLabel`: セクション見出し。`overline` 体裁 (太字・字間広め・二次色)。右端に操作ボタンを置ける
  - `Panel`: 枠線付き領域。`borderRadius: 2`、内側余白 `p: 1.5`、背景 `background.paper`
  - `AppDialog`: 画面内のダイアログは全てこれを使う。**ダイアログ外のクリックでは閉じない**
    (結果や確認を読まずに閉じてしまうのを防ぐため)。閉じる操作は Esc キーと明示的なボタンのみ
  - `SplitPane`: 上下 2 分割の領域。間の仕切りをドラッグして高さの配分を変えられる
  - `ZoomableImage`: 画像の拡大縮小表示。倍率は親が持ち (`null` = 全体表示)、
    実際に表示している倍率を親へ返す。Ctrl + ホイールで拡大縮小、はみ出し時はドラッグで移動。
    ホイールは React の `onWheel` が passive で `preventDefault` できないため直接登録している
  - `NotificationArea` (App が 1 つだけ描画): アップデート通知と画面内の一時通知を右下にまとめ、
    同時に出るときは縦に積み重ねる。一時通知は `stores/noticeStore.ts` の `showNotice()` で
    どの画面からでも出せる (各ページが個別に通知を描画すると位置が重なるため一元化している)
  - 本文・補足は `body2` を基本とし、`lineHeight` は 1.6 前後に揃える
- テーマ: ライト / ダーク / システム (MUI ThemeProvider)。言語: 日本語 / 英語 (i18next、
  `renderer/i18n/locales/ja.ts` と `en.ts`)
- 配色は `renderer/theme/index.ts` に集約する (画面側に色を直書きしない)
  - 背景: ライトは下地 `#f4f5f7` / 面 `#ffffff`、ダークは下地 `#0a0a0a` / 面 `#161616`。
    ライトで下地をわずかに灰色にしているのは、白い面 (Panel) が沈まないようにするため
  - 通知 (Alert) は `standard` を既定にする。`filled` はダークで背景色に `.dark`、
    文字色を `.main` から算出する MUI の実装のため、緑地に黒文字のような読みにくい
    組み合わせになる。`standard` は両モード向けに設計されており、実測でも
    ライト 9.8:1 / ダーク 14.35:1 のコントラストが得られる
  - 機能カードのアイコン背景は `FEATURE_COLORS` に定義し、白いアイコンとの対比が
    3:1 以上になる濃さにする。Avatar の既定文字色は背景色に追随して暗くなるため、
    アイコン色は白を明示する
  - 文字と背景のコントラストは通常の文字で 4.5:1 以上、大きい文字とアイコンで 3:1 以上を満たすこと
- D&D は Electron の `webUtils.getPathForFile` を preload 経由で使用してファイルパスを取得する
  (`File.path` は使用不可)
- 進捗ダイアログ (`components/common/ProgressDialog.tsx`) は全機能で共用する。
  受け取る項目は、進捗バー (`percent` / `showProgressBar`)、件数 (`current` / `total`)、
  短い状況一行 (`status`)、現在の処理対象 (`message`)、開閉して見せる詳細行 (`details`)
  - **完了予測ができない処理では `showProgressBar={false}` にして進捗バーを出さない**。
    総数が分からないまま不確定バーを出しても何も伝わらないため (クリーンアップの検索)
  - `message` の欄は**常に固定の行数を確保**する。処理対象が変わるたびに高さが動くと
    ちらつくため。必要な行数は用途で違うので `messageLines` で渡す
    (既定 1 行。フルパスのような長文を出す画面だけ 2 を指定する)
  - `details` を渡すと「詳細を表示 / 詳細を隠す」ボタンがキャンセルと同じ行の左端に出る。
    閉じている間は場所を取らない。開いた領域は**行数 (= 並列数) に応じた高さで固定**し、
    折り返さずに枠の中で縦横スクロールさせる (パスを 1 行で通して読めるようにするため)。
    横スクロールバーの高さを見込まないと最終行が隠れるので、その分を加えて高さを決める
  - 余白: アクション行があるときは本文の下余白を詰める (アクション行が持つ余白と合わせる)。
    **ボタンが 1 つも無い画面 (SVG 変換、チャプター解析中) ではアクション行自体が出ない**ため、
    本文の下余白は既定のまま残す

## 12. データベース

データベースは使用しない。設定と音声機能のデータは JSON ファイルで保存する。
各 JSON ファイルの項目・型・関連は `Documents/テーブル定義.md` に 1 ファイル 1 表でまとめる。

- 音声機能のデータファイル (取得の記録・声のモデルの情報・プリセットなど) が読めない・JSON として解釈できない場合は、
  そのファイルを示して失敗させる (`DATA_FILE_CORRUPT: <パス>`。空の内容として扱うと、次に書き込んだときに元の内容が
  失われるため)。無いことがあるファイル (取得の記録・プリセットなど) は、無ければ初期状態として扱う。設定ファイルの扱いは 3 章

## 13. 音声機能の共通基盤 (`services/voice/`)

音声分離 (14 章)・音声変換 (15 章)・読み上げ (16 章) が共用する仕組み。
ダウンロードの画面は `components/voice/VoiceLibraryDialog.tsx` (呼び出し方は 13.14)。

基本方針:

- 利用者の操作を妨げない。判断が必要な場面では、状況とリスクを示したうえで利用者に選ばせ、
  選んだ結果は利用者の責任とする (例: 安全な方式で読み込めないモデルの取り込み、13.9)
- 容量の大きいファイルは、従量課金の可能性を考慮し、利用者の確認なしにダウンロードしない (13.3)
- Python 本体・ライブラリ・モデルはアプリに同梱しない。同梱するのは、軽量でライセンス上同梱できる
  テキストデータ (学習用の読み上げ文) に限る
- 処理速度や待ち時間は制約としない。有料のモデルや API は使わない
- 対象の言語は他の画面と同じく日本語と英語。ffmpeg / ffprobe のパスと表示言語はアプリ設定のものを使う
- ffmpeg / ffprobe はアプリ設定 (PATH からの検出、またはパスの個別指定) で決まるものを、Python 側の処理にも使わせる (13.4)。
  Windows は winget で導入した Gyan.FFmpeg、macOS は Homebrew の ffmpeg を想定する。伴奏の移調と話速の微調整には
  rubberband フィルタを使う。すべての ffmpeg のビルドに含まれるわけではないため、フィルタの一覧から有無を調べ、
  無い場合はそれを必要とする処理を使おうとした時点で、指定中の ffmpeg では使えないことと見直し方を示す
- 分離・変換・読み上げのそれぞれで、パラメーターを変えた結果を「候補」として一覧に並べ、聞き比べて選ぶ。
  再生は、候補や再生対象を切り替えても再生位置が変わらない同期再生とする (13.7)

### 13.1 対応環境と処理装置 (`platform.ts`)

- 対応するのは **Windows (x64)** と **macOS (Apple Silicon、macOS 14 以降)** のみ。
  それ以外 (Intel Mac・Arm 版 Windows・Linux・macOS 13 以前) では、各機能の画面とダウンロード画面に
  理由を表示して機能を使えなくする (`unsupportedReason`: `os` / `arch` / `macosVersion`)
  - Intel Mac と Arm 版 Windows は、使用する PyTorch の版が配布されていないため。
    macOS 13 以前を除くのは、使用する PyTorch などが macOS 14 以降を対象としているため
- 処理装置
  - Windows: `nvidia-smi` を PATH から探して実行し、NVIDIA GPU を検出する (実行できなければ NVIDIA GPU なしとする)。
    ドライバーの版と Compute Capability (CC) から CUDA 版 PyTorch の種類を決める (`selectCudaFlavor`)

    | 条件 | 使う PyTorch |
    |---|---|
    | ドライバー 580 以上かつ CC 7.5 以上 | cu130 |
    | ドライバー 570 以上かつ CC 7.0 以上 | cu128 |
    | CC 10 未満かつドライバー 528 以上 | cu126 |
    | 上記以外・NVIDIA GPU なし | CPU 版 (GPU はあるがドライバーが古い場合はドライバーの更新を案内する) |

  - macOS: MPS を使う。未対応の演算は `PYTORCH_ENABLE_MPS_FALLBACK=1` で CPU に回して続行する
  - 分離・変換・読み上げで GPU の失敗 (CUDA・MPS のメモリ不足、CUDA・cuDNN・cuBLAS のエラー、MPS のエラー) が起きた場合は、
    補助プロセスが GPU に読み込んだものを手放してから、その要求だけを CPU で 1 回やり直す (`runtime.run_with_cpu_fallback`。
    OS によらない)。次の要求は再び GPU から始める
  - 検出結果は保持し、ダウンロード画面の「再検出」で取り直す (GPU やドライバーの交換に追随するため)。
    CUDA 版の種類が変わると、パッケージ一式は「更新が必要」になる (`componentVariant`)
- Windows では Microsoft Visual C++ 再頒布可能パッケージ (`vcruntime140.dll` / `vcruntime140_1.dll` /
  `msvcp140.dll`) を System32 で確認し、無ければダウンロード画面で配布ページへ案内する
- 読み上げのモデルの学習は **CUDA 版の PyTorch を使える NVIDIA GPU を搭載した Windows のみ** (`ttsTrainingAvailable`)。
  それ以外では、学習の画面に「NVIDIA GPU を搭載した Windows で作成したモデルを書き出して取り込めば使える」旨を表示する。
  学習専用のダウンロード項目も、それ以外の環境では選べない

### 13.2 保存場所の中の構成 (`paths.ts` / `library.ts`)

保存場所 (ライブラリ・モデル・作業ディレクトリ) はアプリ全体の設定 (3 章「保存場所」)。音声機能はその中に次の構成で置く。

- ライブラリディレクトリ: Python 本体と、ライブラリごとのディレクトリ (`LIBRARY_NAMES`)

```text
<ライブラリディレクトリ>/
├── manifest.json            # Python 本体とパッケージ一式の取得記録 (テーブル定義.md)
├── python/                  # Python 本体 (python-build-standalone)
├── python.tar.gz            # (取得・展開中だけ) Python 本体の書庫
├── pip-cache/               # pip のキャッシュ (失敗・中断後は再試行のために残り、ダウンロードのジョブが全て成功したら消す)
├── audio-separator/         # 音声分離 (audio-separator)
│   ├── venv/                # 仮想環境
│   ├── cache/               # このライブラリのキャッシュ (Hugging Face・torch・numba など)
│   ├── model-list.json      # 分離モデルの一覧 (導入したパッケージから得る)
│   └── model-sources.json   # 分離モデルのファイルの取得元と大きさ (配布元に問い合わせた値。13.3)
├── applio/                  # 音声変換 (Applio)
│   ├── venv/
│   ├── source/              # ソース一式 (変換・RVC の学習の処理本体)
│   ├── source.tar.gz        # (取得・展開中だけ) ソース一式の書庫
│   └── cache/
└── style-bert-vits2/        # 読み上げ (Style-Bert-VITS2)
    ├── venv/
    ├── source/              # 学習用のリポジトリ一式 (tts-train)
    ├── source.tar.gz        # (取得・展開中だけ) ソース一式の書庫
    └── cache/
```

- モデルディレクトリ: 分類 `audio` の下に機能ごと (`MODEL_GROUP_DIRS`)

```text
<モデルディレクトリ>/
├── manifest.json            # ダウンロードしたモデルの取得記録 (テーブル定義.md)
└── audio/
    ├── separation/          # 分離モデル・UVR のモデル設定 (audio-separator が読む場所)
    ├── conversion/
    │   ├── predictors/      # RMVPE・FCPE
    │   ├── embedders/       # ContentVec など
    │   ├── pretraineds/     # RVC の学習用の事前学習モデル
    │   └── voices/<ID>/     # 学習・取り込みした声のモデル (13.9)
    └── tts/
        ├── bert/            # BERT (日本語・英語)
        ├── nltk_data/       # 英語の発音推定のデータ
        ├── presets/<名前>/  # プリセットの声 (JVNV)
        ├── pretrained/・pretrained_jp_extra/・slm/・wespeaker/  # 学習用の事前学習モデル・話者埋め込み
        └── voices/<ID>/     # 学習・取り込みした声のモデル (13.9)
```

- 取得状況の記録は場所ごとに分ける (ライブラリディレクトリの `manifest.json` は Python 本体とパッケージ一式、
  モデルディレクトリの `manifest.json` はモデル)。それぞれの場所を個別に移動しても、記録が中身と一緒に動くようにするため
- ソース一式は自身の中の決まった場所でモデルを探すが、リンク (シンボリックリンク・ジャンクション・ハードリンク) は使わない。
  上流がモデルを読む箇所を Python 側の補正で差し替え、モデルディレクトリのファイルを直接読ませる (13.4)。
  学習の事前学習モデルもコピーせず、モデルディレクトリから直接読ませる
- 常駐の補助プロセスは、そのライブラリのディレクトリで動かす (Applio はソース一式の場所を基準にファイルを探すため、
  変換はソース一式の場所で動かす)
- 保存場所の移動 (`moveStorage`。設定画面から、ライブラリとモデルのそれぞれで行う)
  - 中身を選んだフォルダへ移し、そのフォルダを新しい場所にする。移動先を指定しない場合は既定の場所へ戻し、設定を空にする
  - 今の場所の中・外側 (`STORAGE_MOVE_NESTED`)、ほかの保存場所や作業ディレクトリと重なる場所 (`STORAGE_OVERLAP`) は選べない。
    移動先は空のフォルダに限る (`STORAGE_TARGET_NOT_EMPTY`。他のファイルと混ぜないため)
  - 移動の確認画面を出す前に、移動と同じ確認で移動先を確かめる (`checkStorageMove`。選べない場所を確認の後で知らせないため)
  - ほかのジョブ (分離・変換・読み上げ・学習・ダウンロードなど) の実行中は断る (`LIBRARY_BUSY`。13.3)。移動は
    ダウンロード・削除と同じく 1 つずつ順に実行する (`withLibraryLock`)
  - 移動の前に常駐の補助プロセスをすべて止め、終了するまで待つ (`stopAllWorkersAndWait`。Windows では、終了しきって
    いないプロセスが読み込んだ DLL やモデルのファイルを掴んでいて、移動に失敗するため)
  - 中断は、先に始まった処理を待っている間と補助プロセスの終了を待っている間も受け付ける。順番が来た時点と補助プロセスが
    終了した時点で中断を確かめ、中断されていれば何も移さずに終える (同じドライブの移動でも中断できるようにするため)
  - 同じドライブ (ボリューム。`stat` の `dev` で判定) なら名前の変更だけで移し、コピーしない。移動先のフォルダが無ければ
    元の場所の名前を変えて移動先にし、あれば (空のフォルダ) 中の項目を 1 つずつ名前を変えて移す (途中で失敗したら、
    移した項目を元の場所へ戻す)。ウイルス対策ソフトなどが一時的にファイルを開いている場合に備えて少し待ちながら
    再試行し (`utils/rename-retry.ts`)、それでも移せなければ使用中として止め、元の場所を使い続ける (`STORAGE_IN_USE`)
  - 別のドライブならコピーしてから元を消す。コピー中は進捗を出し、中断・失敗したらコピーしたものを消して
    (移動先のフォルダは、この移動で作った場合だけ消す) 元の場所を使い続ける。シンボリックリンクはリンクを作らず、
    リンク先の中身 (ファイルの中身・ディレクトリの中) を写す。自分を含む親のディレクトリを指すリンクがあれば、
    際限なく辿ることになるため止める (`STORAGE_LINK_LOOP`)
  - 移動が終わった後に元の場所を消せなかった場合も、移動は成功として扱う。残った場所は結果 (`remainingPath`) で返し、
    画面で残っていることを知らせる
  - 新しい場所を設定に保存できなかった場合は失敗とする (`SETTINGS_SAVE_FAILED`。移動は終わっているが、
    次の起動で元の場所を使ってしまうため)。このとき起動中の設定も元の場所のまま変えない (3 章「保存場所」)
  - ライブラリディレクトリの移動では、設定を保存する前に、移動先の仮想環境の `pyvenv.cfg` に記録された Python 本体の場所を
    新しい場所に書き換え、移動先の仮想環境で `import torch` を実行して動作を確かめる (設定を保存できなかったときに、
    仮想環境が元の場所を指したまま残らないようにするため)。Python が起動して失敗した仮想環境だけを「再取得が必要」(broken) に
    し、利用者がダウンロード画面で取り直す (作り直しはパッケージの再ダウンロードを伴うため、自動では行わない)
  - Python を起動できない場合 (Windows で Visual C++ 再頒布可能パッケージが無い `VC_RUNTIME_MISSING` など) は仮想環境の
    問題ではないため broken にしない。中身は移し終えているため設定は保存してから、そのエラーで失敗を知らせる

### 13.3 ダウンロードと削除 (`spec.ts` / `library.ts` / `installer.ts` / `downloader.ts`)

- ダウンロード物の定義は `spec.ts` に固定する (版・取得元 URL・大きさ・SHA-256)。取得元の URL はファイルごとに 1 つで、
  その URL からだけ取得する。Hugging Face と GitHub のファイルはコミットまたはタグを固定した URL で取得する。
  使う版はアプリが決め、利用者による更新はできない
  - 例外: UVR のモデル設定 (TRvlvr/application_data の `main` ブランチ) と NLTK のデータ (nltk_data の `gh-pages`
    ブランチ) は、配布元がブランチでしか公開していないため、ブランチの URL から取得し、大きさと SHA-256 を定義に持たない
    (内容が配布元の更新に従って変わり得る)
- 分離モデルの取得元 (`separator-models.ts`): 一覧 (`model-list.json`) はファイルごとに取得元の候補 (UVR と
  audio-separator の配布場所) を持ち、ファイルは候補のうち 1 か所にだけある
  - 候補を先頭から HEAD で問い合わせ (404 = その場所に無い。それ以外の失敗はエラー)、ファイルがある URL と大きさを
    ライブラリディレクトリの `audio-separator/model-sources.json` に保存する (テーブル定義.md)。取得はその URL からだけ行う
  - 一覧を得たときと、大きさの分からない分離モデルがある状態でダウンロードのダイアログを開いているときに、取得元が
    まだ分からないファイルをまとめて問い合わせる (`probeSeparatorSizes`。同時に 8 件まで。問い合わせに失敗したファイルは
    記録せず、次の機会に問い合わせ直す)
  - 問い合わせの途中で一覧と取得元の記録を読み直させた場合 (`forgetSeparatorModelList`。パッケージ一式の削除・導入、
    ライブラリディレクトリの移動) は、残りの問い合わせをやめ、それまでの結果も記録も保存もしない (世代の番号で判定する。
    消した場所にフォルダを作り直したり、古い場所の結果を書き込んだりしないため)
  - どの候補にも無いファイルを持つモデルは、取得できないものとして理由とともに示す (`separatorModelNotFound`)。
    この結果はアプリの起動中だけ覚え、次に起動したときに調べ直す
  - ダウンロード時に取得元がまだ分からないファイルはその場で調べ、どの候補にも無ければその項目を失敗とする
    (`SEPARATOR_MODEL_NOT_FOUND`)
  - VIP モデルは一覧に出さない (13.13)。一覧が無い場合 (分離のパッケージ一式を削除したときなど) も、取得済みの
    分離モデルはファイル名を名前として示し、削除できるようにする
- 項目は「Python 本体」「パッケージ一式」(separator / converter / tts / tts-train)「モデル」(1 モデル単位) の 3 種類。
  状態は `missing` (未取得) / `installed` / `outdated` (版が定義と違う) / `broken` (ファイルの欠落・動作確認の失敗)
- **すべてのダウンロードは、利用者が対象を選んで実行を指示したときだけ行う**。補助プロセスからの通信も
  環境変数 (13.4) と上流への補正で止め、未取得のモデルを勝手に取得させない
- ダウンロード (`downloadItems`): 選んだ項目に未取得の前提項目を足し、取得する順に並べて 1 つずつ取得する。
  項目ごとと全体の進捗を出し、中断できる。失敗した項目があっても残りを続け、終了後に失敗した項目だけを
  再試行できる (前提項目が失敗した項目は `PREREQUISITE_FAILED`)
  - ファイルは保存先に直接取得する。取得中は保存先のフォルダに `<名前>.part` として書き、SHA-256 を確かめてから
    正式な名前にする。中断した `.part` は次回に続きから取得する
  - 配信元が圧縮して送る場合 (raw.githubusercontent.com の JSON など、`Content-Encoding` 付き) は、
    `Content-Length` が展開後の大きさと異なるため、大きさの照合と続きからの取得を行わない
  - 応答やデータが 120 秒届かなければ打ち切って失敗とする (再試行すれば続きから取得する)
  - 展開する zip (NLTK のデータ) は、zip と同じ場所の `<名前>.staging/` に展開し、中の `<名前>/` を正式な場所へ移してから
    展開途中のフォルダと zip を消す (失敗・キャンセルでも展開途中のものは消す)。取得済みかどうかは、展開を終えたフォルダが
    あるかで判定する。展開の途中で止まったものを展開済みと取り違えず、次の取得で展開し直すため
  - ダウンロード・削除・保存場所の移動 (ライブラリ・モデルディレクトリ) は、ジョブが別でも 1 つずつ順に実行する
    (`withLibraryLock`)。同じ仮想環境への同時の導入や、導入中の pip のキャッシュの削除を防ぐため
  - ダウンロード・削除・保存場所の移動は、ほかのジョブ (分離・変換・読み上げ・学習など。ダウンロードと移動は自身のジョブを
    除く) の実行中は始めずに断る (`checkLibraryIdle` → `LIBRARY_BUSY`)。それらの処理は仮想環境やモデルのファイルを使っており、
    入れ替え・削除・移動すると処理が失敗したり、使用中のファイルを消せずに中途半端な状態が残ったりするため
  - 表示する容量: 単体ファイルは定義の大きさ (分離モデルは、取得元を調べたときに得た大きさ)。
    パッケージ一式は固定の目安 (CUDA 版 PyTorch の実測値 + その他のパッケージの目安 + ソース一式)
- Python 本体: python-build-standalone の CPython 3.11.17 (install_only_stripped) の書庫を、展開先と同じディスク
  (ライブラリディレクトリの `python.tar.gz`) に取得し、`python.staging/` に展開してから `python/` に置き換える。
  書庫と展開途中のものは、成功・失敗・キャンセルを問わず消す
  - tar.gz の展開 (Python 本体・ソース一式) では、シンボリックリンクとハードリンクの項目を展開しない (保存場所にリンクを
    作らないため)。そのため macOS では、リンクである `bin/python3` ではなく、版番号の付いた実体 (`bin/python3.11`) を
    Python 本体の実行ファイルとして使う (`spec.ts` の `pythonExecutable`)
- パッケージ一式 (`installComponent`)
  - `python -m venv --without-pip --copies <ライブラリ>/venv` で仮想環境を作り、Python 本体の pip を
    `python -m pip --python <仮想環境の python> install --progress-bar raw -r <作業ディレクトリ>/requirements.txt
    -c <名前>.lock.txt` の形で仮想環境に向けて使う。`--progress-bar raw` の機械可読の出力から進捗を読む
  - `requirements.txt` は `<名前>.in` から作る (`resolveRequirements`)。`-r <別の名前>.in` の取り込みを展開し、
    Windows の CUDA 版では `torch`・`torchaudio`・`torchvision` の版を `<版>+<cu126|cu128|cu130>` に書き換える
    (`sys_platform == "win32"` 以外の条件付きの行はそのまま)。pip が OS の既定の文字コードで読むため ASCII だけで書く
  - 既にある仮想環境は、その Python で動作を確かめて使い回す。Python が起動して失敗した (`PYTHON_BROKEN`) 場合だけ
    壊れたものとして作り直し、Python を起動できない場合 (作業ディレクトリが無い・実行環境が足りないなど) は作り直しても
    直らないため、そのエラーで失敗させる
  - `--copies` により、どの OS でも仮想環境に Python 本体へのリンクを作らずファイルを写す (保存場所の移動で、
    ファイルをそのまま写せるようにするため)。macOS では python-build-standalone の実行ファイルが libpython を
    `@executable_path/../lib` から読むため、作成後に `libpython3*.dylib` を仮想環境の `lib/` に写す
  - Windows の CUDA 版では `--extra-index-url` に download.pytorch.org の該当する index (cu126 / cu128 / cu130) を加える
  - ソース一式 (Applio・Style-Bert-VITS2) は GitHub のタグのアーカイブを、展開先と同じディスク (そのライブラリの
    ディレクトリの `source.tar.gz`) に取得し、`source.staging/` に展開してから `source/` に置き換える。書庫と展開途中の
    ものは、成功・失敗・キャンセルを問わず消す。Applio は `assets/config.json` を雛形から作る
  - pip に渡す要件ファイルは作業ディレクトリ (`jobs/pip-<項目>-<ID>/`) に作り、pip の終了後に消す
  - パッケージを入れ替える間は、仮想環境のファイルを使っている常駐の補助プロセスを止め、終了を待つ
  - 導入後に代表的なモジュールの import で動作を確かめ、失敗したら記録しない
  - pip のキャッシュは仮想環境への展開先と同じディスク (ライブラリディレクトリの `pip-cache/`) に置き、ダウンロードの
    ジョブが全て成功したら消す。同じ PyTorch を使うパッケージ一式を続けて導入するときと、失敗・中断後の再試行で
    取得し直さないため
  - 利用者の pip の設定 (`PIP_` で始まる環境変数と設定ファイル) は持ち込まない (`PIP_CONFIG_FILE` に null デバイスを指定)
  - 入れるパッケージの版は固定版 (`src/python/requirements/*.lock.txt`) で固定する。
    PyTorch (torch・torchaudio、分離では torchvision も) はプラットフォームと CUDA 版で変わるため、`.in` 側で版を固定し
    lock には含めない。分離の torchvision は torch と対になる版を OS ごとに指定する (Windows 0.26.0 / macOS 0.29.1)。
    分離の diffq は Windows では diffq-fixed 0.2.4、macOS では diffq 0.2.4 とし、macOS ではソースからビルドされる
    (Xcode Command Line Tools が必要。13.13)
- 失敗・中断したときに残すのは、再試行でそのまま使われるものだけ: 取得途中の `.part` (続きから取得する)、
  pip のキャッシュ (取得済みのパッケージを使う)、作りかけの仮想環境 (動作を確かめて使い回す)
- アプリの更新で版が変わった項目 (`outdated` / `broken`) があれば、起動時に一覧と合計容量を示して
  更新するかを確認する (`VoiceUpdatePrompt`)。確認はアプリの版ごとに 1 回だけ出し
  (`settings.voice.updatePromptVersion`)、「後で」を選んでもダウンロード画面から更新できる
- 削除 (`removeItems`): 項目単位で行う。ジョブにはせず、終わるまで待って結果 (項目ごとの成否) を返す
  - 常駐の補助プロセスを止め、終了を待ってから消す (掴まれているファイルは消せないため)
  - 項目のファイルと一緒に、その項目の取得途中で止まった `.part` (書庫のものを含む) も消す (以後は再利用されないため)。
    展開する zip は、展開したフォルダと展開途中のもの (`.staging`) も消す
  - 読み上げのプリセットの声を消すと、`preset-overrides.json` のそのプリセットの記録 (名前と言語の変更) も消す
    (`preset-overrides.ts` の `clearPresetOverride`。声のモデルの画面とダウンロードのダイアログのどちらから消しても同じ。
    取得し直したときは元の名前と言語で使う)
  - Python 本体を消すと、すべての仮想環境も消える (確認画面で明示する)。仮想環境をすべて消す場合は、
    Python 本体も消すかを利用者が選べる
  - 消すと使えなくなる機能を確認画面に示す (消す各項目の `usedBy` (その項目を使う機能) を合わせたもの)
  - パッケージ一式を消すと、そのライブラリのディレクトリ (仮想環境・ソース一式・キャッシュ) ごと消す。
    ダウンロードしたモデルはモデルディレクトリにあり、別の項目として個別に消す
  - tts を消すと tts-train (学習用のソース一式など) も消える。tts-train だけを消す場合、読み上げの仮想環境に
    追加したパッケージは残す (共有している依存パッケージを壊さないため)
  - 他の取得済みモデルと共有しているファイル (分離モデルの設定ファイルなど) は残す
  - 利用者の声のモデル (学習・取り込み) は、ここでは消さない
- 機能の利用時に必要な項目が欠けていれば、`checkFeature` の結果から不足項目を示してダウンロード画面へ案内する。
  処理の途中で未取得のモデルが必要になった場合も、同じ案内を出す。エラーは分離が `MODEL_NOT_INSTALLED`、変換と学習が
  `MODEL_REQUIRED` で、どちらも `<コード>: <項目 ID>, <項目 ID>` の形で不足項目を持つ。renderer は両方から不足項目を取り出す
  (`voiceErrors.ts` の `missingItemsFromError`)

### 13.4 Python の実行 (`python-env.ts` / `python-worker.ts` / `src/python/kura_voice/`)

- 構成
  - Python は python-build-standalone のビルド済みの単体 Python を、利用者の承認後にダウンロードして使う
    (uv などの外部の環境管理ツールは使わない)。版は 3.11 とする。3.10 は 2026 年 10 月末でサポートが終了し、
    PyTorch も 2.15 から 3.11 以上が必要になる。3.11 はセキュリティ修正が 2027 年 10 月まで提供される
  - Python 本体は 1 つとし、コンポーネント (分離・変換・読み上げ) ごとに標準の venv で仮想環境を作る。
    コンポーネントごとに必要な PyTorch の版が異なるため (audio-separator は Apple Silicon で PyTorch 2.13 以上を要求する)
  - 各コンポーネントの採用元: 分離は audio-separator (PyPI)、変換は Applio (GitHub のソース一式)、
    読み上げは Style-Bert-VITS2 の独立派生版 (sync-dev-org 版。推論は PyPI の style-bert-vits2-mk、学習はリポジトリの処理)
- 環境変数 (`buildPythonEnv`)
  - 利用者の環境の Python 関連の変数を持ち込まない (`PYTHONHOME`・`PYTHONPATH`・`PYTHONSTARTUP`・`PYTHONUSERBASE`・
    `VIRTUAL_ENV`・`CONDA_PREFIX`・`CONDA_DEFAULT_ENV`・`AUDIO_SEPARATOR_MODEL_DIR` と、`PIP_` で始まる変数を除く)
  - 各ライブラリのキャッシュの書き込み先 (`HF_HOME`・`TORCH_HOME`・`XDG_CACHE_HOME`・`NUMBA_CACHE_DIR`・
    `MPLCONFIGDIR` など) をそのライブラリのディレクトリの `cache/` に向ける。`NLTK_DATA` はモデルディレクトリのデータを指す
    (削除後の残留と、確認を経ないダウンロードを防ぐ)
  - モデルの場所: `KURA_APPLIO_MODELS` (モデルディレクトリの `audio/conversion`)・`KURA_SBV2_MODELS` (`audio/tts`)。
    上流への補正 (下記) がこの場所のファイルを読ませる
  - `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE` などで通信を止め、利用状況の送信を止める
  - `TEMP` / `TMP` / `TMPDIR` は、プロセスを起動する側 (`process-runner.ts` / `python-worker.ts`) がプロセスごとに
    作業ディレクトリの `tmp/<ID>/` を作って渡し、そのプロセスが終了した時点で消す (3 章「保存場所」)
  - `PYTHONDONTWRITEBYTECODE=1`: 同梱スクリプトの隣に `__pycache__` を作らせない (macOS ではアプリ本体の署名が壊れるため)。
    パッケージは導入時に pip がバイトコードを作成済み
  - ffmpeg / ffprobe はアプリ設定で解決したもののフォルダを PATH の先頭に置く (Python 側はこれを PATH から使う)
  - Windows は `USE_LIBUV=0` (PyTorch の分散処理の初期化が学習で失敗するのを避ける)
- 常駐の補助プロセス (`worker.py --component <separator|converter|tts>`、コンポーネントごとに 1 つ)
  - 標準入出力で 1 行 1 件の JSON をやり取りする。要求は `{id, method, params}`、応答は `{id, result}` または
    `{id, error: {code, message, detail}}`、途中経過は `{id, event}`
  - ライブラリが標準出力へ書く文字で通信が壊れないよう、Python 側で標準出力 (fd 1) を標準エラーへ付け替え、
    通信には複製した元の標準出力を使う
  - 読み込んだモデルを保持し、候補を作り直すたびに読み直さない。要求は 1 件ずつ順に処理する
  - ジョブのキャンセル時はプロセスツリーごと終了させ (Windows は `taskkill /T /F`、macOS はプロセスグループへの
    シグナル)、次の要求で起動し直す。終了させたプロセスはその時点で切り離し、処理中の要求はキャンセルとして終える。
    古いプロセスの終了を待たずに次の要求で新しいプロセスを起動でき、古いプロセスの終了通知と標準エラーは
    新しいプロセスに影響させない。順番を待つ間にジョブがキャンセルされた要求は、プロセスを起動せずに終える。
    標準エラーは main のコンソールへ流し、末尾を異常終了時の詳細に使う
  - ファイルの移動・削除・入れ替え (保存場所の移動・作業ディレクトリの変更・項目の削除・パッケージ一式の導入) の前は、
    止めたうえで終了を待つ (`stopAllWorkersAndWait`)。キャンセルなどで先に終了させ、まだ終了していないプロセスも、
    終了するまで覚えておいて同じく待つ (ファイルを掴んだままの可能性があるため)。15 秒以内に終了しないプロセスがあれば失敗とし
    (`PYTHON_STOP_TIMEOUT`)、画面はアプリを再起動してからやり直すよう求める。アプリの終了時は、終了を妨げないよう
    待たずに止める
  - エラーは `<コード>: <詳細>` の形のメッセージで renderer へ返す。詳細が無い (Python 側がコードをそのまま
    メッセージにした) 場合はコードだけにする。renderer (`voiceErrors.ts`) は既知のコードを表示言語の文に置き換え、
    詳細が無い場合は詳細を入れる括弧ごと取り除く
- 学習は常駐プロセスを使わず、駆動スクリプト (`rvc_train.py` / `sbv2_train.py`) をジョブごとに起動する。
  駆動スクリプトは上流の学習スクリプトを `script_runner.py` 経由で順に実行し、出力からエポックを読み取って
  進捗 (段階とエポック) を返す。出力のうち Python の例外の行 (`RuntimeError: ...` など) の最後のものを覚えておき、
  スクリプトが失敗した場合 (`TRAINING_STEP_FAILED`) と、学習が終わってもモデルが作られなかった場合
  (`TRAINING_NO_MODEL`) の詳細として示す。例外の行が無いまま異常終了した場合は終了コードを示し、
  Windows の異常終了のコードは 16 進と意味で示す (例: `0xC0000005 (access violation)`)
  - 駆動スクリプトは、作業ディレクトリに main プロセスが作ったジョブのフォルダ (`jobs/training-<ID>/`) をカレント
    ディレクトリにして動く。指示ファイル (`job.json`) と学習の途中のデータはこのフォルダに置き、学習が終わった時点
    (成功・エラー・キャンセル) で main プロセスがフォルダごと消す (15.6・16.7)
  - `script_runner.py --patch <applio|sbv2> --root <上流のソース一式> -- <スクリプト> ...` の形で起動する。`--root` の
    場所を import の検索先に加えるため、ソース一式の外のフォルダをカレントディレクトリにしても上流のスクリプトが動く
  - スクリプトがアプリの定めたエラーを返す場合は、`KURA_ERROR: <コード> <詳細>` の 1 行を出力する。駆動スクリプトは
    この行を見つけると、同じコードと詳細のエラーとして学習を止める
- 上流への補正 (Python 側で読み込み時に当てる)
  - audio-separator: モデルの自動ダウンロードを止める。音声の読み書きに soundfile を使う
  - Applio: 常駐の補助プロセスは、カレントディレクトリをソース一式の場所にして読み込む (学習の各段階のカレント
    ディレクトリは 15.6)。wget によるダウンロードを止める。
    faiss が ASCII 以外のパスを開けない問題を、メモリ経由の読み書きで回避する。
    変換では、Applio がインデックスのパスの中の `trained` をすべて `added` に書き換えてから使うため (`D:\pretrained\...`
    のように語を含むパスが壊れる)、変換の処理 (`pipeline`) へは元のパスを渡し直す (`converter_service.py` の
    `StoredModelConverter.setup_vc_instance`)。インデックスはコピーせず、声のモデルのフォルダのものをそのまま読む。
    ピッチ抽出 (RMVPE・FCPE) と埋め込み (ContentVec など) のモデルを、ソース一式の中ではなくモデルディレクトリから読む
    (`runtime.patch_applio_model_paths`。読み込み済みのモジュールが取り込んだ参照も差し替える)。
    学習の特徴量の抽出は、上流が子プロセスに分ける処理を同じプロセスで行う (`rvc_extract.py`。子プロセスには補正が効かないため)。
    事前学習モデルは学習スクリプトへモデルディレクトリのパスを直接渡す
  - Style-Bert-VITS2: BERT と WavLM をモデルディレクトリから読む (`runtime.patch_sbv2_model_paths`・学習の設定)。
    学習の初期値 (G_0 / D_0 / DUR_0 / WD_0) は、学習用のフォルダにコピーせず、モデルディレクトリの事前学習モデルから
    直接読む (`KURA_SBV2_PRETRAINED`)。上流は初期値の読み込みに失敗すると例外を握りつぶして一から学習を続けるが、
    少ない音声では使えないモデルになるため、読み込めなければ `KURA_ERROR` の行で `TRAINING_PRETRAINED_UNREADABLE` を
    知らせてから、上流の `except Exception` で捕まらない例外で学習を止める。
    学習時は話者埋め込みモデル (wespeaker) をモデルディレクトリのファイルから読む。
    学習のテキストの前処理 (`preprocess_text.py`・`bert_gen.py`) では、pyopenjtalk の補助プロセスの待ち受けポートを
    固定の 7861 から OS が空きとして返すポートに置き換え (同じポートで待ち受ける別のプロセスに接続しないため)、
    ユーザー辞書は上流のソース一式の `dict_data/user.dic` ではなくカレントディレクトリ (ジョブのフォルダ) の `user.dic` に
    作って読ませる (上流のソース一式を書き換えないため)。学習スクリプトは GPU が 1 つでもモデルを DDP (DistributedDataParallel) で包むが、
    1 プロセスで学習するときは、中のモデルをそのまま呼ぶ同じ形の包み (`.module` を持ち、`state_dict` の
    `module.` 接頭辞も同じ) に置き換える。Windows では gloo による CUDA の勾配の集約で PyTorch 2.11 が
    アクセス違反で落ちるため (1 プロセスでは集約するものが無く、結果は変わらない。Applio は GPU が複数のときだけ DDP を使う)
  - 学習 (両方): PyTorch の分散処理 (GPU が 1 つでも使われる) の待ち受けポートを、OS が空きとして返すポートに置き換える
    (`MASTER_PORT`。上流は Applio が 20000〜55555 の乱数、Style-Bert-VITS2 が設定の固定値)。
    Windows では Hyper-V などが予約したポートの範囲に当たると待ち受けに失敗し、学習が始まらないため

### 13.5 GPU の排他 (`gpu-lock.ts`)

- GPU を使う処理 (分離・変換・読み上げ・学習) は、アプリ全体で 1 つずつ順に実行する (`withGpu`)。
  順番待ちの間にジョブがキャンセルされたら、待ちから外れる
- 順番待ちに入ったときと抜けたときに `wait` のジョブイベントを送る。画面 (`hooks/useJobRunner.ts`) は待っている間、
  進捗の文言を「他の処理が終わるのを待っています (モデルの学習中は長くかかることがあります)」(`voice.common.waitingGpu`) に
  置き換える (学習中は長く待つことがあり、
  止まって見えないようにするため)。画面はジョブの通知を常に購読し、ジョブの ID を処理の開始前に設定する
  (開始直後に届く順番待ちの通知を取りこぼさないため)
- GPU の持ち主 (コンポーネント) が変わる直前に、他の常駐プロセスへ `unload` を送ってモデルを手放させる
  (`setGpuSwitchHandler` → `unloadOtherWorkers`)

### 13.6 作業ディレクトリの使い方 (`work-dir.ts`)

- 作業ディレクトリはアプリ全体の一時ファイルの置き場 (3 章「保存場所」)。音声機能は作業の結果を
  `session/<作業キー>/`、1 回の処理の中間ファイルを `jobs/` の下の処理ごとのフォルダに置く
- 中間ファイルは 32bit 浮動小数の WAV とする (段階を重ねても音割れや精度の低下が起きないようにするため)
- 作りかけの結果は残さない。分離・変換・読み上げの実行が失敗・キャンセルした場合は、作りかけの候補をその時点で消す。
  読み上げで入力の誤りのため結果を返さない場合も同じ。入力の変換 (`prepareInput`) も、失敗したら書きかけを消す
- 同じ組み合わせなら作り直さない結果 (重ねた音・移調した伴奏・合成結果) は、別の名前に書いてから正式な名前にする
  (`produceFile`)。途中で止まった書きかけを、完成したものと取り違えて使い回さないため
- 候補の破棄では、その候補のファイル (変換は変換後のボーカルと、伴奏と重ねたものの両方) を消す。
  消した結果空になったフォルダもその場で消える (3 章)
- 機能間の受け渡し (分離 → 変換、読み上げ → 変換) は同じ起動中の作業の中だけで行う (`stores/voiceHandoffStore.ts`)。
  作業をまたぐ場合は、書き出したファイルを読み込む
  - 受け渡しは送り元の作業のファイルをそのまま使う (コピーしない)。送り元の画面で候補や作業を破棄しても、渡したファイルを
    受け取り前の受け渡しか変換の画面の入力が使っている間は消さず、使い終わった時点 (変換の画面が別の入力に変えた・作業を
    破棄したなど) で消す (`discardWorkAfterHandoff` / `discardPathsAfterHandoff`)
  - 分離からは、採用した段階のボーカルの出力をすべて渡す (複数あれば、変換と再生の前に 1 つに重ねる。伴奏も同じ)

### 13.7 プレビュー再生 (`media-protocol.ts` / `components/voice/SyncPlayer.tsx`)

- 独自スキーム `kura-media://media/<推測できない識別子>/<ファイル名>` で、main が登録したファイルだけを
  renderer の audio 要素へ公開する (renderer は開発時 http、配布時 file から読み込まれ、file:// を直接参照できないため)。
  Range 要求に部分応答で応える (シークのため)。renderer から再生用 URL を求められるのは作業ディレクトリ内のファイルだけ
- 同期再生: 候補や再生対象 (ボーカル・伴奏・合成結果・元音源など) を切り替えても再生位置を保つ。
  複数の出力を重ねて聞く場合は、main で重ねた WAV を作って再生する (`voice:media:mix`、同じ組み合わせは作り直さない)

### 13.8 書き出し (`exporter.ts` / `components/voice/ExportDialog.tsx`)

- 形式は MP3 と FLAC。WAV は選べない
  - MP3: サンプリング周波数 (8000 / 11025 / 12000 / 16000 / 22050 / 24000 / 32000 / 44100 / 48000 Hz、既定 44100)・
    ビットレートモード (CBR / VBR、既定 CBR)・ビットレート (320〜8 kbps の 18 段階 (`EXPORT_BITRATES`)、既定 160) を選べる。
    VBR では LAME の品質値 (`-q:a`) をビットレートの目安から決める (対応はオーディオ正規化と同じ。7 章)
  - FLAC: 元のサンプリング周波数のまま 24bit で書く (浮動小数の中間ファイルから精度を落としすぎないため)。
    FLAC を選んでいる間は、MP3 の設定を操作できない
- 書き出しの設定は音声機能の設定 (`settings.voice.export`) として変えた時点で保存し、3 機能で共用する
  (どの画面の書き出しから変えても反映される)。オーディオ正規化の出力設定とは別に持つ
- 書き出す対象をチェックで選ぶ。ファイル名は「元のファイル名 + 接尾辞 (`_vocals` など)」で自動決定し、
  名前の個別入力と、保存ダイアログによる場所と名前の個別指定もできる。個別に指定した場所は、隣のボタンで取り消せる
- 出力先 (書き出し先ディレクトリ) の既定は元のファイルと同じ場所で、ダイアログを開くたびに既定に戻す。
  実行ボタンが出力先の入力を必要とするのは、選んだ対象に場所を個別に指定していないものがあるときだけ
- 書き出し先のフォルダは作らない (無ければ `EXPORT_FOLDER_MISSING`)。同じ書き出し先が複数ある場合は、
  後のもので上書きされるため止める (大文字小文字は区別しない)
- 上書きになるファイルがあれば一覧を示して確認する。書き出しは別の名前 (`<書き出し先>.kura-tmp<拡張子>`) に書いてから
  名前の変更で置き換えるため、失敗しても既存のファイルは残る

### 13.9 声のモデルの管理 (`voice-models.ts` / `pages/voice/VoiceModelsPage.tsx`)

- 音声変換と読み上げのそれぞれに管理画面を置く。モデルはモデルディレクトリの `audio/<conversion|tts>/voices/<ID>/` に保存し、
  情報は同じ場所の `meta.json` に持つ (テーブル定義.md)。`meta.json` が読めないモデルがあると、一覧の取得は
  そのファイルを示して失敗する (`DATA_FILE_CORRUPT`)。一覧を使う画面 (声のモデルの管理・変換・読み上げ) は、
  読めなかった理由を通知で示す
- 作成中のモデル (取り込みの確定・学習) は同じ場所の `.staging-<ID>/` に作り、`meta.json` を書いてから `<ID>/` に
  名前を変える (作りかけのものを声のモデルとして扱わないため)。起動時に、前回の起動で残った `.staging-*` と
  取り込みの展開先 (`.import-*`) を裏で消す (`removeVoiceStagingLeftovers`)

| 機能 | 区分 | 構成ファイル |
|---|---|---|
| 音声変換 | 学習 / 取り込み | `model.safetensors` (重み)・`model.json` (設定値)・`model.index` (検索用インデックス、任意) |
| 読み上げ | プリセット / 取り込み / 学習 | `config.json`・`model.safetensors`・`style_vectors.npy` |

- 音声変換のモデルは、変換のときに `model.safetensors` と `model.json` から、Applio が使う形 (.pth を読み込んだものと
  同じ内容) をメモリ上に組み立てる (Applio の `VoiceConverter.load_model` を差し替える)。同じ重みを .pth として
  二重に持たないため

- プリセットの声 (JVNV) はダウンロードした `audio/tts/presets/<名前>/` をそのまま使う。名前と言語の変更は
  `audio/tts/voices/preset-overrides.json` に記録し (`preset-overrides.ts`)、区分はプリセットのまま保つ。
  プリセットを削除すると記録も消す (13.3)
- 書き出し: 拡張子 `.kuravoice` の zip。構成ファイル一式と `kura-voice.json` (形式・機能・名前・区分と、
  読み上げのモデルの対応言語) を入れる。取り込み時は形式と機能を確かめ、元の区分を復元する。モデルの情報
  (RVC の設定値・読み上げのエンジンやスタイル) は `kura-voice.json` に持たせず、取り込むときにモデルのファイルから読み直す
- 取り込み: 毎回注意文を表示し、同意した場合だけファイルの選択に進む。検査 (`inspectImport`) で内容を確かめ、
  確定 (`commitImport`) で保存する
  - 注意文の内容: 配布元の利用規約やライセンスに従って利用すること、声の持ち主やキャラクターの権利者の許諾なく
    作られたモデルを使わないこと、なりすましやディープフェイクの作成などに使わないこと、利用の責任は利用者に
    あること。音声変換では、公式に配布されているモデルがある一方で無断で作られたモデルも公開されていること・
    配布条件 (クレジット表示・商用利用・二次配布など) がモデルごとに異なることを、読み上げでは Style-Bert-VITS2 の
    開発陣もなりすまし・ディープフェイク作成目的などでの利用をしないよう求めていることを添える
  - 本アプリで書き出したファイルは同梱の情報から元の区分を復元し、外部で入手したモデルは「取り込み」の区分とする。
    取り込むファイルの JSON (`kura-voice.json`・`config.json`) が解析できない、またはオブジェクトでない場合は、
    そのファイル名を示して中止する (`IMPORT_INVALID_FILE`)
  - 取り込むものは、ファイル (複数可)・フォルダ (直下のファイルが対象)・zip (中のファイルが対象) で選ぶ。
    `.kuravoice` を 1 つだけ選んだ場合は、本アプリの書き出しファイルとして扱う
  - zip の中身と書き出しファイルは、声のモデルの置き場と同じディスク (`voices/.import-<ID>/`) に展開し、確定時は
    名前の変更で移す (ドライブをまたぐコピーをしないため)。利用者が選んだ元のファイルは移動も削除もしない
  - 音声変換の候補: `.pth` (学習途中のチェックポイント `G_<数字>.pth` / `D_<数字>.pth` を除き、大きいものから並べる) と
    `.index` (任意。RVC・Applio が推論用に作る `added_` で始まる名前のものを先に並べる)。`.pth` が無ければ中止する
    (`IMPORT_PTH_NOT_FOUND`)
  - 読み上げの候補: `.safetensors` (新しいものから並べる)。`config.json` と `style_vectors.npy` は、選んだ `.safetensors` と
    同じフォルダのものを使う (この形式ではファイル名が決まっているため)。足りなければ中止する (`IMPORT_FILES_MISSING`)
  - 候補が複数ある場合は、先頭に並べたものを選んだ状態で確認画面に選択欄を出し、選び直すとそのファイルで検査し直す
    (`chooseImportFiles`)。どのファイルを取り込むかを黙って決めず、利用者が確かめられるようにするため
  - **安全な読み込み**: pth は読み込み時にファイル内のプログラムが実行され得る形式で、実際に悪意あるモデルが
    公開された例もあるため、`torch.load(weights_only=True)` (テンソルと基本的な型だけを復元し、モジュールの取り込みを
    許さない。重みの数値は通常の読み込みと同じで品質に影響しない) で読む。`style_vectors.npy` は
    `np.load(allow_pickle=False)` (数値の配列としてのみ読む) で読む。safetensors はプログラムを含められない形式。
    読めない場合は取り込みを拒否せず、リスクを示して利用者に許可を求め、許可されたときだけ制限なしで読む。
    理由として、ファイルが読み込もうとしたオブジェクトの名前 (`Unsupported global: ...`) を示す
    (PyTorch の元のメッセージは開発者向けの長い説明と端末の色指定を含むため)。
    制限なしで読み込んだ補助プロセスは読み込み後に終了させる。取り込んだモデルは重みと設定値だけを取り出して
    安全な形式 (safetensors・JSON・数値だけの npy) で保存し直し、以降は危険を伴う読み込みを起こさない
  - 音声変換: RVC のバージョン・サンプルレート・ボコーダー・埋め込み方式を読み取り、扱えない形式は理由を示して中止する
    (`RVC_VERSION_UNSUPPORTED`・`RVC_VOCODER_UNSUPPORTED`・`EMBEDDER_UNSUPPORTED`)。本アプリの書き出しファイルは
    `model.json` をそのまま使うため、同じ確認 (版は v1 / v2、ボコーダーは HiFi-GAN / MRF HiFi-GAN / RefineGAN、
    埋め込みは変換に使えるもの) を main で行う (`checkRvcSupported`。変換するまで失敗が分からないことを防ぐため)。
    contentvec 以外の埋め込みで作られたモデルは、対応する埋め込みモデルのダウンロードを案内する
  - 読み上げ: 3 ファイルがそろっているか、`config.json` から JP-Extra 版か多言語版か・対応言語を判定し、
    必要なエンジンが未取得なら理由を示す
- Hugging Face の検索: 外部ブラウザでモデル検索ページを開く (`HUB_SEARCH`)。音声変換は検索語 `RVC` とタグ `rvc`、
  読み上げは検索語 `Style-Bert-VITS2` とタグ `style-bert-vits2` で絞り込む
- 削除: 利用者のデータ (学習・取り込み) は再取得できない旨を明示して確認し、OS のゴミ箱へ移す (戻せるようにするため。
  ゴミ箱へ移せない場合だけ完全に削除する)。プリセットはダウンロードの項目として削除し、ダウンロード画面から取り直せる
- 読み上げの多言語版のモデルは、使う言語を利用者が設定できる (JP-Extra 版は日本語に固定)
- 名前: 取り込みと名前の変更で、同じ機能に同じ表示名 (大文字小文字と前後の空白は区別しない) のモデルがあれば
  注意を出す (選択欄で区別できなくなるため)。登録自体は妨げない

### 13.10 プリセット (`presets.ts` / `components/voice/PresetBar.tsx`)

- 分離のパラメーター (アーキテクチャごと) と合成のパラメーターを、種類ごとに
  `~/.kura_toolkit/voice-presets/<separation|mix>.json` に保存する。保存 (上書き・新規)・呼び出し・名前変更・削除ができる
- 種類は renderer から渡されファイル名に使うため、`separation` と `mix` 以外は断る (`INVALID_PRESET_KIND`)。
  一覧を読めない場合 (`DATA_FILE_CORRUPT`) は、画面がその理由を通知で示す
- 合成には初期のプリセット (標準・リバーブなし・ホール・ボーカル強調) を用意する。名前は翻訳キー (`nameKey`) で持ち、
  表示言語に従う。初期のプリセットは上書き・名前変更・削除できない (`PRESET_BUILTIN`)。変えた値は新しいプリセット
  として保存できる。画面では初期のプリセットを選んでいる間、上書き・名前変更・削除の操作を無効にし、変更できない旨を添える

### 13.13 設計上の判断

| 項目 | 本アプリでの扱い | 理由 |
|---|---|---|
| 対応環境 | Windows (x64) と Apple Silicon の macOS 14 以降に限る。それ以外 (Linux 版のアプリを含む) では使えない理由を表示する | Intel Mac・Arm 版 Windows 向けの PyTorch (必要な版) が配布されていないため |
| 仮想環境への pip の導入 | `--without-pip` で作り、Python 本体に同梱の pip を `--python` で仮想環境に向けて使う | venv が ensurepip で入れる pip 24.0 は進捗の機械可読の出力 (`--progress-bar raw`) に対応せず、進捗を表示できないため |
| Applio の版と導入するパッケージ | 3.6.5 に固定し、変換と学習に必要なパッケージだけを導入する | 版はアプリが決めるため。Applio の requirements は画面 (Gradio) などを含み大きいため |
| 多言語版のエンジンの BERT | 英語と日本語の BERT だけを取得する (中国語は取得しない) | 対象言語が日本語と英語のため |
| 分離モデルの一覧 | audio-separator の一覧のうち VIP モデルは表示しない | VIP は UVR の有償支援者向けで、有料のモデルを使わない方針のため |
| 英語の発音指定 (phoneme) | IPA で指定する。エンジン内部で複数に分かれる語には使えない (読み替えタグを案内する) | 指定した発音を語単位でしか渡せないため |
| 保存場所の既定 | ライブラリ・モデルは `~/.kura_toolkit` の下、作業は OS の一時ディレクトリの中の `kura_toolkit` (アプリが作り、空になったら消す) | アプリのデータはホームディレクトリのアプリ用のフォルダに、一時ファイルは OS の一時ディレクトリに置く一般的な配置に合わせるため。作業ディレクトリをアプリ用のフォルダにするのは、OS の一時ディレクトリにある他のファイルと混ぜないため |
| 保存場所の指定 | 選んだフォルダをそのまま保存場所にする (中にフォルダを挟まない)。選べるのは空のフォルダだけ | 利用者が選んだ場所と実際の保存場所を一致させるため。空のフォルダに限るのは、アプリのファイルと他のファイルを混ぜず、片付けで他のファイルを消さないため |
| 保存場所の構成 | ライブラリはライブラリごと、モデルは分類 (`audio` など) と機能ごとのディレクトリに分ける。保存場所はアプリ全体で共有する | 今後ライブラリやモデルの種類が増えても、同じ場所の下に追加できるようにするため |
| 作業ディレクトリ | アプリは 1 つしか起動しない。作業ディレクトリの中にはアプリのフォルダ (`session/`・`jobs/`・`tmp/`・`recordings/`) だけを作り、それだけを消す | 複数のアプリが同じ保存場所を同時に書き換えないため。起動時に作業ディレクトリにあるアプリのフォルダを前回の残り物と判断でき、他のファイルに触れずに片付けられるため |
| 一時ファイルの置き場 | 作業ディレクトリには、その処理の中で作って使い、消すものだけを置く。ダウンロード・書庫・pip のキャッシュは置き場所と同じディスクに置く | 置き場所が別のドライブの場合に、コピーと削除が発生して時間がかかり、SSD を消耗させるため |
| 一時ファイルを消す時機 | 不要になった時点で消す (成功・エラー・キャンセルを問わない)。アプリの終了時には消さず、終了時に残っていたものは次の起動時に裏で消す | 不要なファイルを残さず、アプリの終了を待たせないため |
| 学習の途中のデータ | 作業ディレクトリのジョブのフォルダに置き、学習が終わったら消す。完成したモデルは、モデルディレクトリの作成中の声のモデルのフォルダに直接書かせる | 上流のソース一式 (ライブラリディレクトリ) を書き換えず、完成したモデルをドライブをまたいでコピーしないため |
| 取り込みのファイルの候補 | 候補が複数ある場合は、先頭に並べたものを選んだ状態で確認画面に示し、選び直せるようにする | 配布物には学習途中のチェックポイントや複数のインデックスが入っていることがあり、どれを取り込むかを利用者が確かめられるようにするため |
| リンク | シンボリックリンク・ジャンクション・ハードリンクを作らない。仮想環境も `--copies` で作る。上流がモデルを読む箇所を補正して、モデルディレクトリのファイルを直接読ませる | OS やファイルシステムの機能に依存する仕組みを持ち込まないため |
| 学習用の音声 | 指定したファイルは元の場所から直接読み、コピー・変換・削除をしない。録音は作業ディレクトリに置き、学習が終わったら消す | 利用者のファイルを複製せず、不要になった録音を残さないため |
| 分離の ONNX モデル (MDX-Net) の実行 | onnxruntime は GPU 版 (onnxruntime-gpu) を使わない。Windows では ONNX のモデルを CPU で実行する (PyTorch のモデルは GPU を使う) | CUDA / cuDNN の版の組み合わせに依存する GPU 版を避けるため |
| macOS の分離 | パッケージの一部 (diffq) がソースからのビルドになるため、Xcode Command Line Tools を必要とする (無ければ案内する) | 配布物に Apple Silicon 向けのビルド済みのものが無いため |
| ダウンロード画面の位置づけ | 必要な箇所から呼び出すダイアログにする | 音声機能を使う途中で必要になるもので、単独で使う機能ではないため |
| 声のモデルの管理と学習 | 音声変換・読み上げの画面上端の切り替えから、入力が無くてもいつでも開ける | 変換や読み上げの作業とは独立して行うため |

### 13.14 画面の構成と呼び出し (`components/voice/VoiceFeatureHeader.tsx` / `stores/voiceLibraryStore.ts`)

- 各音声機能の画面の上端に `VoiceFeatureHeader` を置く
  - 音声変換と読み上げは「変換 (読み上げ)」「声のモデル」「モデルの学習」を切り替えるタブを持つ
    (`/audio/conversion` ⇔ `/audio/conversion/models` ⇔ `/audio/conversion/training`、読み上げも同様)。
    変換する音声や読み上げる文章が無くても、声のモデルの管理と学習はいつでも開ける。
    作業中の内容は zustand ストアに残るため、切り替えても失われない
  - 右端の「ダウンロード管理」でダウンロードのダイアログを開く。開いたときは、その機能に関係する区分を表示する
    (分離 → 分離モデル、変換 → 音声変換のモデル、読み上げ → 読み上げ)
- ダウンロードのダイアログ (`VoiceLibraryDialog`) は App に 1 つだけ置き、`openVoiceLibrary({ select, focus })` で開く。
  `select` の項目を選んだ状態で開く。呼び出す箇所は次のとおり
  - 機能に必要なものが足りないときの案内 (`ReadinessAlert`): 足りない項目を選んで開く
  - 分離: 方式の選択の下の「分離モデルのダウンロード」、未取得のモデルを選んだときの「このモデルをダウンロード」
    (アンサンブルは未取得の構成モデルすべてを選ぶ)
  - 変換・分離・学習の実行時に必要なモデルが無い場合 (変換と学習は `MODEL_REQUIRED`、分離は `MODEL_NOT_INSTALLED`):
    その項目を選んで開く
  - 読み上げ: エンジンの選択の下の「エンジンのダウンロード」、言語に対応するエンジンが無いときの案内
  - 声のモデルの「取り込み」: Python 本体とパッケージ一式が無ければ、それを選んで開く
  - 読み上げの声のモデルの「プリセットの声を取得」: 未取得のプリセットの声をすべて選び、読み上げの区分を表示して開く
  - ライブラリディレクトリの移動後に、使えなくなったパッケージ一式がある場合 (アプリ設定の保存場所から): それを選んで開く
- ダイアログの下端は、左端に「選択した項目を削除」(押すと確認を出す) を置き、ダウンロードの操作 (選んだ項目の数と
  合計の大きさ・「選択した項目をダウンロード」) から離す (誤って押さないため)
- ダウンロード・削除・ライブラリの移動などで取得状況が変わったら `notifyVoiceLibraryChanged()` で `version` を増やす。
  取得状況を表示している画面 (`useFeatureReadiness`、分離の方式の一覧、声のモデルの一覧) は、この値の変化で読み直す。
  そのためダイアログで取得した後、呼び出し元の画面をそのまま続けられる

## 14. 音声分離 (`separation.ts` / `components/voice/SeparationWorkbench.tsx`)

楽曲などの音声を、ボーカル・伴奏・楽器別のパートなどに分離する単独の機能。分離には audio-separator を使う
(UVR で使われている MDX-Net・VR Arch・Demucs・MDXC の各モデルを扱えるパッケージ)。
同じ分離の操作部 (種類とモデルの選択・パラメーター・候補の比較・ボーカルと伴奏の採用) を、音声変換の画面にも組み込む (15.1)。

- 入力: 音声・動画ファイル (ffmpeg で読めるもの) を内部処理用の WAV にする (`prepareInput`)。
  チャンネル構成は元の音源のまま (3 チャンネル以上はステレオにまとめる)。長さ・チャンネル数・サンプリング周波数の
  いずれかを読み取れない音声は扱わない (`AUDIO_INFO_UNKNOWN`。音声変換の入力と学習用の音声の追加でも同じ)
- 方式の一覧 (`listSeparationModels`)
  - audio-separator の `list_models` 相当の一覧 (アーキテクチャ・出力の種類・SDR・表示名) を取得し、
    ライブラリディレクトリの `audio-separator/model-list.json` にキャッシュする (パッケージ一式の版が変わったら取り直す)
  - 分離の種類 (`vocals` 2 分割 / `multi` 楽器別 / `karaoke` メインとコーラス / `cleanup` 残響・エコー・ノイズの除去 /
    `other`) に分け、種類を選ぶとその用途のモデルが並ぶ。分類は出力の種類とモデル名から判定する。
    楽器別では、Demucs 系の 4 分割のモデルはボーカル・ドラム・ベース・その他に、6 分割のモデルはさらにギターとピアノにも分ける
  - アンサンブル: audio-separator 同梱の検証済みの組み合わせ (プリセット) と、任意のモデルの組み合わせ
    (組み合わせ方式を選ぶ) を選べる。一覧に無いモデルを使うプリセットは示さない。一覧に無いプリセットを指定された
    場合は止める (`ENSEMBLE_PRESET_NOT_FOUND`)
  - 機械学習を使わない比較用の手法: 中央定位の打ち消し (ffmpeg。伴奏 = 左右の差、ボーカル = 左右の平均)。ステレオの音源のみ
- パラメーター: 選んだモデルのアーキテクチャに応じて入力項目を切り替える。プリセット (13.10) で保存・呼び出しできる
  - MDX: セグメントサイズ・オーバーラップ・バッチサイズ・ホップ長・デノイズ
  - VR: ウィンドウサイズ・抽出の強さ・TTA・後処理 (としきい値)・高域処理・バッチサイズ
  - Demucs: セグメントサイズ (既定はモデルの値)・シフト数・オーバーラップ・セグメント処理
  - MDXC: セグメントサイズ (モデルの値を上書きするか)・オーバーラップ・バッチサイズ・ピッチシフト
- 実行: 結果を候補として一覧に加える。各出力は元の音源のチャンネル構成に戻す。未取得のモデルを選んだ場合は
  実行ボタンが「このモデルをダウンロード」に変わり、そのモデル (アンサンブルは未取得の構成モデルすべて) を選んだ状態の
  ダウンロード画面を開く
  - 進捗は audio-separator が出す進捗バー (tqdm) から読む。アンサンブルなどで複数のモデルを順に実行する場合は、
    バーが変わるたびに 0 から数え直す (`runtime.TqdmBridge`。1% 刻みの報告を前のバーの最後の値と比べると、
    次のモデルの進捗が報告されないため)
- 採用: 種類ごとに出力へ役割 (ボーカル / 伴奏、メイン / コーラス、整音後 / 除去した音) を割り当てる
  (`separationTracks.ts`)。2 分割の採用は「同じ候補を使う」と「別々に指定する」を切り替えられ、
  別々に切り替えたときはその時点の選択を初期値として引き継ぐ
- 多段処理: 採用した出力を入力にして段階を追加できる。前の段階の採用を変えると、以降の段階の結果を
  破棄することを確認してから変更する。後の段階が使っている候補は削除できない。コーラスの分離で取り除いたコーラスは、
  伴奏へ戻すか破棄するかを選べる
- 段階が 2 つ以上あるときは、最後の段階を取り除ける (「最後の段階を削除」)。その段階に候補があれば、候補ごと破棄する
  ことを確認してから取り除く
- 再生: 元音源・段階の入力・各出力の単独再生と、複数の出力の重ね合わせを同期再生で切り替える。
  出力の数は分離の種類によって異なるため、切り替える対象も出力の数に応じて増減する
- 各出力は、プレビューでも書き出しでも元の音源のチャンネル構成 (ステレオならステレオ) を保つ
- 書き出し (13.8)・音声変換への受け渡し (13.6)

## 15. 音声変換 (`conversion.ts` / `pages/voice/ConversionPage.tsx`)

入力した音声の声質を、選んだ声のモデルの声質に変換する機能。変換方式は RVC とし、変換と学習には Applio を使う。
扱う入力は、楽曲のボーカルの置き換え (分離・変換・伴奏との再合成)、朗読などの音声の置き換え、読み上げで作った音声の変換の 3 つ。

### 15.1 画面の流れ

- 1 つの画面で「入力と分離 → 変換 → 合成」の 3 段階 (ステップ) を順に進め、書き出しは合成の段階から行う。
  前の段階に戻って入力 (ボーカル・伴奏) が変わると、以降の結果を破棄することを確認する。
  合成の段階は、採用した候補が今の入力から作ったものである場合だけ開ける (入力が変わった場合は変換の段階で確認する)。
  合成結果は入力 (伴奏) も含めた組み合わせで作り直しを判定する
- 分離で採用したボーカル・伴奏が複数の出力から成る場合は、1 つに重ねたものを変換・合成・再生に使う
- 入力: 楽曲 (分離の操作部を画面内に組み込み、ボーカルと伴奏を採用する)・伴奏のない音声 (分離を省略)・
  音声分離や読み上げから受け取った音声
- 音声分離や読み上げから音声を受け取ったときに、作業中の結果 (読み込んだ楽曲・変換の候補) があれば、
  「新しい作業」と同じ確認を出す。破棄を承諾した場合は、受け取った音声を入力にして変換の段階から始める。
  承諾しなければ受け取った音声は使わず、作業をそのまま続ける

### 15.2 変換

- 声のモデル・キーの変更量 (-24〜+24 半音)・ピッチ抽出 (RMVPE / FCPE / CREPE / CREPE tiny)・インデックスの効き具合・
  音量エンベロープの混合率・子音の保護を指定する。既定はキー 0・RMVPE・0.75・1・0.5。結果は候補として並べる
- ボーカルは左右を平均したモノラルで変換し、伴奏と合わせるときは左右に同じ音を置いた中央定位のステレオにする
  (元の音源がモノラルならモノラルのまま)。RVC の変換は入力をモノラルとして扱い、Applio も入力を 16kHz の
  モノラルにして読み込むため。左右を別々に変換する方式は、左右の推定のずれで音が揺れやすいため採らない
- 変換後の声は、統合ラウドネス (ffmpeg の `ebur128`。無音の部分を除いて測る) が変換前のボーカル (モノラルにしたもの) と
  同じになるよう、音量をそろえる (`measureLoudness`)。どちらかが無音 (-70 LUFS 以下) で測れない場合はそろえない。
  合成のボーカルの音量 0 dB が、変換前のボーカルと同じ大きさになるようにするため
- キーの変更量がオクターブ単位 (±12 の倍数) 以外なら、伴奏を ffmpeg の rubberband で同じ量だけ移調する。
  指定中の ffmpeg に rubberband が無い場合は、その時点で理由と ffmpeg の見直し方を示して止める (`RUBBERBAND_UNAVAILABLE`)
  - 移調した伴奏は、作業の中に元の伴奏とキーの変更量ごとに置く (`session/<作業キー>/accompaniment/`)。
    同じ伴奏を別のキーで移調したときは、それまでのキーのものを消す (伴奏と重ねた試聴用の音は、候補ごとに持っている)
- 再生: 変換後のボーカル単体・変換前のボーカル・変換後のボーカルと伴奏・元の音源を同期再生で切り替える

### 15.3 合成

- pedalboard で、ボーカル・伴奏・全体の音量、ボーカルへのリバーブ (部屋の大きさ・高域の減衰・残響音の量・原音の量・
  ステレオの広がり。なしも可)、リミッター (音割れの防止) を適用する。パラメーターはプリセットで保存できる
- プレビューは書き出しと同じ処理でレンダリングした結果を再生する。設定や採用した候補を変えた後に書き出す場合は作り直す
- 合成結果は組み合わせ (変換後のボーカル・伴奏・パラメーター) ごとに作り、同じ組み合わせの結果があれば、移調も合成も
  せずにそれを使う。移調した伴奏が無ければ、合成結果を作るときにだけ作る。新しい合成結果を作ると、前の合成結果は消す
- ボーカルの音量の欄には、0 dB で変換前のボーカルと同じ大きさになることを示す (15.2)

### 15.4 声のモデル

- 区分は「学習」と「取り込み」(13.9)。変換のたびに使うモデルを選ぶ

### 15.5 書き出し

- 合成結果と変換後のボーカルを書き出せる (13.8)。書き出しは合成の段階から開き、合成結果が今の設定と合わない場合は、
  書き出しの前に作り直す

### 15.6 学習 (`training.ts` / `pages/voice/RvcTrainingPage.tsx`)

- Windows と macOS の両方で行える (13.1 の処理装置を使う)。学習のパラメーターはアプリが決め、利用者は名前を付けるだけ
- 学習用の音声: アプリ内での録音 (エコーキャンセル・ノイズ抑制・自動ゲイン調整は無効。AudioWorklet で 16bit PCM の WAV にする)、
  または音声ファイルの指定。内容と量に制限は設けず、変換したい音声に近い環境で録音するとよい旨だけを案内する
  - 指定したファイルは元の場所から直接読み、コピー・変換をせず、消さない。形式は学習の処理がそのまま読める
    WAV・MP3・FLAC・OGG に限る (`TRAINING_AUDIO_EXTENSIONS`。ファイルの選択もこの形式に絞り、それ以外は
    `TRAINING_FILE_UNSUPPORTED`)。同じファイルは重ねて加えない。学習の開始時に見つからないファイルがあれば止める
    (`TRAINING_FILE_MISSING`)
  - 録音は作業ディレクトリの `recordings/converter/` に置き、一覧から外したときと、学習が終わった時点 (成功・エラー・
    キャンセル) で消す。録音を一覧から外すときは、元に戻せないことを示して確認する (指定したファイルは一覧から外すだけで
    消さないため、確認せずに外す)
  - 一覧はこの起動中だけ持つ。学習が終わると一覧を空にし (指定したファイルは消さない)、アプリを終了すると一覧は消え、
    録音は次の起動時に消す (画面に注意書きを出す。3 章「保存場所」)
- 合計 10 秒未満では開始しない (`TRAINING_DATA_TOO_SHORT`)。10 分未満なら注意を出す
- パラメーターはアプリが決める: サンプルレート 40kHz・RMVPE・contentvec、エポック数は音声の合計時間で
  250 (5 分未満) / 200 (15 分未満) / 150 (30 分未満) / 100、バッチサイズは CUDA で VRAM 8GB 以上なら 8 それ以外は 4、
  10 エポックごとに保存
- 流れ: 前処理 → 特徴量の抽出 → 学習 → インデックスの作成 → 完成したモデルを安全な形式で声のモデルとして登録
  (区分は「学習」)。進捗は段階とエポックで示す
  - 学習の途中のデータ (前処理した音声・特徴量・チェックポイント) は、作業ディレクトリのジョブのフォルダ
    (`jobs/training-<ID>/`) の実験フォルダ (`logs/<名前>/`) に置き、学習が終わった時点 (成功・エラー・キャンセル) で
    main プロセスがジョブのフォルダごと消す。上流のソース一式の中には書かない
  - 前処理・特徴量の抽出・インデックスの作成は Applio のフォルダをカレントディレクトリにして動かし (Applio の設定と
    無音のサンプルを相対パスで読むため)、実験フォルダを明示して渡す。Applio の学習スクリプトは、ジョブのフォルダを
    カレントディレクトリにして動かす (`<カレントディレクトリ>/logs/<名前>/` にファイルを置くため)。精度の設定は、
    Applio の `assets/config.json` の `precision` をジョブのフォルダの `assets/config.json` に書いて渡す
  - 前処理は、指定したファイルと録音の一覧を Applio の 1 ファイル分の処理で行う (`rvc_preprocess.py`。
    上流の前処理は 1 つのフォルダの中を処理するため)。音声を得られなかったファイルがあれば、そのファイル名を示して止める
    (`TRAINING_FILE_UNREADABLE`)。前処理で切り出した音声が 1 つも無い (無音や短すぎる音声だけ) 場合も止める
    (`TRAINING_NO_AUDIO`)
  - 特徴量の抽出の後、切り出した音声ごとにピッチ (`f0`・`f0_voiced`) と埋め込み (`extracted`) のファイルがそろっているかを
    確かめ、欠けたものがあれば元のファイル名 (5 件まで、残りは件数) を示して止める (`TRAINING_EXTRACT_FAILED`)。
    Applio は抽出に失敗した音声をエラーの表示だけで飛ばし、そろった音声だけで学習を続けるため
  - インデックスは `rvc_index.py` (Applio の `extract_index.py` を、`faiss.write_index` の書き先を差し替えて動かす) で、
    作成中の声のモデルのフォルダに直接書く (作業ディレクトリが別のドライブでもコピーしないため)。
    作られなかった場合は止める (`TRAINING_NO_INDEX`)
  - 完成した重みは、安全な形式 (`model.safetensors`・`model.json`) にして作成中の声のモデルのフォルダに直接書き、
    声のモデルとして登録する (13.9)

## 16. 読み上げ (`tts.ts` / `pages/voice/TtsPage.tsx` / `shared/voice/`)

入力した文章を音声として読み上げる機能。音声合成のエンジンは Style-Bert-VITS2 の派生版 (13.4) に固定する。

### 16.1 入力と設定

- エンジンは日本語版 (JP-Extra) と多言語版の 2 種類。どちらも利用者が任意にダウンロードでき、ダウンロード済みのものだけを
  選択肢に表示する。日本語だけを読む場合は JP-Extra 版が推奨されている。多言語版は言語ごとの BERT を使い、
  英語の読み上げには多言語版が必要 (多言語版の取得には英語の BERT と、英語の発音推定に使う NLTK のデータを含める)

- 入力の種類はテキスト・SRT・WebVTT。ファイルの読み込み時に文字コードを判定する (BOM 付き UTF-8・UTF-16・UTF-8・Shift_JIS)。
  20 MB を超えるファイルは読み込まない (`TEXT_FILE_TOO_LARGE`)。読み込んだ改行は LF にそろえる。
  編集は画面上だけで行い、ファイルへの反映は保存操作のときだけ (BOM なしの UTF-8 で、改行は OS の標準 (Windows は CRLF、
  macOS は LF) にして書く。一時ファイルへ書いてから置き換える)。未保存の変更があれば、新しい文章を始める前と
  ファイルを開く前 (ファイルの選択の前) に、破棄してよいかを確認する
- 言語 (初期値はアプリの表示言語)・エンジン (ダウンロード済みのものだけ)・声のモデル (エンジンと言語が合うものだけ)・
  スタイルと強さ・話速・音高・抑揚・SDP 比・ノイズ・行間の間・記号の読み上げを指定する。
  言語に対応するエンジンが未取得なら、ダウンロード画面への案内を出す
- 結果は候補として並べ、聞き比べる。音声変換へ送れる (13.6)

### 16.2 制御タグ (`shared/voice/control-tags.ts`)

- W3C SSML のサブセット: `break` (time / strength)、`prosody` (rate / pitch / volume)、`sub` (alias)、`phoneme` (ph / alphabet)
  - 入れ子の prosody は話速を掛け合わせ、音高と音量は足し合わせる。範囲は話速 25〜400%、音高 ±24 半音、音量 -40〜+20 dB、
    間は 30 秒まで
- 制御タグとして扱うのは半角の「<」「>」で書かれ、「<」(閉じタグは「</」) の直後が既知のタグ名で、その後に空白・「/」・「>」の
  いずれかが続くものだけ。それ以外の「<～>」は本文として扱い (括弧内の文字は読み上げ、「<」「>」自体は記号の読み上げの設定に従う)、
  全角の「＜」「＞」は常に本文として扱う。本文に既知のタグと同じ文字列を書くときは `&lt;` などの置き換え表記を使う
- 構文チェックは入力中にも行い、誤りは行・文字位置・内容を示して編集画面の該当箇所を強調表示する。合成の開始時に誤りがあれば止める
  - 止める誤り: 属性の誤り (属性名の誤り・値の書式不正や範囲外・必須の属性の欠落) と、構文の誤り (引用符の閉じ忘れ・
    閉じタグの欠落・対応しない閉じタグ・入れ子の不整合)
  - 単独で完結するタグ (break) の終端の「/」の省略は補って受け入れる。閉じタグが必要なタグに閉じタグが無い場合は止める
  - タグ名・属性名の大文字小文字の違いと、タグ内の向き付き引用符は、一覧を示して一括修正の可否を 1 回だけ確認する。
    承諾されれば編集画面の原文を書き換えて合成を続け、拒否されれば止める
- タグの一覧ダイアログ (`TagListDialog.tsx`) で、説明・属性と値の書式・記述例を示し、カーソル位置への挿入と選択範囲の囲みができる。
  挿入と囲みは入力欄への編集として行うため、Ctrl+Z (元に戻す) で取り消せる

### 16.3 日本語アクセント記法 (`shared/voice/accent.ts`)

- `phoneme` の `ph` にカタカナの読みを書き、アクセント核 (音が下がる直前の拍) の直後に「'」、アクセント句の区切りに「/」を置く
  (「'」が無ければ平板型)。本文側には元の表記 (漢字など) を書き、読みとアクセントは属性側に持たせるため、記号が本文に混ざらない
- 東京式アクセントの規則で各拍の高低を求める: アクセント核が 1 拍目なら 1 拍目が高く以降が低い。核がそれ以外の位置なら
  1 拍目が低く、2 拍目から核まで高く、その後が低い。平板型は 1 拍目が低く 2 拍目以降が高い (トーンは 0 が低、1 が高)
- 求めた高低を、読みを表す音素列とトーン列としてエンジンに渡す。エンジンは改行ごとの分割生成を有効にすると
  これらを無視するため、この指定を含む区間は改行ごとの分割生成を使わずに合成する
- 本文の表記と指定した読みをエンジンが対応付けられない場合 (`InvalidPhoneError`) に限り、読み (カタカナ) を本文として
  合成し直す。それ以外のエラーはそのまま失敗とする (別の原因の失敗を読みの問題として隠さないため)
- 日本語以外の文章中で使われた場合は構文の誤りとして止める

### 16.4 英語の発音指定 (`shared/voice/ipa.ts`)

- 英語の `phoneme` は IPA で指定する。ARPAbet に変換してエンジンの発音辞書へ一時的に登録して合成する
- 破擦音は連結記号の有無を問わず読む (`tʃ`・`t͡ʃ`・`t͜ʃ` は CH、`dʒ`・`d͡ʒ`・`d͜ʒ` は JH)
- 包んだ語の数と発音の語の数が一致しない場合と、エンジン内部で複数に分かれる語は、誤りとして止める (読み替えタグを案内する)

### 16.5 記号の読み上げ

- 実行時に読み上げるかを選べる (既定は読み上げない)。記号と読みは言語ごとに初期値を持ち (例: 「<」は日本語なら
  「しょうなり」、英語なら「less than」)、利用者が追加・変更できる (`settings.voice.symbolReadings`、言語ごと)
- 文脈によって読みが変わる記号 (「-」「~」「/」など) は、定義では代表的な読みを 1 つ持ち、個別の箇所は読み替えタグ (`sub`) で指定する
- 全角と半角は別の記号として扱い、アプリ全体で全角・半角の変換は行わない。句読点は常に読みの区切りとして扱い、設定の対象外

### 16.6 タイムライン (`shared/voice/subtitles.ts`)

- SRT / WebVTT の区間ごとに合成し、開始時刻に配置して 1 本の音声にまとめる。区間より短ければ無音で埋める
- WebVTT は先頭 (BOM と空行を除く) が `WEBVTT` で始まること (`subtitleHeader`)。続くヘッダーの行 (`Kind:`・`Language:`
  など) は最初の空行まで読み飛ばす
- 区間は開始時刻の順に並んでいること。前の区間より早く始まる区間があれば誤りとして止める (`subtitleSequence`。
  収まらない場合の扱いを並び順で決めるため)。終了が開始より後でない区間も誤り (`subtitleOrder`)
- 収まらない場合の扱いを「話速を上げて収める (既定)」「次の区間と重ねる」「後続の区間を後ろにずらす」「警告のみ」から選べ、
  区間ごとにも指定できる
- 話速を上げる場合は、エンジンの話速を上げて合成し直し、残ったわずかな差を rubberband の時間伸縮で詰める
  (制御タグで話速を指定している区間は、その指定に倍率を掛ける)。上限は設けず、1.3 倍を超える区間があれば
  区間の番号・時刻・本文・必要な倍率の一覧を示して 1 回だけ確認する。1 回目の合成結果は確認後の続きに使う。
  確認に対応する結果が無い場合と、確認を求めた後に依頼の内容 (文章・設定) が変わった場合は続きから処理せず、
  もう一度実行するよう求める (`TTS_CONFIRMATION_EXPIRED`)
- 実行後に、話速を調整した区間とその倍率、収まらなかった区間を示す

### 16.7 学習 (`training.ts` / `pages/voice/TtsTrainingPage.tsx`)

- NVIDIA GPU を搭載した Windows でのみ行える (上流の Style-Bert-VITS2 が NVIDIA GPU を前提としているため、13.1)
- 言語と文章の種類 (簡易・精度重視) を選び、提示した 1 文ずつ録音するか、その文に対応する音声ファイルを指定する。
  複数の文を続けて録ったファイルの分割は利用者が行い、アプリは自動分割や自動書き起こしを行わない。
  提示した文章をそのまま書き起こしとして使う。学習には 2〜14 秒程度の音声が向くため、外れる音声には注意を出す。
  録音ではエコーキャンセル・ノイズ抑制・自動ゲイン調整を無効にする
- 録音中 (録音の開始操作からマイクの許可の確認を含めて止めるまで) は、文の移動と言語・文章の種類の切り替えを無効にし、
  録音は録音を始めた時点の言語・文章の種類・文に保存する (別の文の録音として保存しないため)
- 録音の画面を離れた後にマイクの許可の確認などの待ちが終わった場合は、開いたマイクと音声処理をその場で閉じる
  (音声機能の録音すべてで同じ。`useRecorder`)
- 文章の種類は renderer から渡され、録音の保存先のフォルダ名に使うため、`quick` と `accurate` 以外は断る (`INVALID_CORPUS_SET`)
- 学習用の音声の扱いは 15.6 と同じ。指定したファイルは元の場所から直接読み、録音は作業ディレクトリの
  `recordings/tts-<言語>-<種類>/` に置く。文の音声を差し替えたときは前の録音を消す (指定したファイルは消さない)。
  文から録音を外すときは、元に戻せないことを示して確認する。一覧は言語と文章の種類ごとにこの起動中だけ持ち、
  学習が終わった時点で録音を消して一覧を空にする
- 学習用の文章 (13.11): 日本語は ITA コーパス (Emotion 100 文と Recitation 324 文。どちらのサブセットも日本語の音の
  組み合わせを豊富に含むよう設計されている) で、簡易は Emotion の 100 文、精度重視は全 424 文。英語は CMU ARCTIC の
  読み上げ文 (Project Gutenberg の著作権切れのテキストから選ばれた 1,132 文) で、簡易は set a の先頭 100 文、精度重視は全文
- 10 文以上で学習できる (`TRAINING_DATA_TOO_FEW`)。日本語は JP-Extra 版と多言語版、英語は多言語版で学習する。
  異なるエンジンで作ったモデル同士に互換性は無い
- パラメーターはアプリが決める: バッチサイズは VRAM 12GB 以上で 4 / 10GB 以上で 3 / 8GB 以上で 2 / それ未満で 1、
  エポック数は総ステップ数がおよそ 8000 になるよう 20〜200 の範囲で決める
- 流れ: データの準備 → 前処理 (リサンプリング・テキストの前処理) → 特徴量の抽出 (BERT・スタイル) → 学習 →
  完成したモデル (`model.safetensors`・`config.json`・`style_vectors.npy`) を声のモデルとして登録 (区分は「学習」)。
  作成したモデルには利用者が名前を付ける
  - リポジトリの学習スクリプトは、作業ディレクトリのジョブのフォルダ (`jobs/training-<ID>/`) をカレントディレクトリに
    して動かし、スクリプトが読む `config.yml` と `configs/paths.yml` をそのフォルダに書く。`dataset_root` はジョブの
    フォルダの `Data/`、`assets_root` はモデルディレクトリの作成中の声のモデルのフォルダとし、完成したモデル
    (重み・`config.json`・`style_vectors.npy`) をモデルディレクトリに直接書かせる。スクリプトが作る `<名前>/` の
    フォルダから 3 ファイルを名前の変更で 1 つ上へ移し (重みは `model.safetensors` にする)、そのフォルダを消す
  - 学習の途中のデータ (リサンプリングした音声・特徴量・チェックポイント) はジョブのフォルダの `Data/<名前>/` に置き、
    学習が終わった時点 (成功・エラー・キャンセル) で main プロセスがジョブのフォルダごと消す。上流のソース一式の中には書かない
  - リサンプリングは、指定したファイルと録音を元の場所から 1 つずつ読み、`Data/<名前>/wavs/` に 44.1kHz の WAV として書く
    (上流の `resample.py` は 1 つのフォルダの中を処理するため、同じ処理をファイルごとに行う)
  - 学習の初期値はモデルディレクトリの事前学習モデルから直接読み、読めなければ止める
    (`TRAINING_PRETRAINED_UNREADABLE`。13.4)。学習の設定を作る時点で事前学習モデル (`G_0.safetensors`) が無ければ、
    学習を始めずに止める (`TRAINING_PRETRAINED_MISSING`)
  - テキストの前処理で読みを得られない文があれば、その文を除かずに前処理を失敗として止める (上流の `--yomi_error raise`。
    `TRAINING_STEP_FAILED`)。提示した文と録音の対応を黙って減らさないため

### 16.8 声のモデルとプリセットの声

- 区分は「プリセット」「取り込み」「学習」(13.9)。各モデルにはエンジンの形式と対応言語を記録し、対応する言語の文章にだけ使う
- プリセットの声: Style-Bert-VITS2 の作者が公開している JVNV コーパスのモデル (女性 2 種・男性 2 種) を、
  ダウンロードのダイアログから取得する。声のモデルの画面の「プリセットの声を取得」は、未取得のプリセットの声を選んだ状態で
  ダイアログを開く (13.14)。JP-Extra 版 (jvnv-F1-jp / F2-jp / M1-jp / M2-jp、本体は約 251MB) と
  多言語版 (jvnv-F1 / F2 / M1 / M2、約 199MB。2.0 より前の形式だが、そのまま使える) がある。
  ライセンスは CC BY-SA 4.0 (学習元の JVNV コーパスから引き継がれている) で、ライセンスと配布元を表示する。
  名前はアプリが自動で付け、利用者が変更してもプリセットの区分は保つ。選んだプリセットに必要なエンジンも一緒に取得し、
  その大きさも合計に含めて示す
- 取り込むモデルは設定ファイル (`config.json`)・モデル本体 (safetensors)・スタイル情報 (`style_vectors.npy`) の 3 ファイルで構成される
  (Style-Bert-VITS2 も推論にこの 3 つを必要とし、モデルを共有する場合はこの 3 つを共有するよう説明している)
- 読み上げで作った音声は、同じ作業の中で音声変換の入力として渡せる (13.6)
